


제시하신 코드는 자바의 가장 기본적인 캡슐화(Encapsulation)를 구현한 메서드들이며, 컴파일러와 JVM(자바 가상 머신)을 통해 메모리 상에서 실행됩니다.
동작 원리를 핵심적인 세 가지 관점으로 나누어 설명해 드립니다.
## 1. 객체 지향적 원리: 캡슐화와 접근 제어

* private 필드 제한: id와 name 변수는 private으로 선언되어 외부 클래스가 직접 수정하거나 읽을 수 없습니다. (예: user.name = "홍길동" 불가)
* 우회 통로 개설: public으로 선언된 Getter와 Setter 메서드가 변수에 접근할 수 있는 유일한 '공식 통로' 역할을 합니다.
* 데이터 보호: 원한다면 Setter 메서드 내부에서 if(name == null) 같은 검증 로직을 추가해 잘못된 데이터가 들어오는 것을 막을 수 있습니다.

## 2. 메모리 상에서의 구체적 동작 방식
컴파일된 자바 코드가 실행되면 메모리(JVM Stack과 Heap 영역)에서 다음과 같이 작동합니다.

* getName() (Getter) 호출 시:
1. 외부에서 user.getName()을 호출합니다.
   2. JVM은 Heap 메모리에 생성된 해당 User 인스턴스를 찾습니다.
   3. 인스턴스 내부의 name 필드에 저장된 데이터의 참조 주소(또는 값)를 복사하여 호출한 곳으로 반환합니다.
* setName(Long id) (Setter) 호출 시:
1. 외부에서 user.setName("이순신")을 호출합니다.
   2. 매개변수로 전달된 "이순신"이라는 값이 메서드의 지역 변수(id 또는 name)로 들어옵니다.
   3. this.name = name; 문장이 실행됩니다. 여기서 this는 현재 접근 중인 실제 인스턴스 자신을 가리키므로, Heap 메모리에 있는 해당 객체의 실제 name 변수 값이 새로운 값으로 갱신됩니다.

## 3. 스프링 및 JPA 프레임워크와의 연동 원리 (Reflection)
스프링과 JPA(Hibernate)는 자바의 리플렉션(Reflection) 기술을 사용해 이 메서드들을 자동으로 찾아 실행합니다.

* 자바 빈 규약(JavaBeans Spec): 자바 진영에는 메서드 이름이 get + 필드명, set + 필드명으로 시작해야 한다는 약속이 있습니다.
* 자동 데이터 매핑: 데이터베이스에서 회원 정보를 조회하면, JPA는 이 규칙을 바탕으로 getName()과 setName()을 알아서 호출하여 DB 데이터를 자바 객체 안으로 쏙 넣어줍니다.

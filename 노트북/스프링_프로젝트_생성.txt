## 빌드 도구 트렌드 요약

* 
* Gradle - Groovy (build.gradle): 여전히 실무와 기존 강의(인프런, 유튜브 등)에서 
가장 흔하게 쓰이는 레거시이자 표준입니다. 무난하고 가벼운 설정을 원할 때 선택합니다. 
* Gradle - Kotlin (build.gradle.kts): 최근 새로 시작하는 프로젝트나 
대규모 프로젝트에서 강력히 권장되는 트렌드입니다. 
스프링 공식 문서의 가이드 코드도 현재는 Groovy와 Kotlin DSL을 동시에 제공하고 있습니다. 
* 

------------------------------
## Groovy vs Kotlin DSL 직관적인 비교

| 비교 항목 | Gradle - Groovy | Gradle - Kotlin |
|---|---|---|
| 확장자 | build.gradle | build.gradle.kts |
| 타입 체크 | 동적 타입 (에러를 실행해 봐야 암) | 정적 타입 (컴파일 시점에 에러 잡음) |
| IDE 지원 | 자동완성이 부실하거나 오타를 잘 못 잡음 | 오타 자동완성, 코드 탐색이 완벽함 |
| 자료의 양 | 수년간 쌓인 레퍼런스가 압도적으로 많음 | 최신 자료 위주이나 공식 문서 지원 완벽 |
| 구문 제약 | 따옴표(', ") 혼용 가능, 괄호 생략 등 자유로움 | 엄격한 문법 제약 (규칙적인 코드 유지 가능) |

------------------------------
## 무엇을 선택해야 할까요?

   1. 학습용 / 인강 시청 중인 경우 ➡️ Gradle - Groovy 추천
   *  대부분의 국내 스프링 부트 강의나 블로그 글이 Groovy 기준으로 작성되어 있습니다. 똑같이 맞춰서 해야 따라 하기 편합니다.
   2. 신규 프로젝트 / 자동완성이 중요한 경우 ➡️ Gradle - Kotlin 추천
   * 자바 개발자라도 빌드 스크립트 작성 시 Kotlin DSL을 쓰면 IntelliJ에서 라이브러리 이름을 자동완성해 주고 오타를 바로 빨간 줄로 잡아주기 때문에 개발 생산성이 훨씬 올라갑니다.
   
💡 결론: 처음이거나 안전하게 가고 싶다면 기본값인 Groovy를, IntelliJ의 강력한 자동완성과 타입 안정성을 경험해 보고 싶다면 Kotlin을 선택하세요.

## 1. Packaging: Jar vs War

* 
* 정답: Jar를 선택하세요.
* 이유: 요즘 배포 환경의 표준인 Docker 컨테이너 및 클라우드(AWS 등) 
환경에서는 내장 톰캣이 포함된 Jar가 압축 및 배포에 압도적으로 유리합니다. 
외장 WAS(톰캣 등)를 서버에 따로 설치하고 밀어 넣는 War 방식은 이제 구형 레거시 시스템 외에는 거의 쓰이지 않습니다.
* 

## 2. Configuration: Properties vs YAML

* 
* 정답: YAML을 강력히 추천합니다.
* 이유: YAML은 계층 구조(Tree)로 가독성이 좋고, 중복 코드가 줄어들어 설정이 복잡해질수록 관리가 훨씬 편합니다.
* 비교:
* Properties: spring.datasource.url=..., spring.datasource.username=... 처럼 매번 앞부분을 중복해서 적어야 합니다.
   * YAML: spring: 아래에 들여쓰기로 깔끔하게 묶을 수 있어 대다수의 최신 실무 프로젝트와 오픈소스에서 표준처럼 사용됩니다.
* 

## 3. Java: 26 / 25 / 21 / 17 버전 선택

* 
* 정답: 일반적으론 21 (안정적), 트렌디하게 가려면 25를 선택하세요. [1, 2] 
* 버전별 상황:
* Java 21: 현재 현업에서 가장 선호하는 대세 LTS(장기 지원) 버전입니다. 가상 스레드(Virtual Thread)를 정식 지원하여 스프링 부트 3.x 환경과 궁합이 가장 좋습니다.
   * Java 25: 최근 출시된 최신 LTS 버전입니다. 스프링 부트 4.x 버전을 사용하거나 최신 기능을 적극 도입하려는 신규 프로젝트에서 빠르게 늘고 있습니다.
   * Java 17: 스프링 부트 3.x의 최소 요구 조건이지만, 이제는 21 버전으로 많이 넘어간 추세입니다.
   * Java 26: 아직 정식 LTS 버전이 아니므로 학습 목적이 아니라면 실무 프로젝트 설정으로는 추천하지 않습니다. [1, 2, 7]

## 빌드 도구 트렌드 요약

* 
* Gradle - Groovy (build.gradle): 여전히 실무와 기존 강의(인프런, 유튜브 등)에서 가장 흔하게 쓰이는 레거시이자 표준입니다. 무난하고 가벼운 설정을 원할 때 선택합니다. [4, 5, 6] 
* Gradle - Kotlin (build.gradle.kts): 최근 새로 시작하는 프로젝트나 대규모 프로젝트에서 강력히 권장되는 트렌드입니다. 스프링 공식 문서의 가이드 코드도 현재는 Groovy와 Kotlin DSL을 동시에 제공하고 있습니다. [1, 7] 
* 

------------------------------
## Groovy vs Kotlin DSL 직관적인 비교

| 비교 항목 | Gradle - Groovy | Gradle - Kotlin |
|---|---|---|
| 확장자 | build.gradle | build.gradle.kts |
| 타입 체크 | 동적 타입 (에러를 실행해 봐야 암) | 정적 타입 (컴파일 시점에 에러 잡음) |
| IDE 지원 | 자동완성이 부실하거나 오타를 잘 못 잡음 | 오타 자동완성, 코드 탐색이 완벽함 |
| 자료의 양 | 수년간 쌓인 레퍼런스가 압도적으로 많음 | 최신 자료 위주이나 공식 문서 지원 완벽 |
| 구문 제약 | 따옴표(', ") 혼용 가능, 괄호 생략 등 자유로움 | 엄격한 문법 제약 (규칙적인 코드 유지 가능) |

------------------------------
## 무엇을 선택해야 할까요?

   1. 학습용 / 인강 시청 중인 경우 ➡️ Gradle - Groovy 추천
   * 김영한 님 강의를 비롯한 대부분의 국내 스프링 부트 강의나 블로그 글이 Groovy 기준으로 작성되어 있습니다. 똑같이 맞춰서 해야 따라 하기 편합니다. [6, 8, 9] 
   2. 신규 프로젝트 / 자동완성이 중요한 경우 ➡️ Gradle - Kotlin 추천
   * 자바 개발자라도 빌드 스크립트 작성 시 Kotlin DSL을 쓰면 IntelliJ에서 라이브러리 이름을 자동완성해 주고 오타를 바로 빨간 줄로 잡아주기 때문에 개발 생산성이 훨씬 올라갑니다. [1, 10] 
   
💡 결론: 처음이거나 안전하게 가고 싶다면 기본값인 Groovy를, IntelliJ의 강력한 자동완성과 타입 안정성을 경험해 보고 싶다면 Kotlin을 선택하세요. [4, 10, 11]

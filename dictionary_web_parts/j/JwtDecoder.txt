org.springframework.security.oauth2.jwt.JwtDecoder는 스프링 시큐리티(Spring Security)에서 
JWT(JSON Web Token) 문자열을 파싱하고 서명·만료 등 유효성을 검증한 뒤 Jwt 객체로 변환하는 인터페이스입니다. 
주로 OAuth2 리소스 서버(spring-boot-starter-oauth2-resource-server)가 요청에 담긴 토큰을 검증할 때 핵심 역할을 합니다. 

주요 역할과 동작 방식

• 토큰 파싱 및 검증: decode(String token) 메서드를 통해 JWT 문자열의 구조와 서명, 만료 시간(exp), 발급자(iss) 
등을 검증하고 실패 시 JwtException을 발생시킵니다.
• 리소스 서버 인증 연동: JwtAuthenticationProvider가 JwtDecoder.decode(token)을 호출해 토큰을 검증하고, 
결과를 바탕으로 인증(Authentication) 객체를 만듭니다.
• 대표 구현체(NimbusJwtDecoder): 인가 서버의 jwk-set-uri에서 공개키(JWK Set)를 가져와(기본 5분 캐시) 서명을 검증하는 기본 구현체입니다. 

사용 예시

• 자동 설정(JWK Set URI 기반): application.yml에 spring.security.oauth2.resourceserver.jwt.jwk-set-uri를 지정하면 
스프링 부트가 NimbusJwtDecoder 빈을 자동으로 구성합니다.
• 커스텀 빈 등록: 대칭키/비대칭키 직접 지정, 커스텀 클레임 검증(OAuth2TokenValidator) 추가 등이 필요할 때 
@Bean으로 JwtDecoder를 직접 정의해 사용합니다. 자세한 검증 흐름은 스프링 시큐리티 JWT 인증 원리 — 리소스 서버 검증 흐름에서 확인할 수 있습니다.

관련 개념 및 대체·보완 요소

• 연관 컴포넌트: Jwt(디코딩된 토큰 모델), JwtEncoder(JWT 생성·서명 인터페이스), JwtAuthenticationConverter(권한 매핑).
• 대체·보완 방식: 불투명 토큰(Opaque Token)을 쓸 때는 OpaqueTokenIntrospector를, 자체 발급 JWT나 커스텀 필터를 쓰는 구조에서는 
별도 토큰 검증기(JwtTokenProvider 등)를 함께 두기도 합니다.
구현 중인 인증 방식(OAuth2 리소스 서버, 자체 JWT 발급 등)이나 커스텀 검증이 필요한 조건을 알려주시면 설정 코드나 빈 구성 예시를 안내해 드릴 수 있습니다.

jwtDecoder.setJwtValidator(JwtValidators.createDefaultWithValidators(
        new JwtIssuerValidator(location),
        JwtTypeValidator.jwt()
));

해당 코드는 Spring Security에서 JWT(JSON Web Token)를 디코딩한 후, 토큰의 유효성을 검증하는 규칙(Validator)을 설정하는 코드입니다.
기본 검증 규칙에 발급자(Issuer) 검증과 토큰 타입(Type) 검증을 추가로 결합하여 적용하겠다는 의미입니다. 각 구성 요소를 하나씩 풀어서 설명해 드리겠습니다.

1. jwtDecoder.setJwtValidator(...)

• JwtDecoder는 문자열 형태의 JWT를 파싱하고 서명(Signature)을 검증한 뒤, 마지막으로 토큰 내부의 클레임(Claim)과 헤더가 정상적인지 확인합니다.
• setJwtValidator는 이 마지막 단계에서 사용할 검증기(Validator)를 지정하는 메서드입니다.

2. JwtValidators.createDefaultWithValidators(...)

• Spring Security가 제공하는 기본 검증기(Default Validator)에 개발자가 원하는 커스텀 검증기들을 추가하여 하나로 묶어주는(Delegating) 유틸리티 메서드입니다.
• 기본 검증기에 포함된 항목:
	• JwtTimestampValidator: 토큰의 만료 시간(exp)이 지나지 않았는지, 활성화 시간(nbf)이 지났는지 검증합니다. (기본적으로 시계 오차 60초를 허용합니다.)

3. new JwtIssuerValidator(location)

• JWT 페이로드(Payload)의 iss (Issuer, 발급자) 클레임이 location 변수에 담긴 값과 정확히 일치하는지 검증합니다.
• 예를 들어 location이 "https://example.com"이라면, 다른 인가 서버에서 발급된 토큰이 들어왔을 때 이를 차단하는 역할을 합니다.

4. JwtTypeValidator.jwt()

• JWT 헤더(Header)의 typ (Type) 값이 표준 JWT 형식인지 검증합니다.
• JwtTypeValidator.jwt()는 헤더의 typ 값이 "JWT"(대소문자 무관, 또는 application/jwt)이거나, typ 헤더 자체가 아예 없는 경우에만 통과시킵니다.
• 만약 typ 헤더에 "at+jwt"(Access Token 전용 타입)나 다른 엉뚱한 값이 들어있다면 검증에 실패하게 됩니다. (토큰 혼동 공격 방지 목적)

요약

이 설정이 적용된 JwtDecoder는 토큰을 받을 때마다 다음 3가지 조건을 모두 만족해야만 정상 토큰으로 인정합니다.
1. 시간이 유효할 것 (exp, nbf 검증 - 기본 포함)
2. 지정된 발급자(location)가 만든 토큰일 것 (iss 검증)
3. 헤더의 타입이 일반 JWT일 것 (typ 검증)
혹시 특정 에러(예: JwtValidationException)를 해결하기 위해 이 코드를 살펴보시는 중인가요? 
발생한 에러 메시지나 사용 중인 인증 서버(Keycloak, Auth0, 자체 서버 등)를 알려주시면 원인과 해결 방법을 바로 짚어드릴 수 있습니다.

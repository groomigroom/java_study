org.springframework.data.redis.serializer.Jackson2JsonRedisSerializer는 Spring Data Redis에서 Java 객체를 JSON 포맷의 바이트 배열로 
직렬화(Serialization)하거나, 반대로 JSON 데이터를 다시 Java 객체로 역직렬화(Deserialization)하기 위해 사용하는 변환기입니다. 
스프링 부트(Spring Boot)에서 RedisTemplate 등을 통해 Java 객체를 Redis에 저장하거나 읽을 때 이 클래스가 어떤 의미를 가지는지 핵심만 정리해 드립니다.

주요 특징과 역할

1. JSON 형태로 데이터 저장
	• Java 객체(예: DTO, Entity 등)를 사람이 읽기 쉬운 표준 JSON 문자열(바이트) 형태로 변환하여 Redis에 저장합니다.
	• 다른 언어(Node.js, Python 등)나 외부 클라이언트가 Redis에 직접 접속해 데이터를 조회했을 때 JSON 구조를 바로 파악할 수 있습니다. 
2. 클래스 타입 정보(@class)를 포함하지 않음
	• GenericJackson2JsonRedisSerializer와 달리, 저장할 때 JSON 내부에 @class 같은 Java 패키지/클래스 메타데이터를 기본적으로 포함하지 않습니다.
	• 따라서 역직렬화할 때 어떤 타입으로 변환할지 명시적으로 지정해 주어야 합니다. (예: new Jackson2JsonRedisSerializer<>(UserDto.class)) 

3. 주의할 점 (Type Cast 이슈)
	• 타입 정보를 명시하지 않고 역직렬화하거나 컨텍스트가 부족하면, Jackson이 JSON을 기본적으로 LinkedHashMap 형태로 읽어 들여 나중에 캐시나 데이터를 
꺼낼 때 ClassCastException이 발생할 위험이 있습니다. 

다른 Serializer와의 간단 비교

• StringRedisSerializer: 문자열(Key나 단순 Text Value) 저장에 주로 사용
• JdkSerializationRedisSerializer: 자바 기본 직렬화 사용 (RedisTemplate의 기본값인 경우가 많음, 바이너리 저장, 용량 큼, 클래스 변경 시 역직렬화 에러 위험)
• GenericJackson2JsonRedisSerializer: JSON으로 직렬화하되 내부에 @class 타입 정보를 함께 저장해서 역직렬화 시 타입을 자동 유추
• Jackson2JsonRedisSerializer: JSON으로 직렬화하지만 타입 정보를 포함하지 않으므로 변환할 대상 클래스 타입을 직접 지정해서 사용 
만약 RedisTemplate이나 Spring Cache 설정 중 해당 Serializer를 적용하려다 발생한 구체적인 에러가 있거나, 다른 Serializer와의 
차이점이 궁금하신가요? 상황을 알려주시면 알맞게 코드를 구성해 드릴 수 있습니다.

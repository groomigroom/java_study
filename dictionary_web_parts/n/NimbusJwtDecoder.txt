org.springframework.security.oauth2.jwt.NimbusJwtDecoder는 스프링 시큐리티(Spring Security)에서 JWT(JSON Web Token)를 
디코딩하고 서명 및 클레임(만료 시간, 발급자 등)을 검증하는 JwtDecoder 인터페이스의 구현체입니다. 

내부적으로 Nimbus JOSE + JWT 라이브러리를 사용하며, 주로 OAuth2 리소스 서버(Resource Server)가 요청에 담긴 
JWT의 유효성을 확인할 때 동작합니다.


주요 역할

• 토큰 디코딩: 헤더(Header)와 페이로드(Payload)를 읽어 클레임 정보를 추출합니다.
• 서명 검증: JWK Set URI(공개키) 또는 대칭키·비대칭키를 이용해 토큰이 위변조되지 않았는지 검증합니다.
• 기본 클레임 검증: 만료 시간(exp), 발급자(iss) 등 표준 검증 규칙을 적용합니다.

사용 방식 및 관련 개념

• 사용 예시: 스프링 부트에서 spring-boot-starter-oauth2-resource-server와 nimbus-jose-jwt 의존성을 추가하고 
jwk-set-uri나 issuer-uri를 설정하면 자동 구성으로 NimbusJwtDecoder 빈이 생성됩니다. 직접 빈으로 등록해 커스텀 검증 로직을 추가할 수도 있습니다.
• 유사·대체 구현체: JwtDecoder 인터페이스를 구현하는 다른 디코더나 검증 방식으로는 SupplierJwtDecoder, 
커스텀 JwtDecoder 구현체, 또는 외부 인증 서버에 토큰 유효성을 묻는 Opaque Token 방식(OpaqueTokenIntrospector) 등이 있습니다.
관련 설정과 서명 검증 흐름은 Spring Security JWT 관련 설정과 Spring Security - OAuth 2(3): 
JWT 와 암호화 서명에서 자세히 확인할 수 있습니다. 
원하시는 방향을 알려주시면 더 구체적으로 안내해 드리겠습니다:
• 코드·설정 예시(SecurityConfig, application.yml 기반) 확인
• 대칭키(HMAC) / 비대칭키(RSA, JWK) 설정 방법 비교
• 현재 겪고 있는 인증·검증 에러 원인 분석

NimbusJwtDecoder.withIssuerLocation(...).validateTypes(false).build()는 인증 서버의 공개키를 자동으로 조회하고, 
JWT 헤더의 typ 필드 검증을 비활성화한 JwtDecoder 객체를 생성하는 코드입니다. 

각 메서드 체이닝의 구체적인 역할은 다음과 같습니다.

1. withIssuerLocation(issuerUri)

• 인증 서버 메타데이터 자동 조회. 전달받은 issuerUri(예: https://example.com)의 표준 경로(/.well-known/openid-configuration 등)를 
호출해 토큰 서명 검증에 필요한 공개키(JWK Set URI)와 발급자 정보를 자동으로 가져옵니다.
• 설정 간소화. JWK Set 주소를 직접 하드코딩하지 않아도 되므로 인증 서버의 키가 교체(Rotation)되더라도 유연하게 대응할 수 있습니다.

2. validateTypes(false)

• typ 헤더 검증 비활성화. JWT의 Header에 포함된 typ 클레임(예: "typ": "JWT" 또는 RFC 9068 표준인 "typ": "at+jwt")에 
대해 내부 Nimbus 라이브러리가 수행하는 기본 타입 검증을 끕니다.
• 주요 사용 이유.
	• 커스텀 Validator 위임. 기본 검증 대신 JwtValidators.createAtJwtValidator()나 직접 
만든 OAuth2TokenValidator를 연결해 typ 헤더를 별도로 검증할 때 중복 검증 충돌을 막기 위해 사용합니다.
	• 비표준 토큰 호환. 일부 인증 서버나 레거시 시스템에서 typ 헤더를 생략하거나 특이한 값으로 발급하는 경우, 파싱 단계에서 예외가 발생하는 것을 방지합니다. 

3. build()

• 객체 생성 완료. 앞서 설정한 옵션들이 반영된 최종 NimbusJwtDecoder 인스턴스를 반환합니다.

💡 실무 참고 사항

Spring Security 공식 가이드에 따르면, validateTypes(false)만 단독으로 쓰고 별도의 Validator를 등록하지 않으면 토큰 타입(typ) 
검증이 완전히 생략됩니다. 만약 보안을 위해 특정 타입(예: Access Token 전용인 at+jwt)만 허용해야 한다면, 생성된 jwtDecoder에 
.setJwtValidator(...)를 호출해 검증기를 직접 추가해야 합니다.
자세한 설정 예시는 Spring Security 공식 API 문서 및 RFC 9068 검증 설정 가이드에서 확인할 수 있습니다.
혹시 사용 중이신 환경에 맞춰 더 구체적인 설정이 필요하시다면 알려주세요:
• 사용 중인 인증 서버(Keycloak, Auth0, Okta, 자체 서버 등)
• 발생한 특정 에러 메시지나 이슈
• 적용하려는 Spring Security 버전
원하시는 검증 방식에 맞는 코드 예제를 작성해 드릴 수 있습니다.

org.springframework.security.oauth2.jwt.NimbusJwtDecoder는 스프링 시큐리티(Spring Security)에서 JWT(JSON Web Token)를 디코딩하고 서명 및 클레임(만료 시간, 발급자 등)을 검증하는 JwtDecoder 인터페이스의 구현체입니다. [1] (https://www.inflearn.com/community/questions/1184977/token-decoder?srsltid=AYCX9vL06u5HMjMm0Zp-nXlQdhwTKOrAkHvdSx-z-hwqAq16CBc1UAuL), [2] (https://velog.io/@wjdtn747/Spring-Boot-3-Spring-Framework-6-Section-19-Spring-Security-JWT-%EA%B4%80%EB%A0%A8-%EC%84%A4%EC%A0%95)
내부적으로 Nimbus JOSE + JWT 라이브러리를 사용하며, 주로 OAuth2 리소스 서버(Resource Server)가 요청에 담긴 JWT의 유효성을 확인할 때 동작합니다. [1] (https://www.inflearn.com/community/questions/1184977/token-decoder?srsltid=AYCX9vL06u5HMjMm0Zp-nXlQdhwTKOrAkHvdSx-z-hwqAq16CBc1UAuL), [2] (https://velog.io/@wjdtn747/Spring-Boot-3-Spring-Framework-6-Section-19-Spring-Security-JWT-%EA%B4%80%EB%A0%A8-%EC%84%A4%EC%A0%95)

주요 역할

• 토큰 디코딩: 헤더(Header)와 페이로드(Payload)를 읽어 클레임 정보를 추출합니다.
• 서명 검증: JWK Set URI(공개키) 또는 대칭키·비대칭키를 이용해 토큰이 위변조되지 않았는지 검증합니다.
• 기본 클레임 검증: 만료 시간(exp), 발급자(iss) 등 표준 검증 규칙을 적용합니다. [1] (https://www.inflearn.com/community/questions/1184977/token-decoder?srsltid=AYCX9vL06u5HMjMm0Zp-nXlQdhwTKOrAkHvdSx-z-hwqAq16CBc1UAuL), [2] (https://velog.io/@wjdtn747/Spring-Boot-3-Spring-Framework-6-Section-19-Spring-Security-JWT-%EA%B4%80%EB%A0%A8-%EC%84%A4%EC%A0%95), [3] (https://assu10.github.io/dev/2024/01/27/springsecurity-oauth2-jwt/)

사용 방식 및 관련 개념

• 사용 예시: 스프링 부트에서 spring-boot-starter-oauth2-resource-server와 nimbus-jose-jwt 의존성을 추가하고 jwk-set-uri나 issuer-uri를 설정하면 자동 구성으로 NimbusJwtDecoder 빈이 생성됩니다. 직접 빈으로 등록해 커스텀 검증 로직을 추가할 수도 있습니다.
• 유사·대체 구현체: JwtDecoder 인터페이스를 구현하는 다른 디코더나 검증 방식으로는 SupplierJwtDecoder, 커스텀 JwtDecoder 구현체, 또는 외부 인증 서버에 토큰 유효성을 묻는 Opaque Token 방식(OpaqueTokenIntrospector) 등이 있습니다.
관련 설정과 서명 검증 흐름은 Spring Security JWT 관련 설정과 Spring Security - OAuth 2(3): JWT 와 암호화 서명에서 자세히 확인할 수 있습니다. • 현재 겪고 있는 인증·검증 에러 원인 분석

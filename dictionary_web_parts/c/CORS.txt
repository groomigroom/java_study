CORS(Cross-Origin Resource Sharing)는 "교차 출처 리소스 공유"를 뜻하며, 브라우저가 다른 출처(Domain, Port, Protocol)의 자원에 접근할 수 있도록 허용하는 보안 메커니즘입니다. [1, 2, 3] 
## 1. CORS가 존재하는 이유

* 기본 규칙(SOP): 웹 브라우저는 보안을 위해 원래 SOP(Same-Origin Policy, 동일 출처 정책)를 따릅니다. 즉, A.com에서 불러온 자바스크립트는 B.com API 서버로 요청을 보낼 수 없도록 기본 차단합니다.
* CORS의 역할: 오늘날 웹 개발은 프론트엔드(localhost:3000)와 백엔드(api.com:8080)의 출처가 다른 경우가 대부분입니다. CORS는 이처럼 출처가 달라도 안전하게 데이터를 주고받을 수 있도록 예외적으로 허용해 주는 브라우저의 규칙입니다. [4, 5, 6, 7, 8] 

## 2. CORS 에러가 발생하는 이유
많은 개발자가 겪는 "CORS 에러"는 백엔드 서버가 무너진 것이 아닙니다. 브라우저가 "백엔드 서버에 물어봤는데, 너(프론트엔드)한테 데이터를 줘도 된다는 허락 서류(헤더)를 못 받았어!"라며 안전을 위해 응답을 차단한 것입니다. [9, 10] 
## 3. 스프링 부트에서 CORS 해결법
스프링 부트(스프링 시큐리티)에서 특정 출처의 접근을 허용하려면 서버 설정을 추가해야 합니다. [11] 

* 방법 1: 특정 컨트롤러에만 적용 (@CrossOrigin)

@RestController
@CrossOrigin(origins = "http://localhost:3000") // 특정 출처 허용public class MyController { ... }

* 방법 2: 시큐리티 설정 내 통합 (HttpSecurity 활용)

@Beanpublic SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
    http.cors(cors -> cors.configurationSource(corsConfigurationSource()));
    return http.build();
}

전자정부 표준프레임워크(기반이 되는 스프링 프레임워크)에서 
Context(컨텍스트)는 애플리케이션이 원활하게 동작할 수 있도록 빈(Bean) 객체들의 생성, 
초기화, 의존관계 연결, 설정 정보 등을 관리하고 제공하는 실행 환경 및 컨테이너(Container)를 의미합니다. 
[1] (https://translate.google.com/translate?u=https://www.quora.com/What-is-meant-by-%25E2%2580%259Capplication-context%25E2%2580%259D-in-spring-and-how-do-you-create-one&hl=ko&sl=en&tl=ko&client=sge)
설정 파일명이나 구조에서 context-*.xml 형태로 자주 등장하며, 크게 다음과 같은 의미와 역할을 담당합니다.

1. 스프링 컨테이너 (ApplicationContext)

• 객체(Bean) 관리: 애플리케이션에서 사용하는 서비스, DAO, 유틸리티 등의 자바 객체를 생성하고 스프링 컨테이너가 직접 관리합니다. 
[1] (https://translate.google.com/translate?u=https://www.quora.com/What-is-meant-by-%25E2%2580%259Capplication-context%25E2%2580%259D-in-spring-and-how-do-you-create-one&hl=ko&sl=en&tl=ko&client=sge)
• 의존성 주입(DI): 객체들이 서로 필요로 할 때, 설정 파일(XML 또는 Java Config, 어노테이션)을 바탕으로 알아서 연결(주입)해 줍니다.
• 이벤트 처리: The ApplicationContext - 전자정부 표준프레임워크에 명시된 대로 ApplicationEvent와 ApplicationListener를 이용한 
이벤트 발행 및 구독 메커니즘을 제공합니다. 
[1] (https://www.egovframe.go.kr/wiki/doku.php?id=egovframework:rte2:fdl:ioc_container:the_applicationcontext)

2. 설정 파일 접두사 (context-*.xml)

전자정부 프레임워크 프로젝트를 생성하면 src/main/resources (또는 WEB-INF/spring) 경로 아래에 context-로 시작하는 XML 설정 파일들이 생성됩니다. 
각 파일은 영역별 설정을 분리하여 담당합니다. [1] (https://velog.io/@crazy-oung/%EC%A0%84%EC%9E%90%EC%A0%95%EB%B6%80%ED%94%84%EB%A0%88%EC%9E%84%EC%9B%8C%ED%81%AC-%EC%A0%95%EB%A6%AC), 
[2] (https://bkjo94.tistory.com/entry/%EC%A0%84%EC%9E%90%EC%A0%95%EB%B6%80-%ED%94%84%EB%A0%88%EC%9E%84%EC%9B%8C%ED%81%AC-%EC%83%98%ED%94%8C-%EC%BD%94%EB%93%9C-%EB%B6%84%EC%84%9Dcontext-commonxml)
• context-common.xml: 공통 설정, 어노테이션 스캔 제외 처리, 다국어 처리 메시지 소스(ReloadableResourceBundleMessageSource) 등을 정의합니다.
• context-datasource.xml: 데이터베이스 연결(DataSource) 및 트랜잭션 관련 설정을 담당합니다.
• context-mapper.xml / context-sql-map.xml: MyBatis 등과 연동하는 ORM/SQL 설정 파일을 연결합니다.
• context-security.xml: Spring Security를 활용한 로그인, 권한 부여, 접근 제어 등 보안 설정을 확장하여 관리합니다.
• context-idgen.xml: 게시물 번호 등 유일한 ID를 생성해 주는 IDgeneration 서비스 설정입니다. 
[1] (https://sharonprogress.tistory.com/323), 
[2] (https://bkjo94.tistory.com/entry/%EC%A0%84%EC%9E%90%EC%A0%95%EB%B6%80-%ED%94%84%EB%A0%88%EC%9E%84%EC%9B%8C%ED%81%AC-%EC%83%98%ED%94%8C-%EC%BD%94%EB%93%9C-%EB%B6%84%EC%84%9Dcontext-commonxml)

3. 웹 어플리케이션에서의 위치 (web.xml)

웹 애플리케이션이 처음 구동될 때 web.xml 파일을 읽는데, 여기에 contextConfigLocation 파라미터를 통해 context-*.xml 파일들의 경로를 지정해 줍니다. 
[1] (https://m.blog.naver.com/1_soft/220704730059), [2] (https://velog.io/@crazy-oung/%EC%A0%84%EC%9E%90%EC%A0%95%EB%B6%80%ED%94%84%EB%A0%88%EC%9E%84%EC%9B%8C%ED%81%AC-%EC%A0%95%EB%A6%AC), 
[3] (https://bkjo94.tistory.com/entry/%EC%A0%84%EC%9E%90%EC%A0%95%EB%B6%80-%ED%94%84%EB%A0%88%EC%9E%84%EC%9B%8C%ED%81%AC-%EC%83%98%ED%94%8C-%EC%BD%94%EB%93%9C-%EB%B6%84%EC%84%9Dcontext-commonxml)
• WAS(웹 애플리케이션 서버)가 시작될 때 이 설정들을 다 읽어서 공통 비즈니스 영역의 컨텍스트를 먼저 로딩하고, 
이후 DispatcherServlet 등을 통해 웹 요청 처리용 서블릿 컨텍스트가 연결됩니다. 
[1] (https://bkjo94.tistory.com/entry/%EC%A0%84%EC%9E%90%EC%A0%95%EB%B6%80-%ED%94%84%EB%A0%88%EC%9E%84%EC%9B%8C%ED%81%AC-%EC%83%98%ED%94%8C-%EC%BD%94%EB%93%9C-%EB%B6%84%EC%84%9Dcontext-commonxml), [2] (https://m.blog.naver.com/1_soft/220704730059)
만약 특정 XML 파일(context-common.xml이나 context-datasource.xml 등)의 구체적인 설정 방법이나 에러 해결에 대해 알고 싶다면 편하게 말씀해 주세요.

전자정부 표준프레임워크(eGovFrame)를 포함한 Java 기반 웹 애플리케이션에서 Context의 lookup() 
메서드는 애플리케이션 외부나 컨테이너에 등록된 자원(Resource)을 이름으로 찾아오는(검색하는) 역할을 합니다.
이것은 Java 표준 기술인 JNDI(Java Naming and Directory Interface)의 핵심 API입니다.

💡 핵심 요약

• 역할: 자원 검색 및 주입 (Tomcat, WebLogic, JBoss 등 WAS 관리 자원 가져오기)
• 주요 대상: 데이터베이스 커넥션 풀(DataSource), JMS 큐, 외부 환경 설정 정보 등
• 의의: 소스코드 변경 없이 WAS 설정만으로 DB 연결 정보 등을 동적으로 변경할 수 있게 함

🛠️ 주로 사용되는 실제 사례 (DataSource 조회)

전자정부프레임워크 환경에서 데이터베이스 연결을 설정할 때, 개발 서버와 운영 서버의 DB 주소가 다를 경우 
소스코드를 수정하지 않고 WAS의 JNDI를 이용해 자원을 lookup합니다.

1. WAS(톰캣 등) 설정 (context.xml)

서버 환경에 DB 연결 정보를 미리 정의하고 jdbc/myDataSource라는 이름을 붙입니다.
xml
<Resource name="jdbc/myDataSource" 
          auth="Container" 
          type="javax.sql.DataSource"
          driverClassName="com.mysql.cj.jdbc.Driver" 
          url="jdbc:mysql://localhost:3306/mydb"
          username="user" password="password" />
코드를 사용할 때는 주의가 필요합니다.

2. Java 코드 또는 스프링 설정에서 lookup() 사용

과거 Java 코드에서는 직접 lookup을 수행했으나, 전자정부프레임워크(스프링 기반)에서는 XML 설정이나 자바 설정을 통해 편리하게 연동합니다.
• 전통적인 Java 방식:java
Context initContext = new InitialContext();
// 기본 네이밍 컨텍스트에서 자원을 찾아옴
Context envContext  = (Context)initContext.lookup("java:/comp/env");
DataSource ds = (DataSource)envContext.lookup("jdbc/myDataSource");
코드를 사용할 때는 주의가 필요합니다.
• 전자정부프레임워크(스프링 XML) 방식:
스프링의 jee 네임스페이스를 사용하여 내부적으로 lookup()을 수행하도록 설정합니다.xml
<jee:jndi-lookup id="dataSource" 
                 jndi-name="jdbc/myDataSource" 
                 expected-type="javax.sql.DataSource" />
코드를 사용할 때는 주의가 필요합니다.

🧐 왜 사용할까요? (장점)

• 설정과 코드의 분리: DB 비밀번호나 서버 IP가 바뀌어도 자바 소스코드를 다시 컴파일하거나 빌드할 필요가 없습니다.
• 보관 및 보안: 민감한 접속 정보를 소스코드나 프로젝트 내부 파일에 두지 않고 관리가 엄격한 WAS 서버 설정을 통해 관리할 수 있습니다.
• 자원 효율성: WAS가 커넥션 풀(Connection Pool)을 직접 관리하므로 효율적이고 안정적입니다.
추가적으로 전자정부프레임워크의 스프링 설정 파일(context-*.xml)이나 특정 컴포넌트의 
자원 검색 방식에 대해 더 궁금한 점이 있으시다면 언제든 말씀해 주세요!

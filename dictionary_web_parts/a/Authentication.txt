제시해주신 Authentication은 Spring Security에서 현재 애플리케이션에 접근한 사용자(또는 시스템)의 신원 정보와 권한 상태를 담고 있는 핵심 인증 객체이자 인터페이스입니다. [1, 2] 
"현재 로그인한 사람이 누구인가?", "그 사람의 권한은 무엇인가?", "인증이 완료된 상태인가?"라는 질문에 대한 모든 해답을 쥐고 있는 보안의 핵심 데이터 상자입니다.
------------------------------
## 1. 코드의 의미
이 인터페이스는 인증 과정의 시작과 끝에 모두 사용되며, Spring Security가 관리하는 보안 컨텍스트(SecurityContext)에 저장되어 애플리케이션 어디서든 현재 유저의 정보를 꺼내볼 수 있도록 지원합니다. [3] 
안에는 크게 3가지 핵심 정보가 저장되어 있습니다.

   1. Principal (교장/주체): 사용자를 식별하는 정보입니다. 보통 로그인한 유저의 정보를 담은 커스텀 객체(예: UserDetails 구현체)나 사용자 아이디(String)가 들어갑니다.
   * 메서드: authentication.getPrincipal() [1] [4, 5, 6, 7] 
   2. Credentials (자격 증명): 사용자가 본인임을 증명하기 위해 입력한 비밀번호나 토큰 값입니다. 보안을 위해 인증이 최종 완료되면 이 부분은 메모리에서 지워지는(null) 경우가 많습니다.
   * 메서드: authentication.getCredentials() [1] [8] 
   3. Authorities (권한 목록): 이 사용자가 가지고 있는 권한(예: ROLE_USER, ROLE_ADMIN)들의 리스트입니다. 앞서 질문하셨던 accessDeniedHandler가 동작할 때 이 권한 목록을 검사하여 접근을 차단하게 됩니다.
   * 메서드: authentication.getAuthorities() [1] [9, 10] 
   
## 💡 실무에서 로그인한 유저 정보 꺼내는 법
컨트롤러나 서비스 레이어 등 자바 코드 어디에서든 아래의 한 줄을 쓰면 현재 로그인한 사용자의 Authentication 객체를 바로 확보할 수 있습니다.

// 현재 쓰레드에 저장된 인증 객체 가져오기
Authentication authentication = SecurityContextHolder.getContext().getAuthentication();
// 유저 아이디(이름) 확인
String username = authentication.getName();

## 2. 소속 스타터 의존성 (Starter Dependency)
이 인터페이스 역시 핵심 보안 아키텍처이므로 Spring Security 라이브러리에 속해 있습니다.
패키지 경로: org.springframework.security.core.Authentication [1] [11] 
Gradle (build.gradle)

implementation 'org.springframework.boot:spring-boot-starter-security'

Maven (pom.xml)

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-security</artifactId>
</dependency>

------------------------------
## 💡 흐름 매핑: Authentication 객체의 일생
이전 질문들과 연결해서 보면 이해가 훨씬 쉽습니다.

   1. 로그인 시도: 유저가 아이디/비번을 전송하면 필터가 이를 가로채서 아직 인증되지 않은 Authentication 객체(UsernamePasswordAuthenticationToken)를 임시로 만듭니다.
   2. 인증 처리: 이 객체를 AuthenticationManager에게 넘깁니다. 매니저는 DB를 조회하여 비밀번호를 검증합니다.
   3. 인증 성공: 검증이 끝나면 사용자의 권한(Authorities)까지 꽉 채워진 최종 인증 완료 상태의 Authentication 객체를 새로 만들어 반환합니다.
   4. 저장 및 유지: 이 완성된 객체를 SecurityContext에 보관해 두기 때문에, 이후 유저가 다른 페이지에 접근할 때마다 매번 로그인하지 않고도 시스템이 이 유저의 신원을 신뢰할 수 있게 됩니다. [12, 13] 

------------------------------
현재 이 Authentication 객체를 컨트롤러 단에서 @AuthenticationPrincipal 어노테이션을 통해 꺼내 쓰려는 단계이신가요? 아니면 JWT 토큰을 검증한 뒤 이 객체를 수동으로 생성해서 컨텍스트에 집어넣는 과정을 구현 중이신가요? 구현 목표를 말씀해 주시면 상황에 맞는 코드를 안내해 드리겠습니다.

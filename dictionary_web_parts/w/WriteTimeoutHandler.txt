전자정부프레임워크(특히 전자정부 표준프레임워크의 리액티브 웹(WebFlux / WebClient) 환경)에서 
io.netty.handler.timeout.WriteTimeoutHandler는 HTTP 요청 바디(Body) 데이터를 상대방(서버)에게 
다 전송하는 데 걸리는 시간이 설정된 제한 시간을 초과했을 때 예외를 발생시키는 핸들러를 의미합니다. 
[1] (https://www.egovframe.go.kr/wiki/doku.php?id=egovframework:rte4.2:ptl:web_reactive_webclient), [2] (https://eottabom.github.io/post/timeout-settings-guide/)

핵심 개념 정리

• 동작 시점: 클라이언트가 서버로 HTTP 요청을 보낼 때, 요청 데이터(Body)를 소켓을 통해 전송하는 구간에서 작동합니다. 
[1] (https://eottabom.github.io/post/timeout-settings-guide/)
• 발생 원인:
	• 네트워크 속도가 지나치게 느릴 때
	• 전송해야 할 데이터 크기가 매우 큰데 상대방이 데이터를 받아가는 속도가 너무 느릴 때
	• 서버 측에서 데이터를 제때 읽지 못해 내 로컬 버퍼가 꽉 찼을 때
• 동작 결과: 설정한 시간 안에 전송을 마치지 못하면 WriteTimeoutException을 발생시키고 연결을 끊습니다.

다른 타임아웃과의 비교


타임아웃 종류	의미
Connect Timeout	서버와 TCP 연결(3-way handshake)을 맺는 데 걸리는 최대 시간
Read Timeout	연결은 맺었으나, 서버로부터 응답 데이터가 돌아오는 것을 기다리는 최대 시간
Write Timeout (WriteTimeoutHandler)	내 쪽에서 요청 데이터(Body)를 상대방에게 다 전송하는 데 허용하는 최대 시간
Response Timeout	HTTP 응답을 읽는 동안 연속된 네트워크 리드 사이에 허용하는 최대 대기 시간 (Reactor Netty 기반 WebClient 등에서 설정)


전자정부프레임워크에서의 활용

• 전자정부프레임워크 4.x 기반의 리액티브 아키텍처에서 비동기 HTTP 클라이언트인 WebClient를 사용할 때 하부 엔진으로 Reactor Netty를 사
용합니다. [1] (https://www.egovframe.go.kr/wiki/doku.php?id=egovframework:rte4.2:ptl:web_reactive_webclient)
• 대용량 파일 업로드나 외부 API 호출 시, 네트워크 장애나 상대 서버 지연으로 인해 애플리케이션 스레드가 무한정 대기(Hang)에 빠지는 것을 
방지하기 위해 이 타임아웃을 설정합니다. [1] (https://eottabom.github.io/post/timeout-settings-guide/)
만약 WebClient나 Reactor Netty 설정을 조정하는 구체적인 코드 예시가 필요하시거나, 특정 타임아웃 에러를 해결하고 싶으신가요?

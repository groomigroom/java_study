위 자바 스프링 코드에서 repository.get(id)의 .get()은 자바의 Map 
  인터페이스에 기본적으로 내장된 메서드로, 지정한 키(Key)에 해당하는 값(Value)을 찾아오는 기능을 합니다.
자료구조적 관점과 현재 코드에서의 역할을 알기 쉽게 정리해 드립니다.
------------------------------
## 1. Map 자료구조에서의 .get(Key)의 의미
자바의 HashMap은 데이터를 Key(키)와 Value(값)의 쌍으로 저장하는 사전 형태의 자료구조입니다.

* repository.put(Key, Value) ➡️ 데이터를 저장할 때 사용
* repository.get(Key) ➡️ 저장된 데이터를 키 값으로 검색해서 꺼낼 때 사용

## 2. 현재 ProductService 코드에서의 구체적 역할
현재 클래스 상단에 상품 데이터를 저장하는 임시 저장소가 다음과 같이 선언되어 있습니다.

private static final Map<Integer, Product> repository = new HashMap<>();

여기서 Key는 상품의 번호(Integer id)이고, Value는 상품 객체(Product) 자체입니다.
따라서 findById(Integer id) 메서드 내부의 repository.get(id)는 다음과 같이 동작합니다.

public Product findById(Integer id) {
    // 괄호 안에 넘겨받은 id(예: 1)를 Key로 사용하여 
    // 저장소(Map)에서 일치하는 Product(예: 구름이의 개껌) 객체를 찾아 리턴합니다.
    return repository.get(id); 
}


* 동작 예시:
* 만약 컨트롤러나 브라우저에서 id 값으로 1을 넘겨주면, repository.get(1)이 실행되어 맵에 
  1번 키로 저장되어 있던 '구름이의 개껌' 상품 객체를 쏙 뽑아서 반환해 줍니다.

## 3. 알아두면 좋은 특징 (예외 처리 관련)

* .get(id)를 호출했을 때, 만약 전달된 id 번호가 맵에 존재하지 않는 번호(예: 999)라면 에러를 발생시키는 대신 null을 반환합니다.
* 실제 서비스를 개발할 때는 존재하지 않는 상품을 조회했을 때 예외가 발생하는 것을 막기 위해 null 체크를 하거나, 
    최신 자바 스타일에서는 Optional 구조로 감싸서 처리하기도 합니다.


----------------------------------


.get("sub", String.class)


자바 스프링 부트 환경에서 .get("sub", String.class)는 JWT의 Payload(내용)에서 "sub"(Subject, 주로 유저 고유 식별자나 아이디)라는 이름의 데이터를 지정한 타입(String)으로 안전하게 꺼내오는 메서드입니다.
이 메서드 역시 앞선 질문들과 동일한 JJWT(Java JWT) 라이브러리의 Claims 인터페이스에 포함되어 있습니다.
## 🔑 소속 의존성 (Starter Dependency)
스프링 부트 자체 내장 라이브러리가 아니므로, 동일하게 JJWT 의존성을 추가해야 사용할 수 있습니다. (build.gradle 기준)

* implementation 'io.jsonwebtoken:jjwt-api:0.12.3'
* runtimeOnly 'io.jsonwebtoken:jjwt-impl:0.12.3'
* runtimeOnly 'io.jsonwebtoken:jjwt-jackson:0.12.3'

## 📝 메서드와 매개변수의 의미
Claims 객체는 기본적으로 데이터를 Map 형태로 가지고 있습니다. .get(key, requiredType) 메서드는 데이터를 꺼낼 때 자동으로 타입을 변환(캐스팅)해 주는 역할을 합니다.

* .get(..., ...): 첫 번째 매개변수로 지정한 키의 값을 찾아서, 두 번째 매개변수로 지정한 클래스 타입으로 형변환하여 반환하는 메서드입니다.
* 첫 번째 매개변수 ("sub"): 꺼내고자 하는 데이터의 Key(키) 이름입니다. "sub"는 JWT 표준 규격(Registered Claim)에서 Subject(주체/유저 ID)를 의미합니다.
* 두 번째 매개변수 (String.class): 반환받고자 하는 데이터의 자바 데이터 타입(Class)입니다. 데이터가 문자열 형식이므로 String.class를 지정합니다. 만약 숫자를 꺼내고 싶다면 Long.class나 Integer.class를 넣어 안전하게 값을 형변환할 수 있습니다.

💡 참고: JJWT 라이브러리는 "sub" 값을 더 직관적으로 꺼낼 수 있도록 .getSubject()라는 전용 메서드도 함께 제공합니다. 즉, claims.get("sub", String.class)와 claims.getSubject()는 완전히 동일한 기능을 합니다.

## 💻 흐름 이해를 위한 예시 코드

// 1. 토큰 검증 및 Payload(Claims) 추출
Claims claims = Jwts.parser()
    .verifyWith(secretKey)
    .build()
    .parseSignedClaims(token)
    .getPayload();
// 2. 매개변수를 활용해 유저 ID("sub")와 커스텀 권한("role") 안전하게 꺼내기
String userId = claims.get("sub", String.class); 
String userRole = claims.get("role", String.class); // 커스텀 데이터도 동일하게 추출 가능

System.out.println("로그인한 유저 ID: " + userId);

* 이렇게 추출한 유저 ID와 권한을 활용해 스프링 시큐리티 필터(JwtAuthenticationFilter)를 구현하는 방법이 궁금하신가요?

## @Entity 클래스에다가 .get()을 붙이면

--------------------------------

SiteUser siteUser = _siteUser.get(); 코드에서 get()은 Optional 상자 안에 담겨 있는 실제 SiteUser 엔티티 객체를 꺼내는 메서드입니다.
SiteUser가 데이터베이스(DB) 테이블과 매핑된 @Entity 클래스일 때, 이 get() 메서드가 가지는 상세한 의미와 특징은 다음과 같습니다.
------------------------------
## 1. 상자 안에서 진짜 '엔티티(Entity)' 꺼내기
userRepository.findById() 같은 메서드는 DB를 조회한 후 결과를 SiteUser 객체로 바로 주시 않고, Optional<SiteUser>라는 보호 상자에 담아서 반환합니다.

* _siteUser: "안에 데이터가 있을 수도 있고 없을 수도 있는" 상자 상태
* _siteUser.get(): 상자를 열고 그 안에 들어있는 실제 영속성 객체(SiteUser 엔티티)를 밖으로 꺼내는 행위

꺼내진 siteUser 객체는 이제부터 일반적인 데이터 변경, 필드 조회 등에 자유롭게 사용될 수 있습니다.
## 2. 영속성 컨텍스트(Persistence Context)의 관리 대상이 됨
get()을 통해 꺼낸 SiteUser 객체는 단순한 자바 객체가 아니라 JPA 영속성 컨텍스트가 관리하는 엔티티입니다.

* 이 객체의 필드 값을 변경하면(siteUser.setUsername("...")), 트랜잭션이 끝날 때 DB에 수정 사항이 자동으로 반영(Dirty Checking)됩니다.

## ⚠️ 주의: get()을 바로 쓰면 위험할 수 있습니다
만약 DB에 해당 데이터가 없어서 Optional 상자가 비어 있는 상태(Optional.empty())인데 .get()을 호출하면, 자바는 NoSuchElementException이라는 에러(런타임 예외)를 발생시키며 서버가 멈출 수 있습니다.
따라서 실무나 안전한 코드 작성을 위해서는 앞서 질문하신 isEmpty()로 검증을 마친 후 get()을 쓰거나, 아래와 같이 더 안전한 대체 메서드를 주로 사용합니다.

// 방법 A: 이전 질문에서 보신 검증 후 꺼내기if (_siteUser.isEmpty()) {
    throw new DataNotFoundException("유저가 없습니다.");
}
SiteUser siteUser = _siteUser.get(); // 이제 안전하게 꺼낼 수 있음
// 방법 B: 실무에서 가장 추천하는 '꺼내면서 예외 던지기' (한 줄로 해결)
SiteUser siteUser = _siteUser.orElseThrow(() -> new DataNotFoundException("유저가 없습니다."));

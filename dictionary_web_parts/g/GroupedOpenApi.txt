org.springdoc.core.models.GroupedOpenApi는 
스프링 부트에서 Swagger/OpenAPI 문서의 API들을 
특정 기준에 따라 그룹화(분리)하여 관리할 수 있게 해주는 클래스입니다.[1, 3]
애플리케이션의 규모가 커지면 하나의 Swagger UI 화면에 수많은 
API가 쏟아져 나와 가독성이 떨어집니다. 이때 이 클래스를 
사용하면 버전별(v1/v2), 도메인별(회원/주문), 또는 권한별
(사용자/관리자)로 API 문서를 깔끔하게 나누어 제공할 수 있습니다.[1]

💡 주요 역할 및 특징

• API 분리 및 그룹 선택: Swagger UI 화면 우측 상단의 Select a spec 
드롭다운 메뉴를 통해 사용자가 원하는 그룹의 API 문서만 골라서 볼 수 있게 합니다.[3]
• 조건별 필터링: pathsToMatch나 packagesToScan 등의 메서드를 사용해, 
특정 URL 경로를 가지거나 특정 패키지에 속한 컨트롤러만 해당 그룹에 포함하도록 필터링합니다.[1, 3]

💻 실제 사용 예시 (코드)

스프링 부트의 Configuration 클래스에서 GroupedOpenApi를 빈(Bean)으로 등록하여 사용합니다.
java
import org.springdoc.core.models.GroupedOpenApi;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class OpenApiConfig {

    // 1. 사용자(User) 관련 API 그룹
    @Bean
    public GroupedOpenApi userApi() {
        return GroupedOpenApi.builder()
                .group("1. User API") // Swagger UI에 표시될 그룹 이름
                .pathsToMatch("/api/v1/users/**") // 이 경로로 시작하는 API만 포함
                .build();
    }

    // 2. 관리자(Admin) 관련 API 그룹
    @Bean
    public GroupedOpenApi adminApi() {
        return GroupedOpenApi.builder()
                .group("2. Admin API")
                .pathsToMatch("/api/v1/admin/**")
                .build();
    }
}
코드를 사용할 때는 주의가 필요합니다.

🔍 요약

• 의미: springdoc-openapi 라이브러리에서 제공하는 API 문서 그룹화 및 필터링용 객체[1, 3]
• 용도: 전체 API를 성격에 맞게 쪼개어, Swagger UI에서 드롭다운 메뉴로 선택해 볼 수 있도록 인터페이스를 제공하는 역할[1, 3]

작성하신 코드에서 .packagesToScan("egovframework.hyb.mbl.acl.web")의 의미는 
"Swagger 문서를 만들 때 egovframework.hyb.mbl.acl.web 패키지(및 그 하위 패키지) 안에 있는 컨트롤러 클래스들만 탐색해서 문서에 포함하겠다"라는 뜻입니다.
여기에 이미 설정하신 pathsToMatch와 결합하여 교집합으로 동작하게 됩니다.

⚙️ 두 조건의 결합 방식 (AND 조건)

현재 코드에서는 두 가지 필터링 조건이 동시에 걸려 있습니다.
1. .pathsToMatch("/acl/**") ➡️ URL 경로가 /acl/로 시작해야 함
2. .packagesToScan("egovframework.hyb.mbl.acl.web") ➡️ 지정된 패키지 안에 위치한 클래스여야 함
즉, Swagger는 egovframework.hyb.mbl.acl.web 패키지 안에 있으면서 동시에 URL 주소가 /acl/** 형태인 API들만 쏙 골라내어 "01. Accelerator Guide Program Service" 그룹에 매핑해 줍니다.

💡 왜 이렇게 두 가지를 같이 쓸까요?

보통 한 가지만 써도 무방하지만, 다음과 같은 상황에서 매우 유용합니다.
• URL 중복 방지: 만약 다른 팀이나 다른 모듈에서 우연히 /acl/something이라는 동일한 패턴의 URL을 사용하더라도, 내 패키지 명을 정확히 지정해 두었기 때문에 다른 사람의 API가 내 문서 그룹에 섞여 들어오는 것을 완벽히 차단할 수 있습니다.
• 성능 및 명확성: Swagger가 프로젝트의 모든 클래스를 다 뒤지는 것이 아니라 지정된 패키지만 집중적으로 스캔하므로 문서 생성 효율이 좋아지고, 관리 측면에서도 명확해집니다.
혹시 설정하신 뒤에 원하는 API가 Swagger 화면에 나오지 않거나, 혹은 패키지 내부의 특정 API만 제외하고 싶으신가요? 상황을 말씀해 주시면 알맞은 필터링 옵션(pathsToExclude 등)을 추가로 소개해 드릴게요!

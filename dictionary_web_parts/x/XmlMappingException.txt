전자정부프레임워크(기반이 되는 스프링 프레임워크)에서 XmlMappingException은 
객체(Object)와 XML 간의 변환(O/X 매핑: Object-XML Mapping) 작업 
중 발생하는 최상위 런타임 예외를 의미합니다. 
[1] (https://docs.spring.io/spring-framework/docs/current/javadoc-api/org/springframework/oxm/XmlMappingException.html), 
[2] (https://godekdls.github.io/Spring%20Data%20Access/marshallingxmlbyusingobjectxmlmappers/), [3] (https://docs.spring.io/spring-framework/reference/data-access/oxm.html)

주요 의미와 특징

• 스프링 OXM 추상화 예외: 전자정부프레임워크는 스프링의 OXM(Object-XML Mapping) 기술을 사용합니다. JAXB, Castor 
등 다양한 내부 XML 매핑 라이브러리를 쓰더라도, 예외가 발생하면 스프링이 이를 공통 예외인 
XmlMappingException 계층으로 감싸서(Wrapping) 던집니다. 
[1] (https://velog.io/@loloy/07.-%EC%8A%A4%ED%94%84%EB%A7%81-%ED%95%B5%EC%8B%AC-%EA%B8%B0%EC%88%A0%EC%9D%98-%EC%9D%91%EC%9A%A9), 
[2] (https://docs.spring.io/spring-framework/reference/data-access/oxm.html), [3] (https://godekdls.github.io/Spring%20Data%20Access/marshallingxmlbyusingobjectxmlmappers/)
• 런타임 예외(RuntimeException): Checked Exception이 아니므로 컴파일 시점에 반드시 try-catch를 강제하지 않는 런타임 예외입니다. 
[1] (https://godekdls.github.io/Spring%20Data%20Access/marshallingxmlbyusingobjectxmlmappers/), 
[2] (https://docs.spring.io/spring-framework/docs/current/javadoc-api/org/springframework/oxm/XmlMappingException.html)
• 원인 보존: 하위 라이브러리(JAXB 등)의 원본 예외 정보를 내부에 품고 있으므로(Nested Exception), 발생 원인을 추적할 수 있습니다. 
[1] (https://docs.spring.io/spring-framework/docs/5.0.0.M4_to_5.0.0.M5/Spring%20Framework%205.0.0.M5/org/springframework/oxm/XmlMappingException.html),
[2] (https://godekdls.github.io/Spring%20Data%20Access/marshallingxmlbyusingobjectxmlmappers/), 
[3] (https://docs.spring.io/spring-framework/reference/data-access/oxm.html)

주요 하위 클래스 유형

• MarshallingFailureException: 자바 객체를 XML로 변환(Marshalling)하는 과정에서 실패했을 때 발생
• UnmarshallingFailureException: XML 데이터를 자바 객체로 변환(Unmarshalling)하는 과정에서 실패했을 때 발생
• ValidationFailureException: XML 스키마 검증이나 매핑 규칙 검증에 실패했을 때 발생 
[1] (https://docs.spring.io/spring-framework/docs/current/javadoc-api/org/springframework/oxm/XmlMappingException.html), 
[2] (https://docs.spring.io/spring-framework/reference/data-access/oxm.html), [3] (https://blog.csdn.net/weixin_34922053/article/details/114085396)

발생 원인 및 대처법

1. XML 구조와 자바 객체(DTO/Model) 구조의 불일치
	• XML 태그 이름, 네임스페이스(namespace), 데이터 타입 등이 자바 클래스의 필드명이나 어노테이션(@XmlRootElement, @XmlElement 등)과 맞지 않는 경우 발생합니다.
2. 잘못된 XML 포맷
	• 파싱하려는 XML 문자열이나 파일이 깨져 있거나 문법에 어긋나는 경우 발생합니다.
3. 대처 방법
	• 스택 트레이스(Stack Trace)의 원인(cause)을 확인하여 어떤 태그나 필드에서 매핑이 실패했는지 파악하고, DTO 구조나 JAXB/Castor 설정 파일을 수정해야 합니다.
[1] (https://docs.spring.io/spring-framework/docs/current/javadoc-api/org/springframework/oxm/XmlMappingException.html), 
[2] (https://docs.spring.io/spring-framework/docs/5.0.0.M4_to_5.0.0.M5/Spring%20Framework%205.0.0.M5/org/springframework/oxm/XmlMappingException.html)
만약 현재 에러 로그 전문이나 사용하고 계신 OXM 구현체(JAXB 등)를 알려주시면, 구체적인 원인과 해결 방법을 함께 찾아볼 수 있습니다.

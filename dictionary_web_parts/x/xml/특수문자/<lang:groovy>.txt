<lang:groovy id="messenger" script-source="classpath:org/springframework/scripting/groovy/Messenger.groovy">

해당 코드는 전자정부 프레임워크(eGovFrame) 및 그 기반이 되는 스프링 프레임워크(Spring Framework)에서 
동적 언어(Groovy)로 작성된 스크립트 파일을 스프링의 빈(Bean)으로 등록하여 사용하겠다는 의미입니다.
전자정부 프레임워크 개발 가이드의 'IoC 컨테이너 - 컨테이너 확장 포인트(Container Extension Points)' 
설명 문서에서 스프링의 기능을 예시로 들 때 자주 등장하는 표준적인 설정 예제입니다.
각 속성이 가지는 구체적인 의미는 다음과 같습니다.

🔍 속성별 상세 의미

• <lang:groovy ... >: 이 빈(Bean)이 자바(Java)가 아닌 Groovy라는 동적 언어 스크립트로 구현되었음을 선언합니다.
• id="messenger": 스프링 IoC 컨테이너 안에서 이 객체(Bean)를 식별하기 위한 이름을 messenger로 지정한 것입니다. 
다른 자바 클래스나 컴포넌트에서 @Autowired나 ref="messenger" 형태로 주입받아 사용할 수 있습니다.
• script-source="classpath:...": Groovy 소스 코드가 위치한 실제 파일 경로를 지정합니다. 
여기서는 프로젝트의 클래스패스(경로) 내부인 org/springframework/scripting/groovy/ 폴더 안의 Messenger.groovy 스크립트 파일을 읽어와 객체로 생성하겠다는 뜻입니다.

💡 왜 이런 방식을 사용할까요? (특징과 장점)

1. 동적 리로딩 (Dynamic Reloading)
	• 일반적인 자바 파일은 코드를 수정하면 서버를 재컴파일하고 재시작해야 합니다.
	• 하지만 이 설정을 사용하면 서버를 켜둔 상태에서 Messenger.groovy 파일의 스크립트 내용만 수정해도 변경 사항이 실시간으로 애플리케이션에 반영됩니다.
2. 유연한 비즈니스 로직 관리
	• 자주 바뀌는 비즈니스 규칙이나 메시지 처리 로직 등을 자바 코드와 분리하여 스크립트 형태로 관리할 때 매우 유용합니다.
추가적으로 이 설정을 정상적으로 사용하려면 XML 설정 상단 <beans> 태그 내에 xmlns:lang="http://www.springframework.org/schema/lang" 네임스페이스가 등록되어 있어야 합니다

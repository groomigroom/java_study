javax.sql.DataSource는 자바 표준(JDK)에서 제공하는 인터페이스로, 스프링 부트 애플리케이션과 데이터베이스(DB) 간의 물리적인 연결을 관리하는 '데이터베이스 커넥션 팩토리(Connection Factory)'를 의미합니다.
스프링 부트에서 이 DataSource 인터페이스는 데이터베이스 연동(MyBatis, JPA, JDBC 등)을 처리하기 위한 가장 밑바탕이 되는 핵심 핵심 객체입니다.

🔑 왜 필요한가요? (핵심 역할)

1. 커넥션 풀(Connection Pool) 관리:
	• 자바 프로그램이 DB에 접근할 때마다 매번 연결을 맺고 끊는 것은 비용이 매우 많이 들고 서버에 큰 부담을 줍니다.
	• DataSource를 구현한 객체(예: 스프링 부트의 기본값인 HikariCP)는 미리 여러 개의 DB 연결(Connection)을 방에 채워두고(Pool), 프로그램이 요청할 때마다 빌려주고 반납받는 방식으로 시스템의 성능을 극대화합니다.
2. DB 접속 정보의 표준 추상화:
	• 어떤 DB를 쓰는지(MySQL, Oracle, PostgreSQL 등), 드라이버 이름이 무엇인지, 계정 ID/PW는 무엇인지와 같은 물리적인 접속 설정을 이 하나의 객체 안에 꽁꽁 숨겨둡니다.
	• 덕분에 MyBatis(SqlSessionFactory)나 JPA(EntityManagerFactory) 같은 상위 기술들은 DB가 무엇이든 상관없이 오직 이 DataSource만 바라보고 일관되게 데이터를 주고받을 수 있습니다.

💻 스프링 부트에서의 특징

스프링 부트(Spring Boot)는 "설정보다 관례(Convention over Configuration)"를 따르기 때문에, 이전 레거시 스프링이나 전자정부 프레임워크처럼 Java Config나 XML에 DataSource를 구구절절 자바 코드로 등록하지 않아도 됩니다.

1. 자동 설정 (스프링 부트 스타일)

pom.xml이나 build.gradle에 DB 드라이버 라이브러리를 넣고, application.properties(또는 yml)에 접속 정보만 적어주면 스프링 부트가 내부적으로 DataSource 빈(Bean)을 자동으로 생성해 줍니다.
properties
# application.properties 예시
spring.datasource.url=jdbc:mysql://localhost:3306/mydb
spring.datasource.username=root
spring.datasource.password=1234
spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver
코드를 사용할 때는 주의가 필요합니다.

2. 필요한 곳에서 주입받아 사용

이렇게 자동 생성되거나, 직접 커스텀하게 만든 DataSource 빈은 스프링 컨테이너에 등록되어 있으므로 필요한 곳에서 언제든 당겨 쓸 수 있습니다. (앞선 질문에서 보신 멀티 DB 설정 등에서 주로 수동 등록합니다.)
java
@Autowired
private DataSource dataSource; // 👈 스프링이 관리하는 DB 연결 객체가 주입됩니다.
코드를 사용할 때는 주의가 필요합니다.

💡 한 줄 요약

"자바 프로그램과 데이터베이스를 연결해 주는 통로이자, 미리 연결 객체들을 만들어두고 효율적으로 돌려쓰는 '데이터베이스 커넥션 풀 매니저'의 표준 인터페이스"입니다.
스프링 부트 2.x 버전부터는 성능이 가장 좋은 HikariCP가 기본 DataSource 구현체로 내장되어 작동합니다.
현재 다루고 계신 프로젝트가 스프링 부트가 알아서 만들어주는 기본 DataSource를 쓰고 계시는가요, 아니면 이전 질문처럼 @Bean(name = "dataSource-mysql")과 같이 복수 개의 데이터베이스(Multi DataSource)를 제어하기 위해 직접 수동 설정을 정의하시는 중인가요? 구현 방향에 맞춰 더 밀접한 가이드를 드릴 수 있습니다.

자바 스프링(정확히는 자바 8 이상 및 JPA)에서 LocalDateTime은 타임존(Timezone) 정보 없이 날짜와 시간을 분 단위, 나노초 단위까지 표현하는 자바 표준 API입니다.
스프링 부트와 JPA 환경에서 게시글 등록일, 회원 가입일, 주문 일자 등 타임존 전환이 필요 없는 대부분의 국내 서비스의 일시 데이터를 저장할 때 가장 기본적으로 사용하는 타입입니다.
------------------------------
## 💡 왜 과거의 Date나 Calendar 대신 사용할까요?
자바 8 이전의 Date 클래스는 많은 단점이 있어 현재는 거의 사용되지 않으며, LocalDateTime이 그 자리를 대체했습니다. [1, 2] 

* 불변 객체 (Immutable): Date는 값을 내부적으로 변경할 수 있어서 멀티스레드 환경에서 안전하지 못했습니다. 반면 LocalDateTime은 불변 객체이므로 값이 변하지 않아 안전합니다.
* 직관적인 설계: 월(Month)이 0부터 시작하던 Date와 달리, LocalDateTime은 1월을 1로 표현하여 훨씬 직관적입니다.
* JPA 2.1 이상 완벽 지원: 스프링 부트 환경에서는 LocalDateTime을 엔티티 필드로 선언하면 별도의 변환기 없이 DB의 TIMESTAMP 나 DATETIME 컬럼과 자동으로 매핑됩니다. [3, 4, 5] 

------------------------------
## 💻 실무 사용 예시
보통 앞서 다룬 @CreatedDate나 @LastModifiedDate와 조합하여 엔티티에서 다음과 같이 사용합니다.

import java.time.LocalDateTime;

@Entitypublic class Order {

    @Id @GeneratedValue
    private Long id;

    // DB의 DATETIME 타입과 매핑되며, 현재 일시가 저장됨
    private LocalDateTime orderDate; 
    
    public void createOrder() {
        this.orderDate = LocalDateTime.now(); // 현재 날짜와 시간 구하기
    }
}

------------------------------
## ⚠️ 주의할 점: 타임존의 부재
LocalDateTime은 이름 그대로 로컬(현재 서버 환경)의 시간만을 가집니다. 즉, 한국 서버에서 실행하면 한국 시간이 나오지만, AWS 미국 서버에서 실행하면 미국 시간이 나옵니다.

* 해외 서비스나 글로벌 결제 시스템을 구축할 때는 타임존 정보가 포함된 ZonedDateTime이나 OffsetDateTime 타입을 사용하는 것이 안전합니다.
* 국내 전용 서비스라면 서버 시간(보통 UTC 또는 KST)을 통일한 뒤 LocalDateTime을 쓰는 것이 가장 편리합니다.

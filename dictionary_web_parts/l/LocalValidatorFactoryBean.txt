org.springframework.validation.beanvalidation.LocalValidatorFactoryBean은 
스프링 부트에서 Java 표준 검증 스펙(Jakarta/Bean Validation)을 스프링부트 
프레임워크와 연결해주는 핵심 어댑터이자 글로벌 검증기(Validator)입니다. 
[1] (https://wannaqueen.gitbook.io/spring5/spring-5.0/3.-by-ys-sh/3.7-by-sh/3.7.2-by-sh), 
[2] (https://bnzn2426.tistory.com/157)
개발자가 데이터를 검증할 때 사용하는 @NotNull, @NotBlank, @Size 같은 애노테이션들이 
실제로 동작할 수 있도록 뒤에서 일해주는 실무자 객체라고 이해하시면 됩니다. 
[1] (https://m.blog.naver.com/hj_kim97/223036873193), [2] (https://bnzn2426.tistory.com/157)

💡 핵심 역할과 의미


1. 글로벌 검증기(Global Validator) 자동 등록

스프링 부트 프로젝트의 build.gradle에 spring-boot-starter-validation 의존성을 추가하면, 
ValidationAutoConfiguration이라는 자동 설정 클래스가 작동합니다. 
이때 스프링 부트는 LocalValidatorFactoryBean을 스프링 컨테이너의 글로벌 Validator로 자동 등록합니다.
덕분에 개발자는 별도의 설정 없이 @Valid나 @Validated만 붙이면 바로 데이터 검증을 사용할 수 있습니다. 
[1] (https://m.blog.naver.com/hj_kim97/223036873193), 
[2] (https://kapentaz.github.io/spring/Spring-Boo-Bean-Validation-%EC%A0%9C%EB%8C%80%EB%A1%9C-%EC%95%8C%EA%B3%A0-%EC%93%B0%EC%9E%90/), 
[3] (https://asas6978.tistory.com/39), 
[4] (https://bnzn2426.tistory.com/157)

2. 기술 표준(API)과 실제 구현체의 다리 역할

• Bean Validation(자바 표준 API): 애노테이션 인터페이스만 정의되어 있고 실제 검증 로직은 없습니다.
• Hibernate Validator(실제 구현체): 그 애노테이션을 해석해서 실제로 값이 비었는지, 
글자수가 맞는지 검증하는 라이브러리입니다. 
[1] (https://wannaqueen.gitbook.io/spring5/spring-5.0/3.-by-ys-sh/3.7-by-sh/3.7.2-by-sh), 
[2] (https://pso62.tistory.com/entry/Error-creating-bean-with-name-LocalValidatorFactoryBean0-%E2%80%94-Unable-to-create-a-Configuration-%ED%95%B4%EA%B2%B0)
• LocalValidatorFactoryBean (연결 고리): 스프링이 위 구현체(Hibernate Validator)를 인식하여 작동할 수 
있도록 초기화하고, 이를 스프링의 org.springframework.validation.Validator 인터페이스 타입으로 감싸서 제공합니다. 
[1] (https://wannaqueen.gitbook.io/spring5/spring-5.0/3.-by-ys-sh/3.7-by-sh/3.7.2-by-sh)

3. Spring MVC 및 데이터 바인딩과의 통합

컨트롤러가 요청 파라미터(DTO 등)를 객체로 받아올 때, 이 LocalValidatorFactoryBean이 개입합니다. 
애노테이션 기반으로 검증을 수행한 후 오류가 발견되면 FieldError나 ObjectError를 생성하여 스프링의 
BindingResult 객체에 차곡차곡 담아주는 역할을 수행합니다. 
[1] (https://bnzn2426.tistory.com/157), 
[2] (https://velog.io/@jeong_woo/Spring-Bean-Validation)

⚠️ 개발 시 주의할 점

• 직접 등록 시 자동 설정 해제: 만약 개발자가 직접 자바 설정 코드(@Bean)를 통해 
커스텀 Validator를 글로벌로 등록해 버리면, 스프링 부트는 LocalValidatorFactoryBean을 
글로벌로 등록하지 않습니다. 
이 경우 기존의 @NotNull 같은 애노테이션 기반 빈 검증이 정상 작동하지 않을 수 있으므로 주의해야 합니다. 
[1] (https://m.blog.naver.com/hj_kim97/223036873193)
• 초기화 에러: 간혹 Error creating bean with name 'LocalValidatorFactoryBean'이라는 
에러가 발생한다면, 대개 validation 라이브러리 의존성이 빠졌거나 스프링 부트 버전에 따른 패키지 
기준(javax.validation vs jakarta.validation)이 꼬였을 가능성이 높습니다. 
[1] (https://pso62.tistory.com/entry/Error-creating-bean-with-name-LocalValidatorFactoryBean0-%E2%80%94-Unable-to-create-a-Configuration-%ED%95%B4%EA%B2%B0)


혹시 현재 프로젝트에서 LocalValidatorFactoryBean과 관련된 에러가 발생했나요? 아니면 검증 로직을 커스텀하게 확장하려는 목적이신가요? 상황을 알려주시면 알맞은 구현 방법이나 해결책을 제안해 드릴 수 있습니다.

-----------------------------------------------------

LocalValidatorFactoryBean의 setValidationMessageSource 메서드는 유효성 검증(Validation) 실패 시 보여줄 에러 메시지를 스프링의 MessageSource와 연동하도록 설정하는 메서드입니다.
이 메서드를 사용하면 자바 표준 검증 메시지 파일(ValidationMessages.properties) 대신, 스프링이 관리하는 메시지 파일(messages.properties)을 통해 에러 메시지를 일원화하여 관리할 수 있습니다.

💡 왜 사용하나요? (핵심 의미)


1. 에러 메시지 관리의 일원화 (Spring 통합)

원래 Bean Validation 표준은 src/main/resources/ValidationMessages.properties 파일에서 메시지를 찾습니다.
반면 스프링은 일반적인 안내 문구나 일반 오류 메시지를 messages.properties에서 관리합니다.
setValidationMessageSource를 사용하면 검증 오류 메시지도 스프링의 messages.properties 한 곳에서 한꺼번에 관리할 수 있게 됩니다.

2. 다국어 지원(i18n) 및 스프링 기능 활용

스프링의 MessageSource는 사용자의 브라우저 언어 설정(Locale)에 따라 messages_en.properties, messages_ko.properties 등을 자동으로 선택해 주는 강력한 다국어 기능을 제공합니다. 이 메서드를 통해 검증기(Validator)가 스프링의 다국어 지원 시스템을 그대로 이용할 수 있게 됩니다.

3. 프로퍼티 플레이스홀더 사용

메시지 내부에서 스프링의 환경 변수나 프로퍼티 값을 참조할 수 있도록 확장하기가 용이해집니다.

💻 코드 예시

보통 커스텀 설정을 통해 스프링의 MessageSource를 LocalValidatorFactoryBean에 주입할 때 다음과 같이 사용합니다.
java
@Configuration
public class WebConfig {

    @Bean
    public LocalValidatorFactoryBean getValidator(MessageSource messageSource) {
        LocalValidatorFactoryBean bean = new LocalValidatorFactoryBean();
        // 스프링의 MessageSource를 Bean Validation의 메시지 소스로 설정
        bean.setValidationMessageSource(messageSource);
        return bean;
    }
}
코드를 사용할 때는 주의가 필요합니다.
이렇게 설정하면 DTO에서 다음과 같이 스프링 메시지 파일의 키 값을 사용할 수 있습니다.
java
public class UserDto {
    // messages.properties에 등록된 'user.name.empty' 키의 메시지를 가져옴
    @NotBlank(message = "{user.name.empty}")
    private String name;
}
코드를 사용할 때는 주의가 필요합니다.
현재 프로젝트에서 다국어(영어/한국어 등) 에러 메시지 처리가 필요하신 상황인가요? 아니면 특정 메시지 파일 이름으로 변경하고 싶으신 것인지 말씀해 주시면 정확한 파일 설정 방법을 안내해 드리겠습니다.

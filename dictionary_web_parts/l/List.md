자바에서 List는 인터페이스(Interface)이고, ArrayList는 이를 구현한 구체적인 클래스(Class)입니다.
쉽게 비유하자면 List는 "운전면허증(규격/설계도)"이고, ArrayList는 "소나타(실제 굴러가는 자동차)"라고 볼 수 있습니다.
------------------------------
## 📊 List와 ArrayList의 주요 차이점

| 구분 | List (인터페이스) | ArrayList (구체 클래스) |
|---|---|---|
| 정의 | 구조에 대한 행동(메서드)만 정의한 규격 | List 규격을 바탕으로 실제 데이터 구조를 구현한 클래스 |
| 인스턴스 생성 | ❌ new List()로 객체 생성 불가능 | ⭕ new ArrayList()로 객체 생성 가능 |
| 내부 구조 | 내부 구조를 가질 수 없음 | 내부적으로 동적 배열(Array) 구조를 사용함 |
| 대체 가능성 | LinkedList, Vector 등으로 유연하게 교체 가능 | ArrayList 고유의 기능 및 특징에 종속됨 |

------------------------------
## 💡 실무에서 코드를 작성하는 정석 방법
자바에서는 선언할 때 인터페이스 타입(List)을 사용하고, 객체를 생성할 때 구체 클래스(ArrayList)를 대입하는 방식을 권장합니다.

// ⭕ 올바르고 권장되는 선언 방식
List<String> list = new ArrayList<>();

## 이렇게 작성하는 이유 (다형성의 장점)
만약 데이터가 빈번하게 추가/삭제되어 성능 향상을 위해 ArrayList 대신 LinkedList로 구조를 바꿔야 하는 상황이 오면, 우측의 생성자 코드만 바꾸면 되기 때문입니다.

// 좌측의 선언부가 List이기 때문에, 우측만 LinkedList로 바꿔도 나머지 소스코드를 수정할 필요가 없습니다.
List<String> list = new LinkedList<>(); 

반면 ArrayList<String> list = new ArrayList<>(); 형태로 선언해 버리면, 나중에 구조를 바꿀 때 좌측의 선언부와 이 변수를 받아 쓰던 다른 메서드들의 파라미터까지 전부 수정해야 하는 번거로움이 생깁니다.
------------------------------
현재 개발 중인 프로젝트에서 데이터의 삽입/삭제가 빈번한가요, 아니면 단순히 데이터를 조회(읽기)하는 작업이 대부분인가요? 상황에 맞는 가장 효율적인 List 구현체(ArrayList vs LinkedList)를 추천해 드릴 수 있습니다.

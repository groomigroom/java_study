독고다이로 혼자 존재하는 클래스는 아니며, 전자정부프레임워크(eGovFrame)의 시큐리티(Security) 
간소화 서비스나 Spring Security 확장 모듈에서 사용하는 클래스/설정 관련 래퍼 객체를 의미합니다.
가장 핵심적인 의미와 역할은 웹 요청(HttpServletRequest)의 보안 관련 메서드를 전자정부프레임워크
(Spring Security)의 인증 정보와 연동되도록 감싸는(Wrapping) 것입니다.

💡 핵심 역할 3가지

1. 표준 Servlet 메서드 재정의(Override)
	• 서블릿 컨테이너(Tomcat 등)가 기본적으로 제공하는 request.getRemoteUser(), 
request.isUserInRole(), request.getUserPrincipal() 같은 메서드들이 있습니다.
	• RequestWrapperForSecurity는 이 메서드들을 가로채어, Spring Security가 
관리하는 인증(Authentication) 객체 및 권한(Role) 정보와 연결해 줍니다.
2. Spring Security와의 심리스(Seamless)한 통합
	• 기존 레거시 코드나 전자정부프레임워크 내부 공통 컴포넌트에서 Spring Security 
전용 API(SecurityContextHolder...)를 쓰지 않고, 단순 HTML/JSP나 서블릿 API 표준 
메서드(request.isUserInRole("ROLE_USER"))만 호출해도 로그인한 사용자의 권한을 올바르게 체크할 수 있도록 돕습니다.
3. 보안 필터 체인(Filter Chain)의 일부
	• 전자정부프레임워크의 EgovSpringSecurityLoginFilter나 관련 서블릿 필터 설정에서 웹 
요청이 들어올 때 이 래퍼클래스로 request 객체를 감싸서 다음 필터나 컨트롤러로 넘겨주는 역할을 합니다.

🛠️ 주로 쓰이는 곳 (설정 예시)

전자정부프레임워크의 context-security.xml 또는 관련 Spring Security 설정 파일(Java Config)을 
보면 다음과 같은 형태로 필터나 빈(Bean)이 등록되어 있는 것을 확인할 수 있습니다.
xml
<!-- 예시: 서블릿 요청을 보안 래퍼로 감싸주는 설정 -->
<b:bean id="requestWrapperFilter" class="org.springframework.security.web.servletapi.SecurityContextHolderAwareRequestFilter" />
코드를 사용할 때는 주의가 필요합니다.
(참고: 전자정부프레임워크 버전에 따라 이를 커스텀하게 구현하여 RequestWrapperForSecurity라는 
이름의 필터나 클래스로 직접 명시해 사용하는 경우가 많습니다.)
추가적으로 프로젝트 내에서 이 클래스로 인해 특정 에러가 발생했거나, 커스텀하게 확장하는 방법이 궁금하신가요? 관련하여 구체적인 소스 코드나 에러 로그를 알려주시면 디버깅을 도와드리겠습니다.

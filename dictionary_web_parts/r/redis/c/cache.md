# 캐시
* 캐시 (Cache)는 원본 저장소보다 빠르게 가져올 수 있는 임시 데이터 저장소를 의미함.
* 인터넷 사용 기록 삭제에서 캐시된 이미지 및 파일 이런식으로도 있음.

# 캐싱
* 캐시에 접근해서 데이터를 빠르게 가져오는 방식

# Cache Aside (= Look Aside, Lazy Loading) 전략
* 데이터를 조회할 때 주로 사용하는 전략이 Cache Aside 전략입니다.
* Look Aside 전략 또는 Lazy Loading 전략이라고 부름.
```
처음으로 게시판 서비스를 베포했다고 가정시에
Cache Aside 작동 방식을 이해하기
```
1. 처음 게시판 서비스를 배포했기 때문에 데이터베이스와 레디스에는 아무런 데이터도 저장이 안되어 있다.
2. 일부 사용자가 들어와 게시물 작성을 함으로써 데이터를 저장함. 이 데이터는 DB에 저장됨. (레디스에는 저장 안됨)
3. 사용자가 데이터를 조회하려고 요청함. 이 때 DB로부터 바로 데이터 조회를 하기 전에 레디스에 있는지 먼저 확인함
4. 레디스에 데이터가 없는 걸 확인한 뒤에 DB로부터 데이터를 조회해서 응답함.
5. 데이터베이스로부터 조회한 데이터를 응답한 뒤에 레디스에도 데이터를 저장해둠.
6. 다시 한 번 사용자가 데이터를 조회하려고 요청
7. 레디스에 조회하고자 하는 데이터가 있는지 확인하니, 데이터가 존재해서 레디스로부터 데이터를 바로 가져와 버림...

# Write Around 전략
```
Cache Aside 전략이 데이터를 어떻게 조회할 지에 대한 전략이었다면,
Write Around 전략은 데이터를 어떻게 쓸 지 (저장, 수정, 삭제)에 대한 전략이다.
Write Around 전략은 Cache Aside 전략과 같이 자주 활용되는 전략이다.
데이터를 저장할 때는 레디스에 저장하지 않고 DB에만 저장하는 방식이다.
그러다 데이터를 조회할 때 레디스에 데이터가 없으면 DB로부터 데이터를 조회해서 레디스에 저장시켜주는 방식

```

전자정부표준프레임워크에서 org.springframework.web.bind.annotation.RequestMethod는 스프링 MVC 기반 컨트롤러가 
처리할 HTTP 요청 방식(GET, POST, PUT, DELETE 등)을 지정하는 열거형(Enum)입니다. 

전자정부표준프레임워크는 스프링(Spring)을 기반으로 구축되어 있으므로, 
RequestMethod의 정의와 역할은 일반 스프링 프레임워크와 동일합니다. 
주로 @RequestMapping 어노테이션의 method 속성에 사용되어 특정 URL 
요청이 어떤 HTTP 메서드로 들어올 때 해당 컨트롤러 메서드를 실행할지 결정합니다. 


주요 역할 및 의미

• 요청 방식 제한: 페이지 조회(GET)와 데이터 등록·수정·삭제(POST, PUT, DELETE)를 구분해 처리합니다.
• URL 충돌 방지: 동일한 URL 경로라도 HTTP 메서드가 다르면 서로 다른 컨트롤러 메서드에 매핑할 수 있습니다.
• 보안 및 명확성 확보: 의도하지 않은 HTTP 메서드 호출을 걸러내어 웹 애플리케이션의 동작을 명확히 합니다.

사용 예시

java
import org.springframework.stereotype.Controller;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestMethod;

@Controller
public class BoardController {

    @RequestMapping(value = "/board/list.do", method = RequestMethod.GET)
    public String list() {
        return "board/list";
    }

    @RequestMapping(value = "/board/write.do", method = RequestMethod.POST)
    public String write() {
        return "redirect:/board/list.do";
    }
}
코드를 사용할 때는 주의가 필요합니다.

유사·대체 표현

• 단축 어노테이션(축약형): RequestMethod.GET 대신 @GetMapping, RequestMethod.POST 대신 
@PostMapping처럼 HTTP 메서드별 전용 어노테이션을 사용할 수 있습니다(@PutMapping, @DeleteMapping, @PatchMapping 등).
• 다중 메서드 지정: {RequestMethod.GET, RequestMethod.POST}처럼 배열 형태로 여러 HTTP 방식을 동시에 허용할 수 있습니다. 

자세한 컨트롤러 매핑 구조는 전자정부 표준프레임워크 문서에서 확인할 수 있습니다. 
현재 사용 중인 전자정부표준프레임워크 버전이나 특정 컨트롤러 코드 상황을 알려주시면, 그에 맞는 매핑 방식이나 대체 어노테이션 적용법을 안내해 드릴 수 있습니다.

RESTful 웹 서버 개발이란 웹의 기존 HTTP 프로토콜을 그대로 활용하여, 화면(HTML) 대신 순수한 '데이터(JSON/XML)'만 주고받는 효율적인 서버를 구축하는 것을 의미합니다. 과거의 웹 서버가 사용자의 브라우저에 보여줄 완성된 화면(HTML)을 직접 만들어 보냈다면, RESTful 웹 서버는 자원(Resource) 중심으로 데이터를 처리하여 프론트엔드와 백엔드를 완전히 분리해 줍니다. [1, 2, 3, 4] 
------------------------------
## 💡 핵심 개발 원칙 (어떻게 만드나요?)
RESTful하게 서버를 설계하려면 보통 다음 3가지 규칙을 철저히 따릅니다. [2, 4, 5] 

* 
* URI는 명사(자원)로만 구성: 주소창에 .../getUsers 같은 행위(동사)를 적지 않고, .../users 처럼 대상이 되는 자원(명사)만 지정합니다. [5, 6] 
* HTTP 메서드로 행위 표현: 데이터에 대한 제어는 HTTP 표준 메서드를 활용합니다.
* GET : 데이터 조회 (Read)
   * POST : 데이터 등록 (Create)
   * PUT / PATCH : 데이터 수정 (Update)
   * DELETE : 데이터 삭제 (Delete) [2, 4, 7, 8, 9] 
* 상태 비저장(Stateless): 서버는 클라이언트의 과거 상태(세션 등)를 기억하지 않으며, 들어오는 각각의 요청을 독립적인 하나의 트랜잭션으로만 처리합니다. [3, 10] 
* 

------------------------------
## 🛠️ 실제 개발에서의 의미와 장점

* 
* 클라이언트와 서버의 완벽한 분리: 서버는 데이터만 던져줄 뿐입니다. 덕분에 동일한 RESTful 서버 하나로 PC 웹, 아이폰 앱, 안드로이드 앱에 모두 데이터를 공급할 수 있습니다. [1] 
* 높은 가독성과 유지보수성: 주소(URI)와 HTTP 메서드만 보고도 이 요청이 무엇을 하려는지 단번에 파악할 수 있어, 협업과 디버깅이 매우 쉬워집니다. [11] 
* 확장성과 표준화: 별도의 특수한 프로토콜을 배울 필요 없이, 전 세계 표준인 HTTP 프로토콜을 그대로 확장하여 사용하므로 시스템 구축 비용이 낮아집니다. [3, 12, 13] 
*

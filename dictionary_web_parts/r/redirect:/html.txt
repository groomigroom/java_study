자바 스프링 부트(Spring Boot)에서 redirect:/html을 반환하는 것은 브라우저에게 "즉시 /html이라는 주소(URL)로 다시 접속해라"라고 명령하는 것입니다.
이것은 단순히 타임리프(Thymeleaf) HTML 파일을 화면에 띄우는 것과 완전히 다릅니다.
## 핵심 동작 원리

* 새로운 요청 발생: 브라우저의 URL 주소창이 실제로 http://localhost:8080/html로 변경됩니다.
* 컨트롤러 재호출: 스프링 부트에서 @GetMapping("/html")로 매핑된 메서드가 새롭게 실행됩니다.
* 타임리프 템플릿 반환: 재호출된 메서드가 최종적으로 타임리프 파일명(예: return "html";)을 반환해야 화면이 나타납니다.

------------------------------
## 일반 반환 vs Redirect 반환 차이점

| 구분 | return "html"; (일반) | return "redirect:/html"; (리다이렉트) |
|---|---|---|
| 의미 | html.html 템플릿 파일을 찾아 바로 렌더링 | /html 주소(URL)로 이동하라고 브라우저에 지시 |
| URL 주소창 | 처음 요청한 주소 그대로 유지 | /html로 변경됨 |
| 데이터 유지 | Model에 담은 데이터가 화면까지 전달됨 | 기존 Model 데이터가 모두 삭제됨 (새 요청이므로) |

------------------------------
## 주요 사용 목적 (PRG 패턴)
가장 대표적인 사용 처는 데이터 저장/수정/삭제 후 화면을 이동할 때입니다.
이를 PRG(Post-Redirect-Get) 패턴이라고 합니다.

   1. 문제 상황: 사용자가 글쓰기 버튼(POST 요청)을 누른 후 화면을 그대로 렌더링하면, 사용자가 새로고침(F5)을 누를 때마다 동일한 글이 중복해서 저장됩니다.
   2. 해결 방법: 저장이 끝나면 return "redirect:/board/list";를 반환합니다. 브라우저는 안전한 조회(GET) 화면으로 이동하므로 새로고침을 해도 중복 저장이 일어나지 않습니다.

------------------------------
현재 작성 중이신 컨트롤러의 구조를 보여주시면, redirect가 왜 필요한지 혹은 어떻게 코드를 수정해야 하는지 더 정확히 설명해 드릴 수 있습니다.
다음 중 어떤 작업에 대해 더 알고 싶으신가요?

* 리다이렉트 시 데이터를 안전하게 넘기는 방법 (RedirectAttributes)
* 중복 제출을 막는 PRG 패턴의 실제 코드 예시
* 타임리프 파일이 열리지 않고 404 에러가 나는 이유

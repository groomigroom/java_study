org.springframework.web.multipart.MultipartResolver;

스프링 부트에서 MultipartResolver는 웹 클라이언트가 보낸 
멀티파트(Multipart) 요청을 추상화하여, 파일 업로드를 쉽게 처리할 수 
있도록 돕는 핵심 인터페이스입니다.
일반적인 텍스트 데이터(이름, 아이디 등)와 달리, 이미지나 파일 같은 
이진 데이터(Binary Data)를 서버로 전송할 때는 HTTP 요청의 
Content-Type을 multipart/form-data로 지정하여 보냅니다. 
MultipartResolver는 이 복잡한 멀티파트 데이터를 가로채서 분석한 뒤, 
스프링 컨트롤러에서 MultipartFile이라는 편리한 객체로 파라미터를 받아 
쓸 수 있도록 가공해 줍니다.

🛠️ 주요 핵심 역할

1. 파일 데이터 파싱(Parsing)
	• HTTP 요청 메시지 바디에 섞여 들어온 텍스트 필드와 파일 데이터를 
	각각 분리해 냅니다.
2. MultipartHttpServletRequest로 변환
	• 일반 서블릿 요청(HttpServletRequest)을 파일 처리가 가능한 형태로 
	확장하여 스프링 MVC 내부로 전달합니다.
3. 용량 제한 및 에러 처리
	• 업로드되는 파일의 최대 크기나 한 번에 보낼 수 있는 총 요청 크기를 
	체크하고, 제한을 넘으면 예외(MaxUploadSizeExceededException)를 발생시킵니다.

🧩 스프링 부트의 기본 동작 (과거와 현재)

• 과거 (스프링 5 / 스프링 부트 2 이전):
	• Apache Commons FileUpload 라이브러리를 기반으로 한 CommonsMultipartResolver를 많이 썼습니다.
• 현재 (스프링 부트 3 이상 표준):
	• 서블릿(Servlet) 표준 자체에 포함된 멀티파트 기능을 사용하는 StandardServletMultipartResolver가 
	기본값(기본 빈)으로 자동 등록됩니다.
	• 따라서 개발자가 MultipartResolver를 자바 코드로 직접 생성하고 빈(@Bean)으로 등록할 필요가 거의 없어졌습니다.

💡 실무에서의 한 줄 요약

스프링 부트에서 파일 업로드 기능을 구현할 때, 자바 설정 파일에서 MultipartResolver를 직접 만질 일은 
거의 없습니다. 대신 application.properties 파일에 용량 설정만 추가하고, 컨트롤러에서 받아 쓰면 끝납니다.
[설정 예시]
properties
# 파일 하나의 최대 용량 제한
spring.servlet.multipart.max-file-size=10MB
# 한 번의 요청에 포함된 전체 파일 총 용량 제한
spring.servlet.multipart.max-request-size=10MB
코드를 사용할 때는 주의가 필요합니다.
[컨트롤러 사용 예시]
java
@PostMapping("/upload")
public String uploadFile(@RequestParam("file") MultipartFile file) {
    if (!file.isEmpty()) {
        String filename = file.getOriginalFilename();
        // 파일 저장 로직 수행...
    }
    return "success";
}
코드를 사용할 때는 주의가 필요합니다.

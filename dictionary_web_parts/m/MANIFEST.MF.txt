전자정부표준프레임워크(eGovFrame)에서 MANIFEST.MF는 특별히 독자적인 기술 구조를 가지는 
파일이 아니라, 자바(Java) 생태계의 표준 규격을 그대로 따르는 JAR/WAR 아카이브의 배포용 
메타데이터 정의 파일입니다. [1] (https://j2doll.tistory.com/981), [2] (https://gogumawang.tistory.com/78)
전자정부프레임워크는 자바(Spring 기반) 플랫폼 위에서 동작하므로, 프로젝트를 빌드하고 패키징할 때 
배포 파일의 루트 디렉토리 내부(META-INF/MANIFEST.MF)에 이 파일이 생성됩니다. [1] (https://haenny
.tistory.com/52), [2] (https://j2doll.tistory.com/981)
전자정부표준프레임워크 환경에서 MANIFEST.MF가 가지는 주요 의미와 역할은 다음과 같습니다.

1. 전자정부프레임워크 및 외부 라이브러리 버전 식별

전자정부표준프레임워크가 제공하는 핵심 오픈소스 라이브러리(egovframework.rte.* 등)나 기타 Spring 
프레임워크 라이브러리들을 모듈(JAR) 형태로 배포할 때, 해당 모듈의 이름, 버전, 구현 벤더 정보(전자정부
표준프레임워크 센터 등)를 명시합니다. 시스템 운영 및 유지보수 시 라이브러리 간의 버전 충돌이 발생하면 
이 파일의 정보를 기반으로 추적합니다. [1] (https://tlo-developer.tistory.com/273)

2. 클래스패스(Class-Path) 경로 지정

전자정부프레임워크 기반의 엔터프레임워크 애플리케이션(예: 외부 WAS에 배포되는 WAR나 단독 실행형 JAR) 내에서 
애플리케이션이 참조해야 하는 외부 JAR 라이브러리들의 경로를 지정할 수 있습니다. 빌드 도구(Maven, Gradle)가 
패키징을 수행할 때 종속된 의존성 라이브러리 목록을 Class-Path 속성에 자동으로 기입해 주기도 합니다. [1] 
(https://knight76.tistory.com/entry/20012032509), [2] (https://codingdreamtree.tistory.com/108)

3. 단독 실행형 애플리케이션의 진입점(Main-Class) 정의

배치(Batch) 서비스나 콘솔 기반의 백그라운드 프로그램을 실행 가능한 JAR(Executable JAR) 형태로 배포할 때 필수적입니다. 
java -jar [파일명].jar 명령어로 구동할 때 어떤 클래스의 main() 메서드를 시작점으로 삼을지(Main-Class) 명시하는 
역할을 합니다. [1] (https://codingdreamtree.tistory.com/108)

4. OSGi 환경 및 전자정부 개발환경(Eclipse) 플러그인 확장

전자정부표준프레임워크 개발환경(eGovFrame IDE)은 이클립스(Eclipse) 기반입니다. 이클립스 플러그인 생태계는 OSGi 모듈 
시스템을 따르는데, 이때 MANIFEST.MF에 플러그인의 식별자, 버전, 종속성 등을 적어 컴포넌트 간의 결합을 관리합니다.
💡 참고 (자주 발생하는 에러)
Maven 프로젝트를 가져오거나 빌드 설정을 변경할 때 META-INF/MANIFEST.MF (지정된 경로를 찾을 수 없습니다)와 같은 오류가 
Eclipse/STS에서 간혹 나타납니다. 이는 주로 프로젝트 빌드 경로 정보가 꼬여 메타데이터 폴더가 누락되었을 때 발생하며, 
Maven 프로젝트 업데이트(Alt+F5) 기능이나 프로젝트 Clean을 실행하면 정상적으로 재생성됩니다. [1] (https://haenny.tistory.com/52)
혹시 현재 개발 중인 전자정부프레임워크 프로젝트에서 특정 에러가 발생했거나, 특수한 배포 설정(예: 배치 실행, 외부 라이브러리 
수동 추가)을 하고 계신 상황인가요? 상황을 말씀해 주시면 알맞은 조치법을 안내해 드리겠습니다.

java.util.Properties

는 자바 표준 라이브러리(JDK)에 내장된 클래스로, 
key-value(키-값) 쌍이 모두 문자열(String) 형태로 
이루어진 데이터를 관리하는 설정 파일용 컬렉션입니다. 
.properties 확장자를 가진 파일(예: application.properties)을 읽고 쓰거나, 
시스템 설정값들을 메모리에 저장할 때 사용합니다.
스프링 부트에서는 주로 애플리케이션의 환경 설정 정보(데이터베이스 
연결 정보, 타임아웃 시간, 다국어 설정 등)를 관리하는 핵심 수단으로 활용됩니다.

💡 작성하신 코드의 구체적인 의미

java
Properties prop = new Properties();
prop.setProperty("org.springframework.dao.DataAccessException", "error");
코드를 사용할 때는 주의가 필요합니다.
이 코드는 메모리 상에 새로운 설정 장부(Properties)를 만들고, 특정 
예외가 발생했을 때 이동할 뷰(View)의 이름을 매핑하는 설정을 담는 과정입니다. 
각 줄의 의미는 다음과 같습니다.
1. new Properties(): 빈 설정 장부(키-값 쌍을 담을 객체)를 생성합니다.
2. prop.setProperty("키", "값"): 장부에 데이터를 하나 저장합니다.
	• Key (왼쪽): "org.springframework.dao.DataAccessException" 
➡️ 스프링에서 데이터베이스 작업 중 에러가 났을 때 발생하는 대표적인 예외 클래스의 풀 네임(Full Name)입니다.
	• Value (오른쪽): "error" 
➡️ 위 예외가 발생했을 때 사용자에게 보여줄 에러 페이지(뷰)의 이름입니다. 
(예: error.html 또는 error.jsp)

🗺️ 맥락으로 보는 이 코드의 진짜 목적

이 코드는 바로 이전 질문에서 다루었던 HandlerExceptionResolver를 설정할 때 주로 사용되는 
방식입니다.
과거 스프링(혹은 구버전 스타일)에서는 예외 처리 해결사인 SimpleMappingExceptionResolver라는 
클래스를 사용할 때 다음과 같이 설정을 넘겨주었습니다.
java
SimpleMappingExceptionResolver resolver = new SimpleMappingExceptionResolver();

Properties prop = new Properties();
prop.setProperty("org.springframework.dao.DataAccessException", "error"); // DB 에러 나면 error 페이지로 가라
prop.setProperty("java.lang.NullPointerException", "null-error");      // 널 포인터 에러 나면 null-error 페이지로 가라

resolver.setExceptionMappings(prop); // 설정 적용
코드를 사용할 때는 주의가 필요합니다.
즉, 작성하신 메서드는 "데이터베이스 관련 에러(DataAccessException)가 터지면, 
개발자가 미리 만들어 둔 error라는 이름의 화면(HTML/JSP)을 사용자에게 띄워줘라"라는 
맵핑 설정을 준비하는 행위입니다.


스프링 부트 환경에서는 이러한 예외-화면 매핑을 자바 코드로 직접 Properties에 적기보다는, @ExceptionHandler 어노테이션을 쓰거나 /templates/error/ 디렉토리에 파일만 두면 자동으로 매핑해주는 편리한 기능을 제공합니다. 이 스프링 부트 표준 에러 페이지 자동 매핑 방식에 대해 알아보고 싶으신가요?

# .load()

java.util.Properties의 .load()는 외부 파일이나 스트림에 적힌 key=value 설정 데이터를 읽어와 Properties 
객체 안에 채워 넣는 메서드예요. 코드를 다시 컴파일하지 않고도 DB 접속 정보나 환경 설정값 등을 쉽게 불러와 쓸 수 있게 해줍니다. 

주요 형태

• load(InputStream inStream): 바이트 스트림(FileInputStream 등)에서 속성을 읽어와 객체에 추가합니다. 
기본적으로 ISO-8859-1 인코딩 기준으로 해석합니다.
• load(Reader reader): 문자 스트림(InputStreamReader, FileReader 등)에서 속성을 읽어와 객체에 추가합니다.
한글 같은 문자가 깨질 때는 UTF-8로 지정한 InputStreamReader를 넘기는 식으로 활용할 수 있어요. 


사용 예시

java
Properties prop = new Properties();

try (InputStreamReader reader = new InputStreamReader(
        new FileInputStream("config.properties"), StandardCharsets.UTF_8)) {
    prop.load(reader); // 파일의 key=value 내용을 불러옴
    String dbUrl = prop.getProperty("db.url"); // 불러온 값 조회
}
코드를 사용할 때는 주의가 필요합니다.
• 불러온 값은 getProperty("키")로 꺼내고, 수정·추가는 setProperty("키", "값")으로 다룹니다.
• 관련 활용법이나 인코딩 처리가 궁금하다면 velog의 Properties 활용 글이나 티스토리의 Properties 
한글 깨짐 해결 글도 참고해 보세요.

# .containsKey()

java.util.Properties에서 .containsKey(Object key)는 해당 Properties 객체(또는 상속받은 상위 
Hashtable)에 특정 키(Key)가 존재하는지 확인하는 메서드입니다. 존재하면 true, 없으면 false를 반환합니다.
Properties 클래스는 내부적으로 Hashtable<Object, Object>을 상속받기 때문에, Hashtable의 
메서드를 그대로 물려받아 사용합니다.

주요 특징 및 주의사항

• 기본 동작: 현재 객체에 키가 매핑되어 있는지 Object 타입으로 검사합니다.
• 기본값(defaults) 미포함: Properties 생성 시 넘겨준 defaults 객체에 키가 있더라도, 현재 객체 자체에 없으면 false를 반환합니다.
• 타입 주의: 파라미터가 Object이므로 문자열(String)이 아닌 다른 타입을 넣어도 컴파일 에러가 나지 않지만, 실제로는 false가 반환됩니다.
• Null 불가: Hashtable 기반이므로 키 값으로 null을 전달하면 NullPointerException이 발생합니다.

containsKey() vs getProperty() 비교

Properties를 다룰 때는 Hashtable에서 상속된 메서드 대신 문자열 전용 메서드(getProperty)를 쓰는 것이 안전합니다.

구분	containsKey(Object key)	getProperty(String key) != null
출처	Hashtable에서 상속	Properties 고유 메서드
기본값(defaults) 탐색	안 함 (현재 객체만 확인)	함 (현재 객체에 없으면 기본값까지 탐색)
권장 여부	일반 Map처럼 쓸 때만 사용	설정 파일(Properties) 조회 시 강력 권장


코드 예시

java
import java.util.Properties;

public class Main {
    public static void main(String[] args) {
        Properties defaultProps = new Properties();
        defaultProps.setProperty("timeout", "5000");

        // defaultProps를 기본값으로 가지는 Properties 생성
        Properties appProps = new Properties(defaultProps);
        appProps.setProperty("username", "admin");

        // 1. 현재 객체에 직접 등록된 키 확인
        System.out.println(appProps.containsKey("username")); // true

        // 2. 기본값(defaults)에만 있는 키 확인 (주의!)
        System.out.println(appProps.containsKey("timeout"));  // false
        System.out.println(appProps.getProperty("timeout"));  // "5000" (정상 조회됨)
    }
}
코드를 사용할 때는 주의가 필요합니다.
따라서 Properties에서 특정 설정 키가 유효한지 확인할 때는 containsKey()보다 props.getProperty("키이름") != null 형태로 확인하는 것이 의도치 않은 버그를 줄이는 좋은 방법입니다.

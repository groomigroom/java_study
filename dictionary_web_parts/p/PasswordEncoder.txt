스프링 부트에서 PasswordEncoder는 사용자의 비밀번호를 안전하게 단방향 암호화(해시)하고, 입력된 비밀번호가 저장된 암호와 일치하는지 검증하는 데 사용하는 인터페이스입니다. [1, 2] 
필요한 스타터 의존성과 핵심 의미를 정리해 드립니다.
------------------------------
## 📦 필요한 스타터 의존성 (Starter Dependency)
PasswordEncoder 인터페이스와 그 구현체들은 스프링 시큐리티 핵심 모듈에 포함되어 있습니다.

* spring-boot-starter-security

이 의존성을 추가하면 BCryptPasswordEncoder, Argon2PasswordEncoder 등 강력한 암호화 알고리즘을 즉시 사용할 수 있습니다.
------------------------------
## 💡 PasswordEncoder의 3가지 핵심 의미 및 역할## 1. 단방향 해시 암호화 (복호화 불가능) [3] 

* 비밀번호는 데이터베이스가 해킹당하더라도 원래 값을 알 수 없도록 단방향(One-Way)으로만 암호화되어야 합니다. 즉, 암호화된 텍스트를 다시 원래 비밀번호로 되돌리는 복호화 기능은 존재하지 않습니다.
* String encode(CharSequence rawPassword) 메서드를 사용하여 평문 비밀번호를 안전한 해시 값으로 변환합니다.

## 2. 솔팅(Salting)과 키 스트레칭(Key Stretching) 자동화

* 기본 구현체로 가장 많이 쓰는 BCryptPasswordEncoder는 암호화할 때마다 내부적으로 랜덤한 소금(Salt)을 쳐서 완전히 다른 결과값을 만들어냅니다.
* 이 덕분에 같은 비밀번호("password123")를 가진 사용자가 여러 명이어도, DB에는 완전히 다른 난수 형태로 저장되어 해커의 사전 공격(Dictionary Attack)을 방어합니다.

## 3. 일치 여부 검증 기능 제공

* 복호화가 불가능하기 때문에 로그인 시 사용자가 입력한 평문 암호와 DB의 암호화된 값을 직접 ==로 비교할 수 없습니다.
* 대신 boolean matches(CharSequence rawPassword, String encodedPassword) 메서드를 제공합니다. 이 메서드는 입력받은 평문에 저장된 솔트 값을 적용해 다시 해싱한 후, DB의 값과 똑같은지 안전하게 비교해 줍니다. [4] 

------------------------------
## 🛠️ 실제 사용 예시 (스프링 부트 3.x 표준)
보통 다음과 같이 스프링 시큐리티 설정 클래스에서 구현체를 빈(Bean)으로 등록한 뒤, 회원가입이나 로그인 서비스에서 주입받아 사용합니다.

@Configuration
@EnableWebSecuritypublic class SecurityConfig {
    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder(); // 가장 권장되는 기본 구현체
    }
}

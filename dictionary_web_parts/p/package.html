package

자바 스프링 메인 패키지 안에 폴더(패키지)를 더 만들어서 넣어도 됩니다.
보통 기능이나 계층별로 나누어 controller, service, repository 같은 하위 패키지를 자유롭게 생성해 사용합니다.
패키지 구조화 방법
기능별 분리: 도메인이나 사용자, 주문 등 기능 단위로 패키지를 묶기
계층별 분리: 성격에 따라 뷰, 로직, 데이터 처리 파일들을 각각 나누기

자바 스프링에서 패키지 내 파일들이 연결되는 원리는 컴파일 타임의 자바 클래스 로딩 및 임포트(import),
그리고 런타임의 스프링 컨테이너(IoC/DI)와 컴포넌트 스캔 덕분입니다.
핵심 원리는 임포트와 패키지 구조, 의존성 주입(DI), 컴포넌트 스캔입니다.
자바 기본 연결 원리
패키지 선언 (package): 파일이 속한 폴더 위치를 지정합니다.
같은 패키지 안에서는 다른 파일을 바로 쓸 수 있습니다.
임포트 선언 (import): 다른 패키지에 있는 파일을 가져와서 연결합니다.
컴파일: 자바가 이 이름을 보고 파일들을 서로 찾아 묶어줍니다.
스프링의 동적 연결 원리 (빈 관리)
컴포넌트 스캔 (@ComponentScan): 스프링이 시작될 때 특정 패키지 안을 돌며 @Component, @Service, @Controller 등이 붙은 클래스들을 찾습니다.
스프링 빈 등록: 찾은 클래스들을 스프링 컨테이너에 객체(빈)로 미리 만들어 담습니다.
의존성 주입 (@Autowired): 빈으로 등록된 객체와 객체 사이를 @Autowired나 생성자를 통해 자동으로 연결(주입)해 줍니다.

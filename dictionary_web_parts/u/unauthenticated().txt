unauthenticated(username, password)

자바 스프링 부트에서 .unauthenticated(username, password)는 아직 인증되지 않은 상태의 사용자 정보(아이디와 비밀번호)를 담은 인증 객체를 생성하는 메서드입니다. [1] 
스프링 부트 3.x 버전 이상(Spring Security 6.x 이상)에서 기존의 생성자 방식 대신, 코드를 더 직관적이고 안전하게 작성할 수 있도록 도입된 UsernamePasswordAuthenticationToken 클래스의 정적 팩토리 메서드(Static Factory Method)입니다.
이와 관련된 상세한 의미와 필수 스타터 의존성, 그리고 매개변수의 의미는 다음과 같습니다.
------------------------------
## 1. .unauthenticated()의 핵심 의미
로그인 요청이 들어왔을 때, 이 사용자가 진짜 회원이 맞는지 검증하기 위해 "검증용 티켓"을 끊는 단계라고 이해하시면 됩니다.

// 💡 아직 인증되지 않은(unauthenticated) 상태의 토큰 객체를 생성합니다.
Authentication authenticationToken = 
    UsernamePasswordAuthenticationToken.unauthenticated(username, password);

이 메서드로 생성된 객체는 내부적으로 authenticated = false (인증되지 않음) 상태로 설정됩니다. 이후 이 객체는 스프링 시큐리티의 AuthenticationManager로 전달되어 데이터베이스의 실제 회원 정보와 일치하는지 비교·검증하는 과정을 거치게 됩니다.
------------------------------
## 2. 매개변수 2개의 각각의 의미

   1. 첫 번째 매개변수 (username 또는 principal)
   * 의미: 로그인을 시도하는 사용자의 식별자(아이디, 이메일 등)입니다.
      * 역할: 인증 과정에서 "내가 누구인지"를 주장하는 주체(Principal) 정보가 됩니다. [2, 3] 
   2. 두 번째 매개변수 (password 또는 credentials)
   * 의미: 사용자가 입력한 비밀번호(암호)입니다.
      * 역할: 사용자가 주장하는 신원(username)이 진짜 맞는지 증명하기 위한 자격 증명(Credentials) 데이터로 사용됩니다. [4] 
   
------------------------------
## 3. 이게 속해있는 Start Dependency (스타터 의존성)
이 메서드는 스프링 시큐리티의 핵심 인증 객체에 포함되어 있으므로 Spring Security 스타터 의존성이 필요합니다.

* Gradle (build.gradle):

implementation 'org.springframework.boot:spring-boot-starter-security'

* Maven (pom.xml):

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-security</artifactId>
</dependency>


의존성이 주입되면 패키지 상단에 import org.springframework.security.authentication.UsernamePasswordAuthenticationToken;을 선언하여 사용합니다.
------------------------------
## 💡 기존 방식과의 차이점 (왜 이걸 쓸까요?)
스프링 부트 과거 버전에서는 아래와 같이 new 키워드로 생성자를 직접 호출했습니다.

// 예전 방식 (생성자 호출)
Authentication token = new UsernamePasswordAuthenticationToken(username, password);

하지만 이 생성자는 코드를 읽을 때 이 토큰이 '인증 전' 토큰인지 '인증 완료' 토큰인지 직관적으로 알기 어려웠습니다. 이를 보완하기 위해 최신 스프링 시큐리티에서는 이름만 봐도 명확한 .unauthenticated() 메서드 사용을 강력히 권장하고 있습니다.
현재 custom 로그인 필터(Filter)나 컨트롤러에서 사용자가 보낸 로그인 데이터를 가로채 인증 토큰을 생성하는 로직을 구현 중이신가요? 이 토큰을 받아 실제 인증을 처리해 주는 AuthenticationManager 설정이나 인증 완료 후 JWT를 발급하는 과정 중 막히는 부분이 있다면 언제든 말씀해 주세요!

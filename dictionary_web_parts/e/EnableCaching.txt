스프링 부트(Spring Boot)에서 @org.springframework.cache.annotation.EnableCaching 
어노테이션은 애플리케이션 내에서 스프링의 캐시 추상화(Spring Cache) 기능을 
활성화하는 역할을 합니다. 

핵심 의미 및 동작 방식

• 캐시 기능 켜기: 이 어노테이션을 설정 클래스(주로 메인 애플리케이션 클래스나 
@Configuration 클래스)에 붙여야 @Cacheable, @CachePut, @CacheEvict 같은 캐시 
관련 어노테이션들이 정상적으로 동작합니다. 
• CacheManager 자동 탐색: @EnableCaching을 선언하면, 
스프링은 컨텍스트에서 CacheManager 빈(Bean)을 자동으로 찾아 등록하고 관리합니다.
• AOP 기반 동작: 스프링은 AOP(관점 지향 프로그래밍)를 이용해 캐시 어노테이션이 붙은 메서드를 가로챕니다.
	• 메서드가 호출되면 먼저 캐시 저장소를 확인하고, 데이터가 있으면(Cache Hit) 
실제 메서드를 실행하지 않고 캐시된 값을 곧바로 반환합니다.
	• 캐시에 데이터가 없으면(Cache Miss) 메서드를 실행한 뒤 그 결과를 캐시에 저장합니다. 

주요 함께 쓰이는 어노테이션


어노테이션	설명
@Cacheable	메서드 결과를 캐시에 저장하며, 동일한 파라미터로 호출 시 캐시된 데이터를 반환
@CachePut	캐시를 갱신하기 위해, 메서드 실행 결과를 무조건 캐시에 저장
@CacheEvict	캐시에서 특정 데이터를 삭제(무효화)할 때 사용
@CacheConfig	클래스 단위로 공통되는 캐시 설정을 묶어서 지정

참고: 스프링 부트에서는 @EnableCaching 선언만으로는 실제 인메모리 저장소
(예: Redis, Caffeine, EhCache 등)가 자동으로 구축되지 않습니다. 
별도의 CacheManager 설정이나 spring-boot-starter-cache 등의 라이브러리 추가가 필요할 수 있습니다.
캐시를 적용하려는 구체적인 저장소(Redis, Caffeine 등)가 있거나, 
@Cacheable 사용 중 겪고 계신 문제가 있다면 말씀해 주세요. 설정 방법을 안내해 드릴 수 있습니다.

org.egovframe.rte.fdl.cmmn.exception.handler.ExceptionHandler는 
전자정부 표준프레임워크(eGovFrame)에서 시스템 내부에서 발생한 예외(Exception)를 
최종적으로 어떻게 처리할지 정의하는 핵심 인터페이스입니다.
일반적으로 자바나 스프링에서 예외가 발생하면 에러 로그를 출력하고 프로그램이 
멈추거나 사용자에게 하얀색 에러 화면(White Label Error Page)을 보여줍니다.
하지만 이 인터페이스를 구현하면 "예외가 발생했을 때 로그를 남기고, 
관리자에게 메일을 보낸 뒤, 특정 에러 페이지로 이동시킨다" 같은 비즈니스 
요구사항에 맞는 후속 조치를 직접 제어할 수 있습니다.

1. 주요 역할과 의미

• 표준화된 예외 처리 창구: 전자정부 프레임워크는 예외가 발생하면 AOP(관점 지향 프로그래밍) 기술을 통해 예외를 가로챕니다. 가로챈 예외는 이 인터페이스를 구현한 클래스로 전달됩니다.
• 비즈니스 로직과의 분리: 개발자가 try-catch 문을 소스코드마다 지저분하게 작성하지 않아도, 예외 처리 로직을 한곳에 모아서 공통으로 관리할 수 있게 해줍니다.

2. 핵심 메서드: occur

이 인터페이스를 열어보면 보통 다음과 같은 구조의 메서드가 선언되어 있습니다.
java
public interface ExceptionHandler {
    void occur(Exception ex, String packageName);
}
코드를 사용할 때는 주의가 필요합니다.
• ex: 발생한 예외 객체 정보가 넘어옵니다. (어떤 에러가 났는지 확인 가능)
• packageName: 에러가 발생한 클래스의 패키지 경로가 넘어옵니다.
개발자는 이 occur 메서드를 오버라이딩(재정의)하여 에러가 발생했을 때 수행할 구체적인 행동을 코딩하게 됩니다.

3. 실제 활용 예시 (구현 클래스 구조)

프로젝트를 하실 때 이 인터페이스를 상속받아 아래와 같이 구현체(예: 앞서 질문하신 egovHandler)를 만들어서 사용합니다.
java
import org.egovframe.rte.fdl.cmmn.exception.handler.ExceptionHandler;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

public class EgovServiceExceptionHandler implements ExceptionHandler {

    private static final Logger LOGGER = LoggerFactory.getLogger(EgovServiceExceptionHandler.class);

    @Override
    public void occur(Exception ex, String packageName) {
        // 1. 로그 남기기
        LOGGER.error("[에러 발생] 패키지: " + packageName);
        LOGGER.error("[에러 내용]: " + ex.getMessage());
        
        // 2. 관리자 알림 알림 (예시)
        // emailService.sendErrorEmail(ex);
        
        // 3. 필요에 따라 공통 예외 페이지로 전환하기 위한 커스텀 처리 등등...
    }
}
코드를 사용할 때는 주의가 필요합니다.
이후 이 구현체를 이전 질문에서 보셨던 DefaultExceptionHandleManager에 등록(setHandlers)하면, 지정된 패턴(**service.impl.*) 안에서 에러가 터졌을 때 자동으로 이 occur 메서드가 실행되는 구조입니다.
현재 프로젝트에서 이 인터페이스를 상속받은 커스텀 에러 처리 클래스(구현체)를 새로 만드셔야 하는 상황인가요? 아니면 전자정부 프레임워크가 기본으로 제공하는 EgovComExcepHndlr 같은 공통 에러 핸들러 클래스를 연동하는 방법을 찾고 계시는지 말씀해 주시면 관련 설정 방법을 공유해 드리겠습니다.

IllegalArgumentException

자바 스프링 부트에서 IllegalArgumentException은 메서드에 전달된 인자(Parameter)가 올바르지 않을 때 발생하는 표준 런타임 예외입니다. [1] 
스프링 부트 환경에서는 주로 클라이언트가 보낸 요청 값이 비즈니스 로직의 검증 조건에 맞지 않거나, 프레임워크 설정과 데이터가 충돌할 때 발생합니다.
## 💡 주요 발생 원인

* 
* 데이터 검증(Validation) 실패: 나이 음수 입력, 필수 파라미터 누락 등 비즈니스 규칙 위반 시 발생합니다.
* 스프링 부트 3.2+ 버전 매개변수 컴파일 오류: 바인딩 시 -parameters 옵션 누락으로 변수명을 인식하지 못할 때 발생합니다. [2] 
* JPA 엔티티 바인딩 오류: 데이터베이스 조회 시 잘못된 타입의 인자를 넘겼거나, Entity가 아닌 클래스를 넘겼을 때 발생합니다. [3, 4] 
* URL/URI 형식 오류: 리다이렉트 경로 형식이 잘못되었거나 톰캣이 허용하지 않는 특수문자가 파라미터에 포함되었을 때 발생합니다. [5, 6] 
* 

## 🛠️ 해결 및 처리 방법
스프링 부트에서는 이 예외를 클라이언트에게 그대로 노출하지 않고, @RestControllerAdvice를 사용해 400 Bad Request 상태 코드로 변환하여 깔끔한 에러 메시지를 응답하는 것이 표준 관례입니다. [7] 

@RestControllerAdvicepublic class GlobalExceptionHandler {

    @ExceptionHandler(IllegalArgumentException.class)
    public ResponseEntity<String> handleIllegalArgumentException(IllegalArgumentException ex) {
        // 클라이언트에게 400 에러와 함께 예외 메시지 반환
        return ResponseEntity.status(HttpStatus.BAD_REQUEST).body(ex.getMessage());
    }
}

현재 작성 중인 코드의 어떤 상황(예: JPA 조회, API 요청 파라미터 수신, 스프링 버전 업그레이드 등)에서 이 에러가 발생했나요? 에러 로그를 보여주시면 정확한 원인을 진단해 드리겠습니다.

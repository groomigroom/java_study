자바와 스프링 부트에서 단독으로 쓰인 .build()는 "지금까지 채워 넣은 설정 데이터를 바탕으로, 최종적으로 사용할 실제 객체를 완성해서 만들어내라"는 명령입니다.
이는 자바 디자인 패턴 중 하나인 빌더 패턴(Builder Pattern)의 마지막 단계에 해당하는 메서드입니다.
------------------------------
## 1. 코드의 의미
설정이나 객체를 생성할 때, 수많은 옵션을 한 번에 넣으면 코드가 복잡해집니다. 이를 해결하기 위해 조립식으로 설정을 하나씩 추가한 뒤, 마지막에 .build()를 호출하여 완성품 객체를 얻어내는 구조입니다.
가장 대표적인 두 가지 활용 사례는 다음과 같습니다.
## ① Spring Security 설정 완성 (SecurityFilterChain)
질문자님이 앞서 질문하셨던 보안 설정들의 가장 마지막에 단독으로 붙어, 최종 보안 필터 체인 객체를 생성합니다.

@Beanpublic SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
    http
        .csrf(csrf -> csrf.disable())
        .sessionManagement(session -> session.sessionCreationPolicy(SessionCreationPolicy.STATELESS));

    // 지금까지 세팅한 내용(csrf 비활성화, 세션 무상태 등)을 모아서 
    // 최종적인 SecurityFilterChain 객체로 완성하여 반환함
    return http.build(); 
}

## ② Lombok 라이브러리를 활용한 일반 객체 생성
DTO나 Entity 객체를 만들 때 빌더 패턴을 쓰면 아래와 같이 마지막에 단독으로 쓰입니다.

User user = User.builder()
                .name("홍길동")
                .email("hong@test.com")
                .build(); // 최종 User 객체 생성

------------------------------
## 2. 소속 스타터 의존성 (Starter Dependency)
단독 .build() 메서드는 특정 라이브러리 하나에만 종속된 문법이 아니라, 어떤 객체를 만드느냐에 따라 소속된 의존성이 다릅니다.
현재 질문자님이 진행 중이신 코드 흐름상 가장 유력한 두 가지 의존성은 다음과 같습니다.
## 상황 A: Spring Security 설정을 마무리하는 중이라면

* 소속 의존성: spring-boot-starter-security [1]
* 설명: HttpSecurity 객체의 설정을 끝내고 SecurityFilterChain 객체를 빌드할 때 사용됩니다.

## 상황 B: 일반 자바 객체(DTO/Entity 등)를 조립하는 중이라면

* 소속 의존성: org.projectlombok:lombok (스타터는 아니지만 필수 라이브러리)
* 설명: 클래스 상단에 @Builder 어노테이션을 붙였을 때 자동으로 생성되는 빌더 메서드입니다.

------------------------------
현재 코드가 return http.build(); 처럼 Spring Security 설정을 마무리하는 단계인가요, 아니면 데이터를 담는 일반 객체를 생성하는 단계인가요? 어떤 객체를 생성하는 과정에서 .build()를 만났는지 알려주시면 해당 객체의 정확한 역할과 앞뒤 코드를 함께 설명해 드리겠습니다.

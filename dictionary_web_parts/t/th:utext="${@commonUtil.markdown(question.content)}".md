Thymeleaf에서 th:utext="${@commonUtil.markdown(question.content)}"는 스프링 빈(Bean)으로 등록된 commonUtil 클래스의 markdown 메서드를 호출하여 마크다운 텍스트를 HTML로 변환한 뒤, HTML 태그가 정상 작동하도록 화면에 그대로 출력하라는 의미입니다.
조금 복잡해 보이지만 내부 구조를 쪼개어 보면 타임리프의 핵심 기능 3가지가 정교하게 얽혀 있습니다.
------------------------------
## 1. th:utext (Unescaped Text) ★가장 중요

* 일반적인 th:text는 보안을 위해 <p>나 <strong> 같은 HTML 태그를 문자열(&lt;p&gt; 등)로 바꿔서 화면에 글자 그대로 보여줍니다(Escape).
* 반면 th:utext는 태그를 이스케이프하지 않고 실제 HTML 태그로 해석하여 반영합니다. 앞서 만든 마크다운 변환 결과물(<p><strong>본문</strong></p>)이 웹 브라우저에서 진짜 굵은 글씨의 문단으로 렌더링되려면 반드시 th:utext를 사용해야 합니다.

## 2. ${@commonUtil...} (스프링 빈 접근)

* 타임리프 표현식(${...}) 내부에서 변수명 앞에 @ 기호를 붙이면, 컨트롤러가 모델(Model)에 담아주지 않았더라도 스프링 컨테이너에 등록된 자바 클래스(스프링 빈)를 직접 호출할 수 있습니다.
* 즉, @commonUtil은 스프링 부트 안에서 @Component 등으로 선언된 CommonUtil 클래스의 인스턴스를 지칭합니다.

## 3. .markdown(question.content) (메서드 실행)

* question.content에 담긴 가공되지 않은 순수 마크다운 본문 텍스트를 CommonUtil 클래스의 markdown() 메서드 파라미터로 넘겨줍니다.
* 이 메서드 내부에서는 우리가 이전에 살펴본 Parser, Node, HtmlRenderer가 동작하며 마크다운을 HTML 문자열로 리턴해 주게 됩니다.

------------------------------
## 💻 동작 흐름 시각화

   1. 사용자가 질문 본문(question.content)에 ## 안녕하세요라고 입력했습니다.
   2. 타임리프 템플릿이 구동되면서 스프링 빈인 @commonUtil의 markdown("## 안녕하세요") 메서드를 호출합니다.
   3. 자바 코드가 가동되며 최종적으로 <h2>안녕하세요</h2>라는 HTML 문자열을 타임리프에 돌려줍니다.
   4. th:utext 속성 덕분에 웹 브라우저는 이를 문자가 아닌 실제 h2 타이틀 태그로 인식하여 화면에 크고 굵은 제목으로 그려냅니다.

------------------------------
## 💡 요약

* 의미: 스프링 빈(@commonUtil)을 타임리프 화면에서 직접 호출해 마크다운 본문을 HTML로 변경합니다.
* 역할: 변환된 HTML 코드를 깨짐 없이(태그가 작동하는 상태로) 화면에 출력하여, 사용자가 작성한 서식(제목, 굵게, 링크 등)이 웹 브라우저에 그대로 표현되도록 만듭니다.

이제 백엔드 자바 로직(Parser, HtmlRenderer)부터 프론트엔드 화면(th:utext, @스프링빈)까지 마크다운 게시판의 전체적인 데이터 흐름이 모두 연결되었습니다!
혹시 화면에 마크다운이 출력되는 과정에서 태그가 작동하지 않고 문자가 그대로 노출되거나, 원하지 않는 보안 이슈(XSS 걱정 등) 등 해결되지 않는 가려운 부분이 있으신가요? 관련하여 코드를 추가로 튜닝하고 싶다면 언제든 말씀해 주세요.

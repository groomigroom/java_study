org.springframework.web.multipart.support.StandardServletMultipartResolver;

스프링 부트에서 StandardServletMultipartResolver는 서블릿 3.0+ 
표준 사양(Specification)에 내장된 멀티파트 파싱 기능을 사용하여 
파일 업로드를 처리하는 MultipartResolver 구현체입니다.
앞서 설명해 드린 MultipartResolver가 "파일 업로드를 처리하겠다"는 
추상적인 약속(인터페이스)이라면, StandardServletMultipartResolver는 
그 약속을 구현한 실제 담당자(클래스)입니다.

🌟 왜 중요할까요? (스프링 부트의 표준)

과거 스프링에서는 파일 업로드를 하려면 Apache Commons FileUpload 같은 
외부 라이브러리를 별도로 추가하고 CommonsMultipartResolver를 개발자가 
직접 빈(Bean)으로 등록해야 했습니다.
하지만 톰캣(Tomcat)을 비롯한 현대 서블릿 컨테이너들이 내부에 파일 업로드 
기능을 기본 탑재하게 되면서, 스프링도 외부 라이브러리 없이 서블릿 표준 기능을 
사용하도록 발전했습니다. 그 중심에 있는 클래스가 바로 StandardServletMultipartResolver입니다.
스프링 부트에서는 이 클래스를 기본적(Default)으로 자동 등록(Auto Configuration)해 줍니다. 
따라서 별도의 자바 설정 없이 곧바로 MultipartFile 객체를 사용할 수 있습니다.

⚙️ 동작의 핵심 메커니즘

1. 톰캣이 먼저 가로챔: 웹브라우저가 파일을 전송하면, 스프링이 아니라 서버(WAS, 
주로 톰캣)가 HTTP 요청을 먼저 받아 디스크의 임시 디렉토리에 파일을 임시 저장합니다.
2. 스프링 객체로 전환: StandardServletMultipartResolver가 톰캣이 파싱해 놓은 
파일 데이터를 가져와서, 스프링의 MultipartHttpServletRequest 및 MultipartFile 객체로 감싸 컨트롤러에 넘겨줍니다.

⚠️ 실무 사용 시 꼭 알아야 할 주의점

만약 이 리졸버의 설정을 커스텀하고 싶어서 자바 코드로 빈(Bean)을 직접 정의할 때는 다음과 같이 작성합니다.
java
@Bean
public MultipartResolver multipartResolver() {
    return new StandardServletMultipartResolver();
}
코드를 사용할 때는 주의가 필요합니다.
하지만 여기서 결정적인 차이가 있습니다.
이 리졸버는 내부 메서드로 파일 용량 제한을 설정하는 setMaxUploadSize() 같은 메서드를 
제공하지 않습니다. 왜냐하면 용량 제한 처리를 스프링이 하는 게 아니라, 이미 서블릿 컨테이너(톰캣) 
단계에서 제어하기 때문입니다.
따라서 용량을 제한하고 싶다면 자바 코드가 아니라 application.properties(또는 application.yml) 
파일에 다음과 같이 설정해야 정상 작동합니다.
properties
# 서블릿 단계에서 파일 용량을 제한하는 설정
spring.servlet.multipart.max-file-size=10MB
spring.servlet.multipart.max-request-size=50MB
코드를 사용할 때는 주의가 필요합니다.
혹시 기존 레거시 스프링 프로젝트를 스프링 부트로 마이그레이션(버전 업그레이드) 하는 
과정에서 CommonsMultipartResolver 코드를 이 StandardServletMultipartResolver로 변경하는 
중이신가요? 아니면 특정 업로드 에러가 발생해 구조를 파악하고 계시는지 알려주시면 상세히 답변해 드리겠습니다.

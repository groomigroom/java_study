SecurityContextHolder는 스프링 시큐리티에서 "현재 로그인한 사용자의 보안 컨텍스트(인증 정보)를 저장하고 관리하는 가장 핵심적인 저장소"입니다. [1] 
## 1. 스프링 부트에서의 의미

* 역할: 애플리케이션 안에서 "지금 이 요청을 보낸 사람이 누구인지" 전역적으로 확인할 수 있게 해줍니다.
* 보관 내용: 내부적으로 SecurityContext를 담고 있으며, 그 안에는 인증된 사용자의 정보, 권한(Role), 인증 상태를 담은 Authentication 객체가 들어있습니다.
* 작동 원리: 기본적으로 ThreadLocal 방식을 사용하여, 하나의 요청을 처리하는 같은 스레드 내에서는 어디서든 로그인한 사용자 정보에 접근할 수 있습니다. [2, 3, 4, 5, 6] 

[코드 예시: 현재 로그인한 사용자명 가져오기]

Authentication auth = SecurityContextHolder.getContext().getAuthentication();
String username = auth.getName(); // 현재 사용자 아이디

## 2. 포함되어 있는 스타터 의존성 (Start Dependency)
앞서 설명해 드린 AccessDeniedException과 마찬가지로 Spring Security 핵심 기능입니다. 프로젝트에 아래 의존성을 추가해야 사용할 수 있습니다. [7] 
Gradle (build.gradle)

implementation 'org.springframework.boot:spring-boot-starter-security'

Maven (pom.xml)

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-security</artifactId>
</dependency>

## 3. 패키지 경로

* org.springframework.security.core.context.SecurityContextHolder [8]

* 현재 로그인한 사용자의 아이디(PK)나 권한 목록을 컨트롤러/서비스에서 꺼내 쓰고 싶으신가요?
* 회원가입 직후 자동으로 로그인 처리를 하거나, 테스트 코드에서 가짜 인증 객체를 주입하려는 상황인가요?
* 비동기 처리(@Async)나 멀티스레드 환경에서 사용자 정보가 무시되는 문제를 겪고 계시나요?

------------------------------

SecurityContextHolder.getContext().getAuthentication().getName()은 스프링 시큐리티에서 "현재 시스템을 사용 중인(로그인한) 사용자의 식별자(보통 아이디 또는 이메일)를 가져오는 가장 표준적인 방법"입니다. [1] 
각 메서드가 체인처럼 연결되어 작동하며, 의미는 다음과 같습니다.
## 1. 단계별 상세 의미

* SecurityContextHolder: 보안 정보의 전체 저장소입니다.
* .getContext(): 현재 스레드에 할당된 보안 컨텍스트(SecurityContext)를 가져옵니다.
* .getAuthentication(): 컨텍이션 내부에서 사용자의 "인증 객체"(Authentication)를 꺼냅니다. 사용자가 누구인지, 인증은 성공했는지에 대한 정보가 들어있습니다.
* .getName(): 인증 객체에서 사용자를 고유하게 식별할 수 있는 이름(아이디)을 문자열(String)로 반환합니다. [2, 3, 4, 5, 6] 

## 2. 구체적인 동작 방식
스프링 시큐리티에서 로그인(인증)이 완료되면 사용자의 정보(UserDetails)를 기반으로 인증 객체가 생성됩니다. 이때 UserDetails 인터페이스의 getUsername()으로 반환되는 값이 결국 .getName()의 결과물이 됩니다.

* 일반적인 로그인 시스템: user123, hong@email.com 같은 로그인 ID
* OAuth2(소셜 로그인) 시스템: 구글이나 카카오에서 제공하는 사용자 고유 일련번호(ID)

* 컨트롤러(Controller)에서 로그인한 사용자의 ID가 필요하다면, 이 긴 코드 대신 @AuthenticationPrincipal 어노테이션을 파라미터에 써서 더 깔끔하게 가져오는 법을 알려드릴까요?
* 게시글 등록이나 수정 시 작성자 검증 로직에 이 코드를 적용하는 구체적인 예시가 필요하신가요?
* 로그인하지 않은 사용자가 접근했을 때 이 코드에서 NullPointerException이 발생하는 예외 처리 방식이 궁금하신가요?

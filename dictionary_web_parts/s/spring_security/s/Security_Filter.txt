Security Filter
Security Filter 가 스프링 시큐리티에서 의미?
스프링 시큐리티(Spring Security)에서 Security Filter(시큐리티 필터)와 이를 
모아둔 Security Filter Chain(시큐리티 필터 체인)은 클라이언트의 요청이 
서블릿(Servlet)에 도달하기 전에 인증(Authentication)과 인가(Authorization)를 
처리하는 핵심 보안 컴포넌트를 의미합니다.

───

1. Security Filter의 기본 개념
서블릿 필터 기반: 스프링 시큐리티의 보안 기능은 자바 서블릿 스펙의 Filter를 기반으로 동작합니다.
전처리와 후처리지점: 클라이언트가 요청을 보내면, 서블릿 컨테이너(톰캣 등)가 
그 요청을 서블릿으로 넘기기 전/후에 필터들이 개입하여 작업을 수행합니다.
인증 및 인가 수행: 사용자가 누구인지 확인하고(인증), 해당 자원에 접근할 수 
있는 권한이 있는지 검사(인가)하며, 필요 시 요청을 차단하거나 에러를 반환합니다.

───

2. Security Filter Chain (시큐리티 필터 체인)
스프링 시큐리티는 단일 필터만 쓰는 것이 아니라, 여러 개의 보안 필터를 
사슬(Chain) 형태로 엮어서 순차적으로 실행합니다.
기본 제공 필터들:UsernamePasswordAuthenticationFilter(폼 로그인 인증), 
DefaultResourcesFilter, SecurityContextPersistenceFilter(보안 컨텍스트 유지), 
LogoutFilter 등 다양한 필터가 순서에 맞게 동작합니다.
커스텀 필터 추가: 개발자가 직접 만든 커스텀 필터(예: JWT 토큰 검증 필터)를 
이 체인에 끼워 넣어서 확장할 수 있습니다.

───

3. 작동 구조와 핵심 역할 (DelegatingFilterProxy)
서블릿과 스프링의 연결: 서블릿 컨테이너는 스프링 컨테이너 안에 있는 
Spring Bean을 직접 인식하지 못합니다. 
이를 해결하기 위해 스프링 시큐리티는 DelegatingFilterProxy라는 
서블릿 필터를 사용해, 요청을 스프링 빈으로 등록된 SecurityFilterChain에 
위임(Delegate)하여 처리합니다. 
참고 자료 및 상세 구조는 Spring Security Filter Chain 개요 및 
스프링 시큐리티 무작정 따라하기에서 더 자세히 확인할 수 있습니다.
스프링 시큐리티 필터 체인의 특정 필터(예: JWT 필터나 
UsernamePasswordAuthenticationFilter)의 동작 방식이나 필터 순서를 커스텀하는 방법에 대해 더 알고 싶으신가요?

Servlet

스프링 시큐리티(Spring Security)에서 서블릿(Servlet) 및 서블릿 기반(Servlet-based)이라는 표현은, 
스프링 시큐리티가 자바 서블릿 컨테이너(Tomcat 등)의 표준 Filter 기반 아키텍처 위에서 
동작한다는 것을 의미합니다.
구체적인 의미와 핵심 내용은 다음과 같습니다:

───

1. 서블릿 필터(Servlet Filter) 기반의 보안 처리
요청 가로채기: 클라이언트가 HTTP 요청을 보내면, 스프링 MVC의 DispatcherServlet에 도달하기 전에 
서블릿 컨테이너 레벨에 등록된 Filter들을 거치게 됩니다.
DelegatingFilterProxy: 스프링 시큐리티는 서블릿 컨테이너의 표준 필터 기술을 이용하면서도, 
스프링 빈(Bean)들을 이용할 수 있도록 DelegatingFilterProxy라는 특수한 서블릿 필터를 앞단에 둡니다. 
이 프록시가 실제 보안을 담당하는 FilterChainProxy로 요청을 위임합니다.
인증 및 인가 수행: 이 필터 체인 안에서 사용자가 누구인지 확인하고(인증, Authentication), 
해당 자원에 접근할 권한이 있는지 검사(인가, Authorization)합니다.
2. 왜 'Servlet' 기반임을 강조할까? (Reactive와의 구분)
스프링 시큐리티는 크게 두 가지 애플리케이션 모델을 지원합니다.
Servlet 기반 (Spring MVC 등): 전통적인 블로킹(Blocking) 방식의 자바 서블릿 아키텍처를 
사용하는 애플리케이션 (예: Tomcat + Spring MVC).
Reactive 기반 (Spring WebFlux 등): 비동기 논블로킹(Non-blocking) 리액티브 스택을 
사용하는 애플리케이션 (이 경우 서블릿 필터 대신 WebFilter를 사용함).
따라서 문서나 설정에서 Servlet 이라는 말이 붙었다면, "이 내용은 톰캣 같은 서블릿 컨테이너 
환경의 javax.servlet.Filter (또는 jakarta.servlet.Filter) 흐름 위에서 동작하는 보안 
구조를 설명하고 있다"는 뜻입니다.
3. 주요 서블릿 구성요소들
서블릿 기반 스프링 시큐리티를 이해할 때 자주 등장하는 핵심 개념들입니다:
SecurityContextHolder: 현재 인증된 사용자의 상세 정보(SecurityContext)를 담고 있는 저장소입니다.
Authentication: 사용자가 제출한 자격 증명(ID/PW 등)이나 인증 완료 후 생성된 인증 객체입니다.
AuthenticationManager: 실제로 인증 처리를 총괄하는 매니저입니다.

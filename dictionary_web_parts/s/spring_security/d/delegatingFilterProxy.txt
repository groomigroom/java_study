delegatingFilterProxy 
가 스프링 시큐리티에서 의미?

스프링 시큐리티에서 DelegatingFilterProxy는 
서블릿 컨테이너(Servlet Container)와 스프링 IoC 컨테이너(Spring ApplicationContext)를 
연결해 주는 다리(가교) 역할을 하는 표준 서블릿 필터입니다.

1. 핵심 의미와 역할

• 서블릿 컨테이너와 스프링 빈의 연결
서블릿 필터(javax.servlet.Filter / jakarta.servlet.Filter)는 
원래 서블릿 컨테이너(Tomcat 등)에서 관리되기 때문에, 
스프링 IoC 컨테이너가 관리하는 스프링 빈(Bean)을 직접 주입받거나 사용할 수 없습니다. 
이 문제를 해결하기 위해 등장한 대리자(Proxy) 필터가 바로 DelegatingFilterProxy입니다.
• 실제 보안 처리를 하지 않는 위임자
DelegatingFilterProxy 자체는 어떤 보안 로직이나 인증/인가 처리를 직접 수행하지 않습니다. 
대신 클라이언트의 요청을 가로채서, 스프링 컨테이너에 등록된 
실제 보안 필터 빈인 FilterChainProxy(보통 springSecurityFilterChain 
이라는 이름의 빈)에 요청을 위임합니다.

2. 작동 흐름 요약

1. 요청 발생: 클라이언트가 서버로 HTTP 요청을 보냅니다.
2. 서블릿 필터 진입: 서블릿 컨테이너에 등록된 DelegatingFilterProxy가 요청을 
가장 먼저 가로챕니다.
3. 빈 검색 및 위임: DelegatingFilterProxy는 스프링 애플리케이션 컨텍스트에서 
springSecurityFilterChain이라는 이름으로 등록된 FilterChainProxy 빈을 찾아 실행합니다.
4. 시큐리티 필터 체인 실행: FilterChainProxy 내부에서 설정된 여러 
SecurityFilterChain(인증, 인가, CSRF 등)을 거쳐 보안 처리를 수행합니다.

3. 왜 이렇게 구조가 되어 있을까?

• 서블릿 컨테이너는 스프링이 뜨기 전에(또는 독립적으로) 초기화되므로 서블릿 
필터 규격만 알지 스프링 빈의 존재를 모릅니다.
• DelegatingFilterProxy를 서블릿 컨테이너에 표준 필터로 등록해 두고, 
실제 무거운 시큐리티 로직은 스프링 빈으로 관리되는 FilterChainProxy 및 
하위 필터들에 위임함으로써 스프링의 DI/AOP 등 강력한 기능을 보안 필터에서도 
온전히 활용할 수 있게 됩니다.
관련 설정 및 자동 등록 과정은 Spring Security - DelegatingFilterProxy 
또는 DelegatingFilterProxy - Spring Security 블로그 글 등에서 더 자세히 
확인할 수 있습니다.
스프링 시큐리티의 전체 필터 구조(FilterChainProxy와 내부 SecurityFilterChain들의 
동작 방식)나 특정 보안 필터의 역할에 대해 더 알고 싶으시면 편하게 말씀해 주세요.

DelegatingFilterProxy는 서블릿 컨테이너(Servlet Container)와 스프링 IoC 컨테이너(ApplicationContext)를 연결해주는 서블릿 필터입니다.
[1] (https://keeeeeepgoing.tistory.com/321), [2] (https://velog.io/@yaho1024/spring-security-delegatingFilterProxy)
서블릿 컨테이너는 스프링의 라이프사이클을 알지 못하기 때문에 스프링 빈으로 등록된 필터를 직접 사용할 수 없습니다. 이 문제를 해결하기 위해 
서블릿 컨테이너에는 DelegatingFilterProxy를 등록하고, 실제 요청이 들어오면 스프링 컨테이너에 존재하는 
springSecurityFilterChain이라는 이름의 빈을 찾아 요청을 위임(Delegate)합니다. 

1. DelegatingFilterProxy 동작 방식

1. 서블릿 컨테이너가 클라이언트의 요청을 받습니다.
2. DelegatingFilterProxy가 요청을 가로채서 스프링 IoC 컨테이너를 조회합니다.
3. IoC 컨테이너 내부의 springSecurityFilterChain 빈(즉, FilterChainProxy)에게 요청 처리를 넘깁니다.
4. FilterChainProxy는 내부에 등록된 여러 개의 SecurityFilterChain을 순회하며 인증/인가를 처리합니다. 

2. Spring Boot에서의 사용 (자동 설정)

오늘날 Spring Boot 환경에서는 spring-boot-starter-security 의존성을 추가하면, SecurityFilterAutoConfiguration이 자동으로 
DelegatingFilterProxyRegistrationBean을 등록해주어 개발자가 직접 DelegatingFilterProxy를 web.xml이나 Java Config로 등록할 필요가 없습니다. 
대신 개발자는 스프링 시큐리티의 보안 필터 체인을 커스텀하기 위해 SecurityFilterChain 빈을 정의합니다.

SecurityFilterChain 설정 예제 (Java / Spring Boot)

java
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.config.annotation.web.configuration.EnableWebSecurity;
import org.springframework.security.web.SecurityFilterChain;

@Configuration
@EnableWebSecurity // 스프링 시큐리티 활성화
public class SecurityConfig {

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        http
            // 람다 기반 설정 (스프링 시큐리티 권장 방식)
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/public/**", "/login").permitAll() // 인증 없이 허용
                .anyRequest().authenticated() // 그 외 요청은 인증 필요
            )
            .formLogin(form -> form
                .loginPage("/login")
                .defaultSuccessUrl("/home")
                .permitAll()
            )
            .logout(logout -> logout
                .logoutUrl("/logout")
                .logoutSuccessUrl("/login?logout")
                .permitAll()
            );

        return http.build();
    }
}
코드를 사용할 때는 주의가 필요합니다.

3. 과거(XML 또는 AbstractSecurityWebApplicationInitializer) 방식의 수동 등록

만약 Spring Boot가 아닌 전통적인 Spring MVC 환경에서 수동으로 DelegatingFilterProxy를 등록해야 했다면 web.xml에 아래와 같이 작성했습니다.
xml
<filter>
    <filter-name>springSecurityFilterChain</filter-name>
    <filter-class>org.springframework.web.filter.DelegatingFilterProxy</filter-class>
</filter>
<filter-mapping>
    <filter-name>springSecurityFilterChain</filter-name>
    <url-pattern>/*</url-pattern>
</filter-mapping>
코드를 사용할 때는 주의가 필요합니다.
• 이 설정 덕분에 서블릿 컨테이너로 들어오는 모든 요청(/*)이 springSecurityFilterChain이라는 이름으로 스프링 컨테이너에 
등록된 빈(FilterChainProxy)으로 전달됩니다. 
자세한 내부 동작 원리는 Spring Security - 1. DelegatingFilterProxy 알아보기에서 확인하실 수 있습니다. 
현재 진행 중인 프로젝트의 Spring Boot 버전이나 구현하려는 인증 방식(예: Form 로그인, JWT, OAuth2 등)을 알려주시면 그에 맞춘 더 구체적인 예제를 작성해 드릴 수 있습니다.

자바 스프링에서 스프링 빈(Spring Bean)은 스프링 컨테이너(IoC 컨테이너)가 생성, 조립, 관리하는 자바 객체를 의미합니다. [1, 2, 3] 
개발자가 new 연산자로 직접 생성한 객체는 일반 자바 객체일 뿐이며, 스프링이 제어권을 가지고 스스로 만들어 컨테이너 안에 담아둔 객체만을 '빈'이라고 부릅니다. 자바의 상징인 커피 원두(Java Bean)에서 유래하여, 스프링의 핵심 구성 요소를 나타내는 귀여운 명칭이 되었습니다. [1, 2, 4, 5] 
------------------------------
## 💡 왜 스프링 빈을 사용할까요?
스프링 빈을 사용하는 이유는 객체의 생성과 관리 책임을 프레임워크에 넘겨(제어의 역전, IoC), 결합도를 낮추고 유지보수를 쉽게 만들기 위해서입니다. [1, 3, 6, 7, 8] 

* 
* 의존성 주입 (DI): 빈으로 등록된 객체끼리는 스프링이 필요한 곳에 알아서 꽂아줍니다 (예: Controller에 Service 주입).
* 싱글톤 관리: 기본적으로 스프링 빈은 애플리케이션 내에서 단 하나의 인스턴스만 생성(싱글톤)되어 공유되므로 메모리가 절약됩니다.
* 생명주기 관리: 객체의 생성부터 소멸까지의 과정을 스프링이 안전하게 관리해 줍니다. [3, 7, 8, 9, 10, 11] 
* 

------------------------------
## 🛠️ 스프링 빈을 등록하는 2가지 방법## 1. 컴포넌트 스캔 (자동 등록) [12] 
가장 흔히 쓰는 방법입니다. 클래스 위에 어노테이션을 붙이면, 스프링이 구동될 때 자동으로 찾아서 빈으로 등록합니다. [12, 13, 14] 

* 
* @Component: 기본 컴포넌트 지정을 위한 어노테이션
* @Controller / @RestController: 웹 MVC 컨트롤러 역할
* @Service: 비즈니스 로직 처리 역할
* @Repository: 데이터베이스 접근 역할 (DAO) [9, 12, 13, 15, 16] 
* 

## 2. 자바 설정 클래스 활용 (수동 등록)
외부 라이브러리 객체를 빈으로 등록하거나, 제어 구조를 명확히 시각화하고 싶을 때 사용합니다. [9] 

@Configurationpublic class AppConfig {
    @Bean
    public MyService myService() {
        return new MyServiceImpl();
    }
}

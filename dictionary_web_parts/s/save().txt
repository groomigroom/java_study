네, 자바 스프링 부트에서 .save()는 따로 존재하며, 주로 데이터베이스에 데이터를 저장하거나 수정(업데이트)할 때 사용하는 가장 대표적인 메서드입니다.
이 메서드는 스프링 부트가 자체적으로 가지고 있는 것은 아니고, 데이터베이스 연동을 편리하게 도와주는 Spring Data JPA(또는 Spring Data MongoDB 등) 라이브러리에서 제공합니다.
------------------------------
## 💡 .save()는 어디에 들어있나요?
스프링 부트 개발 시 데이터베이스 처리를 위해 인터페이스를 만드는데, 이때 JpaRepository를 상속받으면 .save() 메서드를 따로 구현하지 않아도 자동으로 사용할 수 있게 됩니다.

import org.springframework.data.jpa.repository.JpaRepository;
// JpaRepository를 상속받는 순간 .save()를 바로 쓸 수 있습니다.public interface MemberRepository extends JpaRepository<Member, Long> {
}

------------------------------
## 🔄 .save()의 2가지 핵심 역할 (저장과 수정)
.save() 메서드는 똑똑하게 동작합니다. 인자로 넘겨진 객체의 PK(기본키, 예: ID 값) 존재 여부에 따라 알아서 저장할지 수정할지 결정합니다.
## 1. 데이터 새로 저장하기 (Insert)
객체에 ID(PK) 값이 없거나 데이터베이스에 존재하지 않는 ID라면, 새로운 데이터로 인식하고 DB에 INSERT 쿼리를 날립니다.

Member member = Member.builder()
                      .name("홍길동")
                      .build(); // ID가 없는 상태
// 새로운 회원 등록 (INSERT 실행)
memberRepository.save(member); 

## 2. 기존 데이터 수정하기 (Update)
객체에 이미 존재하는 ID(PK) 값이 들어있다면, DB에 있는 기존 데이터를 변경하겠다는 의미로 인식하고 UPDATE 쿼리를 날립니다.

Member member = memberRepository.findById(1L).orElseThrow();
member.changeName("이순신"); // 이름 변경
// 기존 회원 수정 (UPDATE 실행)
memberRepository.save(member); 

(참고: JPA에서는 .save()를 쓰지 않고 객체의 값만 바꾸어도 트랜잭션이 끝날 때 자동으로 수정되는 '더티 체킹' 기능도 지원하지만, 명시적으로 .save()를 호출해 수정하기도 합니다.)
------------------------------
## 📦 필요한 의존성 (Dependency)
이 기능을 쓰려면 build.gradle에 데이터베이스 연동을 위한 Spring Data JPA 라이브러리가 추가되어 있어야 합니다.

dependencies {
    // JPA 및 데이터베이스 연동을 위한 스타터
    implementation 'org.springframework.boot:spring-boot-starter-data-jpa'
}

현재 작성 중인 코드에서 특정 데이터를 DB에 저장하는 단계를 구현 중이신가요? 혹시 컨트롤러나 서비스 레이어 중 어느 위치에서 .save()를 호출하려는지 말씀해 주시면, 전체적인 데이터 저장 흐름(DTO ➡️ Entity ➡️ Repository.save) 코드를 예시로 짜드리겠습니다.

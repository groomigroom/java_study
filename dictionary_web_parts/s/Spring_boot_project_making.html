         ## 빌드 도구 트렌드 요약
         
         * 
         * Gradle - Groovy (build.gradle): 여전히 실무와 기존 강의(인프런, 유튜브 등)에서 
         가장 흔하게 쓰이는 레거시이자 표준입니다. 무난하고 가벼운 설정을 원할 때 선택합니다. 
         * Gradle - Kotlin (build.gradle.kts): 최근 새로 시작하는 프로젝트나 
         대규모 프로젝트에서 강력히 권장되는 트렌드입니다. 
         스프링 공식 문서의 가이드 코드도 현재는 Groovy와 Kotlin DSL을 동시에 제공하고 있습니다. 
         * 
         
         ------------------------------
         ## Groovy vs Kotlin DSL 직관적인 비교
         
         | 비교 항목 | Gradle - Groovy | Gradle - Kotlin |
         |---|---|---|
         | 확장자 | build.gradle | build.gradle.kts |
         | 타입 체크 | 동적 타입 (에러를 실행해 봐야 암) | 정적 타입 (컴파일 시점에 에러 잡음) |
         | IDE 지원 | 자동완성이 부실하거나 오타를 잘 못 잡음 | 오타 자동완성, 코드 탐색이 완벽함 |
         | 자료의 양 | 수년간 쌓인 레퍼런스가 압도적으로 많음 | 최신 자료 위주이나 공식 문서 지원 완벽 |
         | 구문 제약 | 따옴표(', ") 혼용 가능, 괄호 생략 등 자유로움 | 엄격한 문법 제약 (규칙적인 코드 유지 가능) |

         ------------------------------
         ## 1. Packaging: Jar vs War
         
         * 
         * 정답: Jar를 선택하세요.
         * 이유: 요즘 배포 환경의 표준인 Docker 컨테이너 및 클라우드(AWS 등) 
         환경에서는 내장 톰캣이 포함된 Jar가 압축 및 배포에 압도적으로 유리합니다. 
         외장 WAS(톰캣 등)를 서버에 따로 설치하고 밀어 넣는 War 방식은 이제 구형 레거시 시스템 외에는 거의 쓰이지 않습니다.
         * 
         
         ## 2. Configuration: Properties vs YAML
         
         * 
         * 정답: YAML을 강력히 추천합니다.
         * 이유: YAML은 계층 구조(Tree)로 가독성이 좋고, 중복 코드가 줄어들어 설정이 복잡해질수록 관리가 훨씬 편합니다.
         * 비교:
         * Properties: spring.datasource.url=..., spring.datasource.username=... 처럼 매번 앞부분을 중복해서 적어야 합니다.
            * YAML: spring: 아래에 들여쓰기로 깔끔하게 묶을 수 있어 대다수의 최신 실무 프로젝트와 오픈소스에서 표준처럼 사용됩니다.
         * 
         
         ## 3. Java: 26 / 25 / 21 / 17 버전 선택
         
         * 
         * 정답: 일반적으론 21 (안정적), 트렌디하게 가려면 25를 선택하세요. [1, 2] 
         * 버전별 상황:
         * Java 21: 현재 현업에서 가장 선호하는 대세 LTS(장기 지원) 버전입니다. 가상 스레드(Virtual Thread)를 정식 지원하여 스프링 부트 3.x 환경과 궁합이 가장 좋습니다.
            * Java 25: 최근 출시된 최신 LTS 버전입니다. 스프링 부트 4.x 버전을 사용하거나 최신 기능을 적극 도입하려는 신규 프로젝트에서 빠르게 늘고 있습니다.
            * Java 17: 스프링 부트 3.x의 최소 요구 조건이지만, 이제는 21 버전으로 많이 넘어간 추세입니다.
            * Java 26: 아직 정식 LTS 버전이 아니므로 학습 목적이 아니라면 실무 프로젝트 설정으로는 추천하지 않습니다. [1, 2, 7]

        네, 원래 application.yml 파일에는 의존성(Dependencies) 내용이 들어가지 않습니다.
많은 입문자분들이 헷갈려하시는 부분인데요, 스프링 부트 프로젝트에서 의존성을 관리하는 파일과 애플리케이션 설정을 관리하는 파일의 역할은 완전히 분리되어 있습니다.
역할에 따른 파일 위치는 다음과 같습니다.
## 1. 📦 의존성(Libraries)을 관리하는 파일 (따로 있음)
이미지에서 Project 종류를 Gradle - Groovy로 선택하셨기 때문에, 추가하신 OAuth2 Client, MySQL Driver, Lombok 등의 모든 의존성은 프로젝트 루트(최상위) 폴더에 있는 build.gradle 파일에 기록됩니다.

* 파일 위치: 프로젝트 폴더/build.gradle
* 확인 방법: 파일을 열어보시면 dependencies { ... } 블록 안에 선택하신 라이브러리들이 들어가 있는 것을 보실 수 있습니다.

## 2. ⚙️ 애플리케이션 환경을 설정하는 파일 (application.yml)
application.yml 파일은 라이브러리를 가져오는 곳이 아니라, 가져온 라이브러리들을 어떻게 사용할지 옵션을 지정하는 곳입니다.

* 역할: 데이터베이스 접속 주소(ID/PW), 포트 번호(8080 등), 소셜 로그인 Client ID 값 설정 등
* 파일 위치: src/main/resources/application.yml

* 프로그램 세부 세팅(DB 연결 등) ➡️ application.yml

현재 선택하신 MySQL 데이터베이스 연결 설정이나 OAuth2 소셜 로그인 연동 설정을 application.yml에 어떻게 작성해야 하는지 예시 코드가 필요하신가요? 구체적으로 어떤 소셜 로그인(구글/카카오 등)을 먼저 연동하실지 말씀해 주시면 맞춤형 코드를 알려드릴 수 있습니다!

버전 세팅 #####

        
        보내주신 화면을 보니 스프링 이니셜라이저(Spring Initializr) 사이트가 맞네요!
현재 사이트 화면에 3.x 버전이 보이지 않는 이유는 시간이 지나면서 스프링 부트가 새로운 메이저 버전(4.x)으로 기본 선택지를 업데이트했기 때문입니다. 이렇게 공식 사이트에서 원하는 구버전(3.x)이 선택지에 없을 때, 공식 예제를 안전하게 학습하는 방법은 2가지가 있습니다.
------------------------------
## 방법 1: build.gradle에서 버전 수동으로 고치기 (가장 간단함)
스프링 이니셜라이저 사이트에서는 일단 화면에 보이는 아무 버전(예: 4.1.1)이나 선택해서 프로젝트를 다운로드합니다. 그 후 인텔리제이에서 코드를 실행하기 전에 딱 한 줄만 바꿔주면 됩니다.

   1. 다운로드한 프로젝트의 build.gradle 파일을 엽니다.
   2. 맨 위 plugins 블록에서 버전을 원하는 구버전으로 직접 타이핑해서 수정합니다.
   
   plugins {
       id 'java'
       id 'org.springframework.boot' version '3.4.3' // ◀ 다운로드 후 이 부분을 수동으로 수정!
       id 'io.spring.dependency-management' version '1.1.7'
   }
   
   3. 수정 후 우측 상단의 Gradle 새로고침(Sync) 버튼을 누르면, 인텔리제이가 인터넷에서 자동으로 3.4.3 버전을 다운로드하여 프로젝트를 세팅해 줍니다.

------------------------------
## 방법 2: 스프링 이니셜라이저 URL 주소창 조작하기 (꿀팁)
웹 브라우저 주소창의 파라미터를 이용하면 화면에 숨겨진 구버전을 강제로 선택하여 다운로드할 수 있습니다.

   1. 평소처럼 스프링 이니셜라이저(start.spring.io)에 접속합니다.
   2. 주소창 맨 뒤에 ?bootVersion=3.4.3을 붙이고 엔터를 누릅니다.
   
   예시: https://spring.io
   
   3. 이렇게 접속하면 화면에 3.4.3 버전이 강제로 선택된 상태로 나타나며, 그 상태로 프로젝트를 생성(GENERATE)하여 다운로드하시면 됩니다.

## 요약하자면!
공식 사이트 화면에 없다고 해서 그 버전을 못 쓰는 것이 절대 아닙니다. build.gradle 파일은 단순한 텍스트 파일일 뿐이므로, 우리가 원하는 버전 숫자만 정확히 적어주고 Gradle 새로고침을 해주면 인텔리제이가 알아서 완벽하게 버전을 맞춰줍니다.
이제 방법 1이나 방법 2 중 편한 방식으로 프로젝트를 다시 세팅해 보세요. 혹시 버전을 낮춘 후 빌드할 때 자바 버전 관련 오류가 다시 난다면 languageVersion = JavaLanguageVersion.of(17) 정보도 세팅에 맞춰 함께 확인해 주시면 됩니다.

아니요, 처음에 공부할 때는 지금 화면에 보이는 4.x 버전보다는 3.4.x나 3.3.x 같은 안정적인 3.x 버전으로 시작하는 것을 강력히 추천합니다.
그 이유는 기술적인 완성도 문제라기보다는, 학습할 때 겪게 되는 정보의 양과 삽질(시행착오)의 시간 때문입니다. 구체적인 이유는 다음과 같습니다.
## 1. 구글링과 AI 답변의 한계 (가장 중요)
공부하다가 막히면 구글에 검색하거나 ChatGPT 같은 AI에게 물어보게 될 텐데, 인터넷과 AI 학습 데이터에 쌓인 스프링 부트 자료의 95% 이상은 3.x 버전 기준입니다. 4.1.0처럼 너무 최첨단 버전을 쓰면 문법이나 설정이 바뀌었을 때 검색해도 해결책이 안 나와서 혼자 몇 시간씩 헤매게 됩니다.
## 2. 가이드 및 인터넷 예제와의 호환성
조금 전 파일 업로드 가이드 예제를 따라 하실 때도 경험하셨듯이, 공식 문서나 블로그 글의 코드를 그대로 복사해서 가져왔을 때 4.1.0 버전에서는 패키지 이름이나 어노테이션이 달라서 빨간 줄이 터지는 일이 자주 발생합니다. 초보자 단계에서는 이것이 내 코드 오류인지, 버전 문제인지 구분하기 어렵습니다.
## 3. 자바 버전과의 관계
스프링 부트 4.x 버전은 매우 높은 최신 자바 버전(기본 17 또는 21 이상)을 강제합니다. 컴퓨터 환경 세팅이나 인텔리제이 업데이트가 안 되어 있으면 프로그래밍 공부를 시작하기도 전에 '환경 설정 오류'로 진이 빠지기 쉽습니다.
------------------------------
## 결론: 학습 방향 제안
실무 기업 프로젝트나 대다수의 강의(인프런 등)에서도 현재 가장 많이 쓰고 검증된 버전은 스프링 부트 3.x입니다.
따라서 처음 공부하실 때는 방법 1(build.gradle에서 버전을 3.4.x나 3.3.x로 수동 변경)을 사용하여 주변 환경 설정을 안정화해 두고, 온전히 스프링 부트의 사용법과 자바 코드 로직을 익히는 데 집중하는 것이 훨씬 효율적입니다. 4.x 버전은 3.x 버전에 익숙해진 뒤에 변경된 점만 가볍게 살펴보셔도 늦지 않습니다.
안정적인 3.x 버전으로 낮추어서 파일 업로드 예제를 이어서 진행해 보시겠어요? 변경 도중 막히는 부분이 있다면 말씀해 주세요!



        아니요, 스프링 부트 3.x 버전을 쓰실 때는 자바 버전을 25로 지정하시면 빌드 오류가 발생할 확률이 매우 높습니다. 3.x 버전에서는 자바 17 또는 21을 사용하시는 것이 가장 안전합니다.
그렇게 권장해 드리는 명확한 이유는 다음과 같습니다.
## 1. 호환성 검증 문제 (버전 역전)
현재 개발자분들이 널리 사용하는 스프링 부트 3.x는 자바 25가 출시되기 훨씬 전에 설계되고 검증된 버전입니다.
스프링 부트 3.x 내부 라이브러리들은 자바 17과 21 환경에서 완벽하게 돌아가도록 테스트를 마친 상태입니다. 반면, 너무 최신 버전인 자바 25를 집어넣으면 내부 컴파일러나 바이트코드 엔진(ASM 등)이 자바 25의 새로운 구조를 해석하지 못해 프로젝트를 시작하자마자 원인 모를 빌드 에러를 뿜어낼 수 있습니다.
## 2. Gradle 빌드 도구의 한계
프로젝트를 빌드해 주는 Gradle 역시 자바 버전에 맞춰 업데이트되어야 합니다. 자바 25를 완벽히 지원하는 Gradle 버전과 스프링 부트 3.x 버전 간의 삼박자가 모두 맞아떨어져야 에러가 안 나는데, 이 버전을 수동으로 맞추는 과정 자체가 초보자 단계에서는 엄청난 스트레스와 환경 설정 늪에 빠지게 만듭니다.

## 가장 추천하는 조합
처음 공부하실 때는 전 세계 개발자들과 공식 문서가 표준으로 삼고 있는 아래 조합 중 하나를 선택하는 것이 정신 건강과 효율적인 학습에 가장 좋습니다.

* 추천 조합 A (가장 무난함): 스프링 부트 3.4.x + 자바(JDK) 17
* 추천 조합 B (최신 실무 트렌드): 스프링 부트 3.4.x + 자바(JDK) 21

## 조치 방법
아까 다운로드 받으신 프로젝트의 build.gradle 파일에서 toolchain 부분을 다음과 같이 17 또는 21로 수정해 주세요.

java {
	toolchain {
		languageVersion = JavaLanguageVersion.of(17) // ◀ 17 또는 21로 변경해 주세요!
	}
}

변경하신 후에 인텔리제이가 해당 JDK를 찾지 못한다고 에러를 내면, 이전에 안내해 드린 것처럼 File -> Project Structure -> SDK 메뉴에서 해당 버전(17 또는 21)을 인텔리제이 내부에서 자동으로 다운로드 받아서 연결해 주시면 됩니다.
버전을 바꾸고 Gradle 새로고침을 했을 때 에러 없이 깔끔하게 싱크가 완료되는지 확인해 보시겠어요?

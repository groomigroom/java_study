전자정부프레임워크(기반이 되는 스프링(Spring) 프레임워크)에서 @Lazy 어노테이션은
빈(Bean)의 초기화 시점을 '지연(Lazy Initialization)'시키는 기능을 의미합니다. 
[1] (https://kylo8.tistory.com/entry/Spring-Boot-Lazy%EB%A5%BC-%EC%82%AC%EC%9A%A9%ED%95%9C-Bean-%EC%A7%80%EC%97%B0-%EC%B4%88%EA%B8%B0%ED%99%94%ED%95%98%EA%B8%B0), 
[2] (https://codekong.tistory.com/23)

주요 의미와 동작 방식

• 기본 동작 (즉시 초기화, Eager Initialization): 스프링 컨테이너가 실행(부팅)될 때 애플리케이션에서 사용하는 모든 빈을 미리 생성하고 메모리에 올립니다. 
[1] (https://codekong.tistory.com/23)
• @Lazy 적용 시: 서버가 켜질 때 곧바로 빈을 만들지 않고, 해당 빈이 실제로 처음 사용되는 시점(또는 의존성 주입이 요청되는 시점)에 객체가 생성됩니다. 
[1] (https://effortguy.tistory.com/266), [2] (https://codekong.tistory.com/23)

장점과 단점

• 장점:
	• 애플리케이션 부팅 속도가 빨라집니다.
	• 초기 구동 시 불필요한 리소스(DB 연결, 외부 API 클라이언트 등)를 아낄 수 있습니다. [1] (https://effortguy.tistory.com/266), 
[2] (https://codekong.tistory.com/23)
• 단점:
	• 첫 번째 요청(First HTTP request)이나 빈을 실제로 호출할 때 지연 시간이 발생합니다.
	• 서버가 뜰 때 미리 발견되어야 할 설정 오류나 클래스 누락 등의 에러가 뒤늦게(실행 중 호출 시점에) 터질 수 있습니다. [1] (https://effortguy.tistory.com/266)

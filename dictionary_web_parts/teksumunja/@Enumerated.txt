자바 스프링(JPA/Hibernate)에서 @Enumerated는 자바의 Enum(열거형) 타입을 데이터베이스 테이블의 컬럼과 매핑할 때 사용하는 어노테이션입니다. [1] 
자바의 Enum은 객체인 반면, DB는 Enum 구조를 그대로 저장할 수 없기 때문에 문자열이나 숫자 형태로 변환하여 저장하는 역할을 합니다. [2, 3] 
------------------------------
## ⚠️ 필수 선택: 두 가지 저장 방식 (EnumType)
@Enumerated를 사용할 때는 반드시 value 속성으로 저장 방식을 지정해야 합니다. 기본값은 숫자로 저장되는 방식이지만, 실무에서는 절대 권장하지 않습니다. [4] 

| 설정 값 | 저장 방식 | 장점 | 단점 / 위험성 |
|---|---|---|---|
| EnumType.STRING (실무 필수) | Enum의 이름(문자열) 그대로 DB에 저장 (예: "ADMIN", "USER") | Enum 순서가 바뀌거나 추가되어도 안전함 | 문자열이라 숫자보다 DB 용량을 조금 더 차지함 |
| EnumType.ORDINAL (사용 금지) | Enum에 정의된 순서(0부터 시작하는 숫자)로 저장 (예: 0, 1) | DB 용량을 적게 차지하고 속도가 빠름 | 중간에 Enum이 추가되면 기존 데이터의 숫자가 꼬여서 장애 발생 |

------------------------------
## 💻 코드 예시
1. Enum 클래스 정의

public enum RoleType {
    USER,  // ORDINAL로 저장 시 0, STRING으로 저장 시 "USER"
    ADMIN  // ORDINAL로 저장 시 1, STRING으로 저장 시 "ADMIN"
}

2. 엔티티 클래스에서 사용 [5] 

@Entitypublic class Member {

    @Id @GeneratedValue
    private Long id;

    private String username;

    // 🔥 실무에서는 반드시 EnumType.STRING을 사용해야 안전합니다.
    @Enumerated(EnumType.STRING)
    private RoleType roleType; 
}

------------------------------
혹시 현재 생성 중인 Enum에 비즈니스 코드(예: "A01", "B01")나 별도의 설명(예: "관리자", "일반회원")을 매핑하여 DB에 저장하고 싶으신가요?
필요하시다면 더 복잡한 Enum을 DB와 깔끔하게 매핑해 주는 AttributeConverter 활용법도 소개해 드릴 수 있습니다.

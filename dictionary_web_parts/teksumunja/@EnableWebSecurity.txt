스프링 부트에서 @EnableWebSecurity는 웹 보안 기능(Spring Security)을 활성화하고, 개발자가 커스텀한 보안 설정(인증, 인가 등)을 애플리케이션에 적용하도록 알리는 애노테이션입니다.
필요한 스타터 의존성과 핵심 의미를 정리해 드립니다.
------------------------------
## 📦 필요한 스타터 의존성 (Starter Dependency)
스프링 부트에서 이 기능을 사용하려면 다음 의존성을 빌드 파일(build.gradle 또는 pom.xml)에 추가해야 합니다. [1, 2] 

* spring-boot-starter-security

이 스타터 의존성을 추가하면 스프링 시큐리티 코어, 웹 보안 모듈, 기본 서블릿 필터 들이 자동으로 프로젝트에 포함됩니다.
------------------------------
## 💡 @EnableWebSecurity의 3가지 핵심 의미
스프링 부트 2.7 및 3.x 버전부터는 내부적인 자동 설정이 강화되어 이 애노테이션을 생략해도 동작하는 경우가 많지만, 코드의 명시성과 커스텀 설정을 위해 여전히 자주 사용됩니다. 주요 역할은 다음과 같습니다.
## 1. 스프링 시큐리티 필터 체인(Filter Chain) 활성화 [3] 

* 스프링 시큐리티는 HTTP 요청이 서블릿에 도달하기 전, 수많은 보안 필터(Filter)를 거치게 만듭니다.
* @EnableWebSecurity는 웹 취약점 방어(CSRF, CORS, XSS 등), 세션 관리, 로그인/로그아웃 처리를 담당하는 핵심 필터들을 메모리(스프링 빈 Context)에 등록하고 작동시킵니다. [4] 

## 2. 웹 보안 구성 클래스 선언

* 보안 설정을 직접 제어하는 설정 클래스(Configuration Class) 위에 선언합니다.
* 이 애노테이션이 붙은 클래스 안에서 SecurityFilterChain을 빈(Bean)으로 정의하여 "어떤 URL은 로그인 없이 허용하고, 어떤 URL은 인증된 사용자만 접근할 수 있는지" 세부 규칙을 짜게 됩니다.

## 3. 스프링 부트의 기본 웹 보안 초기화

* 의존성만 추가하면 스프링 부트가 제공하는 무작위 비밀번호 기반의 기본 로그인 창이 뜹니다.
* @EnableWebSecurity와 함께 커스텀 설정을 작성하면, 부트가 자동으로 만들어주던 기본 보안 설정을 끄고 개발자가 의도한 보안 아키텍처로 대체합니다. [5] 

------------------------------
현재 개발 중이신 보안 기능에 맞추어 추가적인 구현 방법을 안내해 드릴 수 있습니다. 다음 중 구현하고자 하는 방향을 알려주시겠어요?

* 기본 폼 로그인 방식 외에 JWT(Json Web Token)나 OAuth2 소셜 로그인을 연동할 계획이신가요?
* 스프링 부트 3.x 버전 기준의 최신 SecurityFilterChain 작성 코드 예시가 필요하신가요?

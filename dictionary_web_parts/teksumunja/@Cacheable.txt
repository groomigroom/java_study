전자정부프레임워크(기반이 되는 스프링 프레임워크)에서 @Cacheable 어노테이션은 
메서드의 실행 결과를 캐시(Cache)에 저장하고, 이후 동일한 요청이 들어오면 메서드를 직접 실행하지 않고 
저장해 둔 캐시 데이터를 곧바로 반환하는 기능을 의미합니다. [1] (https://adjh54.tistory.com/165), 
[2] (https://hyeri0903.tistory.com/237), [3] (https://www.coddykit.com/ko/courses/spring_boot/the-spring-cache-abstraction-fundamentals-9298344)

주요 동작 방식

1. 첫 번째 호출:
	• 캐시에 해당 키(Key)의 데이터가 없으므로, 원래의 메서드 로직을 실제로 실행합니다.
	• 메서드가 반환한 결과를 캐시 저장소(전자정부프레임워크에서 기본 권장하는 EhCache 등)에 저장하고 클라이언트에 전달합니다. 
[1] (https://www.egovframe.go.kr/wiki/doku.php?id=egovframework:rte:fdl:cache), [2] (https://adjh54.tistory.com/165)
2. 두 번째 이후 호출:
	• 메서드를 실행하지 않고, 캐시 저장소에서 기존에 저장된 결과를 곧바로 찾아 반환합니다.
	• DB 조회나 복잡한 연산 시간을 줄여 성능을 크게 높입니다. 
[1] (https://velog.io/@taebong98/Spring-Cache-%EC%9D%B4%ED%95%B4%ED%95%98%EA%B8%B0), 
[2] (https://www.coddykit.com/ko/courses/spring_boot/the-spring-cache-abstraction-fundamentals-9298344), [3] (https://adjh54.tistory.com/165)

사용하는 이유

• 성능 향상: 자주 변경되지 않지만 조회 빈도가 높고 연산 비용이 큰 데이터(예: 공통 코드, 상품 목록 등)를 매번 DB에서 읽어오는 부하를 줄여줍니다. 
[1] (https://www.egovframe.go.kr/wiki/doku.php?id=egovframework:rte:fdl:cache), 
[2] (https://www.coddykit.com/ko/courses/spring_boot/the-spring-cache-abstraction-fundamentals-9298344), 
[3] (https://velog.io/@taebong98/Spring-Cache-%EC%9D%B4%ED%95%B4%ED%95%98%EA%B8%B0)
• 코드 간결화: 비즈니스 로직 내부에 if (map.containsKey(...)) 같은 캐시 확인 코드를 직접 짤 필요 없이, 
어노테이션 선언만으로 스프링 AOP가 캐시 처리를 대신해 줍니다. 
[1] (https://www.coddykit.com/ko/courses/spring_boot/the-spring-cache-abstraction-fundamentals-9298344)

관련 주요 어노테이션

• @Cacheable: 캐시를 생성하거나 조회할 때 사용.
• @CachePut: 캐시를 갱신할 때 사용 (조건과 관계없이 항상 메서드를 실행하고 결과를 캐시에 다시 씀).
• @CacheEvict: 캐시를 삭제할 때 사용 (데이터가 수정/삭제되어 기존 캐시를 지워야 할 때 유용). [1] (https://adjh54.tistory.com/165), 
[2] (https://hyeri0903.tistory.com/237), [3] (https://www.coddykit.com/ko/courses/spring_boot/the-spring-cache-abstraction-fundamentals-9298344)
혹시 @Cacheable을 적용하려는 특정 메서드나 캐시 설정(EhCache, Redis 등)에 대해 구체적인 코드 예시나 에러 해결이 필요하신가요?

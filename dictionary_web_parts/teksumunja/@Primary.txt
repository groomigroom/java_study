org.springframework.context.annotation.Primary는 
스프링 부트(Spring Boot)에서 동일한 타입의 빈(Bean)이 여러 개 존재할 때, 
우선순위를 부여하여 "별도의 지정이 없다면 이 객체를 가장 먼저(기본값으로) 
주입해라"고 선언하는 어노테이션입니다.
이전에 질문하셨던 @Qualifier와 자매품 같은 존재이지만, 
해결 방식에 차이가 있습니다.

💡 가장 쉬운 비유

어떤 교실에 "홍길동"이라는 동명이인이 2명 있습니다.
선생님이 이름표 지정 없이 단순히 "길동아, 나와서 심부름 좀 해라"라고 
부르면 둘 다 멈칫하며 에러가 납니다.
• @Qualifier 방식: "축구부 홍길동 나와"라고 지정 호출하는 방식.
• @Primary 방식: 반장 홍길동에게 @Primary 마크를 달아두는 방식.
이제 선생님이 그냥 "길동아"라고만 불러도, 별말 없으면 기본값(반장)인 
홍길동이 알아서 출동합니다.

💻 실제 코드로 보는 예시 (멀티 데이터소스 환경)

이전에 다루었던 MySQL용 DataSource와 Oracle용 DataSource가 
동시에 등록된 멀티 데이터베이스 환경을 예로 들어보겠습니다.

1. 주 데이터베이스에 @Primary 지정하기

java
@Configuration
public class DataSourceConfig {

    @Primary // 👈 핵심! 별도의 지정이 없으면 무조건 이 MySQL을 기본으로 사용합니다.
    @Bean(name = "dataSource-mysql")
    public DataSource mySqlDataSource() {
        return new BasicDataSource(); // MySQL 설정
    }

    @Bean(name = "dataSource-oracle")
    public DataSource oracleDataSource() {
        return new BasicDataSource(); // Oracle 설정
    }
}
코드를 사용할 때는 주의가 필요합니다.

2. 비즈니스 로직(Service 등)에서 주입받을 때

• 아무 조치도 취하지 않았을 때 (MySQL 자동 선택):java
@Autowired
private DataSource dataSource; 
// ⭕ 에러 발생 안 함! @Primary가 붙은 'dataSource-mysql' 빈이 자동으로 주입됩니다.
코드를 사용할 때는 주의가 필요합니다.
• 보조 데이터베이스(Oracle)를 명시적으로 쓰고 싶을 때:java
@Autowired
@Qualifier("dataSource-oracle") // 👈 이름표를 정확히 찍어주면 Primary를 이기고 Oracle이 들어옵니다.
private DataSource dataSource;
코드를 사용할 때는 주의가 필요합니다.

🛠️ 주로 언제 사용하나요?

1. 멀티 데이터소스(Multi DataSource) 환경: 메인 DB(@Primary)와 
서브 DB(통계용, 연동용 등)를 명확히 구분할 때 가장 많이 씁니다 [eGovFrame].
2. 테스트/모킹 환경: 실제 운영 환경에서 쓸 서비스와 테스트 환경에서 
대체할 임시 서비스를 구분할 때 사용합니다.
3. 오픈소스 확장: 전자정부 프레임워크나 내부 공통 라이브러리가 
기본으로 주는 기능이 있지만, 우리 프로젝트에서 특정 빈을 
커스텀하게 덮어쓰고 기본값으로 만들고 싶을 때 사용합니다.

⚖️ @Qualifier vs @Primary 차이점 요약


구분	@Primary	@Qualifier
성격	기본값(Default) 지정	이름표(ID)로 명시적 지정
사용 위치	빈을 생성/등록하는 곳 (@Bean)	빈을 가져와 쓰는 곳 (@Autowired)
장점	가져다 쓰는 곳에서 코드가 깔끔해짐	어떤 빈이 들어오는지 직관적으로 명시됨


💡 한 줄 요약

"동일한 타입의 빈이 여러 개 있을 때, 귀찮게 일일이 이름을 
지정(@Qualifier)하지 않아도 스프링 부트가 군말 없이 가장 먼저 
기본값으로 주입해 주도록 대장(우선순위) 마크를 달아주는 어노테이션"입니다.
이로써 BasicDataSource, @Bean(name, destroyMethod), @Qualifier, 
그리고 @Primary까지 이어지는 스프링 부트 다중 데이터베이스(Multi DataSource) 
설정의 핵심 조각들을 모두 이해하셨습니다!


현재 작성 중이신 DB 설정 클래스에서 어떤 데이터베이스를 @Primary로 두고, 어떤 데이터베이스를 보조로 설계하고 계시는가요? 연동 과정에서 설정이 꼬이거나 제대로 주입이 안 되는 에러가 있다면 관련 코드와 함께 공유해 주세요. 깔끔하게 튜닝해 드리겠습니다.

스프링 부트(Spring Boot)에서 @EnableConfigurationProperties는 @ConfigurationProperties로 정의된 클래스를 
스프링 빈(Bean)으로 등록하고 활성화할 때 사용하는 어노테이션입니다. 

1. 주요 의미와 역할

• 빈 등록: @ConfigurationProperties만 붙인 클래스는 단독으로는 스프링 컨테이너에 빈으로 자동으로 등록되지 않는 경우가 있습니다. 
이때 @EnableConfigurationProperties(MyProperties.class)를 설정 클래스 등에 선언해주면 해당 클래스를 스프링 빈으로 등록해 줍니다.
• 타입 세이프(Type-safe) 바인딩 활성화: application.yml이나 application.properties 파일에 작성된 외부 설정값을 자바 객체에 안전하게 매핑(바인딩)할 수 있도록 돕습니다.
• @Import 기반 동작: @Enable로 시작하는 스프링의 다른 어노테이션들처럼, 내부적으로 @Import 메타 어노테이션을 사용하여 필요한 설정 클래스를 빈으로 끌어오는 구조를 가집니다.

2. 사용 예시

1. 프로퍼티 매핑 클래스 작성 (@ConfigurationProperties)java
@ConfigurationProperties(prefix = "app.mail")
public class MailProperties {
    private String host;
    private int port;
    // getters, setters
}
코드를 사용할 때는 주의가 필요합니다.
2. 어노테이션을 통한 활성화 및 빈 등록 (@EnableConfigurationProperties)java
@Configuration
@EnableConfigurationProperties(MailProperties.class)
public class MailConfig {
    // MailProperties를 주입받아 사용 가능
}
코드를 사용할 때는 주의가 필요합니다.
(참고: @ConfigurationProperties 클래스 내부에 @Component를 붙여 빈으로 자동 등록하는 방법도 있으나, 외부 라이브러리 클래스 등 직접 코드를수정할 수 
없거나 명시적으로 설정 빈을 관리하고 싶을 때 @EnableConfigurationProperties를 주로 사용합니다.)
@ConfigurationProperties를 사용할 때 생성자 기반 바인딩(Immutable 객체 만들기)이나 @ConfigurationPropertiesScan과의 차이점에 대해서도 알고 싶으신가요?

import org.springframework.web.bind.annotation.ResponseStatus;

@ResponseStatus(value = HttpStatus.NOT_FOUND, reason = "entity not found")



스프링 부트에서 @ResponseStatus는 HTTP 요청이 성공하거나 실패했을 때 클라이언트에게 보낼 HTTP 응답 상태 코드(Status Code)를 직접 지정하는 어노테이션입니다.
이 어노테이션을 사용하면 스프링이 기본으로 제공하는 상태 코드(성공 시 200 OK, 서버 에러 시 500 Internal Server Error 등) 대신, 비즈니스 로직에 맞는 정확한 HTTP 상태 코드를 제어할 수 있습니다.
------------------------------
## 💡 주요 사용처 2가지## 1. 커스텀 예외(Exception) 클래스에 사용 (가장 권장됨)
특정 예외가 발생했을 때 어떤 HTTP 상태 코드로 응답할지 예외 클래스 위에 선언합니다.

// 이 예외가 발생하면 클라이언트에게 404 Not Found를 반환합니다.
@ResponseStatus(value = HttpStatus.NOT_FOUND, reason = "해당 리소스를 찾을 수 없습니다.")public class ResourceNotFoundException extends RuntimeException {
    public ResourceNotFoundException(String message) {
        super(message);
    }
}


* 결과: 컨트롤러 내부에서 throw new ResourceNotFoundException("...")이 실행되면, 클라이언트는 자동으로 404 Not Found 응답을 받게 됩니다.

## 2. 컨트롤러 메서드에 사용
메서드가 성공적으로 실행 완료되었을 때, 기본값인 200 OK 대신 다른 코드를 주고 싶을 때 사용합니다. 주로 생성 요청이 성공했을 때 201 Created를 보낼 때 자주 씁니다.

@PostMapping
@ResponseStatus(HttpStatus.CREATED) // 성공 시 201 Created 응답public User createUser(@RequestBody UserDto userDto) {
    return userService.signUp(userDto);
}

------------------------------
## 📌 장점과 단점

* 장점: 코드가 직관적이고 깔끔해집니다. 어노테이션 하나로 상태 코드를 지정할 수 있어 편리합니다.
* 단점: 응답 조건이 유동적일 때(예: 상황에 따라 200을 줄지 201을 줄지 분기 처리해야 할 때)나 응답 헤더를 동적으로 변경해야 할 때는 대응하기 어렵습니다.

------------------------------
## 🆚 ResponseEntity와의 차이점
조금 더 복잡한 응답 제어가 필요할 때는 @ResponseStatus 대신 ResponseEntity 객체를 반환하는 방식을 사용합니다.

| 구분 | @ResponseStatus | ResponseEntity<T> |
|---|---|---|
| 제어 방식 | 어노테이션 기반 (정적임) | 자바 객체 반환 기반 (동적임) |
| 특징 | 코드 작성이 간결하고 가독성이 좋음 | 상황에 따라 상태 코드, 바디, 헤더를 자유롭게 바꿀 수 있음 |
| 추천 상황 | 고정된 예외 처리나 단순 성공 코드 지정 시 | 비즈니스 로직에 따라 응답 코드가 달라질 때 |

// ResponseEntity를 사용한 동적 제어 예시
@GetMapping("/check/{id}")public ResponseEntity<String> checkStatus(@PathVariable Long id) {
    if (userService.isAdmin(id)) {
        return ResponseEntity.ok("관리자입니다."); // 200 OK
    }
    return ResponseEntity.status(HttpStatus.FORBIDDEN).body("권한이 없습니다."); // 403 Forbidden
}

------------------------------
지금 작성 중이신 기능이 데이터 생성(Create) API인가요, 아니면 데이터가 없을 때 던질 예외 처리(Exception Handling)인가요? 구현하고 계신 상황을 말씀해 주시면 상황에 딱 맞는 구현 방식을 제안해 드리겠습니다!

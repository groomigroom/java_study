@RequestMapping은 모든 HTTP 메서드를 아우르는 범용 어노테이션이며, @GetMapping은 HTTP GET 요청만 처리하도록 축소된 특화 어노테이션입니다. [1] 
두 어노테이션의 핵심 차이점을 아래 비교 테이블과 세부 명세로 정리해 드립니다.
## 📊 한눈에 보는 핵심 차이점

| 구분 | @RequestMapping | @GetMapping |
|---|---|---|
| 기능 범위 | 모든 HTTP 메서드 대응 가능 (기본값) | HTTP GET 메서드만 대응 가능 |
| 사용 위치 | 클래스 레벨 및 메서드 레벨 모두 가능 | 메서드 레벨에만 사용 가능 |
| 동작 원리 | 스프링의 기본 매핑 어노테이션 | 내부적으로 @RequestMapping(method = RequestMethod.GET)을 래핑 |
| 지원 버전 | 스프링 초기 버전부터 지원 | 스프링 4.3 버전부터 지원 |

## 💡 주요 차이점 상세 분석## 1. 코드의 간결성과 가독성
@RequestMapping으로 특정 HTTP 메서드를 지정하려면 method 속성을 매번 적어야 해서 코드가 길어집니다. 반면 @GetMapping은 경로만 적으면 되므로 직관적입니다. [2, 3] 

// @RequestMapping 사용 시
@RequestMapping(value = "/users", method = RequestMethod.GET)public List<User> getUsers() { ... }
// @GetMapping 사용 시 (코드가 훨씬 단축됨)
@GetMapping("/users")public List<User> getUsers() { ... }

## 2. 작성할 수 있는 위치 (클래스 vs 메서드)

* 
* @RequestMapping: 보통 클래스 상단에 붙여서 해당 컨트롤러 내부 메서드들의 공통 기본 경로(Prefix)를 지정할 때 자주 씁니다.
* @GetMapping: 클래스 레벨에는 붙일 수 없으며, 실제 비즈니스 로직을 처리하는 개별 메서드에만 선언할 수 있습니다. [2, 4] 
* 

@RestController
@RequestMapping("/api/v1") // 공통 경로 지정public class UserController {

    @GetMapping("/users") // 실제 요청 경로는 /api/v1/users (GET)
    public List<User> getAll() { ... }
}

## 3. HTTP 메서드 제한 유무

* 
* @RequestMapping에 method 속성을 지정하지 않으면 GET, POST, PUT, DELETE 등 모든 HTTP 요청을 다 허용하고 처리하게 됩니다. 보안과 올바른 REST API 설계를 위해서는 지양해야 하는 방식입니다.
* @GetMapping은 오직 GET 요청에만 반응하므로 잘못된 메서드 요청(예: POST)이 들어오면 스프링이 자동으로 이를 차단합니다. [1, 2, 5] 
*

## 🛠️ 실무 권장 스타일
현재 실무에서는 클래스 레벨에는 공통 경로를 위한 @RequestMapping을 사용하고, 메서드 레벨에는 구체적인 행위에 맞는 @GetMapping, @PostMapping, @PutMapping, @DeleteMapping을 사용하는 것이 표준 규격처럼 자리 잡았습니다. [2, 3]

Optional<UserEntity> findByUsernameAndIsLockAndIsSocial(String username, Boolean isLock, Boolean isSocial);
​

-------------------------------

제공해주신 코드는 Spring Data JPA에서 사용하는 쿼리 메서드(Query Method) 선언문입니다. 데이터베이스에서 특정 조건에 맞는 유저 한 명을 조회하는 인터페이스 메서드입니다.
이 한 줄에 담긴 모든 키워드와 동작 원리를 하나씩 자세히 설명해 드리겠습니다.
------------------------------
## 1. Optional<UserEntity> (반환 타입)

* 역할: 조회 결과가 있을 수도 있고, 없을 수도 있음을 표현하는 컨테이너 객체입니다.
* 상세 설명:
* 만약 데이터베이스에 조건과 일치하는 유저가 있다면 Optional 내부에 UserEntity 객체를 담아서 반환합니다.
   * 일치하는 유저가 없다면 null 대신 빈 객체(Optional.empty())를 반환합니다.
   * 이를 통해 호출하는 곳에서 NullPointerException(NPE)을 안전하게 방지하고, .orElseThrow() 같은 메서드로 유저가 없을 때의 예외 처리를 깔끔하게 할 수 있습니다. [1] 

## 2. findByUsernameAndIsLockAndIsSocial (메서드 이름)

* 역할: Spring Data JPA가 이름을 분석하여 자동으로 SQL 쿼리를 생성하는 핵심 규칙입니다.
* 이름 분해 설명:
* findBy: 조회를 시작하겠다는 고정 키워드입니다. SQL의 SELECT * FROM user_entity WHERE에 해당합니다.
   * Username: 첫 번째 조건 필드입니다. UserEntity 클래스의 username 필드 값을 기준으로 검색합니다.
   * And: 논리 연산자입니다. 앞뒤 조건을 모두 만족해야 함을 뜻합니다. SQL의 AND와 같습니다.
   * IsLock: 두 번째 조건 필드입니다. 엔티티의 isLock 필드 값을 검사합니다.
   * And: 두 번째 논리 연산자(AND)입니다.
   * IsSocial: 세 번째 조건 필드입니다. 엔티티의 isSocial 필드 값을 검사합니다.

실제 실행되는 SQL 쿼리 예시:

SELECT * FROM user_entity WHERE username = ? 
  AND is_lock = ? 
  AND is_social = ?;

## 3. 파라미터 (매개변수 부)
메서드 이름에 나열된 조건 필드의 순서대로 데이터 값을 매핑하여 전달합니다.

* String username: 조회할 유저의 아이디 값을 받습니다. (Username 조건에 매핑)
* Boolean isLock: 계정 잠금 상태(true/false)를 받습니다. (IsLock 조건에 매핑)
* Boolean isSocial: 소셜 로그인 계정 여부(true/false)를 받습니다. (IsSocial 조건에 매핑)

------------------------------
## 💡 주로 어떤 상황에서 사용하나요?
이 메서드는 보통 로그인(인증) 로직에서 자주 사용됩니다.

* 아이디가 일치해야 하고,
* 계정이 잠기지 않은 상태(isLock = false)여야 하며,
* 소셜 로그인이 아닌 일반 회원 가입 계정(isSocial = false)인 유저만 콕 집어서 인증을 진행하고 싶을 때 유용하게 쓰입니다.

 domain > user > service > UserService.java : 메소드 추가

@Transactional
public Long updateUser(UserRequestDTO dto) throws AccessDeniedException {

    // 본인만 수정 가능 검증
    String sessionUsername = SecurityContextHolder.getContext().getAuthentication().getName();
    if (!sessionUsername.equals(dto.getUsername())) {
        throw new AccessDeniedException("본인 계정만 수정 가능");
    }

    // 조회
    UserEntity entity = userRepository.findByUsernameAndIsLockAndIsSocial(dto.getUsername(), false, false)
            .orElseThrow(() -> new UsernameNotFoundException(dto.getUsername()));

    // 회원 정보 수정
    entity.updateUser(dto);

    return userRepository.save(entity).getId();
}



-----------------------------------------

제공해주신 코드는 Spring Security와 Spring Data JPA를 활용하여 로그인한 본인의 회원 정보만 안전하게 수정하는 비즈니스 로직(Service 레이어)입니다.
각 코드 라인이 가진 의미와 동작 과정을 하나씩 자세히 설명해 드리겠습니다.
------------------------------
## 1. @Transactional 및 메서드 선언부

@Transactionalpublic Long updateUser(UserRequestDTO dto) throws AccessDeniedException {


* @Transactional: 데이터베이스 작업을 하나의 트랜잭션으로 묶습니다. 정보 수정 중 오류가 발생하면 변경 사항을 모두 취소(Rollback)하고, 성공하면 데이터베이스에 최종 반영(Commit)합니다.
* throws AccessDeniedException: 메서드 내부에서 권한 문제가 발생했을 때, 호출한 곳(Controller 등)으로 AccessDeniedException 예외를 던지겠다고 선언합니다.

------------------------------
## 2. 본인 검증 로직 (Spring Security 활용)

// 본인만 수정 가능 검증
String sessionUsername = SecurityContextHolder.getContext().getAuthentication().getName();if (!sessionUsername.equals(dto.getUsername())) {
    throw new AccessDeniedException("본인 계정만 수정 가능");
}


* SecurityContextHolder.getContext().getAuthentication().getName():
* 현재 시스템(Spring Security 체계)에 로그인한 사용자의 아이디(Username)를 가져오는 공식적인 방법입니다. 세션이나 토큰에 저장된 인증 정보를 기반으로 합니다.
* if (!sessionUsername.equals(...)):
* 로그인한 사람의 아이디(sessionUsername)와 수정을 요청한 아이디(dto.getUsername())가 일치하는지 비교합니다.
* throw new AccessDeniedException(...):
* 만약 다른 사람의 아이디로 수정을 시도했다면, "본인 계정만 수정 가능"이라는 메시지와 함께 접근 거부 예외를 발생시켜 실행을 즉시 중단합니다. (보안 위반 방지)

------------------------------
## 3. 회원 데이터 조회 (JPA 활용)

// 조회
UserEntity entity = userRepository.findByUsernameAndIsLockAndIsSocial(dto.getUsername(), false, false)
        .orElseThrow(() -> new UsernameNotFoundException(dto.getUsername()));


* userRepository.findByUsernameAndIsLockAndIsSocial(..., false, false):
* 앞서 공부했던 쿼리 메서드입니다. 요청한 아이디(dto.getUsername())를 가지면서, 잠기지 않고(isLock=false), 소셜 계정이 아닌(isSocial=false) 일반 유저를 DB에서 찾습니다.
* .orElseThrow(...):
* Optional 처리 방식입니다. 조건에 맞는 유저가 DB에 존재하면 entity 변수에 값을 담고, 존재하지 않으면 괄호 안의 익명 함수(->)를 실행하여 UsernameNotFoundException 예외를 발생시킵니다.

------------------------------
## 4. 회원 정보 수정 및 저장

// 회원 정보 수정
entity.updateUser(dto);
return userRepository.save(entity).getId();


* entity.updateUser(dto):
* 객체지향적인 코드 패턴(도메인 주도 설계 형태)입니다. UserEntity 클래스 내부에 정의된 updateUser 메서드를 호출하여, dto에 담긴 새로운 정보(예: 닉네임, 이메일 등)를 엔티티 객체에 덮어씌웁니다.
* userRepository.save(entity).getId():
* 변경된 정보가 담긴 entity를 데이터베이스에 반영(UPDATE 쿼리 실행)하고, 수정이 완료된 사용자의 고유 식별자(ID값)를 반환합니다.
   * 참고: 영속성 컨텍스트(JPA 특성) 덕분에 @Transactional 환경에서는 사실 save()를 생략해도 메서드가 끝날 때 자동으로 수정사항이 DB에 반영(더티 체킹)되지만, 명시적으로 적어 가독성을 높인 코드입니다.

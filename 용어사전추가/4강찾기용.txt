제공해주신 코드는 스프링 부트(Spring Boot) 환경에서 새로운 사용자를 회원가입(등록)하는 전형적인 비즈니스 로직(Service 레이어)입니다.
각 라인과 키워드가 어떤 역할을 하는지 하나씩 자세히 설명해 드리겠습니다.
------------------------------
## 1. @Transactional

* 역할: 이 메서드 내부의 모든 데이터베이스 작업을 하나의 트랜잭션(Transaction)으로 묶어줍니다. [1] 
* 상세 설명:
* 메서드 실행 중 오류(Runtime Exception)가 발생하면, 이 메서드 안에서 일어난 모든 데이터베이스 변경 사항을 취소(Rollback)합니다.
   * 성공적으로 끝나면 데이터베이스에 완전히 반영(Commit)합니다.
   * 회원가입 과정에서 예기치 못한 에러가 났을 때 데이터가 꼬이는 것을 방지합니다.

## 2. public Long addUser(UserRequestDTO dto)

* 역할: 메서드의 선언부입니다.
* 상세 설명:
* public: 어디서든 접근 가능한 메서드입니다. 보통 Controller 레이어에서 이 메서드를 호출합니다.
   * Long: 회원가입이 성공하면 생성된 사용자의 고유 식별자(ID값)를 반환합니다.
   * addUser: 메서드의 이름입니다.
   * UserRequestDTO dto: 클라이언트(프론트엔드)가 보낸 회원가입 데이터(아이디, 비밀번호, 닉네임 등)가 담겨 있는 객체입니다.

## 3. 중복 아이디 검증 (if문)

if (userRepository.existsByUsername(dto.getUsername())) {
    throw new IllegalArgumentException("이미 유저가 존재합니다.");
}


* 역할: 가입하려는 아이디가 이미 존재하는지 데이터베이스를 확인합니다.
* 상세 설명:
* dto.getUsername(): 사용자가 입력한 아이디를 가져옵니다.
   * userRepository.existsByUsername(...): JPA 리포지토리를 통해 DB에 해당 아이디를 가진 레코드가 있는지 boolean(true/false)으로 조회합니다.
   * throw new IllegalArgumentException(...): 이미 아이디가 존재한다면 "이미 유저가 존재합니다."라는 메시지와 함께 예외를 발생시켜 메서드 실행을 즉시 중단합니다.

## 4. 엔티티 객체 생성 (UserEntity.builder())

UserEntity entity = UserEntity.builder()
        .username(dto.getUsername())
        .password(passwordEncoder.encode(dto.getPassword()))
        .isLock(false)
        .isSocial(false)
        .roleType(UserRoleType.USER)
        .nickname(dto.getNickname())
        .email(dto.getEmail())
        .build();


* 역할: DB 테이블과 매핑되는 UserEntity 객체를 생성하고 데이터를 채웁니다. 롬복(Lombok)의 @Builder 패턴을 사용하고 있습니다. [2] 
* 세부 필드 설명:
* .username(...): 사용자의 아이디를 설정합니다.
   * .password(passwordEncoder.encode(...)): 보안 핵심 부분입니다. 사용자가 입력한 비밀번호를 passwordEncoder를 통해 암호화(해싱)하여 저장합니다. DB 유출 시에도 비밀번호를 알아볼 수 없게 만듭니다.
   * .isLock(false): 계정 잠금 여부입니다. 처음 가입할 때는 잠기지 않은 상태이므로 false를 줍니다.
   * .isSocial(false): 소셜 로그인(구글, 카카오 등) 여부입니다. 일반 회원가입이므로 false를 줍니다.
   * .roleType(UserRoleType.USER): 권한 설정입니다. 회원가입 시 기본 권한인 일반 유저(USER) 등급을 부여합니다.
   * .nickname(...) / .email(...): 사용자가 입력한 닉네임과 이메일을 설정합니다.
   * .build(): 설정을 마치고 최종적으로 UserEntity 객체를 완성하여 반환합니다. [3] 

## 5. 데이터 저장 및 ID 반환 (return문)

return userRepository.save(entity).getId();


* 역할: 완성된 엔티티를 데이터베이스에 저장하고, 생성된 PK(ID) 값을 반환합니다.
* 상세 설명:
* userRepository.save(entity): Spring Data JPA의 기본 메서드로, DB에 INSERT 쿼리를 실행하여 유저 정보를 저장합니다. 저장된 후의 엔티티에는 DB가 자동으로 생성해 준 ID(기본키)가 채워집니다.
   * .getId(): 저장된 유저 객체에서 고유 ID(Long 타입)를 추출합니다.
   * return: 이 ID 값을 메서드 호출처(보통 Controller)로 넘겨주며 메서드가 종료됩니다.

@Transactional
public Long updateUser(UserRequestDTO dto) throws AccessDeniedException {

    // 본인만 수정 가능 검증
    String sessionUsername = SecurityContextHolder.getContext().getAuthentication().getName();
    if (!sessionUsername.equals(dto.getUsername())) {
        throw new AccessDeniedException("본인 계정만 수정 가능");
    }

    // 조회
    UserEntity entity = userRepository.findByUsernameAndIsLockAndIsSocial(dto.getUsername(), false, false)
            .orElseThrow(() -> new UsernameNotFoundException(dto.getUsername()));

    // 회원 정보 수정
    entity.updateUser(dto);

    return userRepository.save(entity).getId();
}

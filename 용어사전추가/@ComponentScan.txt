자바 스프링에서 @ComponentScan은 설정한 패키지 경로를 탐색하여 @Component 애노테이션이
붙은 클래스들을 자동으로 스프링 컨테이너에 빈(Bean)으로 등록하는 기능입니다.
개발자가 @Bean을 통해 객체를 일일이 빈으로 등록하지 않아도, 
스프링이 스스로 클래스를 찾아내 관리해 주므로 대규모 애플리케이션 개발에 필수적입니다.
## 핵심 동작 원리

* 자동 탐색 및 등록: @ComponentScan이 활성화되면 스프링은 지정된 패키지 내부를 검색합니다.
* 스프링 빈 이름: 등록되는 빈의 이름은 기본적으로 클래스명의 첫 글자를 소문자로 변환하여 사용합니다 (예: MemberService → memberService).
* 이름 직접 지정: 원하는 경우 @Component("myService") 형태로 빈 이름을 직접 지정할 수 있습니다. 


## 주요 스캔 대상 (Stereotype 애노테이션)
@ComponentScan은 @Component뿐만 아니라, 내부에 @Component를 포함하고 있는 
다음의 애노테이션들도 모두 인식하여 빈으로 등록합니다.

* 
* @Component: 가장 기본적인 컴포넌트 스캔 대상입니다.
* @Controller: 스프링 MVC 웹 컨트롤러로 인식됩니다.
* @Service: 핵심 비즈니스 로직이 위치한 서비스 레이어에 사용됩니다.
* @Repository: 데이터 접근 레이어(DAO)에 사용되며, 데이터베이스 예외를 스프링 예외로 변환해 줍니다.
* @Configuration: 스프링 설정 정보로 인식되며, 내부의 빈들을 싱글톤으로 유지하도록 돕습니다.
* 

## 스캔 위치 설정 방법
스캔할 범위를 제한하지 않으면 모든 클래스를 찾느라 구동 시간이 오래 걸릴 수 있어 위치를 지정할 수 있습니다.

* 
* 기본값: 위치를 지정하지 않으면 @ComponentScan이 붙은 현재 설정 클래스의 패키지와 그 하위 패키지가 탐색 대상이 됩니다.
* 특정 패키지 지정: 아래 코드처럼 시작 위치를 직접 지정할 수 있습니다. 
* 

@Configuration
@ComponentScan(basePackages = "com.example.myapp")public class AppConfig {
    // com.example.myapp 패키지와 하위 패키지를 스캔합니다.
}

💡 참고 (Spring Boot)
스프링 부트를 사용할 때 핵심이 되는 @SpringBootApplication 애노테이션 내부에는 이미 
@ComponentScan이 포함되어 있습니다. 따라서 이 애노테이션이 붙은 메인 클래스의 
패키지와 그 하위 패키지들은 별도 설정 없이도 자동으로 컴포넌트 스캔이 작동합니다.

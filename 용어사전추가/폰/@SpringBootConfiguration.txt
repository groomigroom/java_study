스프링 부트(Spring Boot)에서 @SpringBootConfiguration은 해당 클래스가 스프링 부트의 구성(Configuration) 파일임을 나타내며, 내부에 정의된 빈(Bean)들을 스프링 컨테이너에 등록하는 역할을 합니다. [1, 2] 
가장 핵심이 되는 스타터 의존성(Starter Dependency)은 spring-boot-starter입니다. [3] 
## 1. @SpringBootConfiguration의 역할

* 
* 기존 @Configuration의 대체 및 확장: 스프링의전통적인 @Configuration 애노테이션과 완전히 동일한 기능을 수행합니다. 클래스 내부에 @Bean 메서드를 작성하여 자바 코드로 스프링 빈을 직접 등록할 수 있게 해줍니다. [1, 4] 
* 스프링 부트 전용 마커(Marker): 스프링 부트 환경에서 구성 클래스임을 명확히 표시합니다. 이를 통해 스프링 부트의 다양한 기능(예: 통합 테스트 시 구성 클래스 자동 탐색)이 이 애노테이션을 기준으로 동작하게 됩니다. [2] 
* @SpringBootApplication의 핵심 구성 요소: 보통 개발자가 이 애노테이션을 직접 쓸 일은 많지 않습니다. 스프링 부트 메인 클래스에 붙는 @SpringBootApplication 내부에 포함되어 있어, 메인 클래스가 자동으로 설정 클래스 역할을 하도록 지원합니다. [4, 5, 6] 
* 

## 2. 소속된 Starter Dependency
@SpringBootConfiguration은 스프링 부트의 가장 기본이 되는 라이브러리에 포함되어 있습니다. [2] 

<!-- Maven 환경 -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter</artifactId>
</dependency>

// Gradle 환경
implementation 'org.springframework.boot:spring-boot-starter'


* 
* spring-boot-starter는 모든 스프링 부트 스타터 패키지의 '기본(Base)'이 되는 의존성입니다.
* 웹 개발을 위한 spring-boot-starter-web이나 데이터베이스 설정을 위한 spring-boot-starter-data-jpa 등을 추가하면, 이 spring-boot-starter가 내부에 자동으로 포함(전이 의존성)되어 들어옵니다.
* 실제 애노테이션 클래스는 이 스타터가 가져오는 최하위 코어 라이브러리인 spring-boot jar 파일 안에 위치합니다. [5, 7] 
* 

추가적으로 스프링 부트의 자동 설정(Auto-Configuration) 원리나 구체적인 빈(Bean) 등록 방식에 대해 더 궁금한 점이 있으시면 언제든 질문해 주세요!



/*
 * The application object needs to be declared first (implements IWebApplication)
 * In this case, the Jakarta-based version will be used.
 */
public void init(final FilterConfig filterConfig) throws ServletException {
    this.application =
            JakartaServletWebApplication.buildApplication(
                filterConfig.getServletContext());
    // We will see later how the TemplateEngine object is built and configured
    this.templateEngine = buildTemplateEngine(this.application);
}

/*
 * Each request will be processed by creating an exchange object (modeling
 * the request, its response and all the data needed for this process) and
 * then calling the corresponding controller.
 */
private boolean process(HttpServletRequest request, HttpServletResponse response)
        throws ServletException {
    
    try {

        final IWebExchange webExchange = 
            this.application.buildExchange(request, response);
        final IWebRequest webRequest = webExchange.getRequest();

        // This prevents triggering engine executions for resource URLs
        if (request.getRequestURI().startsWith("/css") ||
                request.getRequestURI().startsWith("/images") ||
                request.getRequestURI().startsWith("/favicon")) {
            return false;
        }
        
        /*
         * Query controller/URL mapping and obtain the controller
         * that will process the request. If no controller is available,
         * return false and let other filters/servlets process the request.
         */
        final IGTVGController controller = 
            ControllerMappings.resolveControllerForRequest(webRequest);
        if (controller == null) {
            return false;
        }

        /*
         * Write the response headers
         */
        response.setContentType("text/html;charset=UTF-8");
        response.setHeader("Pragma", "no-cache");
        response.setHeader("Cache-Control", "no-cache");
        response.setDateHeader("Expires", 0);

        /*
         * Obtain the response writer
         */
        final Writer writer = response.getWriter();

        /*
         * Execute the controller and process view template,
         * writing the results to the response writer. 
         */
        controller.process(webExchange, this.templateEngine, writer);
        
        return true;
        
    } catch (Exception e) {
        try {
            response.sendError(HttpServletResponse.SC_INTERNAL_SERVER_ERROR);
        } catch (final IOException ignored) {
            // Just ignore this
        }
        throw new ServletException(e);
    }
    
}

2.2 템플릿 엔진 생성 및 구성
필터의 init(…) 메서드에는 다음과 같은 줄이 포함되어 있었습니다 .

org.thymeleaf.TemplateEngine이제 우리 객체가 어떻게 초기화되는지 살펴보겠습니다 .

private static ITemplateEngine buildTemplateEngine(final IWebApplication application) {

    // Templates will be resolved as application (ServletContext) resources
    final WebApplicationTemplateResolver templateResolver = 
            new WebApplicationTemplateResolver(application);

    // HTML is the default mode, but we will set it anyway for better understanding of code
    templateResolver.setTemplateMode(TemplateMode.HTML);
    // This will convert "home" to "/WEB-INF/templates/home.html"
    templateResolver.setPrefix("/WEB-INF/templates/");
    templateResolver.setSuffix(".html");
    // Set template cache TTL to 1 hour. If not set, entries would live in cache until expelled by FIFO
    templateResolver.setCacheTTLMs(Long.valueOf(3600000L));

    // Cache is set to true by default. Set to false if you want templates to
    // be automatically updated when modified.
    templateResolver.setCacheable(true);

    final TemplateEngine templateEngine = new TemplateEngine();
    templateEngine.setTemplateResolver(templateResolver);

    return templateEngine;

}
객체를 구성하는 방법은 여러 가지가 있지만 TemplateEngine, 지금은 이 몇 줄의 코드만으로도 필요한 단계를 충분히 이해할 수 있습니다.

템플릿 리졸버
먼저 템플릿 리졸버부터 살펴보겠습니다.

템플릿 리졸버는 Thymeleaf API에서 제공하는 인터페이스를 구현하는 객체입니다 org.thymeleaf.templateresolver.ITemplateResolver.

이 객체들은 템플릿에 접근하는 방법을 결정하는 역할을 하며, 이 GTVG 애플리케이션에서는 IWebApplicationorg.thymeleaf.templateresolver.WebApplicationTemplateResolver 객체 로부터 템플릿 파일을 리소스로 가져오는 것을 의미합니다 . IWebApplication은 서블릿 기반 애플리케이션에서 서블릿 API의 객체를 래핑하는 Thymeleaf 추상화 클래스로 , 웹 애플리케이션 루트에서 리소스를 해석합니다.[javax|jakarta].servlet.ServletContext

하지만 템플릿 리졸버에 대해 말할 수 있는 것은 이게 전부가 아닙니다. 몇 가지 구성 매개변수를 설정할 수 있기 때문입니다. 먼저 템플릿 모드부터 살펴보겠습니다.

templateResolver.setTemplateMode(TemplateMode.HTML);
HTML은 기본 템플릿 모드이지만 WebApplicationTemplateResolver, 코드가 어떤 작업을 수행하는지 명확하게 문서화하기 위해 템플릿 모드를 설정하는 것이 좋습니다.

templateResolver.setPrefix("/WEB-INF/templates/");
templateResolver.setSuffix(".html");
접두사 와 접미사는 실제 리소스 이름을 얻기 위해 엔진에 전달할 템플릿 이름을 수정합니다.

이 구성을 사용하면 "product/list"라는 템플릿 이름은 다음과 같습니다.

servletContext.getResourceAsStream("/WEB-INF/templates/product/list.html")
선택적으로, 파싱된 템플릿이 캐시에 유지될 수 있는 시간은 템플릿 리졸버에서 cacheTTLMs 속성을 통해 구성할 수 있습니다 .

templateResolver.setCacheTTLMs(3600000L);
최대 캐시 크기에 도달했고 현재 캐시된 항목 중 가장 오래된 항목인 경우, 해당 TTL에 도달하기 전에도 템플릿이 캐시에서 제거될 수 있습니다.

캐시 동작 및 크기는 사용자가 인터페이스를 구현 하거나 기본 캐시를 관리하는 객체를 ICacheManager수정하여 정의할 수 있습니다.StandardCacheManager

템플릿 리졸버에 대해 배울 내용은 훨씬 더 많지만, 지금은 Template Engine 객체의 생성 과정을 살펴보겠습니다.

템플릿 엔진
Template Engine 객체는 org.thymeleaf.ITemplateEngine인터페이스의 구현체입니다. Thymeleaf 코어에서 제공하는 구현체 중 하나를 org.thymeleaf.TemplateEngine여기에서 인스턴스화합니다.

templateEngine = new TemplateEngine();
templateEngine.setTemplateResolver(templateResolver);
꽤 간단하죠? 인스턴스를 생성하고 템플릿 리졸버를 해당 인스턴스로 설정하기만 하면 됩니다.

템플릿 리졸버는 필수 매개변수 중 하나 TemplateEngine일 뿐이며, 이후에 다룰 다른 매개변수들(메시지 리졸버, 캐시 크기 등)도 많습니다. 지금은 이것으로 충분합니다.

템플릿 엔진이 이제 준비되었으므로 Thymeleaf를 사용하여 페이지를 만들 수 있습니다.

3. 텍스트 활용
3.1 다국어 환영 인사
우리의 첫 번째 과제는 식료품점 웹사이트의 홈페이지를 만드는 것입니다.

제목과 환영 메시지만 있을 것입니다. 
/WEB-INF/templates/home.html파일은 다음과 같습니다.

<!DOCTYPE html>

<html xmlns:th="http://www.thymeleaf.org">

  <head>
    <title>Good Thymes Virtual Grocery</title>
    <meta http-equiv="Content-Type" content="text/html; charset=UTF-8" />
    <link rel="stylesheet" type="text/css" media="all" 
          href="../../css/gtvg.css" th:href="@{/css/gtvg.css}" />
  </head>

  <body>
  
    <p th:text="#{home.welcome}">Welcome to our grocery store!</p>
  
  </body>

</html>
가장 먼저 눈에 띄는 것은 이 파일이 HTML5 형식이라는 점입니다. 이 파일에는 HTML 이외의 태그가 포함되어 있지 않기 때문에 모든 브라우저에서 올바르게 표시됩니다(브라우저는 이해하지 못하는 모든 속성(예: <script>)을 무시합니다 th:text).

하지만 이 템플릿이 HTML5 사양에서 허용되지 않는 비표준 속성을 사용하고 있기 때문에 유효한 HTML5 문서가 아니라는 점도 알아두시면 좋을 것입니다 th:*. 실제로, 우리는 태그 xmlns:th에 <html>HTML5와는 전혀 맞지 않는 속성을 추가하고 있습니다.

<html xmlns:th="http://www.thymeleaf.org">
…이는 템플릿 처리에는 전혀 영향을 미치지 않지만, IDE가 해당 속성들에 대한 네임스페이스 정의가 없다는 오류를 표시하지 않도록 하는 일종의 주문th:* 과 같은 역할을 합니다 .

그렇다면 이 템플릿을 HTML5 유효성 검사를 통과하도록 만들려면 어떻게 해야 할까요 ? 간단합니다. Thymeleaf의 데이터 속성 구문으로 바꾸고, data-속성 이름에 접두사를 사용하고, -세미콜론(;) 대신 하이픈(- :)을 구분자로 사용하면 됩니다.

<!DOCTYPE html>

<html>

  <head>
    <title>Good Thymes Virtual Grocery</title>
    <meta http-equiv="Content-Type" content="text/html; charset=UTF-8" />
    <link rel="stylesheet" type="text/css" media="all" 
          href="../../css/gtvg.css" data-th-href="@{/css/gtvg.css}" />
  </head>

  <body>
  
    <p data-th-text="#{home.welcome}">Welcome to our grocery store!</p>
  
  </body>

</html>
HTML5 사양에서는 사용자 지정 접두사가 붙은 속성을 허용하므로 위 코드를 사용하면 템플릿이 유효한 HTML5 문서가data- 됩니다 .

두 표기법은 완전히 동일하며 상호 교환 가능하지만, 코드 예제의 간결성을 위해 이 튜토리얼에서는 네임스페이스 표기법 ( th:*)을 사용합니다. 또한, 네임스페이스 th:*표기법은 더 일반적이며 모든 Thymeleaf 템플릿 모드( XML, TEXT…)에서 사용할 수 있는 반면, 네임 data-스페이스 표기법은 특정 모드에서만 사용할 수 있습니다 HTML.

th:text 사용 및 텍스트 외부화
텍스트 외부화란 템플릿 파일에서 템플릿 코드 조각을 추출하여 별도의 파일(일반적으로 여러 개의 .properties파일)에 저장하고, 다른 언어로 작성된 동등한 텍스트로 쉽게 대체할 수 있도록 하는 과정입니다(이 과정을 국제화 또는 간단히 i18n 이라고 합니다 ). 외부화된 텍스트 조각은 일반적으로 "메시지" 라고 합니다 .

메시지에는 항상 메시지를 식별하는 키가 있으며, Thymeleaf에서는 다음 구문을 사용하여 텍스트가 특정 메시지에 대응하도록 지정할 수 있습니다 #{...}.

<p th:text="#{home.welcome}">Welcome to our grocery store!</p>
여기서 우리가 볼 수 있는 것은 실제로 타임리프 표준 방언의 두 가지 서로 다른 특징입니다.

이 th:text속성은 값 표현식을 평가하고 그 결과를 호스트 태그의 본문으로 설정하여 코드에서 볼 수 있는 "저희 식료품점에 오신 것을 환영합니다!" 텍스트를 효과적으로 대체합니다.
표준 표현식 구문#{home.welcome} 에 지정된 이 표현식은 속성 에 사용할 텍스트가 템플릿을 처리하는 로케일에 해당하는 키를 가진 메시지여야 함을 지시합니다.th:texthome.welcome
자, 그렇다면 이 외부화된 텍스트는 어디에 있을까요?

Thymeleaf에서 외부화된 텍스트의 위치는 완전히 구성 가능하며, org.thymeleaf.messageresolver.IMessageResolver사용되는 특정 구현에 따라 달라집니다. 일반적으로 .properties파일 기반 구현이 사용되지만, 예를 들어 데이터베이스에서 메시지를 가져오는 등 원하는 경우 자체 구현을 만들 수도 있습니다.

하지만 초기화 과정에서 템플릿 엔진에 대한 메시지 리졸버를 지정하지 않았으므로, 애플리케이션은 에서 구현한 표준 메시지 리졸버를org.thymeleaf.messageresolver.StandardMessageResolver 사용하고 있습니다 .

표준 메시지 해석기는 /WEB-INF/templates/home.html템플릿과 동일한 폴더에 동일한 이름의 속성 파일에서 메시지를 찾을 것으로 예상합니다. 예:

/WEB-INF/templates/home_en.properties영어 텍스트용입니다.
/WEB-INF/templates/home_es.properties스페인어 텍스트용입니다.
/WEB-INF/templates/home_pt_BR.properties포르투갈어(브라질) 텍스트용입니다.
/WEB-INF/templates/home.properties(지역 설정이 일치하지 않을 경우) 기본 텍스트로 표시됩니다.
우리 파일을 한번 살펴볼까요 home_es.properties?

3.2 텍스트 및 변수에 대한 추가 설명
이스케이프되지 않은 텍스트
홈페이지의 가장 기본적인 버전은 이제 완성된 것 같지만, 한 가지 미처 생각하지 못한 부분이 있습니다… 만약 이런 메시지를 넣는다면 어떨까요?

home.welcome=Welcome to our <b>fantastic</b> grocery store!
이 템플릿을 이전처럼 실행하면 다음과 같은 결과를 얻습니다.

<p>Welcome to our &lt;b&gt;fantastic&lt;/b&gt; grocery store!</p>
이는 우리가 예상했던 것과는 다릅니다. <b>태그가 이스케이프 처리되었기 때문에 브라우저에 그대로 표시될 것입니다.

이는 해당 속성의 기본 동작입니다 . Thymeleaf가 HTML 태그를 이스케이프하지 않고 그대로 유지하도록 하려면 다른 속성 ("이스케이프되지 않은 텍스트"를 의미) th:text을 사용해야 합니다 .th:utext

<p th:utext="#{home.welcome}">Welcome to our grocery store!</p>
이렇게 하면 우리가 원했던 대로 메시지가 출력됩니다.

<p>Welcome to our <b>fantastic</b> grocery store!</p>
th:utext보안상의 이유로 더 엄격한 표현식 평가 제한이 적용된다는 점에 유의하십시오 . 부록 D: 표현식 제한을 참조하십시오 .

변수 사용 및 표시
이제 홈페이지에 콘텐츠를 좀 더 추가해 보겠습니다. 예를 들어, 환영 메시지 아래에 다음과 같이 날짜를 표시하고 싶을 수 있습니다.

Welcome to our fantastic grocery store!

Today is: 12 july 2010
우선, 해당 날짜를 컨텍스트 변수로 추가하도록 컨트롤러를 수정해야 합니다.

public void process(
        final IWebExchange webExchange, 
        final ITemplateEngine templateEngine,
        final Writer writer)
        throws Exception {
        
    SimpleDateFormat dateFormat = new SimpleDateFormat("dd MMMM yyyy");
    Calendar cal = Calendar.getInstance();

    WebContext ctx = new WebContext(webExchange, webExchange.getLocale());
    ctx.setVariable("today", dateFormat.format(cal.getTime()));
    
    templateEngine.process("home", ctx, writer);

}
컨텍스트에 String라는 변수를 추가했으므로 이제 템플릿에서 해당 변수를 표시할 수 있습니다.today

<body>

  <p th:utext="#{home.welcome}">Welcome to our grocery store!</p>

  <p>Today is: <span th:text="${today}">13 February 2011</span></p>
  
</body>
보시다시피, 우리는 여전히 th:text작업에 속성을 사용하고 있습니다(태그 본문을 바꾸려는 목적이므로 이는 올바른 방법입니다). 하지만 이번에는 구문이 약간 다르고 #{...}표현식 값 대신 변수 표현식을 사용합니다 ${...}. 이 변수 ​​표현식 에는 OGNL(Object-Graph Navigation Language) 이라는 언어로 작성된 표현식이 포함되어 있으며, 이 표현식은 앞서 설명한 컨텍스트 변수 맵에서 실행됩니다.

이 ${today}표현은 간단히 "오늘이라는 변수를 가져오라"는 의미이지만, ${user.name}"user라는 변수를 가져와서 해당 getName()메서드를 호출하라"와 같이 더 복잡한 표현도 가능합니다.

속성 값에는 메시지, 변수 표현식 등 매우 다양한 가능성이 있습니다. 다음 장에서는 이러한 모든 가능성을 살펴보겠습니다.

4. 표준 표현식 구문
식료품 가상 매장 개발을 잠시 중단하고 Thymeleaf 표준 방언의 가장 중요한 부분 중 하나인 Thymeleaf 표준 표현 구문에 대해 알아보겠습니다.

우리는 이미 이 구문에서 표현되는 유효한 속성 값의 두 가지 유형, 즉 메시지 표현식과 변수 표현식을 살펴보았습니다.

<p th:utext="#{home.welcome}">Welcome to our grocery store!</p>

<p>Today is: <span th:text="${today}">13 february 2011</span></p>
하지만 표현식에는 더 많은 유형이 있으며, 우리가 이미 알고 있는 표현식에 대해서도 더 흥미로운 세부 사항들을 알아볼 수 있습니다. 먼저 표준 표현식의 특징을 간단히 요약해 보겠습니다.

간단한 표현:
변수 표현식:${...}
선택 변수 표현식:*{...}
메시지 표현:#{...}
링크 URL 표현식:@{...}
프래그먼트 표현식:~{...}
문자 그대로
텍스트 리터럴: 'one text', 'Another one!',…
숫자 리터럴: 0, 34, 3.0, 12.3,…
불리언 리터럴: true,false
널 리터럴:null
문자 그대로의 토큰: one, sometext, main,…
텍스트 작업:
문자열 연결:+
문자 그대로의 대체:|The name is ${name}|
산술 연산:
이항 연산자: +, -, *, /,%
마이너스 부호(단항 연산자):-
불리언 연산:
이항 연산자: and,or
불리언 부정(단항 연산자): !,not
비교와 평등:
비교 연산자: >, <, >=, <=( gt, lt, ge, le)
등호 연산자: ==, !=( eq, ne)
조건 연산자:
만약 그렇다면:(if) ? (then)
조건문(if-then-else):(if) ? (then) : (else)
기본:(value) ?: (defaultvalue)
특별 토큰:
무작업:_
이러한 모든 기능은 조합 및 중첩될 수 있습니다.

'User is of type ' + (${user.isAdmin()} ? 'Administrator' : (${user.type} ?: 'Unknown'))
4.1 메시지
이미 알고 있듯이, #{...}메시지 표현식을 사용하면 다음과 같이 연결할 수 있습니다.

<p th:utext="#{home.welcome}">Welcome to our grocery store!</p>
…이것에 대하여:

home.welcome=¡Bienvenido a nuestra tienda de comestibles!
하지만 아직 고려하지 못한 부분이 하나 있습니다. 메시지 내용이 완전히 고정되어 있지 않다면 어떻게 될까요? 예를 들어, 애플리케이션이 특정 시점에 사이트를 방문하는 사용자가 누구인지 알고 있고, 그 사용자의 이름으로 인사하고 싶다면 어떻게 해야 할까요?

<p>¡Bienvenido a nuestra tienda de comestibles, John Apricot!</p>
즉, 메시지에 매개변수를 추가해야 합니다. 예를 들어 다음과 같이요.

home.welcome=¡Bienvenido a nuestra tienda de comestibles, {0}!
매개변수는 표준 구문에 따라 지정되므로 패키지 java.text.MessageFormat내 클래스의 API 문서에 명시된 대로 숫자 및 날짜 형식으로 지정할 수 있습니다 java.text.*.

매개변수에 값을 지정하려면, HTTP 세션 속성이 주어졌을 때 다음과 같이 user할 수 있습니다.

<p th:utext="#{home.welcome(${session.user.name})}">
  Welcome to our grocery store, Sebastian Pepper!
</p>
여기서 `@`를 사용하면 th:utext형식화된 메시지가 이스케이프되지 않습니다. 이 예제는 `@`가 user.name이미 이스케이프되었다고 가정합니다.

여러 매개변수를 쉼표로 구분하여 지정할 수 있습니다.

메시지 키 자체는 변수에서 가져올 수 있습니다.

<p th:utext="#{${welcomeMsgKey}(${session.user.name})}">
  Welcome to our grocery store, Sebastian Pepper!
</p>
4.2 변수
앞서 언급했듯이 ${...}표현식은 실제로 컨텍스트에 포함된 변수 맵에서 실행되는 OGNL(Object-Graph Navigation Language) 표현식입니다.

OGNL 구문 및 기능에 대한 자세한 내용은 OGNL 언어 가이드를 참조하십시오.

Spring MVC를 사용하는 애플리케이션에서는 OGNL이 SpringEL 로 대체되지만 , 구문은 OGNL과 매우 유사합니다(실제로 대부분의 일반적인 경우에는 완전히 동일합니다).

OGNL의 구문에서 우리는 다음 표현식을 알 수 있습니다.

<p>Today is: <span th:text="${today}">13 february 2011</span>.</p>
…는 사실상 이것과 같습니다:

ctx.getVariable("today");
하지만 OGNL을 사용하면 훨씬 더 강력한 표현을 만들 수 있으며, 이것이 바로 그 예입니다.

<p th:utext="#{home.welcome(${session.user.name})}">
  Welcome to our grocery store, Sebastian Pepper!
</p>
…다음 명령을 실행하여 사용자 이름을 얻습니다.

((User) ctx.getVariable("session").get("user")).getName();
하지만 게터 메서드 탐색은 OGNL의 기능 중 하나일 뿐입니다. 다른 기능들을 더 살펴보겠습니다.

/*
 * Access to properties using the point (.). Equivalent to calling property getters.
 */
${person.father.name}

/*
 * Access to properties can also be made by using brackets ([]) and writing 
 * the name of the property as a variable or between single quotes.
 */
${person['father']['name']}

/*
 * If the object is a map, both dot and bracket syntax will be equivalent to 
 * executing a call on its get(...) method.
 */
${countriesByCode.ES}
${personsByName['Stephen Zucchini'].age}

/*
 * Indexed access to arrays or collections is also performed with brackets, 
 * writing the index without quotes.
 */
${personsArray[0].name}

/*
 * Methods can be called, even with arguments.
 */
${person.createCompleteName()}
${person.createCompleteNameWithSeparator('-')}
표현식 기본 객체
컨텍스트 변수에 대한 OGNL 표현식을 평가할 때, 더 높은 유연성을 위해 일부 객체가 표현식에서 사용 가능하게 됩니다. 이러한 객체는 (OGNL 표준에 따라) 다음 #기호로 시작하여 참조됩니다.

#ctx컨텍스트 객체입니다.
#vars:컨텍스트 변수.
#locale컨텍스트 로케일.
그래서 우리는 이렇게 할 수 있습니다:

Established locale country: <span th:text="${#locale.country}">US</span>.
이러한 개체에 대한 전체 참조 정보는 부록 A 에서 확인할 수 있습니다 .

표현식 유틸리티 객체
이러한 기본 객체 외에도 Thymeleaf는 표현식에서 일반적인 작업을 수행하는 데 도움이 되는 유틸리티 객체 세트를 제공합니다.

#execInfo처리 중인 템플릿에 대한 정보입니다.
#messages변수 표현식 내에서 외부화된 메시지를 얻는 방법으로, #{…} 구문을 사용하는 것과 동일한 방식으로 얻을 수 있습니다.
#urisURL/URI의 일부를 이스케이프 처리하는 방법
#conversions구성된 변환 서비스를 실행하기 위한 메서드 (있는 경우).
#dates객체 에 대한 메서드 java.util.Date: 서식 지정, 구성 요소 추출 등
#calendars: 와 유사 #dates하지만, java.util.Calendar사물에 적용됩니다.
#temporalsjava.timeJDK8 이상에서 API를 사용하여 날짜와 시간을 처리하기 위한 것입니다 .
#numbers숫자 객체의 형식을 지정하는 메서드입니다.
#strings객체 에 대한 메서드 String: contains, startsWith, prepending/appending 등
#objects객체에 대한 일반적인 메서드입니다.
#bools: 불리언 평가를 위한 메서드.
#arrays배열에 대한 메서드입니다.
#lists리스트 관련 메서드입니다.
#sets집합에 대한 메서드입니다.
#maps지도에 대한 메서드입니다.
#aggregates배열 또는 컬렉션에 대한 집계를 생성하는 메서드입니다.
#ids반복 작업의 결과로 발생할 수 있는 중복된 ID 속성을 처리하는 메서드입니다.
각 유틸리티 객체가 제공하는 기능은 부록 B 에서 확인할 수 있습니다 .

홈페이지의 날짜 형식을 변경합니다
이제 이러한 유틸리티 객체에 대해 알았으니, 이를 사용하여 홈페이지에 날짜를 표시하는 방식을 변경할 수 있습니다. 다음과 같이 하는 대신에 HomeController:

SimpleDateFormat dateFormat = new SimpleDateFormat("dd MMMM yyyy");
Calendar cal = Calendar.getInstance();

WebContext ctx = new WebContext(webExchange, webExchange.getLocale());
ctx.setVariable("today", dateFormat.format(cal.getTime()));

templateEngine.process("home", ctx, writer);
…우리는 바로 이렇게 할 수 있습니다:

WebContext ctx = new WebContext(webExchange, webExchange.getLocale());
ctx.setVariable("today", Calendar.getInstance());

templateEngine.process("home", ctx, writer);
…그런 다음 뷰 레이어 자체에서 날짜 형식을 지정합니다.

<p>
  Today is: <span th:text="${#calendars.format(today,'dd MMMM yyyy')}">13 May 2011</span>
</p>
4.3 선택 항목에 대한 표현식(별표 구문)
${...}변수 표현식은 뿐만 아니라 로도 작성할 수 있습니다 *{...}.

하지만 중요한 차이점이 있습니다. 별표 구문은 전체 컨텍스트가 아닌 선택된 객체 에 대해 표현식을 평가합니다 . 즉, 선택된 객체가 없는 경우에는 달러 기호 구문과 별표 구문이 완전히 동일하게 작동합니다.

그렇다면 선택된 객체란 무엇일까요? 속성을 사용한 표현식의 결과입니다 . 사용자 프로필( ) 페이지 th:object에서 하나를 사용해 보겠습니다 .userprofile.html

  <div th:object="${session.user}">
    <p>Name: <span th:text="*{firstName}">Sebastian</span>.</p>
    <p>Surname: <span th:text="*{lastName}">Pepper</span>.</p>
    <p>Nationality: <span th:text="*{nationality}">Saturn</span>.</p>
  </div>
이는 정확히 다음과 같습니다.

<div>
  <p>Name: <span th:text="${session.user.firstName}">Sebastian</span>.</p>
  <p>Surname: <span th:text="${session.user.lastName}">Pepper</span>.</p>
  <p>Nationality: <span th:text="${session.user.nationality}">Saturn</span>.</p>
</div>
물론 달러 기호와 별표 기호를 혼합하여 사용할 수 있습니다.

<div th:object="${session.user}">
  <p>Name: <span th:text="*{firstName}">Sebastian</span>.</p>
  <p>Surname: <span th:text="${session.user.lastName}">Pepper</span>.</p>
  <p>Nationality: <span th:text="*{nationality}">Saturn</span>.</p>
</div>
객체 선택이 완료되면 선택된 객체는 달러 표현식에서 #object표현식 변수로도 사용할 수 있습니다.

<div th:object="${session.user}">
  <p>Name: <span th:text="${#object.firstName}">Sebastian</span>.</p>
  <p>Surname: <span th:text="${session.user.lastName}">Pepper</span>.</p>
  <p>Nationality: <span th:text="*{nationality}">Saturn</span>.</p>
</div>
앞서 언급했듯이 객체 선택이 수행되지 않은 경우 달러 기호와 별표 기호는 동일한 의미를 가집니다.

<div>
  <p>Name: <span th:text="*{session.user.name}">Sebastian</span>.</p>
  <p>Surname: <span th:text="*{session.user.surname}">Pepper</span>.</p>
  <p>Nationality: <span th:text="*{session.user.nationality}">Saturn</span>.</p>
</div>
4.4 링크 URL
URL은 그 중요성 때문에 웹 애플리케이션 템플릿에서 핵심적인 요소이며, Thymeleaf 표준 방언은 URL에 대한 특별한 구문을 제공합니다 @. 그 구문은 다음과 같습니다.@{...}

URL에는 여러 종류가 있습니다.

절대 URL:http://www.thymeleaf.org
상대 URL은 다음과 같은 형태를 가질 수 있습니다.
페이지 상대적:user/login.html
컨텍스트 상대적: /itemdetails?id=3(서버의 컨텍스트 이름이 자동으로 추가됩니다)
서버 상대 경로: ~/billing/processInvoice(동일한 서버 내의 다른 컨텍스트(= 애플리케이션)에서 URL을 호출할 수 있도록 합니다.)
프로토콜 상대 URL://code.jquery.com/jquery-2.0.3.min.js
이러한 표현식을 실제로 처리하고 출력될 URL로 변환하는 작업은 사용 중인 객체 org.thymeleaf.linkbuilder.ILinkBuilder에 등록된 인터페이스 구현체에 의해 수행됩니다.ITemplateEngine

기본적으로 이 인터페이스의 구현체 하나만 클래스에 등록되며 org.thymeleaf.linkbuilder.StandardLinkBuilder, 이는 오프라인(비웹) 시나리오와 서블릿 API 기반 웹 시나리오 모두에 충분합니다. 다른 시나리오(예: 서블릿 API를 사용하지 않는 웹 프레임워크와의 통합)에서는 링크 빌더 인터페이스의 특정 구현체가 필요할 수 있습니다.

이 새로운 구문을 사용해 봅시다. th:href속성을 소개합니다.

<!-- Will produce 'http://localhost:8080/gtvg/order/details?orderId=3' (plus rewriting) -->
<a href="details.html" 
   th:href="@{http://localhost:8080/gtvg/order/details(orderId=${o.id})}">view</a>

<!-- Will produce '/gtvg/order/details?orderId=3' (plus rewriting) -->
<a href="details.html" th:href="@{/order/details(orderId=${o.id})}">view</a>

<!-- Will produce '/gtvg/order/3/details' (plus rewriting) -->
<a href="details.html" th:href="@{/order/{orderId}/details(orderId=${o.id})}">view</a>
여기서 몇 가지 유의할 점이 있습니다.

th:href이는 수정자 속성입니다. 처리가 완료되면 사용할 링크 URL을 계산하고 해당 값을 태그 href의 속성 에 설정합니다 <a>.
URL 매개변수에 표현식을 사용할 수 있습니다(아래 참조 orderId=${o.id}). 필요한 URL 매개변수 인코딩 작업도 자동으로 수행됩니다.
여러 매개변수가 필요한 경우 쉼표로 구분합니다.@{/order/process(execId=${execId},execType='FAST')}
URL 경로에서 변수 템플릿도 허용됩니다.@{/order/{orderId}/details(orderId=${orderId})}
/(예: ) 로 시작하는 상대 URL에는 /order/details애플리케이션 컨텍스트 이름이 자동으로 접두사로 붙습니다.
쿠키가 활성화되어 있지 않거나 활성화 여부를 알 수 없는 경우, ";jsessionid=..."세션을 유지하기 위해 상대 URL에 접미사가 추가될 수 있습니다. 이를 URL 재작성 이라고 하며 , Thymeleaf는 서블릿 API의 메커니즘을 사용하여 모든 URL에 대해 자체 재작성 필터를 적용할 수 있도록 지원합니다 response.encodeURL(...).
이 th:href속성을 사용하면 템플릿에 (선택적으로) 작동하는 정적 속성을 가질 수 있으므로 href프로토타이핑 목적으로 브라우저를 직접 열었을 때 템플릿 링크를 계속 탐색할 수 있습니다.
메시지 구문( )의 경우와 마찬가지로 #{...}URL 기본 주소도 다른 표현식을 평가한 결과일 수 있습니다.

<a th:href="@{${url}(orderId=${o.id})}">view</a>
<a th:href="@{'/details/'+${user.login}(orderId=${o.id})}">view</a>

서버 루트 상대 URL
동일한 서버 내의 서로 다른 컨텍스트에 연결하기 위해 컨텍스트 루트 상대 URL 대신 서버 루트 상대 URL을 생성하는 추가 구문을 사용할 수 있습니다. 이러한 URL은 다음과 같이 지정됩니다.@{~/path/to/something}

4.5 조각
프래그먼트 표현식은 마크업 조각을 표현하고 템플릿 간에 이동하는 쉬운 방법입니다. 이를 통해 프래그먼트를 복제하거나 다른 템플릿에 인수로 전달하는 등의 작업을 수행할 수 있습니다.

가장 일반적인 용도는 th:insert또는 를 사용하여 조각을 삽입하는 것입니다 th:replace(이에 대한 자세한 내용은 뒷부분에서 설명합니다).

<div th:insert="~{commons :: main}">...</div>
하지만 다른 변수들과 마찬가지로 어디에서든 사용할 수 있습니다.

<div th:with="frag=~{footer :: #main/text()}">
  <p th:insert="${frag}">
</div>
이 튜토리얼의 뒷부분에는 템플릿 레이아웃에 대한 전체 섹션이 있으며, 여기에는 프래그먼트 표현식에 대한 더 자세한 설명이 포함됩니다.

4.6 문자 그대로
텍스트 리터럴
텍스트 리터럴은 작은따옴표로 묶인 문자열입니다. 어떤 문자든 포함할 수 있지만, 작은따옴표 안에 있는 문자는 반드시 이스케이프해야 합니다 \'.

<p>
  Now you are looking at a <span th:text="'working web application'">template file</span>.
</p>
숫자 리터럴
숫자 리터럴은 말 그대로 숫자입니다.

<p>The year is <span th:text="2013">1492</span>.</p>
<p>In two years, it will be <span th:text="2013 + 2">1494</span>.</p>
불리언 리터럴
불리언 리터럴은 ` trueand`와 `and` 입니다 false. 예를 들면 다음과 같습니다.

<div th:if="${user.isAdmin()} == false"> ...
이 예시에서는 == false중괄호 밖에 작성되어 있으므로 Thymeleaf가 이를 처리합니다. 만약 중괄호 안에 작성되었다면 OGNL/SpringEL 엔진이 이를 처리하게 됩니다.

<div th:if="${user.isAdmin() == false}"> ...
널 리터럴
문자 null그대로의 표현도 사용할 수 있습니다.

<div th:if="${variable.something} == null"> ...
문자 그대로의 토큰
숫자, 부울 및 null 리터럴은 실제로 리터럴 토큰 의 특정 사례입니다 .

이 토큰들은 표준 표현식을 약간 간소화해줍니다. 텍스트 리터럴( )과 정확히 똑같이 작동 하지만, 문자( 및 ), 숫자( ), 대괄호( 및 ), 마침표( ), 하이픈 ( ) 및 밑줄( ) '...'만 사용할 수 있습니다 . 따라서 공백이나 쉼표 등은 사용할 수 없습니다.A-Za-z0-9[].-_

좋은 점은 무엇일까요? 토큰은 따옴표로 묶을 필요가 없다는 것입니다. 따라서 다음과 같이 할 수 있습니다.

<div th:class="content">...</div>
대신:

<div th:class="'content'">...</div>
4.7 텍스트 추가
텍스트는 리터럴이든 변수 또는 메시지 표현식을 평가한 결과이든 관계없이 +연산자를 사용하여 쉽게 추가할 수 있습니다.

<span th:text="'The name of the user is ' + ${user.name}">
4.8 문자적 대체
리터럴 치환을 사용하면 리터럴 뒤에 마침표(.)를 붙이지 않고도 변수 값을 포함하는 문자열의 형식을 쉽게 지정할 수 있습니다 '...' + '...'.

|이러한 대체어는 세로 막대( ) 로 둘러싸여 있어야 합니다 . 예:

<span th:text="|Welcome to our application, ${user.name}!|">
이는 다음과 같습니다.

<span th:text="'Welcome to our application, ' + ${user.name} + '!'">
문자 그대로의 대체는 다른 유형의 표현과 결합될 수 있습니다.

<span th:text="${onevar} + ' ' + |${twovar}, ${threevar}|">
리터럴 치환 내부에는 변수/메시지 표현식( ${...}, *{...}, #{...})만 허용됩니다 |...|. 다른 리터럴( '...'), 부울/숫자 토큰, 조건식 등은 허용되지 않습니다.

4.9 산술 연산
또한 다음과 같은 몇 가지 산술 연산을 사용할 수 있습니다: +, -, *, /및 %.

<div th:with="isEven=(${prodStat.count} % 2 == 0)">
참고로, 이러한 연산자는 OGNL 변수 표현식 자체 내에서도 적용될 수 있으며, 이 경우 Thymeleaf 표준 표현식 엔진 대신 OGNL에서 실행됩니다.

<div th:with="isEven=${prodStat.count % 2 == 0}">
참고로 이러한 연산자 중 일부에는 텍스트 별칭이 존재합니다: div( /), mod( %).

4.10 비교급과 등호
>표현식의 값은 , <, >=및 기호를 사용하여 비교할 수 있으며 <=, 및 ==연산자 !=를 사용하여 같음(또는 같지 않음)을 확인할 수 있습니다. XML에서는 <및 기호를 속성 값에 사용해서는 안 되므로 및 >로 대체해야 합니다 .&lt;&gt;

<div th:if="${prodStat.count} &gt; 1">
<span th:text="'Execution mode is ' + ( (${execMode} == 'dev')? 'Development' : 'Production')">
더 간단한 대안은 이러한 연산자 중 일부에 대해 존재하는 텍스트 별칭을 사용하는 것입니다: gt( >), lt( <), ge( >=), le( <=), not( !). 또한 eq( ==), neq/ ne( !=).

4.11 조건식
조건식은 조건(그 자체로 또 다른 표현식임)을 평가한 결과에 따라 두 표현식 중 하나만 평가하도록 설계되었습니다.

또 다른 속성 수정자 ( , th:class) 를 도입한 예시 코드를 살펴보겠습니다 .

<tr th:class="${row.even}? 'even' : 'odd'">
  ...
</tr>
조건식의 세 부분( condition, then및 else)은 모두 그 자체로 표현식입니다. 즉, 변수( ${...}, *{...}), 메시지( #{...}), URL( @{...}) 또는 리터럴( '...')이 될 수 있습니다.

조건식은 괄호를 사용하여 중첩할 수도 있습니다.

<tr th:class="${row.even}? (${row.first}? 'first' : 'even') : 'odd'">
  ...
</tr>
else 절은 생략할 수도 있으며, 이 경우 조건이 거짓이면 null 값이 반환됩니다.

<tr th:class="${row.even}? 'alt'">
  ...
</tr>
4.12 기본 표현식(엘비스 연산자)
기본 표현식은 then 부분 이 없는 특별한 종류의 조건부 값입니다 . 이는 Groovy와 같은 일부 언어에 있는 엘비스 연산자 와 유사 하며, 두 개의 표현식을 지정할 수 있습니다. 첫 번째 표현식은 null이 아니면 사용되고, null이면 두 번째 표현식이 사용됩니다.

사용자 프로필 페이지에서 실제로 어떻게 작동하는지 살펴보겠습니다.

<div th:object="${session.user}">
  ...
  <p>Age: <span th:text="*{age}?: '(no age specified)'">27</span>.</p>
</div>
보시다시피, 연산자는 `null` ?:이며, 여기서는 평가 결과가 `null`인 경우에만 이름(이 경우 리터럴 값)에 대한 기본값을 지정하는 데 사용합니다 *{age}. 따라서 이는 다음과 같습니다.

<p>Age: <span th:text="*{age != null}? *{age} : '(no age specified)'">27</span>.</p>
조건부 값과 마찬가지로 괄호 안에 중첩된 표현식을 포함할 수 있습니다.

<p>
  Name: 
  <span th:text="*{firstName}?: (*{admin}? 'Admin' : #{default.username})">Sebastian</span>
</p>
4.13 무작업 토큰
아무 작업도 수행하지 않음을 나타내는 토큰은 밑줄 기호( _)로 표시됩니다.

이 토큰의 기본 아이디어는 표현식에 대해 원하는 결과가 아무것도 하지 않는 것 , 즉 처리 가능한 속성(예:  th:text)이 전혀 없는 것처럼 정확히 동작하는 것임을 지정하는 것입니다.

다른 가능성 중 하나로, 이를 통해 개발자는 프로토타입 텍스트를 기본값으로 사용할 수 있습니다. 예를 들어 다음과 같이 사용하는 대신:

<span th:text="${user.name} ?: 'no user authenticated'">...</span>
… ‘사용자 인증 안 됨’을 프로토타이핑 텍스트로 직접 사용할 수 있으므로 디자인 관점에서 더 간결하고 다용도로 활용할 수 있는 코드를 얻을 수 있습니다.

<span th:text="${user.name} ?: _">no user authenticated</span>
4.14 데이터 변환/형식 지정
Thymeleaf는 변수( ) 및 선택( ) 표현식에 대해 이중 중괄호 구문을 정의하여 구성된 변환 서비스를 통해 데이터 변환을 적용할 수 있도록 합니다 .${...}*{...}

기본적으로는 다음과 같습니다.

<td th:text="${{user.lastAccessDate}}">...</td>
저기 있는 이중 중괄호(:)를 보셨나요? ${{...}}이것은 Thymeleaf에게 표현식의 결과를 변환 서비스user.lastAccessDate 에 전달하고 결과를 쓰기 전에 서식 지정 작업 (예: 로의 변환 ) 을 수행하도록 지시합니다 .String

user.lastAccessDate해당 타입이 라고 가정할 때 java.util.Calendar, 변환 서비스 ( 의 구현체 IStandardConversionService)가 등록되어 있고 에 대한 유효한 변환을 포함하고 있다면 Calendar -> String해당 변환이 적용됩니다.

IStandardConversionService(해당 StandardConversionService클래스의) 기본 구현은 .toString()변환된 모든 객체에 대해 실행됩니다. 사용자 지정 변환 서비스String 구현을 등록하는 방법에 대한 자세한 내용은 구성에 대한 추가 정보 를 참조하세요 .

공식 thymeleaf-spring3 및 thymeleaf-spring4 통합 패키지는 Thymeleaf의 변환 서비스 메커니즘을 Spring 자체의 변환 서비스 인프라와 투명하게 통합하여 Spring 설정에 선언된 변환 서비스 및 포맷터를 표현식에서 자동으로 사용할 수 있도록 ${{...}}합니다 *{{...}}.

4.15 전처리
Thymeleaf는 표현식 처리를 위한 이러한 모든 기능 외에도 표현식을 전처리하는 기능을 제공합니다 .

전처리란 일반적인 표현식 실행 전에 수행되는 단계로, 최종적으로 실행될 표현식을 수정할 수 있도록 합니다.

전처리된 표현식은 일반 표현식과 완전히 동일하지만 이중 밑줄 기호(예: __${expression}__)로 둘러싸여 나타납니다.

Messages_fr.properties언어별 정적 메서드를 호출하는 OGNL 표현식을 포함하는 i18n 항목이 있다고 가정해 보겠습니다. 예를 들면 다음과 같습니다.

article.text=@myapp.translator.Translator@translateToFrench({0})
…그리고 a Messages_es.properties equivalent:

article.text=@myapp.translator.Translator@translateToSpanish({0})
로케일에 따라 하나의 표현식 또는 다른 표현식을 평가하는 마크업 조각을 만들 수 있습니다. 이를 위해 먼저 전처리를 통해 표현식을 선택한 다음 Thymeleaf가 실행하도록 합니다.

<p th:text="${__#{article.text('textVar')}__}">Some text here...</p>
참고로 프랑스어 로케일에 대한 전처리 단계에서는 다음과 같은 결과가 생성됩니다.

<p th:text="${@myapp.translator.Translator@translateToFrench(textVar)}">Some text here...</p>
전처리 문자열은 __속성에서 .을 사용하여 이스케이프 처리할 수 있습니다 \_\_.

보안상의 이유로 전처리에는 더욱 엄격한 표현식 평가 제한이 적용됩니다. 부록 D: 표현식 제한을 참조하십시오 .

5. 속성 값 설정
이 장에서는 마크업에서 속성 값을 설정(또는 수정)하는 방법을 설명합니다.

5.1 속성 값 설정
/WEB-INF/templates/subscribe.html우리 웹사이트에서 뉴스레터를 발행하고 사용자들이 구독할 수 있도록 하고 싶다고 가정해 봅시다. 그래서 구독 양식이 포함된 템플릿을 만듭니다 .

<form action="subscribe.html">
  <fieldset>
    <input type="text" name="email" />
    <input type="submit" value="Subscribe!" />
  </fieldset>
</form>
Thymeleaf와 마찬가지로, 이 템플릿은 웹 애플리케이션 템플릿이라기보다는 정적 프로토타입에 더 가깝습니다. 첫째, action폼의 속성이 템플릿 파일 자체에 정적으로 연결되어 있어 유용한 URL 재작성을 위한 공간이 없습니다. 둘째, value제출 버튼의 속성으로 인해 텍스트가 영어로 표시되지만, 우리는 이를 국제화하고 싶습니다.

그다음 th:attr속성을 입력하고, 해당 속성이 설정된 태그의 속성 값을 변경할 수 있는 기능을 설명합니다.

<form action="subscribe.html" th:attr="action=@{/subscribe}">
  <fieldset>
    <input type="text" name="email" />
    <input type="submit" value="Subscribe!" th:attr="value=#{subscribe.submit}"/>
  </fieldset>
</form>
개념은 매우 간단합니다. th:attr속성에 값을 할당하는 표현식을 사용하면 됩니다. 해당 컨트롤러 및 메시지 파일을 생성한 후 이 파일을 처리하면 다음과 같은 결과가 나타납니다.

<form action="/gtvg/subscribe">
  <fieldset>
    <input type="text" name="email" />
    <input type="submit" value="¡Suscríbe!"/>
  </fieldset>
</form>
/gtvg/subscribe새로운 속성 값 외에도 이전 장에서 설명했듯이 애플리케이션 컨텍스트 이름이 URL 기본 주소 앞에 자동으로 접두사로 추가된 것을 확인할 수 있습니다 .

하지만 한 번에 여러 속성을 설정하고 싶다면 어떻게 해야 할까요? XML 규칙에 따르면 태그 내에서 동일한 속성을 두 번 설정할 수 없으므로 다음 th:attr과 같이 쉼표로 구분된 속성 목록을 사용해야 합니다.

<img src="../../images/gtvglogo.png" 
     th:attr="src=@{/images/gtvglogo.png},title=#{logo},alt=#{logo}" />
필요한 메시지 파일이 주어지면 다음과 같은 결과가 출력됩니다.

<img src="/gtgv/images/gtvglogo.png" title="Logo de Good Thymes" alt="Logo de Good Thymes" />
5.2 특정 속성에 값 설정
지금쯤이면 아마 이런 생각을 하고 계실지도 모르겠습니다.

<input type="submit" value="Subscribe!" th:attr="value=#{subscribe.submit}"/>
…는 상당히 보기 흉한 마크업입니다. 속성 값 안에 할당을 지정하는 것은 매우 실용적일 수 있지만, 매번 이렇게 해야 한다면 템플릿을 만드는 가장 우아한 방법은 아닙니다.

Thymeleaf도 당신의 의견에 동의하며, 그렇기 때문에 th:attr템플릿에서 해당 속성은 거의 사용되지 않습니다. 일반적으로는 특정 태그 속성을 설정하는 다른 속성들을 사용하게 될 것입니다 th:*(단순히 아무 속성이나 설정하는 것이 아니라요 th:attr).

예를 들어 속성을 설정하려면 value다음을 사용하세요 th:value.

<input type="submit" value="Subscribe!" th:value="#{subscribe.submit}"/>
action훨씬 좋아 보이네요! 이제 태그 의 속성 에도 똑같이 적용해 봅시다 form.

<form action="subscribe.html" th:action="@{/subscribe}">
th:href그리고 이전 에 언급했던 내용들을 기억하시나요 home.html? 바로 이런 종류의 속성들입니다.

<li><a href="product/list.html" th:href="@{/product/list}">Product List</a></li>

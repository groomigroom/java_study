public void init(final FilterConfig filterConfig) throws ServletException {
    this.application =
            JakartaServletWebApplication.buildApplication(
                filterConfig.getServletContext());
    // We will see later how the TemplateEngine object is built and configured
    this.templateEngine = buildTemplateEngine(this.application);

/*
 * Each request will be processed by creating an exchange object (modeling
 * the request, its response and all the data needed for this process) and
 * then calling the corresponding controller.
 */
private boolean process(HttpServletRequest request, HttpServletResponse response)
        throws ServletException {
    
    try {

        final IWebExchange webExchange = 
            this.application.buildExchange(request, response);
        final IWebRequest webRequest = webExchange.getRequest();

        // This prevents triggering engine executions for resource URLs
        if (request.getRequestURI().startsWith("/css") ||
                request.getRequestURI().startsWith("/images") ||
                request.getRequestURI().startsWith("/favicon")) {
            return false;
        }
        
        /*
         * Query controller/URL mapping and obtain the controller
         * that will process the request. If no controller is available,
         * return false and let other filters/servlets process the request.
         */
        final IGTVGController controller = 
            ControllerMappings.resolveControllerForRequest(webRequest);
        if (controller == null) {
            return false;
        }

        /*
         * Write the response headers
         */
        response.setContentType("text/html;charset=UTF-8");
        response.setHeader("Pragma", "no-cache");
        response.setHeader("Cache-Control", "no-cache");
        response.setDateHeader("Expires", 0);

        /*
         * Obtain the response writer
         */
        final Writer writer = response.getWriter();

        /*
         * Execute the controller and process view template,
         * writing the results to the response writer. 
         */
        controller.process(webExchange, this.templateEngine, writer);
        
        return true;
        
    } catch (Exception e) {
        try {
            response.sendError(HttpServletResponse.SC_INTERNAL_SERVER_ERROR);
        } catch (final IOException ignored) {
            // Just ignore this
        }
        throw new ServletException(e);
    }
    
}

private static ITemplateEngine buildTemplateEngine(final IWebApplication application) {

    // Templates will be resolved as application (ServletContext) resources
    final WebApplicationTemplateResolver templateResolver = 
            new WebApplicationTemplateResolver(application);

    // HTML is the default mode, but we will set it anyway for better understanding of code
    templateResolver.setTemplateMode(TemplateMode.HTML);
    // This will convert "home" to "/WEB-INF/templates/home.html"
    templateResolver.setPrefix("/WEB-INF/templates/");
    templateResolver.setSuffix(".html");
    // Set template cache TTL to 1 hour. If not set, entries would live in cache until expelled by FIFO
    templateResolver.setCacheTTLMs(Long.valueOf(3600000L));

    // Cache is set to true by default. Set to false if you want templates to
    // be automatically updated when modified.
    templateResolver.setCacheable(true);

    final TemplateEngine templateEngine = new TemplateEngine();
    templateEngine.setTemplateResolver(templateResolver);

    return templateEngine;

}

3.1 다국어 환영 인사
우리의 첫 번째 과제는 식료품점 웹사이트의 홈페이지를 만드는 것입니다.

이 페이지의 첫 번째 버전은 매우 간단합니다. 제목과 환영 메시지만 있을 것입니다. /WEB-INF/templates/home.html파일은 다음과 같습니다.

<!DOCTYPE html>

<html xmlns:th="http://www.thymeleaf.org">

  <head>
    <title>Good Thymes Virtual Grocery</title>
    <meta http-equiv="Content-Type" content="text/html; charset=UTF-8" />
    <link rel="stylesheet" type="text/css" media="all" 
          href="../../css/gtvg.css" th:href="@{/css/gtvg.css}" />
  </head>

  <body>
  
    <p th:text="#{home.welcome}">Welcome to our grocery store!</p>
  
  </body>

</html>
가장 먼저 눈에 띄는 것은 이 파일이 HTML5 형식이라는 점입니다. 이 파일에는 HTML 이외의 태그가 포함되어 있지 않기 때문에 모든 브라우저에서 올바르게 표시됩니다(브라우저는 이해하지 못하는 모든 속성(예: <script>)을 무시합니다 th:text).

하지만 이 템플릿이 HTML5 사양에서 허용되지 않는 비표준 속성을 사용하고 있기 때문에 유효한 HTML5 문서가 아니라는 점도 알아두시면 좋을 것입니다 th:*. 실제로, 우리는 태그 xmlns:th에 <html>HTML5와는 전혀 맞지 않는 속성을 추가하고 있습니다.

<html xmlns:th="http://www.thymeleaf.org">
…이는 템플릿 처리에는 전혀 영향을 미치지 않지만, IDE가 해당 속성들에 대한 네임스페이스 정의가 없다는 오류를 표시하지 않도록 하는 일종의 주문th:* 과 같은 역할을 합니다 .

그렇다면 이 템플릿을 HTML5 유효성 검사를 통과하도록 만들려면 어떻게 해야 할까요 ? 간단합니다. Thymeleaf의 데이터 속성 구문으로 바꾸고, data-속성 이름에 접두사를 사용하고, -세미콜론(;) 대신 하이픈(- :)을 구분자로 사용하면 됩니다.

<!DOCTYPE html>

<html>

  <head>
    <title>Good Thymes Virtual Grocery</title>
    <meta http-equiv="Content-Type" content="text/html; charset=UTF-8" />
    <link rel="stylesheet" type="text/css" media="all" 
          href="../../css/gtvg.css" data-th-href="@{/css/gtvg.css}" />
  </head>

  <body>
  
    <p data-th-text="#{home.welcome}">Welcome to our grocery store!</p>
  
  </body>

</html>
HTML5 사양에서는 사용자 지정 접두사가 붙은 속성을 허용하므로 위 코드를 사용하면 템플릿이 유효한 HTML5 문서가data- 됩니다 .

두 표기법은 완전히 동일하며 상호 교환 가능하지만, 코드 예제의 간결성을 위해 이 튜토리얼에서는 네임스페이스 표기법 ( th:*)을 사용합니다. 또한, 네임스페이스 th:*표기법은 더 일반적이며 모든 Thymeleaf 템플릿 모드( XML, TEXT…)에서 사용할 수 있는 반면, 네임 data-스페이스 표기법은 특정 모드에서만 사용할 수 있습니다 HTML.

th:text 사용 및 텍스트 외부화
텍스트 외부화란 템플릿 파일에서 템플릿 코드 조각을 추출하여 별도의 파일(일반적으로 여러 개의 .properties파일)에 저장하고, 다른 언어로 작성된 동등한 텍스트로 쉽게 대체할 수 있도록 하는 과정입니다(이 과정을 국제화 또는 간단히 i18n 이라고 합니다 ). 외부화된 텍스트 조각은 일반적으로 "메시지" 라고 합니다 .

메시지에는 항상 메시지를 식별하는 키가 있으며, Thymeleaf에서는 다음 구문을 사용하여 텍스트가 특정 메시지에 대응하도록 지정할 수 있습니다 #{...}.

<p th:text="#{home.welcome}">Welcome to our grocery store!</p>
여기서 우리가 볼 수 있는 것은 실제로 타임리프 표준 방언의 두 가지 서로 다른 특징입니다.

이 th:text속성은 값 표현식을 평가하고 그 결과를 호스트 태그의 본문으로 설정하여 코드에서 볼 수 있는 "저희 식료품점에 오신 것을 환영합니다!" 텍스트를 효과적으로 대체합니다.
표준 표현식 구문#{home.welcome} 에 지정된 이 표현식은 속성 에 사용할 텍스트가 템플릿을 처리하는 로케일에 해당하는 키를 가진 메시지여야 함을 지시합니다.th:texthome.welcome

Thymeleaf에서 외부화된 텍스트의 위치는 완전히 구성 가능하며, org.thymeleaf.messageresolver.IMessageResolver사용되는 특정 구현에 따라 달라집니다. 일반적으로 .properties파일 기반 구현이 사용되지만, 예를 들어 데이터베이스에서 메시지를 가져오는 등 원하는 경우 자체 구현을 만들 수도 있습니다.

하지만 초기화 과정에서 템플릿 엔진에 대한 메시지 리졸버를 지정하지 않았으므로, 애플리케이션은 에서 구현한 표준 메시지 리졸버를org.thymeleaf.messageresolver.StandardMessageResolver 사용하고 있습니다 .

3.2 텍스트 및 변수에 대한 추가 설명
이스케이프되지 않은 텍스트
홈페이지의 가장 기본적인 버전은 이제 완성된 것 같지만, 한 가지 미처 생각하지 못한 부분이 있습니다… 만약 이런 메시지를 넣는다면 어떨까요?

home.welcome=Welcome to our <b>fantastic</b> grocery store!
이 템플릿을 이전처럼 실행하면 다음과 같은 결과를 얻습니다.

<p>Welcome to our &lt;b&gt;fantastic&lt;/b&gt; grocery store!</p>
이는 우리가 예상했던 것과는 다릅니다. <b>태그가 이스케이프 처리되었기 때문에 브라우저에 그대로 표시될 것입니다.

이는 해당 속성의 기본 동작입니다 . Thymeleaf가 HTML 태그를 이스케이프하지 않고 그대로 유지하도록 하려면 다른 속성 ("이스케이프되지 않은 텍스트"를 의미) th:text을 사용해야 합니다 .th:utext

<p th:utext="#{home.welcome}">Welcome to our grocery store!</p>
이렇게 하면 우리가 원했던 대로 메시지가 출력됩니다.

<p>Welcome to our <b>fantastic</b> grocery store!</p>
th:utext보안상의 이유로 더 엄격한 표현식 평가 제한이 적용된다는 점에 유의하십시오 . 부록 D: 표현식 제한을 참조하십시오 .

변수 사용 및 표시
이제 홈페이지에 콘텐츠를 좀 더 추가해 보겠습니다. 예를 들어, 환영 메시지 아래에 다음과 같이 날짜를 표시하고 싶을 수 있습니다.

Welcome to our fantastic grocery store!

Today is: 12 july 2010
우선, 해당 날짜를 컨텍스트 변수로 추가하도록 컨트롤러를 수정해야 합니다.

public void process(
        final IWebExchange webExchange, 
        final ITemplateEngine templateEngine,
        final Writer writer)
        throws Exception {
        
    SimpleDateFormat dateFormat = new SimpleDateFormat("dd MMMM yyyy");
    Calendar cal = Calendar.getInstance();

    WebContext ctx = new WebContext(webExchange, webExchange.getLocale());
    ctx.setVariable("today", dateFormat.format(cal.getTime()));
    
    templateEngine.process("home", ctx, writer);

}
컨텍스트에 String라는 변수를 추가했으므로 이제 템플릿에서 해당 변수를 표시할 수 있습니다.today

<body>

  <p th:utext="#{home.welcome}">Welcome to our grocery store!</p>

  <p>Today is: <span th:text="${today}">13 February 2011</span></p>
  
</body>
보시다시피, 우리는 여전히 th:text작업에 속성을 사용하고 있습니다(태그 본문을 바꾸려는 목적이므로 이는 올바른 방법입니다). 하지만 이번에는 구문이 약간 다르고 #{...}표현식 값 대신 변수 표현식을 사용합니다 ${...}. 이 변수 ​​표현식 에는 OGNL(Object-Graph Navigation Language) 이라는 언어로 작성된 표현식이 포함되어 있으며, 이 표현식은 앞서 설명한 컨텍스트 변수 맵에서 실행됩니다.

이 ${today}표현은 간단히 "오늘이라는 변수를 가져오라"는 의미이지만, ${user.name}"user라는 변수를 가져와서 해당 getName()메서드를 호출하라"와 같이 더 복잡한 표현도 가능합니다.

속성 값에는 메시지, 변수 표현식 등 매우 다양한 가능성이 있습니다. 다음 장에서는 이러한 모든 가능성을 살펴보겠습니다.

4. 표준 표현식 구문
식료품 가상 매장 개발을 잠시 중단하고 Thymeleaf 표준 방언의 가장 중요한 부분 중 하나인 Thymeleaf 표준 표현 구문에 대해 알아보겠습니다.

우리는 이미 이 구문에서 표현되는 유효한 속성 값의 두 가지 유형, 즉 메시지 표현식과 변수 표현식을 살펴보았습니다.

<p th:utext="#{home.welcome}">Welcome to our grocery store!</p>

<p>Today is: <span th:text="${today}">13 february 2011</span></p>
하지만 표현식에는 더 많은 유형이 있으며, 우리가 이미 알고 있는 표현식에 대해서도 더 흥미로운 세부 사항들을 알아볼 수 있습니다. 먼저 표준 표현식의 특징을 간단히 요약해 보겠습니다.

간단한 표현:
변수 표현식:${...}
선택 변수 표현식:*{...}
메시지 표현:#{...}
링크 URL 표현식:@{...}
프래그먼트 표현식:~{...}
문자 그대로
텍스트 리터럴: 'one text', 'Another one!',…
숫자 리터럴: 0, 34, 3.0, 12.3,…
불리언 리터럴: true,false
널 리터럴:null
문자 그대로의 토큰: one, sometext, main,…
텍스트 작업:
문자열 연결:+
문자 그대로의 대체:|The name is ${name}|
산술 연산:
이항 연산자: +, -, *, /,%
마이너스 부호(단항 연산자):-
불리언 연산:
이항 연산자: and,or
불리언 부정(단항 연산자): !,not
비교와 평등:
비교 연산자: >, <, >=, <=( gt, lt, ge, le)
등호 연산자: ==, !=( eq, ne)
조건 연산자:
만약 그렇다면:(if) ? (then)
조건문(if-then-else):(if) ? (then) : (else)
기본:(value) ?: (defaultvalue)
특별 토큰:
무작업:_
이러한 모든 기능은 조합 및 중첩될 수 있습니다.

'User is of type ' + (${user.isAdmin()} ? 'Administrator' : (${user.type} ?: 'Unknown'))
4.1 메시지
이미 알고 있듯이, #{...}메시지 표현식을 사용하면 다음과 같이 연결할 수 있습니다.

<p th:utext="#{home.welcome}">Welcome to our grocery store!</p>
…이것에 대하여:

home.welcome=¡Bienvenido a nuestra tienda de comestibles!
하지만 아직 고려하지 못한 부분이 하나 있습니다. 메시지 내용이 완전히 고정되어 있지 않다면 어떻게 될까요? 예를 들어, 애플리케이션이 특정 시점에 사이트를 방문하는 사용자가 누구인지 알고 있고, 그 사용자의 이름으로 인사하고 싶다면 어떻게 해야 할까요?

<p>¡Bienvenido a nuestra tienda de comestibles, John Apricot!</p>
즉, 메시지에 매개변수를 추가해야 합니다. 예를 들어 다음과 같이요.

home.welcome=¡Bienvenido a nuestra tienda de comestibles, {0}!
매개변수는 표준 구문에 따라 지정되므로 패키지 java.text.MessageFormat내 클래스의 API 문서에 명시된 대로 숫자 및 날짜 형식으로 지정할 수 있습니다 java.text.*.

매개변수에 값을 지정하려면, HTTP 세션 속성이 주어졌을 때 다음과 같이 user할 수 있습니다.

<p th:utext="#{home.welcome(${session.user.name})}">
  Welcome to our grocery store, Sebastian Pepper!
</p>
여기서 `@`를 사용하면 th:utext형식화된 메시지가 이스케이프되지 않습니다. 이 예제는 `@`가 user.name이미 이스케이프되었다고 가정합니다.

여러 매개변수를 쉼표로 구분하여 지정할 수 있습니다.

메시지 키 자체는 변수에서 가져올 수 있습니다.

<p th:utext="#{${welcomeMsgKey}(${session.user.name})}">
  Welcome to our grocery store, Sebastian Pepper!
</p>
4.2 변수
앞서 언급했듯이 ${...}표현식은 실제로 컨텍스트에 포함된 변수 맵에서 실행되는 OGNL(Object-Graph Navigation Language) 표현식입니다.

OGNL 구문 및 기능에 대한 자세한 내용은 OGNL 언어 가이드를 참조하십시오.

Spring MVC를 사용하는 애플리케이션에서는 OGNL이 SpringEL 로 대체되지만 , 구문은 OGNL과 매우 유사합니다(실제로 대부분의 일반적인 경우에는 완전히 동일합니다).

OGNL의 구문에서 우리는 다음 표현식을 알 수 있습니다.

<p>Today is: <span th:text="${today}">13 february 2011</span>.</p>
…는 사실상 이것과 같습니다:

ctx.getVariable("today");
하지만 OGNL을 사용하면 훨씬 더 강력한 표현을 만들 수 있으며, 이것이 바로 그 예입니다.

<p th:utext="#{home.welcome(${session.user.name})}">
  Welcome to our grocery store, Sebastian Pepper!
</p>
…다음 명령을 실행하여 사용자 이름을 얻습니다.

((User) ctx.getVariable("session").get("user")).getName();
하지만 게터 메서드 탐색은 OGNL의 기능 중 하나일 뿐입니다. 다른 기능들을 더 살펴보겠습니다.

/*
 * Access to properties using the point (.). Equivalent to calling property getters.
 */
${person.father.name}

/*
 * Access to properties can also be made by using brackets ([]) and writing 
 * the name of the property as a variable or between single quotes.
 */
${person['father']['name']}

/*
 * If the object is a map, both dot and bracket syntax will be equivalent to 
 * executing a call on its get(...) method.
 */
${countriesByCode.ES}
${personsByName['Stephen Zucchini'].age}

/*
 * Indexed access to arrays or collections is also performed with brackets, 
 * writing the index without quotes.
 */
${personsArray[0].name}

/*
 * Methods can be called, even with arguments.
 */
${person.createCompleteName()}
${person.createCompleteNameWithSeparator('-')}
표현식 기본 객체
컨텍스트 변수에 대한 OGNL 표현식을 평가할 때, 더 높은 유연성을 위해 일부 객체가 표현식에서 사용 가능하게 됩니다. 이러한 객체는 (OGNL 표준에 따라) 다음 #기호로 시작하여 참조됩니다.

#ctx컨텍스트 객체입니다.
#vars:컨텍스트 변수.
#locale컨텍스트 로케일.
그래서 우리는 이렇게 할 수 있습니다:

Established locale country: <span th:text="${#locale.country}">US</span>.
이러한 개체에 대한 전체 참조 정보는 부록 A 에서 확인할 수 있습니다 .

표현식 유틸리티 객체
이러한 기본 객체 외에도 Thymeleaf는 표현식에서 일반적인 작업을 수행하는 데 도움이 되는 유틸리티 객체 세트를 제공합니다.

#execInfo처리 중인 템플릿에 대한 정보입니다.
#messages변수 표현식 내에서 외부화된 메시지를 얻는 방법으로, #{…} 구문을 사용하는 것과 동일한 방식으로 얻을 수 있습니다.
#urisURL/URI의 일부를 이스케이프 처리하는 방법
#conversions구성된 변환 서비스를 실행하기 위한 메서드 (있는 경우).
#dates객체 에 대한 메서드 java.util.Date: 서식 지정, 구성 요소 추출 등
#calendars: 와 유사 #dates하지만, java.util.Calendar사물에 적용됩니다.
#temporalsjava.timeJDK8 이상에서 API를 사용하여 날짜와 시간을 처리하기 위한 것입니다 .
#numbers숫자 객체의 형식을 지정하는 메서드입니다.
#strings객체 에 대한 메서드 String: contains, startsWith, prepending/appending 등
#objects객체에 대한 일반적인 메서드입니다.
#bools: 불리언 평가를 위한 메서드.
#arrays배열에 대한 메서드입니다.
#lists리스트 관련 메서드입니다.
#sets집합에 대한 메서드입니다.
#maps지도에 대한 메서드입니다.
#aggregates배열 또는 컬렉션에 대한 집계를 생성하는 메서드입니다.
#ids반복 작업의 결과로 발생할 수 있는 중복된 ID 속성을 처리하는 메서드입니다.
각 유틸리티 객체가 제공하는 기능은 부록 B 에서 확인할 수 있습니다 .

이제 이러한 유틸리티 객체에 대해 알았으니, 이를 사용하여 홈페이지에 날짜를 표시하는 방식을 변경할 수 있습니다. 다음과 같이 하는 대신에 HomeController:

SimpleDateFormat dateFormat = new SimpleDateFormat("dd MMMM yyyy");

WebContext ctx = new WebContext(webExchange, webExchange.getLocale());
ctx.setVariable("today", dateFormat.format(cal.getTime()));

…우리는 바로 이렇게 할 수 있습니다:

WebContext ctx = new WebContext(webExchange, webExchange.getLocale());
ctx.setVariable("today", Calendar.getInstance());

templateEngine.process("home", ctx, writer);
…그런 다음 뷰 레이어 자체에서 날짜 형식을 지정합니다.

<p>
  Today is: <span th:text="${#calendars.format(today,'dd MMMM yyyy')}">13 May 2011</span>
</p>
4.3 선택 항목에 대한 표현식(별표 구문)
${...}변수 표현식은 뿐만 아니라 로도 작성할 수 있습니다 *{...}.

하지만 중요한 차이점이 있습니다. 별표 구문은 전체 컨텍스트가 아닌 선택된 객체 에 대해 표현식을 평가합니다 . 즉, 선택된 객체가 없는 경우에는 달러 기호 구문과 별표 구문이 완전히 동일하게 작동합니다.

그렇다면 선택된 객체란 무엇일까요? 속성을 사용한 표현식의 결과입니다 . 사용자 프로필( ) 페이지 th:object에서 하나를 사용해 보겠습니다 .userprofile.html

  <div th:object="${session.user}">
    <p>Name: <span th:text="*{firstName}">Sebastian</span>.</p>
    <p>Surname: <span th:text="*{lastName}">Pepper</span>.</p>
    <p>Nationality: <span th:text="*{nationality}">Saturn</span>.</p>
  </div>
이는 정확히 다음과 같습니다.

<div>
  <p>Name: <span th:text="${session.user.firstName}">Sebastian</span>.</p>
  <p>Surname: <span th:text="${session.user.lastName}">Pepper</span>.</p>
  <p>Nationality: <span th:text="${session.user.nationality}">Saturn</span>.</p>
</div>
물론 달러 기호와 별표 기호를 혼합하여 사용할 수 있습니다.

<div th:object="${session.user}">
  <p>Name: <span th:text="*{firstName}">Sebastian</span>.</p>
  <p>Surname: <span th:text="${session.user.lastName}">Pepper</span>.</p>
  <p>Nationality: <span th:text="*{nationality}">Saturn</span>.</p>
</div>
객체 선택이 완료되면 선택된 객체는 달러 표현식에서 #object표현식 변수로도 사용할 수 있습니다.

<div th:object="${session.user}">
  <p>Name: <span th:text="${#object.firstName}">Sebastian</span>.</p>
  <p>Surname: <span th:text="${session.user.lastName}">Pepper</span>.</p>
  <p>Nationality: <span th:text="*{nationality}">Saturn</span>.</p>
</div>
앞서 언급했듯이 객체 선택이 수행되지 않은 경우 달러 기호와 별표 기호는 동일한 의미를 가집니다.

<div>
  <p>Name: <span th:text="*{session.user.name}">Sebastian</span>.</p>
  <p>Surname: <span th:text="*{session.user.surname}">Pepper</span>.</p>
  <p>Nationality: <span th:text="*{session.user.nationality}">Saturn</span>.</p>
</div>
4.4 링크 URL
URL은 그 중요성 때문에 웹 애플리케이션 템플릿에서 핵심적인 요소이며, Thymeleaf 표준 방언은 URL에 대한 특별한 구문을 제공합니다 @. 그 구문은 다음과 같습니다.@{...}

URL에는 여러 종류가 있습니다.

절대 URL:http://www.thymeleaf.org
상대 URL은 다음과 같은 형태를 가질 수 있습니다.
페이지 상대적:user/login.html
컨텍스트 상대적: /itemdetails?id=3(서버의 컨텍스트 이름이 자동으로 추가됩니다)
서버 상대 경로: ~/billing/processInvoice(동일한 서버 내의 다른 컨텍스트(= 애플리케이션)에서 URL을 호출할 수 있도록 합니다.)
프로토콜 상대 URL://code.jquery.com/jquery-2.0.3.min.js
이러한 표현식을 실제로 처리하고 출력될 URL로 변환하는 작업은 사용 중인 객체 org.thymeleaf.linkbuilder.ILinkBuilder에 등록된 인터페이스 구현체에 의해 수행됩니다.ITemplateEngine

기본적으로 이 인터페이스의 구현체 하나만 클래스에 등록되며 org.thymeleaf.linkbuilder.StandardLinkBuilder, 이는 오프라인(비웹) 시나리오와 서블릿 API 기반 웹 시나리오 모두에 충분합니다. 다른 시나리오(예: 서블릿 API를 사용하지 않는 웹 프레임워크와의 통합)에서는 링크 빌더 인터페이스의 특정 구현체가 필요할 수 있습니다.

이 새로운 구문을 사용해 봅시다. th:href속성을 소개합니다.

<!-- Will produce 'http://localhost:8080/gtvg/order/details?orderId=3' (plus rewriting) -->
<a href="details.html" 
   th:href="@{http://localhost:8080/gtvg/order/details(orderId=${o.id})}">view</a>

<!-- Will produce '/gtvg/order/details?orderId=3' (plus rewriting) -->
<a href="details.html" th:href="@{/order/details(orderId=${o.id})}">view</a>

<!-- Will produce '/gtvg/order/3/details' (plus rewriting) -->
<a href="details.html" th:href="@{/order/{orderId}/details(orderId=${o.id})}">view</a>
여기서 몇 가지 유의할 점이 있습니다.

th:href이는 수정자 속성입니다. 처리가 완료되면 사용할 링크 URL을 계산하고 해당 값을 태그 href의 속성 에 설정합니다 <a>.
URL 매개변수에 표현식을 사용할 수 있습니다(아래 참조 orderId=${o.id}). 필요한 URL 매개변수 인코딩 작업도 자동으로 수행됩니다.
여러 매개변수가 필요한 경우 쉼표로 구분합니다.@{/order/process(execId=${execId},execType='FAST')}
URL 경로에서 변수 템플릿도 허용됩니다.@{/order/{orderId}/details(orderId=${orderId})}
/(예: ) 로 시작하는 상대 URL에는 /order/details애플리케이션 컨텍스트 이름이 자동으로 접두사로 붙습니다.
쿠키가 활성화되어 있지 않거나 활성화 여부를 알 수 없는 경우, ";jsessionid=..."세션을 유지하기 위해 상대 URL에 접미사가 추가될 수 있습니다. 이를 URL 재작성 이라고 하며 , Thymeleaf는 서블릿 API의 메커니즘을 사용하여 모든 URL에 대해 자체 재작성 필터를 적용할 수 있도록 지원합니다 response.encodeURL(...).
이 th:href속성을 사용하면 템플릿에 (선택적으로) 작동하는 정적 속성을 가질 수 있으므로 href프로토타이핑 목적으로 브라우저를 직접 열었을 때 템플릿 링크를 계속 탐색할 수 있습니다.
메시지 구문( )의 경우와 마찬가지로 #{...}URL 기본 주소도 다른 표현식을 평가한 결과일 수 있습니다.

<a th:href="@{${url}(orderId=${o.id})}">view</a>
<a th:href="@{'/details/'+${user.login}(orderId=${o.id})}">view</a>

동일한 서버 내의 서로 다른 컨텍스트에 연결하기 위해 컨텍스트 루트 상대 URL 대신 서버 루트 상대 URL을 생성하는 추가 구문을 사용할 수 있습니다. 이러한 URL은 다음과 같이 지정됩니다.@{~/path/to/something}

4.5 조각
프래그먼트 표현식은 마크업 조각을 표현하고 템플릿 간에 이동하는 쉬운 방법입니다. 이를 통해 프래그먼트를 복제하거나 다른 템플릿에 인수로 전달하는 등의 작업을 수행할 수 있습니다.

가장 일반적인 용도는 th:insert또는 를 사용하여 조각을 삽입하는 것입니다 th:replace(이에 대한 자세한 내용은 뒷부분에서 설명합니다).

<div th:insert="~{commons :: main}">...</div>
하지만 다른 변수들과 마찬가지로 어디에서든 사용할 수 있습니다.

<div th:with="frag=~{footer :: #main/text()}">
  <p th:insert="${frag}">
</div>
이 튜토리얼의 뒷부분에는 템플릿 레이아웃에 대한 전체 섹션이 있으며, 여기에는 프래그먼트 표현식에 대한 더 자세한 설명이 포함됩니다.

4.6 문자 그대로
텍스트 리터럴
텍스트 리터럴은 작은따옴표로 묶인 문자열입니다. 어떤 문자든 포함할 수 있지만, 작은따옴표 안에 있는 문자는 반드시 이스케이프해야 합니다 \'.

<p>
  Now you are looking at a <span th:text="'working web application'">template file</span>.
</p>
숫자 리터럴
숫자 리터럴은 말 그대로 숫자입니다.

<p>The year is <span th:text="2013">1492</span>.</p>
<p>In two years, it will be <span th:text="2013 + 2">1494</span>.</p>
불리언 리터럴
불리언 리터럴은 ` trueand`와 `and` 입니다 false. 예를 들면 다음과 같습니다.

<div th:if="${user.isAdmin()} == false"> ...
이 예시에서는 == false중괄호 밖에 작성되어 있으므로 Thymeleaf가 이를 처리합니다. 만약 중괄호 안에 작성되었다면 OGNL/SpringEL 엔진이 이를 처리하게 됩니다.

<div th:if="${user.isAdmin() == false}"> ...
널 리터럴

<div th:if="${variable.something} == null"> ...

이 토큰들은 표준 표현식을 약간 간소화해줍니다. 텍스트 리터럴( )과 정확히 똑같이 작동 하지만, 문자( 및 ), 숫자( ), 대괄호( 및 ), 마침표( ), 하이픈 ( ) 및 밑줄( ) '...'만 사용할 수 있습니다 . 따라서 공백이나 쉼표 등은 사용할 수 없습니다.A-Za-z0-9[].-_

좋은 점은 무엇일까요? 토큰은 따옴표로 묶을 필요가 없다는 것입니다. 따라서 다음과 같이 할 수 있습니다.

<div th:class="content">...</div>
대신:

<div th:class="'content'">...</div>
4.7 텍스트 추가
텍스트는 리터럴이든 변수 또는 메시지 표현식을 평가한 결과이든 관계없이 +연산자를 사용하여 쉽게 추가할 수 있습니다.

<span th:text="'The name of the user is ' + ${user.name}">
4.8 문자적 대체
리터럴 치환을 사용하면 리터럴 뒤에 마침표(.)를 붙이지 않고도 변수 값을 포함하는 문자열의 형식을 쉽게 지정할 수 있습니다 '...' + '...'.

|이러한 대체어는 세로 막대( ) 로 둘러싸여 있어야 합니다 . 예:

<span th:text="|Welcome to our application, ${user.name}!|">
이는 다음과 같습니다.

<span th:text="'Welcome to our application, ' + ${user.name} + '!'">
문자 그대로의 대체는 다른 유형의 표현과 결합될 수 있습니다.

<span th:text="${onevar} + ' ' + |${twovar}, ${threevar}|">
리터럴 치환 내부에는 변수/메시지 표현식( ${...}, *{...}, #{...})만 허용됩니다 |...|. 다른 리터럴( '...'), 부울/숫자 토큰, 조건식 등은 허용되지 않습니다.

4.9 산술 연산
또한 다음과 같은 몇 가지 산술 연산을 사용할 수 있습니다: +, -, *, /및 %.

<div th:with="isEven=(${prodStat.count} % 2 == 0)">
참고로, 이러한 연산자는 OGNL 변수 표현식 자체 내에서도 적용될 수 있으며, 이 경우 Thymeleaf 표준 표현식 엔진 대신 OGNL에서 실행됩니다.

<div th:with="isEven=${prodStat.count % 2 == 0}">
참고로 이러한 연산자 중 일부에는 텍스트 별칭이 존재합니다: div( /), mod( %).

4.10 비교급과 등호
>표현식의 값은 , <, >=및 기호를 사용하여 비교할 수 있으며 <=, 및 ==연산자 !=를 사용하여 같음(또는 같지 않음)을 확인할 수 있습니다. XML에서는 <및 기호를 속성 값에 사용해서는 안 되므로 및 >로 대체해야 합니다 .&lt;&gt;

<div th:if="${prodStat.count} &gt; 1">
<span th:text="'Execution mode is ' + ( (${execMode} == 'dev')? 'Development' : 'Production')">
더 간단한 대안은 이러한 연산자 중 일부에 대해 존재하는 텍스트 별칭을 사용하는 것입니다: gt( >), lt( <), ge( >=), le( <=), not( !). 또한 eq( ==), neq/ ne( !=).

4.11 조건식
조건식은 조건(그 자체로 또 다른 표현식임)을 평가한 결과에 따라 두 표현식 중 하나만 평가하도록 설계되었습니다.

또 다른 속성 수정자 ( , th:class) 를 도입한 예시 코드를 살펴보겠습니다 .

<tr th:class="${row.even}? 'even' : 'odd'">
  ...
</tr>
조건식의 세 부분( condition, then및 else)은 모두 그 자체로 표현식입니다. 즉, 변수( ${...}, *{...}), 메시지( #{...}), URL( @{...}) 또는 리터럴( '...')이 될 수 있습니다.

조건식은 괄호를 사용하여 중첩할 수도 있습니다.

<tr th:class="${row.even}? (${row.first}? 'first' : 'even') : 'odd'">
  ...
</tr>
else 절은 생략할 수도 있으며, 이 경우 조건이 거짓이면 null 값이 반환됩니다.

<tr th:class="${row.even}? 'alt'">
  ...
</tr>
4.12 기본 표현식(엘비스 연산자)
기본 표현식은 then 부분 이 없는 특별한 종류의 조건부 값입니다 . 이는 Groovy와 같은 일부 언어에 있는 엘비스 연산자 와 유사 하며, 두 개의 표현식을 지정할 수 있습니다. 첫 번째 표현식은 null이 아니면 사용되고, null이면 두 번째 표현식이 사용됩니다.

사용자 프로필 페이지에서 실제로 어떻게 작동하는지 살펴보겠습니다.

<div th:object="${session.user}">
  ...
  <p>Age: <span th:text="*{age}?: '(no age specified)'">27</span>.</p>
</div>
보시다시피, 연산자는 `null` ?:이며, 여기서는 평가 결과가 `null`인 경우에만 이름(이 경우 리터럴 값)에 대한 기본값을 지정하는 데 사용합니다 *{age}. 따라서 이는 다음과 같습니다.

<p>Age: <span th:text="*{age != null}? *{age} : '(no age specified)'">27</span>.</p>
조건부 값과 마찬가지로 괄호 안에 중첩된 표현식을 포함할 수 있습니다.

<p>
  Name: 
  <span th:text="*{firstName}?: (*{admin}? 'Admin' : #{default.username})">Sebastian</span>
</p>
4.13 무작업 토큰
아무 작업도 수행하지 않음을 나타내는 토큰은 밑줄 기호( _)로 표시됩니다.

이 토큰의 기본 아이디어는 표현식에 대해 원하는 결과가 아무것도 하지 않는 것 , 즉 처리 가능한 속성(예:  th:text)이 전혀 없는 것처럼 정확히 동작하는 것임을 지정하는 것입니다.

다른 가능성 중 하나로, 이를 통해 개발자는 프로토타입 텍스트를 기본값으로 사용할 수 있습니다. 예를 들어 다음과 같이 사용하는 대신:

<span th:text="${user.name} ?: 'no user authenticated'">...</span>
… ‘사용자 인증 안 됨’을 프로토타이핑 텍스트로 직접 사용할 수 있으므로 디자인 관점에서 더 간결하고 다용도로 활용할 수 있는 코드를 얻을 수 있습니다.

<span th:text="${user.name} ?: _">no user authenticated</span>
4.14 데이터 변환/형식 지정
Thymeleaf는 변수( ) 및 선택( ) 표현식에 대해 이중 중괄호 구문을 정의하여 구성된 변환 서비스를 통해 데이터 변환을 적용할 수 있도록 합니다 .${...}*{...}

기본적으로는 다음과 같습니다.

<td th:text="${{user.lastAccessDate}}">...</td>
저기 있는 이중 중괄호(:)를 보셨나요? ${{...}}이것은 Thymeleaf에게 표현식의 결과를 변환 서비스user.lastAccessDate 에 전달하고 결과를 쓰기 전에 서식 지정 작업 (예: 로의 변환 ) 을 수행하도록 지시합니다 .String

user.lastAccessDate해당 타입이 라고 가정할 때 java.util.Calendar, 변환 서비스 ( 의 구현체 IStandardConversionService)가 등록되어 있고 에 대한 유효한 변환을 포함하고 있다면 Calendar -> String해당 변환이 적용됩니다.

IStandardConversionService(해당 StandardConversionService클래스의) 기본 구현은 .toString()변환된 모든 객체에 대해 실행됩니다. 사용자 지정 변환 서비스String 구현을 등록하는 방법에 대한 자세한 내용은 구성에 대한 추가 정보 를 참조하세요 .

공식 thymeleaf-spring3 및 thymeleaf-spring4 통합 패키지는 Thymeleaf의 변환 서비스 메커니즘을 Spring 자체의 변환 서비스 인프라와 투명하게 통합하여 Spring 설정에 선언된 변환 서비스 및 포맷터를 표현식에서 자동으로 사용할 수 있도록 ${{...}}합니다 *{{...}}.

4.15 전처리
Thymeleaf는 표현식 처리를 위한 이러한 모든 기능 외에도 표현식을 전처리하는 기능을 제공합니다 .

전처리란 일반적인 표현식 실행 전에 수행되는 단계로, 최종적으로 실행될 표현식을 수정할 수 있도록 합니다.

전처리된 표현식은 일반 표현식과 완전히 동일하지만 이중 밑줄 기호(예: __${expression}__)로 둘러싸여 나타납니다.

Messages_fr.properties언어별 정적 메서드를 호출하는 OGNL 표현식을 포함하는 i18n 항목이 있다고 가정해 보겠습니다. 예를 들면 다음과 같습니다.

article.text=@myapp.translator.Translator@translateToFrench({0})
…그리고 a Messages_es.properties equivalent:

article.text=@myapp.translator.Translator@translateToSpanish({0})
로케일에 따라 하나의 표현식 또는 다른 표현식을 평가하는 마크업 조각을 만들 수 있습니다. 이를 위해 먼저 전처리를 통해 표현식을 선택한 다음 Thymeleaf가 실행하도록 합니다.

<p th:text="${__#{article.text('textVar')}__}">Some text here...</p>
참고로 프랑스어 로케일에 대한 전처리 단계에서는 다음과 같은 결과가 생성됩니다.

<p th:text="${@myapp.translator.Translator@translateToFrench(textVar)}">Some text here...</p>
전처리 문자열은 __속성에서 .을 사용하여 이스케이프 처리할 수 있습니다 \_\_.

보안상의 이유로 전처리에는 더욱 엄격한 표현식 평가 제한이 적용됩니다. 부록 D: 표현식 제한을 참조하십시오 .

5. 속성 값 설정

5.1 속성 값 설정
/WEB-INF/templates/subscribe.html우리 웹사이트에서 뉴스레터를 발행하고 사용자들이 구독할 수 있도록 하고 싶다고 가정해 봅시다. 그래서 구독 양식이 포함된 템플릿을 만듭니다 .

<form action="subscribe.html">
  <fieldset>
    <input type="text" name="email" />
    <input type="submit" value="Subscribe!" />
  </fieldset>
</form>
Thymeleaf와 마찬가지로, 이 템플릿은 웹 애플리케이션 템플릿이라기보다는 정적 프로토타입에 더 가깝습니다. 첫째, action폼의 속성이 템플릿 파일 자체에 정적으로 연결되어 있어 유용한 URL 재작성을 위한 공간이 없습니다. 둘째, value제출 버튼의 속성으로 인해 텍스트가 영어로 표시되지만, 우리는 이를 국제화하고 싶습니다.

그다음 th:attr속성을 입력하고, 해당 속성이 설정된 태그의 속성 값을 변경할 수 있는 기능을 설명합니다.

<form action="subscribe.html" th:attr="action=@{/subscribe}">
  <fieldset>
    <input type="text" name="email" />
    <input type="submit" value="Subscribe!" th:attr="value=#{subscribe.submit}"/>
  </fieldset>
</form>
개념은 매우 간단합니다. th:attr속성에 값을 할당하는 표현식을 사용하면 됩니다. 해당 컨트롤러 및 메시지 파일을 생성한 후 이 파일을 처리하면 다음과 같은 결과가 나타납니다.

<form action="/gtvg/subscribe">
  <fieldset>
    <input type="text" name="email" />
    <input type="submit" value="¡Suscríbe!"/>
  </fieldset>
</form>
/gtvg/subscribe새로운 속성 값 외에도 이전 장에서 설명했듯이 애플리케이션 컨텍스트 이름이 URL 기본 주소 앞에 자동으로 접두사로 추가된 것을 확인할 수 있습니다 .

하지만 한 번에 여러 속성을 설정하고 싶다면 어떻게 해야 할까요? XML 규칙에 따르면 태그 내에서 동일한 속성을 두 번 설정할 수 없으므로 다음 th:attr과 같이 쉼표로 구분된 속성 목록을 사용해야 합니다.

<img src="../../images/gtvglogo.png" 
     th:attr="src=@{/images/gtvglogo.png},title=#{logo},alt=#{logo}" />
필요한 메시지 파일이 주어지면 다음과 같은 결과가 출력됩니다.

<img src="/gtgv/images/gtvglogo.png" title="Logo de Good Thymes" alt="Logo de Good Thymes" />
5.2 특정 속성에 값 설정
지금쯤이면 아마 이런 생각을 하고 계실지도 모르겠습니다.

<input type="submit" value="Subscribe!" th:attr="value=#{subscribe.submit}"/>
…는 상당히 보기 흉한 마크업입니다. 속성 값 안에 할당을 지정하는 것은 매우 실용적일 수 있지만, 매번 이렇게 해야 한다면 템플릿을 만드는 가장 우아한 방법은 아닙니다.

Thymeleaf도 당신의 의견에 동의하며, 그렇기 때문에 th:attr템플릿에서 해당 속성은 거의 사용되지 않습니다. 일반적으로는 특정 태그 속성을 설정하는 다른 속성들을 사용하게 될 것입니다 th:*(단순히 아무 속성이나 설정하는 것이 아니라요 th:attr).

<input type="submit" value="Subscribe!" th:value="#{subscribe.submit}"/>

<form action="subscribe.html" th:action="@{/subscribe}">

<li><a href="product/list.html" th:href="@{/product/list}">Product List</a></li>

5.5 고정값 부울 속성
HTML에는 불리언 속성 이라는 개념이 있습니다 . 불리언 속성은 값이 없는 속성으로, 값이 존재하면 "참"을 의미합니다. XHTML에서는 이러한 속성이 오직 하나의 값, 즉 자기 자신만을 가집니다.

예를 들어, checked:

<input type="checkbox" name="option2" checked /> <!-- HTML -->
<input type="checkbox" name="option1" checked="checked" /> <!-- XHTML -->
표준 방언에는 조건을 평가하여 속성을 설정할 수 있는 속성이 포함되어 있습니다. 즉, 조건이 참으로 평가되면 해당 속성은 고정된 값으로 설정되고, 거짓으로 평가되면 속성은 설정되지 않습니다.

<input type="checkbox" name="active" th:checked="${user.active}" />

5.6 속성 값 설정(기본 속성 처리기)
Thymeleaf는 기본 속성 처리기를 제공하므로 표준 방언에서 특정 처리기가 정의되지 않은 속성이라도 모든 속성 의 값을 설정할 수 있습니다 .th:*

<span th:whatever="${user.name}">...</span>
결과는 다음과 같습니다:

5.7 HTML5 친화적인 속성 및 요소 이름 지원
또한 완전히 다른 구문을 사용하여 HTML5 친화적인 방식으로 템플릿에 프로세서를 적용할 수도 있습니다.

<table>
    <tr data-th-each="user : ${users}">
        <td data-th-text="${user.login}">...</td>
        <td data-th-text="${user.name}">...</td>
    </tr>
</table>
이 data-{prefix}-{name}구문은 개발자가 네임스페이스 이름(예: `<code>`)을 사용하지 않고도 HTML5에서 사용자 지정 속성을 작성하는 표준 방식입니다 th:*. Thymeleaf는 이 구문을 모든 방언트(표준 방언뿐만 아니라)에서 자동으로 사용할 수 있도록 지원합니다.

또한 사용자 정의 태그를 지정하는 구문도 있습니다. {prefix}-{name}이는 W3C 사용자 정의 요소 사양 (더 큰 W3C 웹 구성 요소 사양 의 일부 )을 따릅니다. 예를 들어, 이 구문은 th:block요소(또는 ) 에 사용할 수 있으며 th-block, 이는 뒷부분에서 설명하겠습니다.

중요: 이 구문은 네임스페이스 th:*구문에 추가되는 기능이며, 기존 구문을 대체하는 것이 아닙니다. 향후 네임스페이스 구문을 더 이상 사용하지 않도록 할 계획은 전혀 없습니다.

public void process(

6.2 반복 상태 유지
Thymeleaf를 사용할 때 th:each, Thymeleaf는 반복 작업의 상태를 추적하는 데 유용한 메커니즘인 ` status` 변수를 제공합니다 .

상태 변수는 속성 내에 정의되며 th:each다음과 같은 데이터를 포함합니다.

현재 반복 인덱스 (0부터 시작). 이것이 index속성입니다.
현재 반복 인덱스는 1부터 시작합니다. 이것이 count속성입니다.
반복 변수에 포함된 요소의 총 개수입니다. 이것이 size속성입니다.
각 반복마다 사용되는 iter 변수입니다 . 이것이 current속성입니다.
현재 반복이 짝수인지 홀수인지 여부. 이것은 even/odd부울 속성입니다.
현재 반복이 첫 번째 반복인지 여부입니다. 이는 first부울 속성입니다.
현재 반복이 마지막 반복인지 여부입니다. 이는 last부울 속성입니다.

6.3 지연 데이터 검색을 통한 최적화

사실 이는 어떤 데이터 에든 적용할 수 있는 내용이지만 , 메모리 내 컬렉션의 크기를 고려할 때, 반복 처리가 필요한 컬렉션을 검색하는 경우가 이 시나리오에서 가장 일반적인 경우입니다.

이를 지원하기 위해 Thymeleaf는 컨텍스트 변수를 지연 로드 하는 메커니즘을 제공합니다 . 인터페이스를 구현하는 컨텍스트 변수 ILazyContextVariable(대부분 LazyContextVariable기본 구현을 확장하는 방식)는 실행 시점에 해석됩니다. 예를 들면 다음과 같습니다.

context.setVariable(
     "users",
     new LazyContextVariable<List<User>>() {
         @Override
         protected List<User> loadValue() {
             return databaseRepository.findAllUsers();
         }
     });
이 변수는 지연 평가 방식 이라는 사실을 몰라도 다음과 같은 코드에서 사용할 수 있습니다 .

<ul>
  <li th:each="u : ${users}" th:text="${u.name}">user name</li>
</ul>
하지만 동시에, 다음과 같은 코드에서 값이 로 평가 loadValue()되면 해당 객체는 절대 초기화되지 않습니다(해당 메서드는 절대 호출되지 않습니다) .conditionfalse

<ul th:if="${condition}">
  <li th:each="u : ${users}" th:text="${u.name}">user name</li>
</ul>

자바의 switch 문과 유사한 방식으로 조건을 걸어 콘텐츠를 표시하는 방법도 있습니다 . 바로 ` th:switch/` th:case속성 세트를 사용하는 것입니다.

<div th:switch="${user.role}">

  <p th:case="#{roles.manager}">User is a manager</p>

<div th:switch="${user.role}">

8가지 템플릿 레이아웃
8.1 템플릿 조각 포함
조각 정의 및 참조
템플릿을 만들 때, 푸터, 헤더, 메뉴 등 다른 템플릿의 요소들을 포함시키고 싶을 때가 많습니다.

이를 위해 Thymeleaf는 포함할 부분, 즉 "조각"을 정의해야 하며, 이는 th:fragment속성을 사용하여 수행할 수 있습니다.

예를 들어 모든 식료품점 페이지에 표준 저작권 바닥글을 추가하고 싶다고 가정해 보겠습니다. 그래서 /WEB-INF/templates/footer.html다음과 같은 코드가 포함된 파일을 만듭니다.

<!DOCTYPE html>

<html xmlns:th="http://www.thymeleaf.org">

  <body>
  
    <div th:fragment="copy">
      &copy; 2011 The Good Thymes Virtual Grocery
    </div>
  
  </body>
  
</html>
위 코드는 `<script>`라는 이름의 조각을 정의하며, `<script>` 또는 `<script>` 속성 copy중 하나를 사용하여 홈페이지에 쉽게 포함할 수 있습니다 .th:insertth:replace

<body>

  ...

  <div th:insert="~{footer :: copy}"></div>
  
</body>
참고로, 이는 단편 표현식 ( ) 을 th:insert예상하는데 , 이는 단편을 생성하는 표현식 입니다 .~{...}

조각 명세 구문
프래그먼트 표현식 의 구문은 매우 간단합니다. 세 가지 형식이 있습니다.

"~{templatename::selector}"지정된 마크업 선택기를 이름이 지정된 템플릿에 적용하여 생성된 조각을 포함합니다 templatename. 여기서 는 selector단순한 조각 이름일 수 있으므로 위와 ~{templatename::fragmentname}같이 간단하게 지정할 수도 있습니다 ~{footer :: copy}.

마크업 선택자 구문은 기본 AttoParser 구문 분석 라이브러리에 의해 정의되며 XPath 표현식이나 CSS 선택자와 유사합니다. 자세한 내용은 부록 C를 참조하십시오.

"~{templatename}"이라는 이름의 전체 템플릿이 포함되어 있습니다 templatename.

th:insert참고로, `/` 태그 에 사용하는 템플릿 이름은 th:replace현재 템플릿 엔진에서 사용 중인 템플릿 확인자가 해석할 수 있어야 합니다.

~{::selector}"또는 "~{this::selector}"동일한 템플릿에서 일치하는 조각을 삽입합니다 selector. 표현식이 나타나는 템플릿에서 해당 조각을 찾지 못하면 템플릿 호출(삽입) 스택을 원래 처리된 템플릿(루트 ) 방향 으로 탐색하여 selector어떤 수준에서든 일치하는 항목을 찾습니다.

위 예시의 ` and`는 모두 다음 templatename과 같이 완전한 기능을 갖춘 표현식(조건문 포함!)이 될 수 있습니다.selector

<div th:insert="~{ footer :: (${user.isAdmin}? #{footer.admin} : #{footer.normaluser}) }"></div>
프래그먼트는 어떤 th:*속성이든 포함할 수 있습니다. 이러한 속성은 프래그먼트가 대상 템플릿(` th:insert/` th:replace속성이 있는 템플릿)에 포함되면 평가되며, 대상 템플릿에 정의된 컨텍스트 변수를 참조할 수 있습니다.

이러한 프래그먼트 접근 방식의 큰 장점은 완전하고 유효한 마크업 구조를 갖춘, 브라우저에서 완벽하게 표시 가능한 페이지에 프래그먼트를 작성할 수 있으면서도 Thymeleaf가 다른 템플릿에 해당 프래그먼트를 포함할 수 있도록 하는 기능을 유지할 수 있다는 것입니다.

참고로, 프래그먼트 표현식은 보안상의 이유로 더 엄격한 표현식 평가 제한을 받습니다. 부록 D: 표현식 제한 사항을 참조하십시오 .

참조 조각 없이th:fragment
마크업 선택자의 강력한 기능 덕분에 th:fragment속성을 전혀 사용하지 않는 코드 조각도 포함할 수 있습니다. 심지어 Thymeleaf에 대해 전혀 알지 못하는 다른 애플리케이션에서 가져온 마크업 코드도 포함할 수 있습니다.

...
<div id="copy-section">
  &copy; 2011 The Good Thymes Virtual Grocery
</div>
...
id위 코드 조각은 CSS 선택자와 유사한 방식으로 속성 을 참조하여 사용할 수 있습니다 .

<body>

  ...

  <div th:insert="~{footer :: #copy-section}"></div>
  
</body>
th:insert와 의 차이점th:replace
th:insert그렇다면 와 의 차이점은 무엇일까요 th:replace?

th:insert지정된 조각을 호스트 태그의 본문으로 삽입합니다.

th:replace실제로 호스트 태그를 지정된 조각으로 바꿉니다 .

다음과 같은 HTML 조각입니다.

<footer th:fragment="copy">
  &copy; 2011 The Good Thymes Virtual Grocery
</footer>

  <div th:replace="~{footer :: copy}"></div>
  
</body>

8.2 매개변수화 가능한 프래그먼트 시그니처
템플릿 조각에 보다 함수적인 메커니즘을 구현하기 위해 , 정의된 조각은 th:fragment일련의 매개변수를 지정할 수 있습니다.

<div th:fragment="frag (onevar,twovar)">
    <p th:text="${onevar} + ' - ' + ${twovar}">...</p>
</div>
이를 위해서는 다음 두 구문 중 하나를 사용하여 해당 조각 을 호출해야 합니다 th:insert.th:replace

<div th:replace="~{ ::frag (${value1},${value2}) }">...</div>
<div th:replace="~{ ::frag (onevar=${value1},twovar=${value2}) }">...</div>
마지막 옵션에서는 순서가 중요하지 않다는 점에 유의하세요.

<div th:replace="~{ ::frag (twovar=${value2},onevar=${value1}) }">...</div>
프래그먼트 인자 없이 프래그먼트 로컬 변수 사용
조각이 다음과 같이 인자 없이 정의되더라도:

<div th:fragment="frag">
    ...
</div>
위에서 언급한 두 번째 구문을 사용하여 해당 함수들을 호출할 수 있습니다(그리고 두 번째 구문만 사용 가능합니다).

<div th:replace="~{::frag (onevar=${value1},twovar=${value2})}">
th:replace이는 와 의 조합과 같습니다 th:with.

<div th:replace="~{::frag}" th:with="onevar=${value1},twovar=${value2}">
참고 로, 프래그먼트에 대한 지역 변수 지정은 인자 시그니처가 있든 없든 관계없이 실행 전에 컨텍스트를 비우지 않습니다. 프래그먼트는 현재와 마찬가지로 호출 템플릿에서 사용되는 모든 컨텍스트 변수에 계속 접근할 수 있습니다.

th:템플릿 내 어설션을 위한 assert
이 th:assert속성은 평가해야 하는 표현식 목록을 쉼표로 구분하여 지정할 수 있으며, 모든 평가에서 참을 반환해야 하고 그렇지 않을 경우 예외를 발생시켜야 합니다.

<div th:assert="${onevar},(${twovar} != 43)">...</div>

<div th:insert="${user.isAdmin()} ? ~{common :: adminhead} : _">

</div>
...

8.5 레이아웃 상속
레이아웃을 하나의 파일로 구성하려면 프래그먼트를 사용할 수 있습니다. 다음은 프래그먼트를 사용하는 title간단한 레이아웃의 예입니다 .contentth:fragmentth:replace

<!DOCTYPE html>
<html th:fragment="layout (title, content)" xmlns:th="http://www.thymeleaf.org">
<head>
    <title th:replace="${title}">Layout Title</title>
</head>
<body>
    <h1>Layout H1</h1>
    <div th:replace="${content}">
        <p>Layout content</p>
    </div>
    <footer>
        Layout footer
    </footer>
</body>
</html>
이 예제는 제목 과 내용을 매개변수로 받는 '레이아웃' 이라는 프래그먼트를 선언합니다 . 이 프래그먼트를 상속받는 페이지에서는 제목과 내용이 아래 예제에 제공된 프래그먼트 표현식으로 대체됩니다.

<!DOCTYPE html>
<html th:replace="~{layoutFile :: layout(~{::title}, ~{::section})}">
<head>
    <title>Page Title</title>
</head>
<body>
<section>
    <p>Page content</p>
    <div>Included on page</div>
</section>
</body>
</html>
이 파일에서 태그는 레이아웃html 으로 대체되지만 , 레이아웃에서는 와 가 각각 및 블록으로 대체됩니다 .titlecontenttitlesection

원하는 경우, 레이아웃은 헤더 와 푸터 와 같은 여러 조각으로 구성할 수 있습니다 .

9 지역 변수
Thymeleaf에서는 로컬 변수를 템플릿의 특정 부분에 대해 정의된 변수로, 해당 부분 내에서만 평가할 수 있는 변수라고 합니다 .

이미 살펴본 예시로 prod제품 목록 페이지의 iter 변수를 들 수 있습니다.

<tr th:each="prod : ${prods}">
    ...
</tr>
해당 prod변수는 태그 범위 내에서만 사용 가능합니다 <tr>. 구체적으로는 다음과 같습니다.

th:*해당 태그에서 우선순위가 낮은 다른 속성에 대해 이 속성을 사용할 수 있습니다 th:each(즉, 해당 속성이 실행된 후에 실행됩니다 th:each).
<tr>이 기능은 태그의 모든 하위 요소, 예를 들어 다른 요소들 에서도 사용할 수 있습니다 <td>.
Thymeleaf는 속성을 사용하여 반복문 없이 지역 변수를 선언하는 방법을 제공하며 th:with, 그 구문은 속성 값 할당과 유사합니다.

<div th:with="firstPer=${persons[0]}">
  <p>
    The name of the first person is <span th:text="${firstPer.name}">Julius Caesar</span>.
  </p>
</div>
th:with해당 변수가 처리될 때 , firstPer로컬 변수로 생성되어 컨텍스트에서 가져온 변수 맵에 추가됩니다. 따라서 컨텍스트에 선언된 다른 변수들과 함께 평가할 수 있지만, 포함하는 <div>태그의 범위 내에서만 가능합니다.

일반적인 다중 변수 할당 구문을 사용하여 여러 변수를 동시에 정의할 수 있습니다.

<div th:with="firstPer=${persons[0]},secondPer=${persons[1]}">
  <p>
    The name of the first person is <span th:text="${firstPer.name}">Julius Caesar</span>.
  </p>
  <p>
    But the name of the second person is 
    <span th:text="${secondPer.name}">Marcus Antonius</span>.
  </p>
</div>
이 th:with속성을 사용하면 동일한 속성에 정의된 변수를 재사용할 수 있습니다.

<div th:with="company=${user.company + ' Co.'},account=${accounts[company]}">...</div>
이 코드를 우리 식료품점 홈페이지에 사용해 봅시다! 형식화된 날짜를 출력하기 위해 작성했던 코드 기억하시죠?

<p>
  Today is: 
  <span th:text="${#calendars.format(today,'dd MMMM yyyy')}">13 february 2011</span>
</p>
그런데 만약 이 기능이 지역 설정에 따라 달라지도록 하고 싶다면 어떻게 해야 할까요 "dd MMMM yyyy"? 예를 들어, 다음과 같은 메시지를 추가하고 싶을 수도 있습니다 home_en.properties.

date.format=MMMM dd'','' yyyy
…그리고 우리와 동등한 것 home_es.properties:

date.format=dd ''de'' MMMM'','' yyyy
이제 th:with지역화된 날짜 형식을 변수에 저장한 다음, 해당 변수를 표현식에 사용해 보겠습니다 th:text.

<p th:with="df=#{date.format}">
  Today is: <span th:text="${#calendars.format(today,df)}">13 February 2011</span>
</p>
깔끔하고 간단했습니다. 사실, 값 이 보다 th:with높다는 점을 고려하면 , 이 모든 것을 태그 안에서 해결할 수 있었을 것입니다 .precedenceth:textspan

<p>
  Today is: 
  <span th:with="df=#{date.format}" 
        th:text="${#calendars.format(today,df)}">13 February 2011</span>
</p>
'우선순위? 아직 그런 얘기는 안 했잖아!'라고 생각하실지도 모르겠네요. 하지만 걱정 마세요. 다음 장에서 바로 그 주제를 다룰 예정입니다.

10. 속성 우선순위
th:*같은 태그에 속성을 두 개 이상 작성하면 어떻게 될까요 ? 예를 들면 다음과 같습니다.

<ul>
  <li th:each="item : ${items}" th:text="${item.description}">Item description here...</li>
</ul>
원하는 결과를 얻으려면 해당 th:each속성이 먼저 실행될 것으로 예상했지만 , HTML/XML 표준은 태그 내 속성이 작성되는 순서에 아무런 의미를 부여하지 않기 때문에 예상대로 작동하도록 속성 자체에 우선순위 메커니즘을 설정해야 했습니다.th:text

따라서 모든 Thymeleaf 속성은 숫자 우선순위를 정의하며, 이는 태그에서 속성이 실행되는 순서를 결정합니다. 그 순서는 다음과 같습니다.

주문하다	특징	속성
1	조각 포함	th:insert
th:replace
2	조각 반복	th:each
3	조건부 평가	th:if
th:unless
th:switch
th:case
4	지역 변수 정의	th:object
th:with
5	일반 속성 수정	th:attr
th:attrprepend
th:attrappend
6	특정 속성 수정	th:value
th:href
th:src
...
7	텍스트(태그 본문 수정)	th:text
th:utext
8	조각 명세	th:fragment
9	조각 제거	th:remove
이 우선순위 메커니즘은 속성 위치를 반전시키더라도 위의 반복문이 정확히 동일한 결과를 제공한다는 것을 의미합니다(다만 가독성은 약간 떨어질 수 있습니다).

<ul>
  <li th:text="${item.description}" th:each="item : ${items}">Item description here...</li>
</ul>

<!-- User info follows -->

11.2. Thymeleaf 파서 수준 주석 블록
파서 레벨 주석 블록은 Thymeleaf가 템플릿을 파싱할 때 단순히 제거되는 코드입니다. 다음과 같은 형식입니다.

<!--/* This code will be removed at Thymeleaf parsing time! */-->
<!--/*Thymeleaf는 와 사이의 모든 내용을 제거하므로 */-->, 이러한 주석 블록은 템플릿이 정적으로 열려 있을 때 코드를 표시하는 데 사용할 수도 있습니다. 단, Thymeleaf가 처리할 때 제거된다는 점을 염두에 두어야 합니다.

<!--/*--> 
  <div>
     you can see me only before Thymeleaf processes me!
  </div>
<!--*/-->
<tr>예를 들어, 's'가 많이 포함된 표의 프로토타입을 만들 때 매우 유용할 수 있습니다 .

<table>

   </tr>
   <!--/*-->
   <tr>
     ...
   </tr>
   <tr>
     ...
   </tr>
   <!--*/-->
</table>
11.3. Thymeleaf 프로토타입 전용 댓글 블록
Thymeleaf는 템플릿이 정적으로 열려 있을 때(즉, 프로토타입으로 열려 있을 때) 주석으로 표시되지만, 템플릿을 실행할 때는 Thymeleaf에서 일반 마크업으로 간주되는 특수 주석 블록을 정의할 수 있도록 합니다.

<span>hello!</span>
<!--/*/
  <div th:text="${...}">
    ...
  </div>
/*/-->
<span>goodbye!</span>
<!--/*/Thymeleaf의 구문 분석 시스템은 ` &` 및 `& ` 마커 만 제거하고 /*/-->그 내용은 그대로 남겨두기 때문에 주석 처리되지 않습니다. 따라서 템플릿을 실행할 때 Thymeleaf는 실제로 다음과 같은 내용을 보게 됩니다.

<span>hello!</span>
 
  <div th:text="${...}">
    ...
  </div>
 
<span>goodbye!</span>
파서 수준 주석 블록과 마찬가지로 이 기능은 방언에 구애받지 않습니다.

11.4. 합성 th:block태그
Thymeleaf의 표준 방언에 포함된 유일한 요소 처리기(속성이 아님)는 입니다 th:block.

th:block`__`는 템플릿 개발자가 원하는 속성을 지정할 수 있도록 하는 단순한 속성 컨테이너입니다. Thymeleaf는 이러한 속성을 실행한 다음 블록 자체는 사라지게 하지만 블록의 내용은 그대로 유지합니다.

<tr>예를 들어 각 요소에 대해 여러 개가 필요한 반복 테이블을 만들 때 유용할 수 있습니다 .

<table>
  <th:block th:each="user : ${users}">
    <tr>
        <td th:text="${user.login}">...</td>
        <td th:text="${user.name}">...</td>
    </tr>
    <tr>
        <td colspan="2" th:text="${user.address}">...</td>
    </tr>
  </th:block>
</table>
특히 프로토타입 전용 댓글 블록과 함께 사용하면 더욱 유용합니다.

<table>
    <!--/*/ <th:block th:each="user : ${users}"> /*/-->
    <tr>
        <td th:text="${user.login}">...</td>
        <td th:text="${user.name}">...</td>
    </tr>
    <tr>
        <td colspan="2" th:text="${user.address}">...</td>
    </tr>
    <!--/*/ </th:block> /*/-->
</table>
<div>이 해결책은 템플릿을 유효한 HTML로 만들 수 있도록 해주며(금지된 블록을 내부에 추가할 필요 없음 <table>), 프로토타입으로 브라우저에서 정적으로 열었을 때도 제대로 작동한다는 점에 주목하세요!

12 인라인
12.1 표현식 인라인화
표준 HTML 구문에서는 태그 속성을 사용하여 거의 모든 작업을 수행할 수 있지만, HTML 텍스트에 직접 표현식을 작성하는 것이 더 편리한 경우도 있습니다. 예를 들어 다음과 같이 작성하는 것이 더 나을 수 있습니다.

<p>Hello, [[${session.user.name}]]!</p>
…이것 대신에:

<p>Hello, <span th:text="${session.user.name}">Sebastian</span>!</p>
[[...]]Thymeleaf에서 `or` 사이에 있는 표현식은 인라인 표현식[(...)] 으로 간주되며 , 그 안에는 `a` 또는 `b` 속성 에서 유효한 모든 종류의 표현식을 사용할 수 있습니다 .th:textth:utext

참고로, 는 (결과가 HTML 이스케이프 처리됨 ) [[...]]에 해당 하지만, 는 HTML 이스케이프 처리를 수행하지 않습니다. 따라서 와 같은 변수를 사용하면 다음 코드 조각을 예로 들 수 있습니다.th:text[(...)]th:utextmsg = 'This is <b>great!</b>'

<p>The message is "[(${msg})]"</p>
결과적으로 해당 <b>태그들은 이스케이프 처리되지 않은 상태가 됩니다. 따라서 다음과 같습니다.

<p>The message is "This is <b>great!</b>"</p>
반면에 다음과 같이 탈출하면:

<p>The message is "[[${msg}]]"</p>
결과는 HTML 이스케이프 처리됩니다.

<p>The message is "This is &lt;b&gt;great!&lt;/b&gt;"</p>
참고로, 텍스트 인라인 기능은 마크업의 모든 태그 본문(태그 자체가 아니라)에서 기본적으로 활성화되어 있으므로 , 별도로 활성화할 필요가 없습니다.

인라인 방식 vs. 내추럴 템플릿
만약 여러분이 이런 방식의 텍스트 출력이 일반적인 다른 템플릿 엔진을 사용해 본 경험이 있다면, " 왜 처음부터 이렇게 하지 않았을까? th:text 속성들을 일일이 입력하는 것보다 코드가 훨씬 간단한데!" 라고 생각할 수도 있습니다.

하지만 인라인 구문이 꽤 흥미로울 수 있지만, 인라인으로 작성된 표현식은 HTML 파일을 정적으로 열었을 때 그대로 표시되므로 디자인 프로토타입으로 더 이상 사용할 수 없다는 점을 항상 명심해야 합니다!

인라인 처리를 사용하지 않고 브라우저가 코드 조각을 정적으로 표시하는 방식과 그렇지 않은 방식의 차이점은 다음과 같습니다.

Hello, Sebastian!
…그리고 그것을 사용하는 것…

Hello, [[${session.user.name}]]!
디자인 유용성 측면에서 보면 …매우 명확합니다.

인라인 기능 비활성화
하지만 이 메커니즘은 비활성화할 수 있습니다. 왜냐하면 내용이 표현식으로 처리되지 않고 [[...]]또는 시퀀스만 출력해야 하는 경우가 있을 수 있기 때문입니다 . 이를 위해 다음과 같이 사용합니다 .[(...)]th:inline="none"

<p th:inline="none">A double array looks like this: [[1, 2, 3], [4, 5]]!</p>
이로 인해 다음과 같은 결과가 나타납니다.

<p>A double array looks like this: [[1, 2, 3], [4, 5]]!</p>
12.2 텍스트 인라인
텍스트 인라인은 방금 살펴본 표현식 인라인 기능 과 매우 유사 하지만, 실제로는 더 강력한 기능을 제공합니다. 이 기능은 명시적으로 활성화해야 합니다 th:inline="text".

텍스트 인라인 기능을 사용하면 방금 살펴본 인라인 표현식을 그대로 사용할 수 있을 뿐만 아니라, 태그 본문을 템플릿 모드 에서 처리되는 템플릿처럼 처리할 수 있습니다 TEXT. 이를 통해 텍스트 기반 템플릿 로직(출력 표현식뿐 아니라)도 수행할 수 있습니다.

텍스트 템플릿 모드 에 대한 다음 장에서 이에 대해 더 자세히 살펴보겠습니다 .

12.3 자바스크립트 인라이닝
<script>JavaScript 인라이닝을 사용하면 템플릿 모드 에서 처리되는 템플릿에 JavaScript 블록을 더 효과적으로 통합할 수 있습니다 HTML.

텍스트 인라인 과 마찬가지로 , 이는 스크립트 내용을 템플릿 모드의 템플릿처럼 처리하는 것과 동일하며 JAVASCRIPT, 따라서 텍스트 템플릿 모드 의 모든 강력한 기능 (다음 장 참조)을 활용할 수 있습니다. 하지만 이 섹션에서는 Thymeleaf 표현식의 출력을 JavaScript 블록에 추가하는 데 이 기능을 사용하는 방법에 초점을 맞추겠습니다.

이 모드는 다음을 사용하여 명시적으로 활성화해야 합니다 th:inline="javascript".

<script th:inline="javascript">
    ...
    var username = [[${session.user.name}]];
    ...
</script>
이로 인해 다음과 같은 결과가 나타납니다.

<script th:inline="javascript">
    ...
    var username = "Sebastian \"Fruity\" Applejuice";
    ...
</script>
위 코드에서 주목해야 할 두 가지 중요한 사항은 다음과 같습니다.

첫째 , JavaScript 인라인은 필요한 텍스트를 출력할 뿐만 아니라 따옴표로 묶고 JavaScript 이스케이프 처리를 하여 표현식 결과가 올바른 형식의 JavaScript 리터럴 로 출력되도록 합니다 .

둘째 , 이러한 현상이 발생하는 이유는 ${session.user.name}표현식을 이스케이프 처리 하여 출력하기 때문입니다 . 즉, 이중 대괄호 표현식을 사용하고 있습니다 [[${session.user.name}]]. 만약 이스케이프 처리하지 않은 표현식을 사용한다면 다음 과 같습니다.

<script th:inline="javascript">
    ...
    var username = [(${session.user.name})];
    ...
</script>
결과는 다음과 같습니다.

<script th:inline="javascript">
    ...
    var username = Sebastian "Fruity" Applejuice;
    ...
</script>
…이는 형식이 잘못된 자바스크립트 코드입니다. 하지만 인라인 표현식을 추가하여 스크립트의 일부를 구성하는 경우 이스케이프되지 않은 출력이 필요할 수 있으므로 이 도구를 사용하는 것이 좋습니다.

자바스크립트 자연 템플릿
앞서 언급한 자바스크립트 인라이닝 메커니즘의 지능은 단순히 자바스크립트 특유의 이스케이핑을 적용하고 표현식 결과를 유효한 리터럴로 출력하는 것 이상입니다.

예를 들어, (이스케이프 처리된) 인라인 표현식을 다음과 같은 JavaScript 주석으로 감쌀 수 있습니다.

<script th:inline="javascript">
    ...
    var username = /*[[${session.user.name}]]*/ "Gertrud Kiwifruit";
    ...
</script>
그리고 Thymeleaf는 주석 뒤와 세미콜론 (이 경우 ) 앞에 쓴 모든 내용을 무시하므로 'Gertrud Kiwifruit', 이 코드를 실행하면 래핑 주석을 사용하지 않았을 때와 정확히 같은 결과가 나타납니다.

<script th:inline="javascript">
    ...
    var username = "Sebastian \"Fruity\" Applejuice";
    ...
</script>
하지만 원래 템플릿 코드를 다시 한번 자세히 살펴보세요.

<script th:inline="javascript">
    ...
    var username = /*[[${session.user.name}]]*/ "Gertrud Kiwifruit";
    ...
</script>
이 코드가 유효한 자바스크립트 코드 라는 점에 주목하세요 . 그리고 서버에서 실행하지 않고 템플릿 파일을 정적으로 열면 이 코드가 완벽하게 실행됩니다.

그러니까 여기서는 자바스크립트를 이용한 자연스러운 템플릿을 만드는 방법을 보여드리겠습니다 !

13.1 텍스트 구문
Thymeleaf 템플릿 모드 중 세 가지 ( , 및 )는 텍스트 기반입니다 . 이는 마크업 템플릿 모드인 ( 및 ) 와 구별되는 점입니다 .TEXTJAVASCRIPTCSSHTMLXML

텍스트 템플릿 모드와 마크업 모드 의 주요 차이점은 텍스트 템플릿에는 속성 형태로 로직을 삽입할 수 있는 태그가 없으므로 다른 메커니즘에 의존해야 한다는 것입니다.

이러한 메커니즘 중 첫 번째이자 가장 기본적인 것은 인라인 처리 이며 , 이는 이전 장에서 이미 자세히 설명했습니다. 인라인 구문은 텍스트 템플릿 모드에서 표현식 결과를 출력하는 가장 간단한 방법이므로 텍스트 이메일에 완벽하게 적합한 템플릿입니다.

  Dear [(${name})],

  Please find attached the results of the report you requested
  with name "[(${report.name})]".

  Sincerely,
    The Reporter.
태그가 없더라도 위의 예시는 TEXT템플릿 모드에서 실행할 수 있는 완전하고 유효한 Thymeleaf 템플릿입니다.

하지만 단순한 출력 표현식 보다 더 복잡한 논리를 포함하려면 태그 기반이 아닌 새로운 구문이 필요합니다.

[# th:each="item : ${items}"]
  - [(${item})]
[/]
이는 사실 더 자세한 설명을 간략하게 줄인 버전입니다.

[#th:block th:each="item : ${items}"]
  - [#th:block th:utext="${item}" /]
[/th:block]
[#element ...]이 새로운 구문은 <p> 대신 <div> 로 선언되는 요소(즉, 처리 가능한 태그)를 기반으로 한다는 점에 유의하십시오 <element ...>. 요소는 <p>처럼 열고 [#element ...]<div>처럼 닫 으며, 독립형 태그는 XML 태그와 거의 동일한 방식 [/element]으로 <p>를 사용하여 여는 요소를 최소화함으로써 선언할 수 있습니다 ./[#element ... /]

표준 방언에는 이러한 요소 중 하나, 즉 이미 알려진 요소에 대한 프로세서만 포함되어 있지만 th:block, 일반적인 방식으로 방언을 확장하고 새 요소를 만들 수 있습니다. 또한 th:block요소( [#th:block ...] ... [/th:block])는 빈 문자열( )로 축약할 수 있으므로 [# ...] ... [/]위의 블록은 실제로 다음과 같습니다.

[# th:each="item : ${items}"]
  - [# th:utext="${item}" /]
[/]
그리고 `enable`은 이스케이프되지 않은 인라인 표현식[# th:utext="${item}" /] 과 동일하므로 , 코드를 줄이기 위해 이를 사용할 수 있습니다. 따라서 위에서 보았던 첫 번째 코드 조각을 얻게 됩니다.

[# th:each="item : ${items}"]
  - [(${item})]
[/]
참고로, 텍스트 구문은 모든 요소의 균형을 유지해야 하며(닫히지 않은 태그 없음) 속성을 따옴표로 묶어야 합니다 . 이는 HTML 스타일보다는 XML 스타일에 더 가깝습니다.

TEXT좀 더 완벽한 템플릿 예시인 일반 텍스트 이메일 템플릿을 살펴보겠습니다 .

15.1 템플릿 리졸버
저희 Good Thymes 가상 식료품점에서는 애플리케이션 리소스( 서블릿 기반 웹 애플리케이션의 서블릿 컨텍스트ITemplateResolver )에서 템플릿을 리소스로 가져올 수 있는 구현 방식 을 선택했습니다.WebApplicationTemplateResolver

Thymeleaf는 자체 템플릿 리졸버를 구현할 수 있는 기능을 제공할 뿐만 아니라 ITemplateResolver,기본적으로 네 가지 구현체를 제공합니다.

org.thymeleaf.templateresolver.ClassLoaderTemplateResolver이는 템플릿을 다음과 같은 클래스로더 리소스로 해석합니다.

return Thread.currentThread().getContextClassLoader().getResourceAsStream(template);
org.thymeleaf.templateresolver.FileTemplateResolver파일 시스템에서 템플릿을 파일로 해석하는 기능입니다. 예를 들면 다음과 같습니다.

return new FileInputStream(new File(template));
org.thymeleaf.templateresolver.UrlTemplateResolver템플릿을 URL(로컬 URL이 아닌 경우에도 포함)로 해석하는 기능은 다음과 같습니다.

return (new URL(template)).openStream();
org.thymeleaf.templateresolver.StringTemplateResolver이는 String지정된 대로 템플릿을 직접 해석합니다 template(또는 템플릿 이름 , 이 경우 템플릿 이름은 단순한 이름 이상의 의미를 가집니다).

return new StringReader(templateName);
미리 번들로 제공되는 모든 구현체는 ITemplateResolver다음과 같은 동일한 구성 매개변수 세트를 허용합니다.

접두사와 접미사(앞서 살펴본 바와 같이):

templateResolver.setPrefix("/WEB-INF/templates/");
templateResolver.setSuffix(".html");
파일 이름과 직접적으로 일치하지 않는 템플릿 이름을 사용할 수 있도록 하는 템플릿 별칭입니다. 접미사/접두사와 별칭이 모두 있는 경우, 별칭이 접두사/접미사보다 먼저 적용됩니다.

templateResolver.addTemplateAlias("adminHome","profiles/admin/home");
templateResolver.setTemplateAliases(aliasesMap);
템플릿을 읽을 때 적용할 인코딩:

templateResolver.setCharacterEncoding("UTF-8");
사용할 템플릿 모드:

// Default is HTML
templateResolver.setTemplateMode(TemplateMode.XML);
템플릿 캐시의 기본 모드와 특정 템플릿의 캐시 가능 여부를 정의하는 패턴:

// Default is true
templateResolver.setCacheable(false);
templateResolver.getCacheablePatternSpec().addPattern("/users/*");
이 템플릿 리졸버에서 생성된 파싱된 템플릿 캐시 항목의 TTL(밀리초)입니다. 설정하지 않으면 캐시에서 항목을 제거하는 유일한 방법은 캐시 최대 크기를 초과하는 것뿐입니다(가장 오래된 항목이 제거됨).

// Default is no TTL (only cache size exceeded would remove entries)
templateResolver.setCacheTTLMs(60000L);
Thymeleaf와 Spring 통합 패키지는 SpringResourceTemplateResolver애플리케이션에서 리소스에 접근하고 읽기 위해 Spring 인프라를 모두 활용하는 구현을 제공하며, 이는 Spring 기반 애플리케이션에서 권장되는 구현입니다.

체이닝 템플릿 리졸버
또한, 템플릿 엔진은 여러 개의 템플릿 리졸버를 지정할 수 있으며, 이 경우 템플릿 해결 순서를 정할 수 있습니다. 즉, 첫 번째 리졸버가 템플릿을 해결할 수 없는 경우 두 번째 리졸버에 요청하는 식으로 진행됩니다.

ClassLoaderTemplateResolver classLoaderTemplateResolver = new ClassLoaderTemplateResolver();
classLoaderTemplateResolver.setOrder(Integer.valueOf(1));

WebApplicationTemplateResolver webApplicationTemplateResolver = 
        new WebApplicationTemplateResolver(application);
webApplicationTemplateResolver.setOrder(Integer.valueOf(2));

templateEngine.addTemplateResolver(classLoaderTemplateResolver);
templateEngine.addTemplateResolver(webApplicationTemplateResolver);
여러 템플릿 리졸버를 사용하는 경우, 각 템플릿 리졸버에 패턴을 지정하여 Thymeleaf가 해당 템플릿을 해석하도록 설계되지 않은 리졸버를 신속하게 걸러내도록 하는 것이 좋습니다. 이렇게 하면 성능이 향상됩니다. 이는 필수 사항은 아니지만 권장 사항입니다.

ClassLoaderTemplateResolver classLoaderTemplateResolver = new ClassLoaderTemplateResolver();
classLoaderTemplateResolver.setOrder(Integer.valueOf(1));
// This classloader will not be even asked for any templates not matching these patterns 
classLoaderTemplateResolver.getResolvablePatternSpec().addPattern("/layout/*.html");
classLoaderTemplateResolver.getResolvablePatternSpec().addPattern("/menu/*.html");

WebApplicationTemplateResolver webApplicationTemplateResolver = 
        new WebApplicationTemplateResolver(application);
webApplicationTemplateResolver.setOrder(Integer.valueOf(2));
해결 가능한 패턴 이 지정되지 않은 경우 , ITemplateResolver사용 중인 각 구현체의 특정 기능에 의존하게 됩니다 . 모든 구현체가 해석 전에 템플릿의 존재 여부를 확인할 수 있는 것은 아니며, 따라서 템플릿을 항상 해석 가능한 것으로 간주 하여 해석 체인을 중단할 수 있습니다(다른 해석기가 동일한 템플릿을 확인할 수 없도록 함). 이 경우 실제 리소스를 읽을 수 없게 됩니다.

ITemplateResolverThymeleaf 코어에 포함된 모든 구현에는 리졸버가 리소스가 실제로 존재하는지 확인한 후에야 리졸버 로 간주할 수 있도록 하는 메커니즘이 포함되어 있습니다 . 이는 checkExistence다음과 같이 작동하는 플래그입니다.

ClassLoaderTemplateResolver classLoaderTemplateResolver = new ClassLoaderTemplateResolver();
classLoaderTemplateResolver.setOrder(Integer.valueOf(1));
classLoaderTemplateResolver.setCheckExistence(true);
이 checkExistence플래그는 리졸버가 해석 단계에서 리소스 존재 여부를 실제로 확인 하도록 강제합니다 (존재 여부 확인이 실패하면 체인의 다음 리졸버가 호출됩니다). 모든 경우에 좋아 보일 수 있지만, 대부분의 경우 리소스 자체에 두 번 접근하게 됩니다(한 번은 존재 여부 확인, 다른 한 번은 읽기). 따라서 일부 시나리오에서는 성능 문제가 발생할 수 있습니다. 예를 들어 원격 URL 기반 템플릿 리소스의 경우, 템플릿 캐시를 사용하면 이러한 성능 문제를 상당 부분 완화할 수 있습니다(템플릿은 처음 접근할 때만 해석 됩니다).

15.2 메시지 리졸버
저희는 식료품점 애플리케이션에 대한 메시지 리졸버 구현을 명시적으로 지정하지 않았으며, 앞서 설명드린 바와 같이 이는 사용된 구현이 객체임을 의미합니다 org.thymeleaf.messageresolver.StandardMessageResolver.

StandardMessageResolver이는 인터페이스의 표준 구현이지만 IMessageResolver, 원한다면 애플리케이션의 특정 요구 사항에 맞춰 자체 구현을 만들 수도 있습니다.

Thymeleaf와 Spring 통합 패키지는 기본적으로 Spring 애플리케이션 컨텍스트에 선언된 빈을 IMessageResolver사용하여 외부화된 메시지를 가져오는 표준 Spring 방식을 사용하는 구현을 제공합니다.MessageSource

표준 메시지 리졸버
그렇다면 StandardMessageResolver특정 템플릿에서 요청된 메시지는 어떤 모습일까요?

템플릿 이름이 home이고 해당 템플릿이 에 있으며 /WEB-INF/templates/home.html요청된 로케일이 인 경우, gl_ES이 리졸버는 다음 파일에서 이 순서대로 메시지를 찾습니다.

/WEB-INF/templates/home_gl_ES.properties
/WEB-INF/templates/home_gl.properties
/WEB-INF/templates/home.properties
클래스 의 JavaDoc 문서를 참조하면 StandardMessageResolver전체 메시지 해결 메커니즘이 어떻게 작동하는지에 대한 자세한 내용을 확인할 수 있습니다.

메시지 리졸버 구성
템플릿 엔진에 메시지 리졸버(또는 그 이상)를 추가하고 싶다면 어떻게 해야 할까요? 간단합니다.

// For setting only one
templateEngine.setMessageResolver(messageResolver);

// For setting more than one
templateEngine.addMessageResolver(messageResolver);
그렇다면 메시지 리졸버를 두 개 이상 두려는 이유는 무엇일까요? 템플릿 리졸버와 같은 이유입니다. 메시지 리졸버는 순서대로 작동하며, 첫 번째 리졸버가 특정 메시지를 해결할 수 없으면 두 번째 리졸버에 요청하고, 그 다음에는 세 번째 리졸버에 요청하는 식으로 진행됩니다.

15.3 변환 서비스
이중 중괄호 구문( ) 을 사용하여 데이터 변환 및 서식 지정 작업을 수행할 수 있도록 하는 변환 서비스는 실제로 Thymeleaf 템플릿 엔진 자체의 기능이 아니라 표준 방언의 기능입니다.${{...}}

따라서 이를 구성하는 방법은 템플릿 엔진에 구성 중인 IStandardConversionService인스턴스에 인터페이스의 사용자 지정 구현을 직접 설정하는 것입니다. 예를 들면 다음과 같습니다.StandardDialect

IStandardConversionService customConversionService = ...

StandardDialect dialect = new StandardDialect();
dialect.setConversionService(customConversionService);

templateEngine.setDialect(dialect);
참고로 thymeleaf-spring3 및 thymeleaf-spring4 패키지에는 해당 기능이 포함되어 있으며 , 이 다이얼렉트는 Spring 자체의 변환 서비스 인프라를 Thymeleaf에 통합하는 SpringStandardDialect구현이 이미 사전 구성되어 있습니다 .IStandardConversionService

15.4 로깅
Thymeleaf는 로깅에 상당한 신경을 쓰고 있으며, 로깅 인터페이스를 통해 최대한 많은 유용한 정보를 제공하기 위해 항상 노력합니다.

사용된 로깅 라이브러리는 slf4j,실제로 애플리케이션에서 사용하려는 모든 로깅 구현(예: log4j)과의 연결 고리 역할을 합니다.

Thymeleaf 클래스는 원하는 세부 수준에 따라 일반 로깅 TRACE, 하위 로깅 DEBUG및 하위 수준 정보를 기록하며 , 일반 로깅 외에도 TemplateEngine 클래스와 관련된 세 가지 특수 로거를 사용하는데, 이 로거들은 각각 다른 용도로 개별적으로 구성할 수 있습니다.INFO

org.thymeleaf.TemplateEngine.CONFIG초기화 중에 라이브러리의 상세 구성 정보를 출력합니다.
org.thymeleaf.TemplateEngine.TIMER각 템플릿을 처리하는 데 걸린 시간에 대한 정보를 출력합니다(벤치마킹에 유용합니다!).
org.thymeleaf.TemplateEngine.cache는 캐시에 대한 특정 정보를 출력하는 로거 집합의 접두사입니다. 캐시 로거의 이름은 사용자가 구성할 수 있으므로 변경될 수 있지만 기본값은 다음과 같습니다.
org.thymeleaf.TemplateEngine.cache.TEMPLATE_CACHE
org.thymeleaf.TemplateEngine.cache.EXPRESSION_CACHE
Thymeleaf의 로깅 인프라를 사용하는 예시 구성은 log4j다음과 같습니다.

log4j.logger.org.thymeleaf=DEBUG
log4j.logger.org.thymeleaf.TemplateEngine.CONFIG=TRACE
log4j.logger.org.thymeleaf.TemplateEngine.TIMER=TRACE
log4j.logger.org.thymeleaf.TemplateEngine.cache.TEMPLATE_CACHE=TRACE
16 템플릿 캐시
Thymeleaf는 마크업 및 텍스트 파서 세트를 통해 템플릿을 일련의 이벤트(열기 태그, 텍스트, 닫기 태그, 주석 등)로 파싱하고, 적용해야 하는 각 동작 유형에 대한 프로세서 세트를 통해 파싱된 템플릿 이벤트 시퀀스를 수정하여 원래 템플릿과 데이터를 결합함으로써 원하는 결과를 생성합니다.

또한 기본적으로 파싱된 템플릿을 저장하는 캐시가 포함되어 있습니다. 이는 템플릿 파일을 읽고 파싱한 후 처리하기 전에 발생하는 일련의 이벤트를 저장합니다. 특히 웹 애플리케이션 작업 시 유용하며, 다음과 같은 개념을 기반으로 합니다.

입출력은 거의 모든 애플리케이션에서 가장 느린 부분입니다. 반면에 메모리 처리는 매우 빠릅니다.
기존 메모리 내 이벤트 시퀀스를 복제하는 것은 템플릿 파일을 읽고 구문 분석하여 새 이벤트 시퀀스를 생성하는 것보다 항상 훨씬 빠릅니다.
웹 애플리케이션은 일반적으로 템플릿이 수십 개 정도밖에 없습니다.
템플릿 파일은 크기가 작거나 중간 정도이며, 애플리케이션이 실행되는 동안에는 수정되지 않습니다.
이 모든 것을 종합해 보면, 웹 애플리케이션에서 가장 많이 사용되는 템플릿을 캐싱하는 것이 많은 메모리를 낭비하지 않고도 가능하며, 실제로 변경되지 않는 소수의 파일에 대한 입출력 작업에 소요되는 시간을 크게 절약할 수 있다는 결론에 도달합니다.

그렇다면 이 캐시를 어떻게 제어할 수 있을까요? 우선, 템플릿 리졸버에서 캐시를 활성화 또는 비활성화할 수 있으며, 특정 템플릿에만 적용할 수도 있다는 것을 이미 배웠습니다.

// Default is true
templateResolver.setCacheable(false);
templateResolver.getCacheablePatternSpec().addPattern("/users/*");
또한, 기본 구현의 인스턴스가 될 수 있는 자체 캐시 관리자StandardCacheManager 객체를 설정하여 구성을 수정할 수도 있습니다 .

// Default is 200
StandardCacheManager cacheManager = new StandardCacheManager();
cacheManager.setTemplateCacheMaxSize(100);
...
templateEngine.setCacheManager(cacheManager);
org.thymeleaf.cache.StandardCacheManager캐시 구성에 대한 자세한 내용은 해당 API의 Javadoc을 참조하십시오 .

템플릿 캐시에서 항목을 수동으로 삭제할 수 있습니다.

// Clear the cache completely
templateEngine.clearTemplateCache();

// Clear a specific template from the cache
templateEngine.clearTemplateCacheFor("/users/userList");
17. 분리형 템플릿 로직
17.1 분리된 논리: 개념
지금까지 저희는 일반적인 방식 으로 템플릿을 만들어 식료품점 웹사이트를 운영해 왔으며 , 템플릿에 속성 형태로 로직을 삽입해 왔습니다.

하지만 Thymeleaf는 템플릿 마크업과 로직을 완전히 분리할 수 있도록 해주므로 , 로직이 전혀 없는 마크업 템플릿을HTML 템플릿 모드 에서 생성할 수 있습니다 XML.

핵심 아이디어는 템플릿 로직이 별도의 로직 파일 (더 정확히는 로직 리소스 이며, 반드시 파일 일 필요는 없음 )에 정의된다는 것입니다. 기본적으로 이 로직 리소스는 템플릿 파일과 동일한 위치(예: 폴더)에 있는 추가 파일로, 이름은 같지만 .th.xml확장자는 다릅니다.

/templates
+->/home.html
+->/home.th.xml
따라서 home.html파일에는 논리적인 내용이 전혀 없을 수 있습니다. 예를 들어 다음과 같을 수 있습니다.

<!DOCTYPE html>
<html>
  <body>
    <table id="usersTable">
      <tr>
        <td class="username">Jeremy Grapefruit</td>
        <td class="usertype">Normal User</td>
      </tr>
      <tr>
        <td class="username">Alice Watermelon</td>
        <td class="usertype">Administrator</td>
      </tr>
    </table>
  </body>
</html>
여기에는 Thymeleaf 코드가 전혀 없습니다. Thymeleaf나 템플릿에 대한 지식이 없는 디자이너도 만들거나 편집하거나 이해할 수 있는 템플릿 파일입니다. 또는 Thymeleaf 관련 코드가 전혀 없는 외부 시스템에서 제공한 HTML 조각일 수도 있습니다.

이제 다음과 같이 home.html추가 파일을 생성하여 해당 템플릿을 Thymeleaf 템플릿으로 바꿔 보겠습니다 .home.th.xml

<?xml version="1.0"?>
<thlogic>
  <attr sel="#usersTable" th:remove="all-but-first">
    <attr sel="/tr[0]" th:each="user : ${users}">
      <attr sel="td.username" th:text="${user.name}" />
      <attr sel="td.usertype" th:text="#{|user.type.${user.type}|}" />
    </attr>
  </attr>
</thlogic>
<attr>여기서는 블록 안에 많은 태그가 있는 것을 볼 수 있습니다 thlogic. 이러한 <attr>태그는 속성을 통해 선택된 원래 템플릿의 노드에 속성을 삽입sel 하는데 , 이 속성에는 Thymeleaf 마크업 선택자 (실제로는 AttoParser 마크업 선택자 )가 포함되어 있습니다.

또한 <attr>태그는 중첩될 수 있으며, 이 경우 선택자가 태그 뒤에 추가 됩니다 . sel="/tr[0]"예를 들어 위의 코드는 로 처리됩니다 sel="#usersTable/tr[0]". 그리고 사용자 이름에 대한 선택자는 <td>로 처리됩니다 sel="#usersTable/tr[0]//td.username".

따라서 두 파일을 병합하면 위에 보이는 두 파일은 다음과 같이 동일해집니다.

<!DOCTYPE html>
<html>
  <body>
    <table id="usersTable" th:remove="all-but-first">
      <tr th:each="user : ${users}">
        <td class="username" th:text="${user.name}">Jeremy Grapefruit</td>
        <td class="usertype" th:text="#{|user.type.${user.type}|}">Normal User</td>
      </tr>
      <tr>
        <td class="username">Alice Watermelon</td>
        <td class="usertype">Administrator</td>
      </tr>
    </table>
  </body>
</html>
이 방식이 더 익숙해 보이고, 실제로 두 개의 별도 파일을 만드는 것보다 간결합니다 . 하지만 템플릿을 분리하는 장점은 템플릿을 Thymeleaf와 완전히 독립적으로 만들 수 있어 설계 관점에서 유지 관리가 훨씬 용이하다는 것입니다.

물론 디자이너와 개발자 간의 일부 계약 , 예를 들어 사용자가 <table>필요로 하는 사항 등은 여전히 ​​필요하겠지만 id="usersTable", 많은 경우 순수 HTML 템플릿이 디자인 팀과 개발 팀 간의 훨씬 더 나은 소통 수단이 될 것입니다.

17.2 분리형 템플릿 구성
분리된 템플릿 활성화
기본적으로 모든 템플릿에 대해 분리된 로직이 요구되지는 않습니다. 대신, 구성된 템플릿 리졸버(구현체)는 분리된 로직을 사용ITemplateResolver 하는 템플릿을 명시적으로 표시해야 합니다 .

(분리된 로직을 허용하지 않는) 예외를 제외하고 StringTemplateResolver, 의 다른 모든 기본 구현은 해당 리졸버가 해결하는 모든 템플릿에 로직의 전부 또는 일부가 별도의 리소스에 있을 가능성이 있음을 표시하는 ITemplateResolver플래그를 제공합니다 .useDecoupledLogic

final WebApplicationTemplateResolver templateResolver = 
        new WebApplicationTemplateResolver(application);
...
templateResolver.setUseDecoupledLogic(true);
결합 논리와 비결합 논리의 혼합
분리된 템플릿 로직은 활성화 시 필수 사항이 아닙니다. 활성화되면 엔진은 분리된 로직이 포함된 리소스를 찾아 해당 리소스를 파싱하고, 존재하면 원래 템플릿과 병합합니다. 분리된 로직 리소스가 없더라도 오류는 발생하지 않습니다.

또한, 동일한 템플릿 내에서 결합된 로직 과 분리된 로직을 혼합하여 사용할 수 있습니다. 예를 들어, 일부 Thymeleaf 속성은 원래 템플릿 파일에 추가하고 나머지는 별도의 분리된 로직 파일에 남겨둘 수 있습니다. 가장 일반적인 예는 (v3.0에서 새로 추가된) th:ref속성을 사용하는 것입니다.

17.3 th:ref 속성
th:ref이는 단지 마커 속성일 뿐입니다. 처리 관점에서는 아무런 역할을 하지 않으며 템플릿이 처리될 때 단순히 사라지지만, 마크업 참조 역할을 한다는 점에서 유용합니다. 즉, 태그 이름 이나 프래그먼트 처럼 마크업 선택기 에서 이름 으로 확인할 수 있습니다 .th:fragment

만약 다음과 같은 선택자가 있다면:

  <attr sel="whatever" .../>
이것은 다음과 일치합니다:

태그 없음 <whatever>.
속성을 가진 모든 태그 th:fragment="whatever".
속성을 가진 모든 태그 th:ref="whatever".
th:ref예를 들어 순수 HTML 속성을 사용하는 것과 비교했을 때 어떤 장점이 있을까요 ? 단순히 논리 앵커 역할을 하는 속성 을 태그에 너무 많이 추가하여 출력 결과를 복잡하게 만들지 id않으려는 것뿐입니다 .idclass

같은 맥락에서, 단점은 무엇일까요 ? 당연히 템플릿에 Thymeleaf 로직( "로직"th:ref ) 을 조금 추가해야 한다는 점입니다 .

참고로 이 th:ref속성 의 적용 가능성은 분리된 로직 템플릿 파일에만 적용되는 것이 아닙니다 . 프래그먼트 표현식( )과 같은 다른 유형의 시나리오에서도 동일하게 작동합니다 ~{...}.

17.4 분리된 템플릿의 성능 영향
영향은 극히 미미합니다. 해결된 템플릿이 분리된 로직을 사용하도록 표시되어 있고 캐시되지 않은 경우, 템플릿 로직 리소스가 먼저 해결되어 메모리에서 구문 분석되고 일련의 명령어로 처리됩니다. 기본적으로 각 마크업 선택기에 삽입될 속성 목록입니다.

하지만 이것이 필요한 유일한 추가 단계 입니다 . 이후에는 실제 템플릿이 파싱되고, 파싱 과정에서 AttoParser의 고급 노드 선택 기능 덕분에 파서 자체에서 이러한 속성들을 즉시 삽입합니다 . 따라서 파싱된 노드는 마치 원래 템플릿 파일에 삽입된 속성이 이미 작성된 것처럼 파서에서 출력됩니다.

이것의 가장 큰 장점은 무엇일까요? 템플릿이 캐시되도록 구성되면, 주입된 속성이 이미 포함된 상태로 캐시됩니다. 따라서 캐시 가능한 템플릿에 대해 분리된 템플릿을 사용하는 데 따른 오버헤드는 일단 캐시되면 완전히 0이 됩니다 .

17.5 분리된 논리의 해결
Thymeleaf가 각 템플릿에 해당하는 분리된 로직 리소스를 해결하는 방식은 사용자가 구성할 수 있습니다. 이는 확장 지점인 에 의해 결정되며, org.thymeleaf.templateparser.markup.decoupled.IDecoupledTemplateLogicResolver기본 구현이 제공됩니다 StandardDecoupledTemplateLogicResolver.

이 표준 구현 방식은 무엇을 하는가?

먼저, 해당 메서드를 통해 얻은 템플릿 리소스의 기본 이름 에 접두사 prefix와 접미사를 적용합니다 . 접두사와 접미사 모두 구성 가능하며, 기본적으로 접두사는 비어 있고 접미사는 비어 있습니다 .suffixITemplateResource#getBaseName().th.xml
둘째, 템플릿 리소스에게 해당 메서드를 사용하여 계산된 이름으로 상대 리소스를ITemplateResource#relative(String relativeLocation) 확인하도록 요청합니다 .
IDecoupledTemplateLogicResolver사용할 구체적인 구현 방식은 다음에서 TemplateEngine쉽게 설정할 수 있습니다.

final StandardDecoupledTemplateLogicResolver decoupledResolver = 
        new StandardDecoupledTemplateLogicResolver();
decoupledResolver.setPrefix("../viewlogic/");
...
templateEngine.setDecoupledTemplateLogicResolver(decoupledResolver);

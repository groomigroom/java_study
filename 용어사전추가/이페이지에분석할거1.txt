환경 변수와 시스템 속성에는 종종 제약 조건이 있어 일부 속성 이름을 사용할 수 없는 경우가 있습니다. 이러한 문제를 해결하기 위해 Spring Boot는 여러 속성 블록을 단일 JSON 구조로 인코딩할 수 있도록 지원합니다.

애플리케이션이 시작될 때 모든 spring.application.json속성 SPRING_APPLICATION_JSON이 파싱되어 에 추가됩니다 Environment.

$ SPRING_APPLICATION_JSON='{"my":{"name":"test"}}' java -jar myapp.jar
앞의 예에서, 당신은 my.name=test봄에 다음과 같은 결과를 얻게 됩니다 Environment.

동일한 JSON 데이터를 시스템 속성으로도 제공할 수 있습니다.

$ java -Dspring.application.json='{"my":{"name":"test"}}' -jar myapp.jar
또는 명령줄 인수를 사용하여 JSON을 제공할 수도 있습니다.

$ java -jar myapp.jar --spring.application.json='{"my":{"name":"test"}}'

위치 설정이 복잡하고 프로필별 구성 파일을 사용하는 경우, Spring Boot가 위치를 어떻게 그룹화해야 하는지 알 수 있도록 추가적인 힌트를 제공해야 할 수 있습니다. 위치 그룹은 동일한 수준으로 간주되는 위치들의 모음입니다. 예를 들어, 모든 클래스패스 위치를 그룹화한 다음 모든 외부 위치를 그룹화할 수 있습니다. 위치 그룹 내의 항목은 쉼표(,)로 구분해야 합니다 . 자세한 내용은 프로필별 파일; 섹션 의 예제를 참조하십시오 .

와일드카드 위치
설정 파일 위치에 *마지막 경로 세그먼트에 해당하는 문자가 포함되어 있으면 와일드카드 위치로 간주됩니다. 와일드카드는 설정이 로드될 때 확장되어 바로 아래 하위 디렉터리도 검사합니다. 와일드카드 위치는 Kubernetes와 같이 설정 속성에 대한 소스가 여러 개인 환경에서 특히 유용합니다.

예를 들어, Redis 설정과 MySQL 설정이 각각 있는 경우, 두 설정을 분리하여 관리하면서도 하나의 파일에 모두 저장되도록 하고 싶을 수 있습니다 . 이 경우, 서로 다른 위치(예: application.properties`/etc/redis/my-system/`)에 두 개의 별도 application.properties파일을 마운트할 수 있습니다. 하지만 와일드카드로 `/etc/redis/my-system/`을 지정하면 두 파일 모두 처리됩니다./config/redis/application.properties/config/mysql/application.propertiesconfig/*/

기본적으로 Spring Boot는 config/*/기본 검색 위치에 특정 디렉토리를 포함합니다. 즉 , /configjar 파일 외부의 모든 하위 디렉토리를 검색한다는 의미입니다.

"고정" 및 "상대 위치 가져오기" 사용
가져오기 위치는 고정 위치 또는 상대 위치 로 지정할 수 있습니다 . 고정 위치는 속성이 선언된 위치에 관계없이 항상 동일한 기본 리소스로 해석됩니다 spring.config.import. 상대 위치는 속성을 선언한 파일을 기준으로 해석됩니다 spring.config.import.

슬래시(/ /) 또는 URL 스타일 접두사( file:, classpath:, 등)로 시작하는 위치는 고정된 것으로 간주됩니다. 그 외의 모든 위치는 가져오기 상대 위치로 간주됩니다.

optional:위치가 고정된 위치인지 아니면 상대적인 위치인지 판단할 때 접두사는 고려되지 않습니다.

spring.config.import=optional:core/core.properties
이 경로는 상대 경로로 가져오기되므로 파일이 /demo/core/core.properties존재하면 해당 파일을 로드하려고 시도합니다.

@ConfigurationProperties("my.service")
public class MyProperties {

	private InetAddress remoteAddress;

	private final Security security = new Security();

	// getters / setters...

	}

		this.enabled = enabled;
	}

		return this.remoteAddress;
	}

	}

	public Security getSecurity() {
		return this.security;
	}

		private String username;

		private String password;

		private List<String> roles = new ArrayList<>(Collections.singleton("USER"));

		// getters / setters...

		public String getUsername() {
			return this.username;
		}

		public void setUsername(String username) {
			this.username = username;
		}

		public String getPassword() {
			return this.password;
		}

		public void setPassword(String password) {
			this.password = password;
		}

		public List<String> getRoles() {
			return this.roles;
		}

Spring Boot에서 사용 가능한 클래스 에 매핑되는 속성은 @ConfigurationProperties속성 파일, YAML 파일, 환경 변수 및 기타 메커니즘을 통해 구성되며 공개 API이지만 클래스 자체의 접근자(getter/setter)는 직접 사용하도록 설계되지 않았습니다.
이러한 구성은 기본적으로 비어 있는 생성자를 사용하며, 바인딩이 Spring MVC와 마찬가지로 표준 Java Beans 속성 디스크립터를 통해 이루어지기 때문에 일반적으로 getter와 setter가 필수적입니다. 다음의 경우에는 setter를 생략할 수 있습니다.

roles미리 초기화된 맵과 컬렉션은, 앞의 예제에서처럼 변경 가능한 구현으로 초기화된 경우에 한해 사용 가능합니다 .

미리 초기화된 중첩 POJO( Security앞의 예제 필드와 같은)입니다. 바인더가 기본 생성자를 사용하여 인스턴스를 즉시 생성하도록 하려면 setter가 필요합니다.

일부 사용자는 Project Lombok을 사용하여 getter와 setter를 자동으로 추가합니다. 컨테이너가 객체를 인스턴스화할 때 해당 타입에 대한 특정 생성자를 자동으로 사용하므로 Lombok이 이러한 타입에 대해 특정 생성자를 생성하지 않도록 주의해야 합니다.

마지막으로, 표준 Java Bean 속성만 고려되며 정적 속성에 대한 바인딩은 지원되지 않습니다.

이전 섹션의 예제는 다음 예제와 같이 불변 방식으로 다시 작성할 수 있습니다.

import java.net.InetAddress;
import java.util.List;

import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.boot.context.properties.bind.DefaultValue;

@ConfigurationProperties("my.service")
public class MyProperties {

	// fields...

	private final boolean enabled;

	private final InetAddress remoteAddress;

	private final Security security;


	public MyProperties(boolean enabled, InetAddress remoteAddress, Security security) {
		this.enabled = enabled;
		this.remoteAddress = remoteAddress;
		this.security = security;
	}

	// getters...

	public boolean isEnabled() {
		return this.enabled;
	}

	public InetAddress getRemoteAddress() {
		return this.remoteAddress;
	}

	public Security getSecurity() {
		return this.security;
	}

	public static class Security {

		// fields...

		private final String username;

		private final String password;

		private final List<String> roles;


		public Security(String username, String password, @DefaultValue("USER") List<String> roles) {
			this.username = username;
			this.password = password;
			this.roles = roles;
		}

		// getters...

		public String getUsername() {
			return this.username;
		}

		public String getPassword() {
			return this.password;
		}

		public List<String> getRoles() {
			return this.roles;
		}

	}

}

import java.time.Duration;
import java.time.temporal.ChronoUnit;

import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.boot.convert.DurationUnit;

@ConfigurationProperties("my")
public class MyProperties {

	@DurationUnit(ChronoUnit.SECONDS)
	private Duration sessionTimeout = Duration.ofSeconds(30);

	private Duration readTimeout = Duration.ofMillis(1000);

	// getters / setters...

	public Duration getSessionTimeout() {
		return this.sessionTimeout;
	}

	public void setSessionTimeout(Duration sessionTimeout) {
		this.sessionTimeout = sessionTimeout;
	}

	public Duration getReadTimeout() {
		return this.readTimeout;
	}

	public void setReadTimeout(Duration readTimeout) {
		this.readTimeout = readTimeout;
	}

}

import java.time.Duration;
import java.time.temporal.ChronoUnit;

import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.boot.context.properties.bind.DefaultValue;
import org.springframework.boot.convert.DurationUnit;

@ConfigurationProperties("my")
public class MyProperties {

	// fields...
	private final Duration sessionTimeout;

	private final Duration readTimeout;

	public MyProperties(@DurationUnit(ChronoUnit.SECONDS) @DefaultValue("30s") Duration sessionTimeout,
			@DefaultValue("1000ms") Duration readTimeout) {
		this.sessionTimeout = sessionTimeout;
		this.readTimeout = readTimeout;
	}

	// getters...

	public Duration getSessionTimeout() {
		return this.sessionTimeout;
	}

	public Duration getReadTimeout() {
		return this.readTimeout;
	}

}

기간 변환
Spring Boot는 기간 외에도 Period유형을 사용할 수 있습니다. 애플리케이션 속성에서 사용할 수 있는 형식은 다음과 같습니다.

일반적인 표현 방식 ( 별도로 지정하지 int않는 한 기본 단위는 일입니다 )@PeriodUnit

ISO-8601 표준 형식은 다음과 같은 데 사용됩니다.Period

값과 단위가 쌍으로 연결된 더 간단한 형식입니다( 1y3d예: 1년 3일).

다음 단위들이 간편 형식으로 지원됩니다:

y수년간

m몇 달 동안

w몇 주 동안

d며칠 동안

해당 Period데이터 유형은 실제로 주 수를 저장하는 것이 아니라, "7일"을 의미하는 약어입니다.
데이터 크기 변환
Spring Framework는 DataSize크기를 바이트 단위로 표현하는 값 형식을 제공합니다. DataSize속성을 노출하는 경우 애플리케이션 속성에서 다음과 같은 형식을 사용할 수 있습니다.

일반적인 표현 방식 ( 별도로 지정하지 long않는 한 기본 단위는 바이트입니다 )@DataSizeUnit

값과 단위가 함께 표시된 더 읽기 쉬운 형식입니다( 10MB예: 10메가바이트).

다음 예를 생각해 보세요.

자바

코틀린

import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.boot.convert.DataSizeUnit;
import org.springframework.util.unit.DataSize;
import org.springframework.util.unit.DataUnit;

@ConfigurationProperties("my")
public class MyProperties {

	@DataSizeUnit(DataUnit.MEGABYTES)
	private DataSize bufferSize = DataSize.ofMegabytes(2);

	private DataSize sizeThreshold = DataSize.ofBytes(512);

	// getters/setters...

	public DataSize getBufferSize() {
		return this.bufferSize;
	}

	public void setBufferSize(DataSize bufferSize) {
		this.bufferSize = bufferSize;
	}

	public DataSize getSizeThreshold() {
		return this.sizeThreshold;
	}

	public void setSizeThreshold(DataSize sizeThreshold) {
		this.sizeThreshold = sizeThreshold;
	}

}
버퍼 크기를 10메가바이트로 지정하려면 10와 는 동일합니다. 크기 임계값 256바이트는 또는 10MB로 지정할 수 있습니다 .256256B

지원되는 단위를 사용하셔도 됩니다. 지원되는 단위는 다음과 같습니다.

B바이트의 경우

KB킬로바이트 단위

MB메가바이트의 경우

GB기가바이트의 경우

TB테라바이트의 경우

기본 단위는 바이트이며, @DataSizeUnit위 예시에서처럼 단위를 변경하여 재정의할 수 있습니다.

생성자 바인딩을 사용하려는 경우 다음 예제와 같이 동일한 속성을 노출할 수 있습니다.

자바

코틀린

import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.boot.context.properties.bind.DefaultValue;
import org.springframework.boot.convert.DataSizeUnit;
import org.springframework.util.unit.DataSize;
import org.springframework.util.unit.DataUnit;

@ConfigurationProperties("my")
public class MyProperties {

	// fields...
	private final DataSize bufferSize;

	private final DataSize sizeThreshold;

	public MyProperties(@DataSizeUnit(DataUnit.MEGABYTES) @DefaultValue("2MB") DataSize bufferSize,
			@DefaultValue("512B") DataSize sizeThreshold) {
		this.bufferSize = bufferSize;
		this.sizeThreshold = sizeThreshold;
	}

	// getters...

	public DataSize getBufferSize() {
		return this.bufferSize;
	}

	public DataSize getSizeThreshold() {
		return this.sizeThreshold;
	}

}
속성 을 업그레이드할 경우 , 단위 가 바이트가 아니면 Long(를 사용하여) 단위를 정의해야 합니다 . 이렇게 하면 훨씬 더 풍부한 형식을 지원하면서 투명한 업그레이드 경로를 제공할 수 있습니다.@DataSizeUnit

@ConfigurationProperties 유효성 검사
@ConfigurationPropertiesSpring Boot는 클래스에 Spring 어노테이션이 추가될 때마다 유효성 검사를 시도합니다 @Validated. JSR-303 제약 조건 어노테이션을 구성 클래스에 직접 사용할 수도 있습니다 jakarta.validation. 이를 위해서는 JSR-303을 준수하는 구현체가 클래스패스에 있는지 확인한 다음, 다음 예제와 같이 필드에 제약 조건 어노테이션을 추가하면 됩니다.

자바

코틀린

import java.net.InetAddress;

import jakarta.validation.constraints.NotNull;

import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.validation.annotation.Validated;

@ConfigurationProperties("my.service")
@Validated
public class MyProperties {

	@NotNull
	private InetAddress remoteAddress;

	// getters/setters...

	public InetAddress getRemoteAddress() {
		return this.remoteAddress;
	}

	public void setRemoteAddress(InetAddress remoteAddress) {
		this.remoteAddress = remoteAddress;
	}

}
@Bean구성 속성을 생성하는 메서드에 어노테이션을 추가하여 유효성 검사를 트리거할 수도 있습니다 @Validated.
중첩된 속성에 대한 유효성 검사를 적용하려면 관련 필드에 어노테이션을 추가해야 합니다 @Valid. 다음 예제는 앞의 MyProperties예제를 기반으로 합니다.

코틀린

import java.net.InetAddress;

import jakarta.validation.Valid;
import jakarta.validation.constraints.NotEmpty;
import jakarta.validation.constraints.NotNull;

import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.validation.annotation.Validated;

@ConfigurationProperties("my.service")
@Validated
public class MyProperties {

	@NotNull
	private InetAddress remoteAddress;

	@Valid
	private final Security security = new Security();

	// getters/setters...

	public InetAddress getRemoteAddress() {
		return this.remoteAddress;
	}

	public void setRemoteAddress(InetAddress remoteAddress) {
		this.remoteAddress = remoteAddress;
	}

	public Security getSecurity() {
		return this.security;
	}

	public static class Security {

		@NotEmpty
		private String username;

		// getters/setters...

		public String getUsername() {
			return this.username;
		}

		public void setUsername(String username) {
			this.username = username;
		}

	}

}
Validator또한 `construction properties validator` 라는 이름의 빈 정의를 생성하여 사용자 지정 Spring 빈을 추가할 수 있습니다 configurationPropertiesValidator. 해당 @Bean메서드는 `static`으로 선언해야 합니다 static. 구성 속성 유효성 검사기는 애플리케이션 수명 주기 초기에 생성되므로, 메서드를 @Bean`static`으로 선언하면 클래스를 인스턴스화하지 않고도 빈을 생성할 수 있습니다 @Configuration. 이렇게 하면 조기 인스턴스화로 인해 발생할 수 있는 문제를 방지할 수 있습니다.

이 spring-boot-actuator모듈에는 모든 빈을 노출하는 엔드포인트가 포함되어 있습니다 @ConfigurationProperties. 웹 브라우저에서 /actuator/configprops해당 엔드포인트로 접속하거나, 이에 상응하는 JMX 엔드포인트를 사용하십시오. 자세한 내용은 프로덕션 환경 기능 섹션을 참조하십시오.
@ConfigurationProperties와 @Value의 차이점
어노테이션 @Value은 컨테이너의 핵심 기능이며, 타입 안전 구성 속성과 동일한 기능을 제공하지는 않습니다. 다음 표는 @ConfigurationProperties어노테이션 에서 지원하는 기능을 요약한 것입니다 @Value.

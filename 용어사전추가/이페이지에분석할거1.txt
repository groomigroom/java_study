속성 변환
Spring Boot는 외부 애플리케이션 속성을 빈에 바인딩할 때 올바른 유형으로 강제 변환하려고 시도합니다 @ConfigurationProperties. 사용자 지정 유형 변환이 필요한 경우, ConversionService빈(이름이 인 빈 conversionService)이나 사용자 지정 속성 편집기(빈을 통해 CustomEditorConfigurer) 또는 사용자 지정 변환기(빈 정의에 어노테이션이 있는 @ConfigurationPropertiesBinding)를 제공할 수 있습니다.

속성 변환에 사용되는 빈은 애플리케이션 수명 주기 초기에 요청되므로 사용하는 종속성을 제한해야 합니다 ConversionService. 일반적으로 필요한 종속성은 생성 시점에 완전히 초기화되지 않은 경우가 많습니다.

ConversionService구성 키 강제 변환에 필요하지 않고, 특정 조건으로 한정된 사용자 지정 변환기만 사용하는 경우 사용자 지정 변환기의 이름을 변경하는 것이 좋습니다 . 특정 조건으로 메서드를 @ConfigurationPropertiesBinding한정할 때는 "모든 BeanPostProcessors에서 처리될 수 없는 빈입니다"라는 경고를 피하기 위해 메서드 이름이 특정 조건이어야 합니다 .@Bean@ConfigurationPropertiesBindingstatic
기간 변환
Spring Boot는 기간을 표현하기 위한 전용 지원 기능을 제공합니다. 속성을 노출하는 경우 Duration애플리케이션 속성에서 다음과 같은 형식을 사용할 수 있습니다.

일반적인 표현 방식 ( 별도로 지정하지 long않는 한 기본 단위는 밀리초입니다 )@DurationUnit

ISO-8601 표준 형식은 다음과 같은 데 사용됩니다.Duration

값과 단위가 함께 표시된 더 읽기 쉬운 형식입니다( 10s예: 10초).

import java.time.Duration;
import java.time.temporal.ChronoUnit;

import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.boot.convert.DurationUnit;

@ConfigurationProperties("my")
public class MyProperties {

	@DurationUnit(ChronoUnit.SECONDS)
	private Duration sessionTimeout = Duration.ofSeconds(30);

	private Duration readTimeout = Duration.ofMillis(1000);

	// getters / setters...

	public Duration getSessionTimeout() {
		return this.sessionTimeout;
	}

	public void setSessionTimeout(Duration sessionTimeout) {
		this.sessionTimeout = sessionTimeout;
	}

	public Duration getReadTimeout() {
		return this.readTimeout;
	}

	public void setReadTimeout(Duration readTimeout) {
		this.readTimeout = readTimeout;
	}

}
세션 시간 제한을 30초로 지정하려면 30, PT30S및 30s는 모두 동일합니다. 읽기 시간 제한을 500ms로 지정하려면 다음 형식 중 하나를 사용할 수 있습니다. 500, PT0.5S및 500ms.

지원되는 단위를 사용하셔도 됩니다. 지원되는 단위는 다음과 같습니다.

us마이크로초 동안

ms밀리초 동안

s초 동안

m몇 분 동안

h몇 시간 동안

d며칠 동안

기본 단위는 밀리초이며, @DurationUnit위 예시에서처럼 단위를 변경하여 재정의할 수 있습니다.

import java.net.InetAddress;

import jakarta.validation.Valid;
import jakarta.validation.constraints.NotEmpty;
import jakarta.validation.constraints.NotNull;

import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.validation.annotation.Validated;

@ConfigurationProperties("my.service")
@Validated
public class MyProperties {

	@NotNull
	private InetAddress remoteAddress;

	@Valid
	private final Security security = new Security();

	// getters/setters...

	public InetAddress getRemoteAddress() {
		return this.remoteAddress;
	}

	public void setRemoteAddress(InetAddress remoteAddress) {
		this.remoteAddress = remoteAddress;
	}

	public Security getSecurity() {
		return this.security;
	}

	public static class Security {

		@NotEmpty
		private String username;

		// getters/setters...

		public String getUsername() {
			return this.username;
		}

		public void setUsername(String username) {
			this.username = username;
		}

	}

}

만약 `react-binding`을 사용하고 싶다면 , 속성 이름을 표준 형식(소문자만 사용하는 케밥 케이스)으로 참조하는 것이 좋습니다. 이렇게 하면 Spring Boot가 완화된 바인딩을@Value 사용할 때와 동일한 로직을 적용할 수 있습니다 . @ConfigurationProperties

예를 들어, 는 파일과 시스템 환경에서 양식을 가져옵니다. 대신 를 사용하면 파일 과 @Value("${demo.item-price}")시스템 환경에서 양식을 가져 오지만, 는 고려 되지 않습니다.demo.item-pricedemo.itemPriceapplication.propertiesDEMO_ITEMPRICE@Value("${demo.itemPrice}")demo.itemPriceapplication.propertiesDEMO_ITEMPRICEdemo.item-price

컴포넌트에 대한 설정 키 세트를 정의하는 경우, `@Process` 어노테이션이 있는 POJO에 해당 키들을 그룹화하는 것이 좋습니다 @ConfigurationProperties. 이렇게 하면 구조화되고 타입 안정성이 확보된 객체를 생성하여 자체 빈에 주입할 수 있습니다.

SpEL애플리케이션 속성 파일 의 표현식은 해당 파일을 구문 분석하고 환경을 채울 때 처리되지 않습니다. 그러나 SpEL표현식을 직접 작성할 수는 있습니다 @Value. 애플리케이션 속성 파일의 속성 값이 SpEL표현식인 경우, 해당 표현식은 를 통해 사용될 때 평가됩니다 @Value.

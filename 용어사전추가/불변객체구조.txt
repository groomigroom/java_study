    <pre>
        자바에서 불변 객체 구조            
        
        자바에서 불변 객체(Immutable Object)란
        한 번 생성되면
        그 내부의 상태(필드 값)를 절대 변경할 수
        없는 객체를 말합니다.
        즉, 객체 안의 데이터를 수정하는 것이 불가능하며,
        값을 바꾸고 싶다면 기존 객체를 수정하는 대신
        새로운 객체를 생성해야 합니다.
        
        자바의 대표적인 불변 객체로는 String 클래스가 있습니다.
        불변 객체의 핵심 구조와 원칙자바에서
        불변 클래스를 만들려면 다음과 같은 구조적
        규칙을 지켜야 합니다.
        모든 필드를 private과 final로 선언: 외부에서 직접 
        필드에 접근하거나 값을 바꿀 수 없으며,
        생성자를 통해서만 초기화됩니다.
        Setter 메서드 미제공: 객체 생성 이후 상태
        변경을 유도하는 수정자(Setter) 메서드를
        아예 제공하지 않습니다.
        상속 방지 (final 클래스): 하위 클래스가 필드나
        메서드를 오버라이딩하여 가변 상태로 만드는 것을
         막기 위해 클래스 자체를 final로 선언합니다.
        가변 필드 방어적 복사 (Defensive Copy): 내부에 가변 객체(예: Date, List 등) 필드가 있다면, 
        생성자와 Getter에서 객체를 그대로 반환하지 않고 복사본을 주고받아야 합니다.
        
        불변 객체를 사용하는 이유
        스레드 안전성 (Thread-Safe): 여러 스레드가 동시에 객체를 읽어도 상태가 변하지 않으므로 
        별도의 동기화(Synchronized) 작업이 필요 없습니다.
        높은 신뢰성과 안정성: 코드가 복잡해도 객체의 값이 어디선가 예기치 않게 변경될 
        공포가 없어 디버깅이 쉽습니다.
        사이드 이펙트(Side Effect) 방지: 참조를 공유해도 원본 데이터가 훼손되지 않아 함수형 
        프로그래밍이나 맵(Map)의 키(Key), 셋(Set)의 요소로 쓰기에 적합합니다.
        
        ---------------------------------------------------------------------------------
        
        자바에서 String이 불변 객체인 이유
        
        자바에서 String 객체가 불변(Immutable)인 이유는 메모리 절약(String Pool), 
        보안 유지, 스레드 안전성, 그리고 해시코드 캐싱을 통한 성능 향상을 위해서입니다. 
        한 번 생성된 문자열은 내부 값이 바뀌지 않습니다.
        주요 이유
        문자열 상수 풀 (String Pool)같은 문자열을 여러 변수가 나누어 쓸 수 있습니다.
        만약 수정이 가능하면, 
        한 변수에서 값을 바꿀 때 공유하는 다른 모든 변수의 값도 함께 바뀌는 문제가 생깁니다.
        보안 (Security)파일 경로, 데이터베이스 연결 URL, 
        네트워크 호스트 이름 등이 문자열로 주로 쓰입니다.
        중간에 값이 바뀔 위험이 없어야 안전한 권한 검사와 로직 실행이 가능합니다.
        스레드 안전성 (Thread Safety)여러 스레드가 동시에 같은 문자열을 
        읽어도 값이 변하지 않습니다.
        따로 값을 동기화(Synchronize)할 필요가 없어 효율적입니다.
        해시코드 캐싱 (Caching Hash Code)HashMap이나 HashSet에서 키로 자주 쓰입니다.
        생성할 때 해시코드를 미리 구해두고 재사용하므로, 
        매번 계산하지 않아 속도가 빠릅니다.

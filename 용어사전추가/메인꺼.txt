자바 스프링에서 @SpringBootApplication의 의미
자바 스프링 부트에서 @SpringBootApplication은 핵심 
메인 클래스에 붙이는 통합 어노테이션으로, 
스프링 부트 애플리케이션의 자동 설정(Auto-Configuration), 
빈 스캔(Component Scan), 스프링 설정(Configuration) 등 
3가지 핵심 기능을 한 번에 활성화합니다.구성하는 3가지 핵심 
어노테이션@SpringBootConfiguration스프링의 @Configuration과 같은 역할을 합니다.
해당 클래스가 스프링 빈(Bean) 설정 클래스임을 나타냅니다.
@EnableAutoConfiguration스프링 부트가 사전에 정의한 다양한 라이브러리와 
설정들을 자동으로 구성해 줍니다.
예를 들어, spring-boot-starter-web이 있다면 톰캣(Tomcat)과 스프링 MVC를 
자동으로 설정합니다.
@ComponentScan현재 패키지와 그 하위 패키지를 전부 탐색합니다.
@Component, @Service, @Repository, @Controller 등의 어노테이션이 붙은 클래스를 찾아 스프링 빈으로 등록합니다.
주의해야 할 점 (위치)
@SpringBootApplication이 선언된 클래스는 항상 프로젝트의 최상단(Root 패키지)에 위치해야 합니다.
하위 패키지 전체를 스캔하기 때문에, 
패키지 구조가 잘못되면 다른 컴포넌트나 서비스 빈들을 찾지 못하는 문제가 발생할 수 있습니다.


SpringApplication.run(MyApplication.class, args);는 스프링 부트 
애플리케이션을 구동(구축 및 실행)하는 실제 시작점입니다.
일반적인 자바 프로그램이 main() 메서드에서 시작하듯, 
스프링 부트 역시 이 코드를 만나면서 자바 환경 위에서 스프링 컨테이너를 초기화하고 
웹 서버를 띄우는 일련의 과정을 시작합니다. 

## 1. 인자(Parameter)의 의미
메서드에 넘겨주는 두 개의 인자는 각각 중요한 역할을 합니다.

* 
* MyApplication.class (기본 설정 소스)
* 스프링 부트에게 "어떤 클래스를 기준으로 설정을 읽고 빈 스캔을 시작할지" 
알려주는 기준점입니다.
   * 앞서 설명한 @SpringBootApplication 어노테이션이 붙어 있는 클래스를 전달함으로써, 
그 위치를 기준으로 컴포넌트 스캔(@ComponentScan)을 진행하게 됩니다. 
* args (커맨드 라인 인수)
* 애플리케이션 실행 시 외부(터미널 등)에서 전달된 설정 인자들을 스프링 내부로 전달합니다.
   * 예를 들어 구동 시 매개변수로 포트 번호(--server.port=8081)나 
특정 프로필 설정을 동적으로 주입할 때 활용됩니다.

## 2. 실행 시 내부에서 일어나는 일
이 정적(static) 메서드가 호출되면, 내부적으로 다음과 같은 복잡한 작업들이 
순서대로 자동 처리됩니다:

   1. 스프링 컨텍스트 생성: 빈(Bean) 객체들을 생성하고 관리할 중심 컨테이너(ApplicationContext)를 만듭니다. [6] 
   2. 자동 설정 및 빈 등록: 프로젝트에 포함된 라이브러리(starter)와 코드를 분석해 필요한 객체들을 생성하고 컨테이너에 등록합니다. [6] 
   3. 내장 웹 서버 구동: 톰캣(Tomcat) 같은 웹 서버를 별도 설치 없이 내부에서 자동으로 구동하여 웹 요청을 받을 준비를 마칩니다. [6]

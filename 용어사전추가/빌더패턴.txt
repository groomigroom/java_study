자바 스프링에서 빌더 패턴의 의미?                    자바 스프링에서 빌더 패턴(Builder Pattern)은
복잡한 객체를 쉽고 안전하게 만드는 방법입니다.
생성자에 값을 순서대로 넣는 대신,
이름이 있는 메서드를 통해 원하는 값만
명확하게 채워 객체를 생성합니다.
주로 롬복(@Builder) 라이브러리와 함께 쓰입니다.
빌더 패턴이 필요한 이유
가독성 좋음: 어떤 자리에 어떤 값이 들어가는지
이름으로 알 수 있습니다.
순서 상관없음: 생성자처럼 순서를 외울 필요가 없습니다.
유연함: 필요한 값만 골라서 넣을 수 있습니다.
안전성: 값을 한 번만 넣고 바꿀 수 없게(불변성) 
만들기 좋습니다.
기존 방식과 비교
생성자 방식
세터(Setter) 방식
빌더 패턴
new User("김", 20, "서울");
User u = new User(); 
u.setName("김");
User.builder().name("김").age(20).build();

순서가 헷갈림
객체가 함부로 변할 수 있음
안전하고 읽기 쉬움


User.builder().name("김").age(20).build(); 코드는 롬복(Lombok) 라이브러리의 @Builder 어노테이션을 활용해 객체를 생성하는 자바 패턴입니다. 스프링 부트(Spring Boot) 애플리케이션에서는 주로 데이터베이스 엔티티, DTO(Data Transfer Object), 또는 비즈니스 로직 내에서 이 패턴을 자주 사용합니다.
이 코드가 실제 스프링 프로젝트에서 어떻게 정의되고 활용되는지 전체 레이어(Entity/DTO ➡️ Service ➡️ Controller) 예제로 설명해 드리겠습니다.
------------------------------
## 1. User 도메인 클래스 정의 (Lombok 활용)
먼저 @Builder 어노테이션을 클래스에 부여하여 빌더 패턴 코드를 자동으로 생성합니다.

import lombok.Builder;
import lombok.Getter;
import lombok.NoArgsConstructor;
import lombok.AllArgsConstructor;

@Getter
@NoArgsConstructor // 스프링/JPA가 객체를 생성할 때 필요한 기본 생성자
@AllArgsConstructor // @Builder가 정상 작동하기 위해 필요한 전체 필드 생성자
@Builder // 빌더 패턴 지원public class User {
    private Long id;
    private String name;
    private int age;
}

------------------------------
## 2. 비즈니스 로직에서의 활용 (Service 레이어)
회원가입 기능이나 테스트 데이터를 생성할 때 질문하신 빌더 코드를 사용하여 객체를 직관적으로 생성하고 저장합니다.

import org.springframework.stereotype.Service;import java.util.ArrayList;import java.util.List;

@Servicepublic class UserService {

    // 예제를 위한 임시 인메모리 저장소
    private final List<User> userStorage = new ArrayList<>();

    public User createUser() {
        // 빌더 패턴을 사용하여 안전하고 가독성 좋게 객체 생성
        User newUser = User.builder()
                .name("김")
                .age(20)
                .build();

        userStorage.add(newUser);
        return newUser;
    }
}

------------------------------
## 3. 클라이언트 요청 처리 (Controller 레이어)
사용자가 특정 주소로 요청을 보냈을 때, 서비스의 메서드를 호출하여 결과를 JSON 형태로 반환하는 컨트롤러 예제입니다.

import org.springframework.web.bind.annotation.PostMapping;import org.springframework.web.bind.annotation.RequestMapping;import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/api/users")public class UserController {

    private final UserService userService;

    // 생성자 주입
    public UserController(UserService userService) {
        this.userService = userService;
    }

    @PostMapping("/sample")
    public User createSampleUser() {
        return userService.createUser();
    }
}

------------------------------
## 빌더 패턴을 스프링에서 쓰는 이유

* 
* 가독성 향상: 매개변수가 많아져도 어떤 필드에 어떤 값이 들어가는지 명확히 알 수 있습니다.
* 불변성(Immutability) 유지: Setter 메서드를 만들지 않아도 되므로 객체의 무분별한 상태 변경을 막을 수 있습니다.
* 유연성: 생성자 오버로딩 없이 필요한 필드만 선택해서 객체를 만들 수 있습니다.
*

스프링을 활용한 구체적인 아키텍처에 대해 더 알고 싶으시다면 다음 내용을 알려주세요:

* 
* 이 User 객체를 JPA/Hibernate 엔티티로 변경하여 실제 DB와 연동하는 예제가 필요하신가요?
* 클라이언트의 요청 데이터를 받아오는 DTO 활용 예제나 단위 테스트(JUnit) 코드가 필요하신가요?
* 

이 예제 코드를 실제로 작동시키려면 스프링 부트(Spring Boot) 프로젝트를 생성하고 필요한 라이브러리를 설정해야 합니다. 단계별 실행 가이드는 다음과 같습니다.
------------------------------
## 1. 프로젝트 생성 및 의존성(Dependencies) 설정
가장 쉬운 방법은 [Spring Initializr](https://start.spring.io/) 사이트에서 프로젝트를 생성하는 것입니다. 빌더 패턴을 쓰기 위해 Lombok과 Spring Web이 반드시 필요합니다.
build.gradle 설정 예시:

dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-web'
    
    // 롬복(Lombok) 필수 설정
    compileOnly 'org.projectlombok:lombok'
    annotationProcessor 'org.projectlombok:lombok'
    
    testImplementation 'org.springframework.boot:spring-boot-starter-test'
}

------------------------------
## 2. IDE(IntelliJ IDEA 등)에서 Lombok 활성화
Lombok은 코드를 컴파일할 때 빌더를 자동으로 만들어주기 때문에, IDE 설정을 켜주어야 에러가 나지 않습니다. (IntelliJ 기준)

   1. Settings (Windows: Ctrl + Alt + S / Mac: Cmd + ,) 창을 엽니다.
   2. Annotation Processors를 검색합니다.
   3. Enable annotation processing 체크박스를 체크하고 저장합니다.

------------------------------
## 3. 메인 애플리케이션 클래스 확인
스프링 부트를 실행할 진입점(Main) 클래스가 필요합니다. 기본적으로 프로젝트 생성 시 만들어집니다.

package com.example.demo;
import org.springframework.boot.SpringApplication;import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplicationpublic class DemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}

앞서 안내해 드린 User, UserService, UserController 클래스들을 이 메인 클래스와 같은 패키지(예: com.example.demo) 또는 하위 패키지에 저장합니다.
------------------------------
## 4. 애플리케이션 실행하기

   1. DemoApplication 클래스의 main 메서드 옆에 있는 초록색 재생 버튼(Run)을 클릭합니다.
   2. 콘솔 창에 Tomcat started on port 8080이라는 메시지가 뜨면 성공적으로 서버가 켜진 것입니다.

------------------------------
## 5. 작동 확인 (테스트)
서버가 켜진 상태에서, 앞서 컨트롤러에 만든 URL(/api/users/sample)로 요청을 보내 코드를 작동시킵니다.
## 방법 A: 웹 브라우저 이용 (가장 간단함)
다만, 예제 코드가 POST 메서드로 되어 있으므로 브라우저 주소창에 직접 입력해 테스트하려면 UserController의 코드를 잠시 수정하는 것이 편합니다.

// UserController.java 내의 어노테이션을 POST에서 GET으로 잠시 변경
@GetMapping("/sample") public User createSampleUser() { ... }

그 후 브라우저를 열고 주소창에 http://localhost:8080/api/users/sample을 입력하면 아래와 같은 JSON 데이터가 화면에 출력됩니다.

{
  "id": null,
  "name": "김",
  "age": 20
}

## 방법 B: 터미널에서 curl 명령어 이용 (POST 그대로 유지 시)
터미널(Cmd 또는 Terminal)을 열고 다음 명령어를 입력합니다. [1] 

curl -X POST http://localhost:8080/api/users/sample

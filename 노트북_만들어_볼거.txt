Spring Data JPA만으로는 실제 데이터베이스인 MySQL과 통신할 수 없으며,
MySQL JDBC 드라이버가 물리적인 연결과 SQL 전송을 담당하기 때문에 두 라이브러리를 함께 사용해야 합니다.
역할 분담과 필요성
spring-boot-starter-data-jpa ->
Spring Data JPA: 자바 객체와 데이터베이스 테이블을 연결해 주는 규칙(ORM)과 쿼리 자동 생성 기능을 제공합니다.
MySQL Driver: 자바 프로그램이 MySQL 서버에 실제로 접속하여 데이터를 읽고 쓸 수 있게 해주는 저수준 통신 라이브러리(JDBC 구현체)입니다.
상호 작용: JPA가 번역한 SQL 명령어를 실제 MySQL 서버가 이해할 수 있는 네트워크 패킷으로 바꾸어 전달하는 주체가 바로 MySQL 드라이버입니다.


자바 스프링 부트에서 MySQL 드라이버를 사용하려면 Spring Data JPA, MySQL Driver, Spring Web 의존성을 추가해야 합니다.
1. 의존성 설정 (build.gradle)build.gradle 파일에 아래 내용을 추가합니다.groovy
dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-data-jpa'
    implementation 'org.springframework.boot:spring-boot-starter-web'
    runtimeOnly 'com.mysql:mysql-connector-j'
}

2. 데이터베이스 연결 설정 (src/main/resources/application.properties)MySQL 서버 주소, 계정, 비밀번호를 적습니다.
propertiesspring.datasource.url=jdbc:mysql://localhost:3306/mydb?useSSL=false&serverTimezone=UTC&allowPublicKeyRetrieval=true
spring.datasource.username=root
spring.datasource.password=your_password
spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver

spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true

3. 엔티티(Entity) 클래스 작성테이블과 매핑될 기본 모델을 만듭니다.java

package com.example.demo;

import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;

@Entity
public class User {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private String name;

    // Getter and Setter
    public Long getId() { return id; }
    public void setId(Long id) { this.id = id; }
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
}

/*
@Entity의

@Entity 어노테이션을 사용하기 위해 필요한 스타터 의존성은 spring-boot-starter-data-jpa입니다. 

자바 스프링(JPA)에서 @Entity는 자바 클래스를 데이터베이스의 테이블과 연결(매핑)하는 선언입니다.
이 어노테이션이 붙은 클래스는 데이터베이스의 행(row) 하나와 대응되며,
JPA(Java Persistence API)가 데이터를 영구적으로 관리하는 기준 객체가 됩니다.
주요 특징
테이블 매핑: 클래스 이름이나 지정한 테이블 이름이 실제 DB 테이블과 연결됩니다.
필드 매핑: 클래스의 멤버 변수는 DB 테이블의 열(column)로 작동합니다.
관리 대상: JPA 영속성 컨텍스트가 데이터를 감지하고 저장, 수정(Dirty Checking)할 수 있게 됩니다.
함께 쓰이는 필수 어노테이션@Id: 테이블의 기본 키(Primary Key)를 지정합니다.
@GeneratedValue: 기본 키의 자동 생성 전략을 설정합니다 (예: Auto Increment).
@Table: 매핑할 DB 테이블 이름을 따로 지정할 때 사용합니다.
*/

코드를 사용할 때는 주의가 필요합니다.4. 리포지토리(Repository) 인터페이스 작성데이터베이스 작업을 처리할 인터페이스를 만듭니다.java

package com.example.demo;

import org.springframework.data.jpa.repository.JpaRepository;

public interface UserRepository extends JpaRepository<User, Long> {
}


제공해주신 User 엔티티와 UserRepository 인터페이스를 작성하고 애플리케이션을 실행하면, Spring Data JPA와 MySQL 드라이버가 협력하여 복잡한 SQL 작성 없이 데이터베이스 제어가 가능해지는 강력한 효과들이 나타납니다.
구체적인 효과를 핵심 기능별로 나누어 설명해 드리겠습니다.
## 1. 테이블 자동 생성 (DDL Auto)

* 효과: MySQL 데이터베이스에 직접 가서 CREATE TABLE 명령어를 칠 필요가 없습니다.
* 원리: 애플리케이션이 실행될 때 User 클래스의 구조를 분석하여, MySQL 드라이버를 통해 user 테이블을 자동으로 만들어 줍니다. (id는 BIGINT AUTO_INCREMENT로, name은 VARCHAR로 자동 매핑됩니다.)

## 2. SQL문 없는 CRUD 구현 (생산성 폭발)

* 효과: 반복적이고 지루한 SQL(Insert, Update, Select, Delete) 작성이 완전히 사라집니다.
* 예시: UserRepository를 주입받아 아래 메서드들을 바로 호출할 수 있습니다.
* userRepository.save(user) → 내부적으로 INSERT INTO user ... 쿼리 자동 실행
   * userRepository.findById(1L) → 내부적으로 SELECT * FROM user WHERE id = 1 쿼리 자동 실행
   * userRepository.deleteById(1L) → 내부적으로 DELETE FROM user WHERE id = 1 쿼리 자동 실행

## 3. 자바 객체 중심의 개발 (인프라 격리)

* 효과: 개발자는 '데이터베이스 테이블'을 신경 쓰지 않고, '자바 객체(User)'를 다루는 데에만 집중할 수 있습니다.
* 원리: 데이터를 조회하면 MySQL의 로우(Row) 데이터가 자바의 User 객체 인스턴스로 자동 변환(매핑)되어 반환됩니다.

## 4. 데이터베이스 교체의 유연성

* 효과: 나중에 데이터베이스를 MySQL에서 PostgreSQL이나 Oracle로 바꾸더라도, 자바 코드를 단 한 줄도 수정할 필요가 없습니다.
* 원리: Spring Data JPA가 추상화 계층 역할을 하고 있으므로, 설정 파일(application.properties)에서 드라이버와 방언(Dialect) 설정만 변경해 주면 됩니다.

롬복(Lombok)의 @Getter, @Setter, @ToString은 반복되는 메서드 작성 코드를 줄여주는 자바 라이브러리 어노테이션입니다. DTO나 모델 클래스 상단에 선언하여 사용합니다.1. 롬복 설정 (build.gradle)groovydependencies {
    compileOnly 'org.projectlombok:lombok'
    annotationProcessor 'org.projectlombok:lombok'
}
코드를 사용할 때는 주의가 필요합니다.2. 예제 코드 (UserDto.java)java

package com.example.demo.dto;

import lombok.Getter;
import lombok.Setter;
import lombok.ToString;

@Getter
@Setter
@ToString
public class UserDto {
    private String name;
    private int age;
}
코드를 사용할 때는 주의가 필요합니다.3. 사용 예시 (TestController.java)java

package com.example.demo.controller;

import com.example.demo.dto.UserDto;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class TestController {

    @GetMapping("/user")
    public String userTest() {
        UserDto user = new UserDto();
        
        // @Setter 작동 확인
        user.setName("홍길동");
        user.setAge(25);
        
        // @Getter 및 @ToString 작동 확인
        System.out.println(user.toString()); 
        
        return user.getName() + "의 나이는 " + user.getAge() + "세 입니다.";
    }
}

아래꺼는 설명....

롬복(Lombok)의 @Getter, @Setter, @ToString은 자바 컴파일 시점에 반복적인 코드(Boilerplate code)를 자동으로 생성해 주는 어노테이션입니다.
각 어노테이션의 핵심 의미와 실제 컴파일 후의 모습을 직관적으로 정리해 드립니다.
------------------------------
## 1. @Getter (데이터 조회 메서드 자동 생성)

* 의미: 클래스의 필드(변수) 값을 외부에서 읽을 수 있도록 getXxx() 메서드를 자동으로 만들어 줍니다.
* 필요한 이유: 자바에서는 객체의 캡슐화를 위해 필드를 private으로 숨기고 메서드로 접근하는 것이 원칙입니다. 이를 직접 쓰면 코드가 길어지는데, 롬복이 이를 대신해 줍니다.
* 실제 생성되는 코드 (뒷단의 모습):

public Long getId() {
    return this.id;
}public String getName() {
    return this.name;
}

[1] 

------------------------------
## 2. @Setter (데이터 수정 메서드 자동 생성)

* 의미: 클래스의 필드(변수) 값을 외부에서 변경할 수 있도록 setXxx() 메서드를 자동으로 만들어 줍니다.
* 필요한 이유: 객체의 상태를 안전하게 변경하기 위한 진입로 역할을 합니다.
* 실제 생성되는 [코드 (뒷단의 모습):

public void setId(Long id) {
    this.id = id;
}public void setName(String name) {
    this.name = name;
}

(⚠️ 주의: 데이터의 무분별한 변조를 막기 위해, 실무의 핵심 엔티티(Entity) 클래스에서는 @Setter 사용을 지양하고 꼭 필요한 수정 메서드만 따로 만드는 편입니다.)

------------------------------
## 3. @ToString (객체 정보 문자열 출력)

* 의미: 클래스의 이름과 현재 가지고 있는 필드 값들을 한눈에 보기 쉬운 텍스트 문장으로 만들어 주는 toString() 메서드를 자동 생성합니다.
* 필요한 이유: 원래 자바에서 객체를 그대로 출력(System.out.println(user))하면 UserDto@1a2b3c4d 같은 알 수 없는 메모리 주소 값이 나옵니다. 롬복을 쓰면 객체 내부 데이터를 사람이 읽을 수 있게 바로 출력해 주어 디버깅과 로그 확인이 매우 편해집니다.
* 실제 생성되는 코드 (뒷단의 모습):

@Overridepublic String toString() {
    return "UserDto(id=" + this.id + ", name=" + this.name + ")";
}

## 요약 비교

| 어노테이션 | 역할 | 호출 예시 | 주로 쓰이는 용도 |
|---|---|---|---|
| @Getter | 데이터를 가져옴 | user.getName() | 데이터 조회, API 응답 |
| @Setter | 데이터를 저장/수정 | user.setName("홍길동") | 데이터 입력, Request 맵핑 |
| @ToString | 객체 상태를 텍스트화 | user.toString() | 디버깅, 로그(log.info) 출력 |

## ⚠️ 정상 작동을 위한 필수 체크리스트
코드는 올바르지만, 실행 환경에 따라 아래 두 가지 설정이 되어 있지 않으면 컴파일 에러(예: cannot find symbol setName)가 발생할 수 있습니다.

* Lombok 의존성 추가: pom.xml(Maven)이나 build.gradle(Gradle) 파일에 Lombok 라이브러리가 포함되어 있어야 합니다.
* IDE 플러그인 및 설정: IntelliJ IDEA나 Eclipse 같은 개발 도구에서 Lombok 플러그인이 설치되어 있어야 하며, IntelliJ 기준 Settings -> Annotation Processors에서 Enable annotation processing이 체크되어 있어야 합니다.

## 💡 한 단계 더 나아가는 스프링 팁

@GetMapping("/user")public UserDto userTest() {

    user.setName("홍길동");
    user.setAge(25);
    
    return user; // 브라우저에 {"name":"홍길동","age":25} 로 출력됨

import java.text.SimpleDateFormat;

package groom_date;

import java.text.SimpleDateFormat;
import java.util.Date;

public class main {
    public static void main(String[] args) {
        // 1. 현재 날짜와 시간 생성
        Date now = new Date();
        System.out.println("기본 출력: " + now.toString());

        // 2. 밀리초(Long) 값 가져오기 (1970년 1월 1일 이후)
        long millis = now.getTime();
        System.out.println("밀리초 시간: " + millis);

        // 3. 원하는 형식으로 출력하기 (SimpleDateFormat)
        SimpleDateFormat formatter = new SimpleDateFormat("yyyy-MM-dd HH:mm:ss");
        String formattedDate = formatter.format(now);
        System.out.println("포맷 지정 출력: " + formattedDate);
    }
}

## 방법 2: 리다이렉트(Redirect)와 쿼리 스트링 사용
로그인 성공 후 브라우저의 URL 주소 자체를 새로운 HTML 페이지로 바꾸고, 데이터를 URL 파라미터(Query String)로 넘기는 방법입니다.
컨트롤러 수정

package com.example.demo;

import org.springframework.stereotype.Controller;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.servlet.mvc.support.RedirectAttributes;

@Controller
public class SimpleRestController {

    @RequestMapping("/login_anne")
    public String create_login (
            @RequestParam("title") String title,
            @RequestParam("content") String content,
            @RequestParam("password") String password,
            @RequestParam("id") String id,
            RedirectAttributes redirectAttributes) { // RedirectAttributes 추가

        if ("kimgroom".equals(id) && "groomgroom".equals(password)) {
            //addAttribute를 쓰면 스프링이 알아서 URL 파라미터 인코딩을 해줍니다.
            redirectAttributes.addAttribute("title", title);
            redirectAttributes.addAttribute("content", content);
            
            return "redirect:/result.html";
        }
        return "redirect:/login_fail.html";
    }
}


이 방식은 이동할 result.html에서 자바스크립트(URLSearchParams)를 사용해 URL에 담긴 title과 content를 꺼내서 화면에 뿌려주어야 합니다.

해당 코드가 가진 의미와 생략했을 때의 차이점은 다음과 같습니다.
## 1. 코드의 역할
xmlns:th="http://www.thymeleaf.org"는 이 HTML 파일 안에서 th:로 시작하는 타임리프 문법(예: th:text, th:if)을 사용하겠다고 브라우저나 개발 도구에 선언하는 일종의 네임스페이스(Name Space) 지정입니다.
## 2. 안 적으면 생략했을 때 생기는 일

* 화면 동작 (정상): 스프링 부트(서버)가 내부적으로 HTML 코드를 해석해서 데이터를 다 채운 뒤 완성된 HTML만 브라우저로 보내기 때문에, 저 선언문이 없어도 화면은 문제없이 잘 나옵니다.
* 인텔리제이/이클립스 자동 완성 (불가): 개발 툴(IDE)이 타임리프 문법을 인식하지 못합니다. HTML 파일 안에서 th:text 등을 타이핑할 때 자동 완성(Auto-complete) 기능이 작동하지 않고, 코드에 빨간색 줄이나 노란색 경고 표시가 뜰 수 있습니다.

package kr.co.hanbit;

import org.springframework.http.HttpHeaders;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

import java.net.URI;

@RestController
public class RedirectRestController {
    @RequestMapping("/redirectToTarget")
    public ResponseEntity redirectToTarget() {
        HttpHeaders headers = new HttpHeaders();
        headers.setLocation(URI.create("/targetOfRedirect"));
        return new ResponseEntity<>(headers, HttpStatus.MOVED_PERMANENTLY);
    }
    @RequestMapping("/targetOfRedirect")
    public String targetOfRedirect() {
        return "This is Redirect!";
    }
}


제공해주신 코드는 사용자가 특정 주소로 접속했을 때, 다른 주소로 강제 이동(리다이렉트)시키는 스프링 부트 컨트롤러 예제입니다.
코드의 각 줄이 어떤 역할을 하는지 핵심만 쉽게 설명해 드릴게요.
------------------------------
## 코드 한 줄씩 해석하기

package kr.co.hanbit;


* 이 소스 코드가 kr.co.hanbit이라는 폴더(패키지) 구조 안에 저장되어 있음을 선언합니다.

import org.springframework.http.HttpHeaders;import org.springframework.http.HttpStatus;import org.springframework.http.ResponseEntity;import org.springframework.web.bind.annotation.RequestMapping;import org.springframework.web.bind.annotation.RestController;import java.net.URI;


* 외부 폴더에 있는 자바 및 스프링의 핵심 도구(클래스)들을 가져와 이 코드 안에서 사용하겠다고 등록하는 부분입니다.

@RestController


* 이 클래스가 데이터나 결과물을 브라우저에 바로 전달하는 컨트롤러(서버 통신 창구) 역할을 하겠다고 스프링에게 알려주는 표식(어노테이션)입니다.

public class RedirectRestController {


* RedirectRestController라는 이름의 공개(public) 클래스를 정의합니다. 모든 웹 요청 처리 로직이 이 안에 작성됩니다.

    @RequestMapping("/redirectToTarget")


* 사용자가 브라우저 주소창에 http://서버주소/redirectToTarget을 입력하고 들어오면, 바로 아래에 있는 redirectToTarget() 메서드를 실행하라는 매핑 선언입니다.

    public ResponseEntity redirectToTarget() {


* 데이터와 함께 HTTP 응답 상태 코드, 헤더 정보를 세밀하게 조작해서 브라우저에게 돌려주는 redirectToTarget 메서드를 시작합니다.

        HttpHeaders headers = new HttpHeaders();


* 브라우저에게 보낼 메인 데이터 외에, '부가적인 정보(안내문)'를 담을 헤더(headers)라는 빈 바구니를 생성합니다.

        headers.setLocation(URI.create("/targetOfRedirect"));


* 방금 만든 바구니에 "너는 바로 /targetOfRedirect 주소로 이동해야 해"라는 이정표(Location) 정보를 주소(URI) 형태로 만들어 집어넣습니다.

        return new ResponseEntity<>(headers, HttpStatus.MOVED_PERMANENTLY);


* 브라우저에게 "이 주소는 영구적으로 이동했어(Status 301 - MOVED_PERMANENTLY)"라는 상태 코드와 함께, 방금 만든 이동 주소 바구니(headers)를 최종 반환(Return)합니다. 이를 받은 브라우저는 자동으로 새 주소로 날아갑니다.

    }


* redirectToTarget 메서드의 끝을 알리는 중괄호입니다.

    @RequestMapping("/targetOfRedirect")


* 사용자가 주소창에 직접 접속하거나, 위에서 리다이렉트되어 http://서버주소/targetOfRedirect로 들어왔을 때 아래 메서드를 실행시킵니다.

    public String targetOfRedirect() {


* 화면에 글자를 보여주기 위해 문자열(String)을 반환하는 targetOfRedirect 메서드를 시작합니다.

        return "This is Redirect!";


* 브라우저 화면에 This is Redirect!라는 텍스트 문구를 그대로 출력(반환)합니다.

    }
}


* 각각 메서드와 클래스가 모두 끝났음을 닫는 중괄호들입니다.

## 💡 전체 동작 흐름 요약

   1. 사용자가 /redirectToTarget 주소로 접속 요청을 보냅니다.
   2. 서버가 응답으로 "여긴 이제 없는 주소니 /targetOfRedirect로 다시 가세요(301 응답)"라고 알려줍니다.
   3. 브라우저가 주소창을 자동으로 바꾸며 /targetOfRedirect로 재접속합니다.
   4. 화면에 "This is Redirect!"라는 문구가 최종적으로 보입니다.

혹시 리다이렉트와 관련해서 영구 이동(301/MOVED_PERMANENTLY) 대신 임시 이동(302/FOUND) 상태 코드를 쓰는 이유나, 단순 페이지 이동을 위한 다른 편리한 스프링 문법(return "redirect:/주소")이 궁금하신가요? 구체적인 상황을 알려주시면 상세히 설명해 드릴게요.

package kr.co.hanbit;

import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class ServerErrorRestController {
    @RequestMapping("/throwServerError")
    public void throwServerError() {
        throw new RuntimeException();
    }
}


이 코드는 사용자가 특정 주소로 접속했을 때, 서버가 의도적으로 강제 에러(500 Internal Server Error)를 발생시키는 코드입니다.
각 줄의 구체적인 의미는 다음과 같습니다.
## 코드 한 줄씩 해석하기

@RequestMapping("/throwServerError")


* 사용자가 브라우저 주소창에 http://서버주소/throwServerError를 입력하고 들어오면, 바로 아래에 있는 throwServerError() 메서드를 실행하라는 매핑 선언입니다.

public void throwServerError() {


* 반환하는 결과물(리턴값)이 아무것도 없는(void) throwServerError 메서드를 시작합니다.

    throw new RuntimeException();


* 이 코드가 핵심입니다. 자바 프로그램 실행 중에 예기치 못한 문제가 생겼음을 알리는 RuntimeException(실행 시점 예외) 객체를 새로 만들어서 시스템에 강제로 던집니다(throw).

}


* 메서드가 끝났음을 알리는 중괄호입니다.

## 💻 브라우저에는 어떻게 보일까요?
이 주소로 접속하면 스프링 내부에서 에러가 처리되지 않고 터지기 때문에, 웹 브라우저 화면에는 HTTP Status 500 – Internal Server Error (서버 내부 에러) 페이지가 나타나게 됩니다. (스프링 부트 기본 화면인 하얀색 'Whitelabel Error Page'가 뜹니다.)
## 💡 실무에서는 왜 이런 코드를 쓸까요?
일부러 에러를 내는 코드는 실제 서비스용이 아니라 보통 다음과 같은 테스트 목적으로 작성합니다.

   1. 에러 페이지 테스트: 서버에 에러가 났을 때 사용자에게 보여줄 예쁜 커스텀 에러 화면(예: "점검 중입니다")이 잘 작동하는지 확인하고 싶을 때
   2. 글로벌 에러 처리기(ControllerAdvice) 테스트: 서버 전체에서 발생하는 에러를 한곳으로 모아서 이쁘게 JSON 데이터로 가공해 주는 공통 에러 처리 로직이 잘 굴러가는지 테스트할 때

------------------------------
혹시 스프링에서 이런 에러가 발생했을 때 사용자에게 500 화면 대신 안전한 안내 문구나 특정 데이터(JSON)를 리턴하는 예외 처리 기법(@ExceptionHandler)이 궁금하신가요? 필요하시면 연관된 코드를 더 소개해 드릴게요!

## 방법 1: 타임리프(Thymeleaf) 템플릿 엔진 사용 (추천)
서버에서 데이터를 처리한 뒤, 새로운 HTML 파일에 데이터를 담아서 브라우저로 렌더링하는 가장 정석적인 방법입니다.
1. 컨트롤러 수정
@RestController 대신 @Controller를 사용해야 HTML 뷰(View)를 반환할 수 있습니다.

import org.springframework.stereotype.Controller;import org.springframework.ui.Model;import org.springframework.web.bind.annotation.RequestMapping;import org.springframework.web.bind.annotation.RequestParam;

@Controller // RestController에서 변경public class NewBack {
    
    @RequestMapping("/login_anne")
    public String create_login(
            @RequestParam("title") String title,
            @RequestParam("content") String content,
            @RequestParam("password") String password,
            @RequestParam("id") String id,
            Model model) { // 데이터를 HTML에 전달하기 위한 Model 객체 추가

        if ("kimgroom".equals(id) && "groomgroom".equals(password)) {
            // HTML로 보낼 데이터 바인딩
            model.addAttribute("title", title);
            model.addAttribute("content", content);
            return "success"; // success.html 파일로 이동
        }
        
        return "fail"; // fail.html 파일로 이동
    }
}

2. 새로운 HTML 파일 생성 (src/main/resources/templates/success.html)

    <h1>로그인 성공</h1>
    <p>title은 <span th:text="${title}">제목</span>이며,</p>
    <p>content는 <span th:text="${content}">내용</span>입니다.</p>
</body>
</html>

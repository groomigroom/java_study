api

API는 Application Programming Interface(응용 프로그램 프로그래밍 인터페이스)의 약자로,
서로 다른 소프트웨어가 서로 통신하고 데이터를 주고받을 수 있게 해주는 규칙이나 도구입니다.
식당에서 손님(클라이언트)이 주문을 하면 웨이터(API)가 주방(서버)에 전달하고 음식을 다시 가져다주는 것과 비슷한 역할을 합니다.
API의 핵심 특징
연결성: 프로그램과 프로그램을 이어줍니다.
규칙 제공: 정해진 방식대로 요청하고 응답을 받게 돕습니다.
은닉성: 내부 작동 방식을 몰라도 기능을 쓸 수 있습니다.
일상 속 API 예시
날씨 앱: 기상청의 데이터를 가져와 화면에 보여줍니다.
지도 연동: 배달 앱에서 가게 위치를 지도에 띄울 때 네이버나 카카오 지도를 불러옵니다.
간편 로그인: 다른 웹사이트에서 '카카오로 로그인'을 누르면 인증 정보를 받아옵니다.

자바 통합개발환경(IDE)의 Add unimplemented methods 
기능은 타입 계층 구조 분석, 추상 메서드 추출, AST(추상 구문 트) 기반 코드 생성 과정을 통해 작동합니다.이 기능의 작동 원리는 다음과 같은 단계로 이루어집니다:상속 및 구현 관계 분석: IDE의 컴파일러 엔진(예: 이클립스 JDT 등)이 현재 클래스가 extends한 부모 클래스나 implements한 인터페이스 정보를 스캔합니다.미구현 메서드 탐색: 부모나 인터페이스에 선언된 메서드 중 현재 클래스에 오버라이딩(구현)되지 않은 abstract 메서드나 미구현 메서드 목록을 추려냅니다.AST 노드 생성 및 삽입: 사용자가 기능을 실행하면 IDE 내부의 AST(추상 구문 트리) 조작기를 통해 선택된 메서드의 시그니처(이름, 반환 타입, 매개변수)를 가진 MethodDeclaration 노드를 동적으로 생성하고 클래스 본문 내부에 추가합니다.코드 포맷팅 및 주석 템플릿 적용: 설정된 코드 스타일에 맞춰 자동으로 들여쓰기와 @Override 어노테이션 등을 붙여 최종 소스 코드 파일에 반영합니다.

노트북 하기

application.properties

자바 스프링(특히 스프링 부트) 프로젝트에서
application.properties
파일은 서버 포트, 데이터베이스 연결 정보, 로그 수준 등 프로젝트 전체의 기본 설정 값들을 '키-값(Key-Value)' 형태로 정의하고 관리하는 핵심 구성 파일입니다. 
이 파일은 주로 src/main/resources 폴더에 위치하며, 코드를 수정하지 않고도 실행 환경에 맞춰 프로그램 동작을 쉽게 바꿀 수 있게 도와줍니다.
주요 역할 및 설정 내용
서버 설정: 웹 서버의 포트 번호(server.port=8080) 등을 지정합니다.
데이터베이스 연결: DB 접속 주소, 사용자 이름, 비밀번호 등을 설정합니다.
로깅 관리: 기록되는 로그의 출력 수준(Debug, Info 등)을 조절합니다.
사용하는 이유
하드코딩 방지: 소스 코드 내부에 중요한 설정 값을 직접 적어두지 않아 보안과 유지보수가 편리합니다.
환경별 분리: 개발, 테스트, 운영(실서비스) 등 환경에 따라 다른 설정 파일을 적용할 수 있습니다.
자동 구성 연동: 스프링 부트가 제공하는 다양한 자동 설정 기능의 기본값을 이 파일을 통해 손쉽게 덮어쓰고 제어할 수 있습니다.

스프링과 스프링 부트 차이???

자바 스프링(Spring)과 스프링 부트(Spring Boot)의 주요 차이점은 설정 방식, 내장 서버 유무, 의존성 관리 방법에 있습니다. 
스프링은 복잡하고 세밀한 설정이 필요한 [기반 프레임워크]이며, 스프링 부트는 이를 쉽고 빠르게 시작할 수 있게 돕는 [확장 도구]입니다.
주요 차이점설정 (Configuration)스프링: XML이나 자바 설정 파일을 통해 수많은 빈(Bean)과 컴포넌트를 개발자가 직접 일일이 설정해야 합니다.
스프링 부트: 자주 사용하는 설정을 미리 자동으로 잡아주는 [자동 설정(Auto-Configuration)] 기능을 제공하여 별도의 복잡한 설정이 필요 없습니다.
서버 (Server)스프링: 톰캣(Tomcat) 같은 외부 웹 서버(WAS)를 따로 설치하고 프로젝트를 WAR 파일로 묶어 배포해야 합니다.
스프링 부트: 톰캣 등의 웹 서버를 [내장(Embedded)]하고 있어 별도의 서버 설치 없이 바로 실행 가능합니다.
의존성 관리 (Dependency)스프링: 필요한 라이브러리마다 버전(Version)을 하나씩 직접 맞추어 복잡하게 관리해야 합니다.
스프링 부트: spring-boot-starter를 통해 호환되는 라이브러리 묶음을 제공하므로 버전 고민 없이 쉽게 추가할 수 있습니다.

분석하기....

Date expiredDate = Date.from(Instant.now().plus(1, ChronoUnit.HOURS));


네, 질문하신 expiredDate 변수의 데이터 타입은 java.util.Date 형 변수가 맞습니다.
작성하신 코드는 Java 8의 최신 날짜 API(Instant)를 사용하여 계산을 수행한 뒤, 최종 결과물만 과거의 java.util.Date 형태로 변환(Conversion)하여 대입하는 방식입니다.
코드의 동작 과정을 한 단계씩 풀어서 설명해 드릴게요.
## 1. 코드 동작 단계별 분석

Date expiredDate = Date.from(Instant.now().plus(1, ChronoUnit.HOURS));


* Instant.now(): 현재 시점의 UTC 기준 시간을 나노초 단위까지 정밀하게 가져옵니다. (Java 8+ 타입)
* .plus(1, ChronoUnit.HOURS): 현재 시간에 정확히 1시간을 더합니다.
* Date.from(...): Java 8 스타일의 Instant 객체를 기존 레거시 타입인 java.util.Date 객체로 변환해 주는 표준 메서드입니다.
* Date expiredDate = ...: 변환 완료된 Date 객체가 좌측의 expiredDate 변수에 담깁니다.

## 2. 왜 이렇게 코드를 작성할까요?
보통 다음 2가지 상황에서 이와 같은 코드를 자주 사용합니다.

* JWT(Json Web Token) 토큰 생성: jjwt 같은 라이브러리는 토큰 만료 시간(Expiration)을 설정할 때 인자값으로 여전히 옛날 java.util.Date 타입을 요구합니다.
* 레거시 라이브러리 연동: 프레임워크나 외부 라이브러리가 최신 날짜 타입을 지원하지 않아서, 계산은 편리하고 정확한 Instant로 처리한 뒤 변환만 해서 넘겨주는 패턴입니다.

## 3. Java 8+ 스타일로만 작성한다면?
만약 java.util.Date를 반드시 써야 하는 제약 조건이 없다면, 아래와 같이 최신 타입으로 변수와 계산을 통일하는 것이 훨씬 직관적이고 깔끔합니다.

// 변수 타입 자체를 LocalDateTime으로 지정
LocalDateTime expiredDate = LocalDateTime.now().plusHours(1);
